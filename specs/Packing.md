## 1. 개요

여행 출발 직전, 배낭에 계획해 둔 장비를 실제로 챙겼는지 하나씩 확인하는 **패킹 모드**.
단순 할 일 목록이 아니라 "배낭이 무게로 차오르는" 경험을 제공한다 — 진행률을 개수와 함께
**챙긴 무게(kg)** 로 보여주는 것이 핵심 차별점. D-1 알림([Notification.md](Notification.md) NT-2)이
유도하는 "여행 전날 앱을 다시 여는" 행동의 랜딩 경험이다.

## 2. 화면 및 진입

```
app/bag/[id]/packing.tsx → BagPackingWrapper → BagPackingView
                                               ├─ BagPackingChromeView (Android·Web 유리 크롬)
                                               ├─ BagPackingHeaderView (진행 유리 카드)
                                               ├─ BagPackingCategorySectionView → BagPackingGearRowView
                                               └─ BagPackingCompleteView (완료 카드)
```

- 진입 경로: 배낭 상세(`/bag/[id]`)의 `패킹 시작` CTA ([BagDetail.md](BagDetail.md) BD-9) → `/bag/[id]/packing` push.
- 도메인 객체: `BagPacking.from(router, bagId)` — `app` 싱글톤에서 `BagStore`·`AnalyticsManager`를 주입받고 `BagDetailFilterManager`로 카테고리 그룹핑 (장비 로드는 `BagStore.getBagWithAllFilter`가 담당하므로 `GearStore` 불필요).

### 화면 문법 (as-built, 2026-08-10 — Liquid Depth)

패킹 모드의 시각만 서술한다. 무엇을 언제 보여주는지는 PK-1~PK-6이 정의한다.

- 지면은 **지형 이미지(0.8) + 앱에서 가장 짙은 베일**이다(.16/.50/.70 — 배낭 상세보다 한 단계 더 누른다). 여기는 읽을 지형이 아니라 **할 일 목록**이라 산세를 가장 많이 가라앉힌다. **라임 글로우는 두지 않는다** — 유리 진행 카드가 지면 최상단(헤더 바로 아래)에 앉아, 모서리 글로우가 카드 뒤에서 얼룩으로 읽힌다.
- 크롬은 지면 위에 뜬 **유리**다: iOS는 네이티브 투명 헤더가 원형 글래스 back + 글래스 바 버튼(`처음부터 다시`)을 내주고(LG-1), Android·Web은 같은 그림을 직접 그린다(원 38 유리 back + 텍스트 유리 알약). 유리 원·알약은 배낭 상세와 **같은 공용 프리미티브**(`components/liquid/LiquidGlassCircleButton`·`LiquidGlassCapsule`)에서 나온다 — 화면마다 따로 그리면 시스템이 아니라 화면별 장식으로 읽힌다. 화면 좌우 여백은 20, 섹션 사이는 26, 목록 카드 사이는 10.
- **진행 유리 카드는 상단에 고정**이고 목록만 그 아래로 흐른다(PK-3). 목록 스크롤 끝에는 공통 하단 여백을 비운다.
- **라임 면은 화면에 하나뿐이다** — 진행률 퍼센트 알약(PK-3). 완료 카드의 체크 표식·행의 체크 원은 **잉크 면 + 라임 글리프**라 라임 면으로 세지 않는다. 라임을 글자색으로 쓰지 않는다.
- 숫자(개수·퍼센트·무게)는 **콘덴스드(Archivo Narrow)**, 한글이 섞이는 값은 본문 서체(Pretendard)를 쓴다 — `처음부터 다시`·`패킹 완료`는 본문 서체다.
- 카테고리 머리글은 큰 제목이 아니라 **대문자 마이크로 라벨**이다.
- 각진 면은 쓰지 않는다(행 카드 20, 유리·완료 카드 26, 알약은 height/2).

## 3. 요구사항

### PK-1 패킹 시작 진입

사용자는 배낭 상세에서 패킹 모드로 들어갈 수 있다.

**수용 기준**

- 배낭 상세 **하단 고정 액션 바의 보조 버튼**으로 진입한다(주 버튼 `수정하기` 왼쪽, 회색 `surfaceMuted`). 스크롤과 무관하게 항상 보인다. ([BagDetail.md](BagDetail.md) BD-9. 기존 우하단 플로팅 버튼은 폐기 — 장비 행을 가리던 문제 해소.)
- **장비가 1개 이상 담긴 배낭에서만** 노출한다 (빈 배낭은 미노출).
- 라벨은 패킹 상태에 따라 달라진다:
  - 패킹 기록 없음 → `패킹 시작`
  - 진행 중(챙긴 장비 1개 이상, 미완료) → `패킹 {n}/{m}`
  - 완료(`packingCompletedAt` 존재) → `패킹 완료` (재진입 가능)
- 탭 → `/bag/[id]/packing` 이동. 터치 타깃 44pt 이상.

### PK-2 패킹 모드 화면

사용자는 배낭의 장비를 카테고리별로 보며 하나씩 "챙김" 처리할 수 있다.

**수용 기준**

- 배낭 상세(BD-1)와 동일한 규칙으로 장비를 카테고리별 그룹핑해 표시한다 (비어 있지 않은 카테고리만, 동일 정렬).
- **행 전체가 탭 타깃**이다 — 체크박스 모양의 별도 컨트롤을 두지 않는다. 탭하면 챙김 ↔ 해제 토글. 우측 체크 원(26)은 상태 **표식**이라 자체 터치 타깃이 아니며, 행은 44pt 이상이다.
- **행 하나가 곧 카드다**(2026-08-10 개정 — 배낭 상세처럼 카테고리를 한 카드에 묶지 않는다). 행마다 면이 갈려야 무엇을 챙겼는지 한눈에 스캔된다.
  - 미체크 = **흰 종이 면 + 그림자**로 떠 있다. 무게는 잉크.
  - 챙김 = **가라앉은 면(`surfaceDone`, 그림자 없음)** + 본문(정체·무게·썸네일) 낮춤. 낮추는 값은 앱 공통 완료 투명도(`doneOpacity`)를 쓴다 — 목록에서 지우지 않고 무게만 빼는 표현을 앱 전체에서 한 값으로 맞춘다([BagDetail.md](BagDetail.md) BD-5와 같은 값).
  - 행 구성은 **좌 정체(브랜드 → 이름) · 우 무게 · 그 오른쪽 체크 원**이다. 무게가 행마다 같은 자리에 와야 장비끼리 비교된다. **행 무게는 장비 개별 무게라 g이고 헤더(PK-3)는 합계라 kg다** — 축이 달라 단위가 다른 것이 맞다([DataModel.md](DataModel.md) DM-26). 무게가 미입력이면 칸을 비우지 않고 `무게 미입력`을 놓는다. 썸네일 규칙은 창고·배낭 상세와 같다([Warehouse.md](Warehouse.md) WH-1) — 사용자가 올린 본인 사진이 있을 때만 좌측에 붙는다.
- 챙긴 장비는 **제자리에서** 시각적으로 가라앉는다(면 전환 + 체크 표시). 리스트 순서를 재배열하지 않는다 — 물건을 찾을 때 위치 기억이 깨지면 안 된다.
- 토글 시 스프링 기반 전환 애니메이션을 준다 (햅틱·진동 없음. 신규 네이티브 의존성 금지 — OTA 배포 가능 범위 유지).
  - 스프링에는 **오버슈트를 걸지 않는다**(`overshootClamping`) — 체크나 진행 바가 목표를 지나쳤다 돌아오면 값이 틀린 것처럼 보인다. 진행 바와 체크 원이 같은 스프링 설정(`LiquidMotion.spring`)을 공유한다.
  - 스프링이 붙는 것은 **체크 원의 채움**(잉크 원 + 라임 체크가 자라남)과 **진행 바**다. 카드 면 색·본문 낮춤은 낙관적 토글과 같은 프레임에서 즉시 바뀐다 — 면 색을 보간하면 중간 상태가 "반쯤 챙긴" 것처럼 읽힌다.
  - 빈 체크 원(1.5px 테두리)은 챙기기 전에도 **항상 보인다** — 이 행이 고를 수 있는 항목임을 드러낸다.
- **접근성(HIG)**: 행은 `accessibilityRole='checkbox'` + `accessibilityState.checked`를 갖고, 라벨은 `{장비명}, {무게}`이며 미입력이면 `{장비명}, 무게 미입력`으로 읽는다(화면과 같은 말 — DM-26) — 챙김 여부를 시각 표기(면·체크)에만 의존하지 않는다.
- 화면은 push로 열리는 전체 화면이며, 뒤로가기로 언제든 이탈 가능하다 (블로킹 아님).

### PK-3 진행률 표시

사용자는 얼마나 쌌는지 개수·퍼센트·무게로 확인할 수 있다.

**수용 기준**

- 상단 고정 **유리 카드** 하나에 같은 사실을 세 방식으로 담는다(2026-08-10 개정 — 지면 위 맨 텍스트가 아니라 떠 있는 면이다):
  - 개수: `{챙긴 수} / {전체 수}` — 챙긴 수가 큰 수치(콘덴스드 52)이고 전체 수는 한 단계 낮춘다. 시선이 먼저 닿아야 하는 값은 챙긴 개수다.
  - 진행 바(퍼센트에 비례, 스프링 트래킹, h8)와 퍼센트 텍스트. 퍼센트는 카드 우측 **라임 알약**이며 이 화면의 유일한 라임 면이다. 유리 면 위라 진행 바 채움은 잉크다.
  - **챙긴 무게**: `{챙긴 장비 무게 합} / {배낭 총 무게}`(예 `4.9kg / 8.4kg`). 표기는 [DataModel.md](DataModel.md) DM-26을 따른다 — 합산은 g로 하고 kg 한 자리로 내며 뒤의 `.0`은 뗀다(2026-08-11 개정: 그전에는 소수 둘째 자리였다). 개수가 아니라 **무게가 차오르는** 감각이 이 앱의 차별점이라 같은 카드에 둔다(§1).
- 무게 합산은 기존 규칙(DM-3 `weight` g 단위, `parseInt`/`Number` 변환 후 합산)을 따른다.
- **진행값의 단일 소스**: `{n}/{m}`·퍼센트는 **현재 로드된 장비 기준 교집합**(`packedGears ∩ gears`)에서만 파생한다(§6 stale ID 규칙). 홈 히어로([Home.md](Home.md) HM-1)·배낭 목록 카드([Bag.md](Bag.md) BAG-1)·이 헤더가 같은 계산을 읽는다 — 세 곳이 어긋나면 안 된다.
- **접근성(HIG)**: 개수 + 퍼센트는 한 덩어리로 읽고(`패킹 {n}/{m}, {p}%`), 무게 줄은 `챙긴 무게 {n}kg, 총 무게 {m}kg`로 읽는다 — `4.9kg / 8.4kg`을 그대로 읽히면 두 값의 뜻이 갈리지 않는다.

### PK-4 패킹 상태 저장·복원

패킹 진행 상태는 배낭에 저장되어 이탈 후 재진입해도 이어진다.

**수용 기준**

- 챙긴 장비 ID 배열을 `bag.packedGears`에 저장한다 ([DataModel.md](DataModel.md) DM-5).
- 토글은 로컬에 즉시 반영(옵티미스틱)하고, 쓰기는 **디바운스(약 800ms) 후 배열 통째로 1회** 수행한다. 화면 이탈·완료 시점에는 미저장분을 즉시 플러시한다.
- 최초 패킹 시작(패킹 기록이 없는 배낭에서 패킹 모드 진입) 시 `packingStartedAt`을 기록한다.
- 재진입 시 `packedGears`를 읽어 체크 상태를 복원한다.
- 헤더 메뉴에 `처음부터 다시`를 제공한다 — 확인 다이얼로그 후 `packedGears`를 비우고 `packingCompletedAt`을 제거한다. (완료 카드가 떠 있는 동안은 노출하지 않는다 — PK-5.)
- 저장 실패는 앱 동작을 막지 않는다 (Firestore 오프라인 persistence로 오프라인에서도 동작, 재접속 시 동기화).

### PK-5 패킹 완료

모든 장비를 챙기면 완료 상태가 된다.

**수용 기준**

- 전체 장비를 챙기면 완료 전환을 표시한다: 진행 바 100% 채움 애니메이션 + 완료 카드.
- 완료 카드는 지면을 어둡힌 막(`scrim`) 위에 뜬 **흰 종이 카드**다(2026-08-10 개정): 잉크 원 + 라임 체크 표식 → `패킹 완료` → 배낭 총 무게(콘덴스드) → 남은 일수 → 잉크 알약 `닫기`. 표식이 잉크 면인 이유는 뒤에 이미 라임 퍼센트 알약이 떠 있어서다(§2 화면 문법 — 라임 면은 화면에 하나).
- 막은 **화면 전체**를 덮는다 — 세이프에어리어 여백까지 포함하고, 카드가 떠 있는 동안 뒤 화면은 만질 수 없다(접근성 포커스도 카드 안에 갇힌다). 카드가 떠 있는 동안 헤더의 `처음부터 다시`는 **내린다**: iOS 네이티브 헤더는 JS 막이 덮지 못해, 남겨 두면 모달 위에서 눌리는 유일한 컨트롤이 된다. 닫으면 다시 나타난다.
- 완료 카드에는 `패킹 완료`, 배낭 총 무게, 출발까지 남은 일수(출발일 지났으면 미표시)를 표시하고 `닫기` 액션만 제공한다:
  - `닫기` → **완료 카드(오버레이)만 닫는다** — 패킹 화면에 남으며, 상세 복귀는 헤더 뒤로가기로 한다
  - (레디샷 만들기 버튼은 제거됨. 배낭 상세의 진입 타일도 같은 시기 제거되어 기능이 도달 불가가 되었고, 2026-07-21 코드·스펙을 함께 제거했다)
- 카드를 닫은 뒤 항목을 해제했다가 다시 전체를 챙기면 완료 카드가 다시 표시된다.
- 완료 시 `packingCompletedAt`을 기록한다.
- 완료 후 항목을 해제해 전체 미만이 되면 완료 상태를 해제한다 (`packingCompletedAt` 제거, 완료 카드 닫힘).

### PK-7 준비물 체크리스트 `[제안 · v1.5 — 이번 구현 범위 제외]`

장비 외 소모품·필수 준비물(물, 음식, 지갑, 차량 키, 보조배터리 등)을 함께 챙길 수 있다.

**설계 방향 (구현 시 상세화)**

- 창고(장비 모델)에 넣지 않는다 — 소유·무게 관리 대상이 아니다. 배낭 문서의 `checklist` 배열(`{ id, name, isPacked }`)로 배낭 단위 저장.
- 패킹 모드 하단에 `준비물` 별도 섹션: 프리셋 칩(물/음식/지갑/차량 키/보조배터리) 탭 추가 + 자유 입력.
- 진행률 **개수에는 포함**, **무게 표시에는 미포함** (장비=무게, 준비물=개수).

## 4. 데이터

- [DataModel.md](DataModel.md) DM-5 `bag` 문서의 `packedGears` / `packingStartedAt` / `packingCompletedAt`.
- 패킹 상태는 여행 후에도 **삭제하지 않고 보존**한다 — 과거 배낭들의 패킹 기록이 곧 히스토리 데이터다(아래 §8 확장).
- 배낭 복사 시 패킹 상태는 복사하지 않는다 ([Bag.md](Bag.md) BAG-4).

## 6. 엣지 케이스

- **빈 배낭**: 진입 CTA 미노출. URL 직접 진입 시 빈 상태 카드 + 뒤로가기. 문구는 **사실 + 다음 걸음 두 줄**이다 — `담긴 장비가 없어요` / `배낭에 장비를 담고 다시 시작해요`(2026-08-10 개정). 이 화면에서는 장비를 담을 수 없으므로 CTA를 두지 않는다(담기는 배낭 상세의 BD-4가 맡는다).
- **삭제된 장비 참조**: `packedGears`에 남은 stale ID는 무시한다 — 진행률·완료 판정은 **현재 로드된 장비 기준**으로만 계산 (BD 상세와 동일 원칙).
- **여행이 끝난 배낭**: CTA·패킹 모드 모두 정상 동작 (남은 일수 표기만 생략).
- **오프라인**: 로컬 반영 + Firestore persistence, 재접속 동기화. 에러 알럿 금지.
- **로딩**: 초기화 전 콘텐츠 미렌더 (BD 편집/useless와 동일). 단 **지면(지형 + 베일)은 먼저 깐다** — 아무것도 렌더하지 않으면 진입 순간 흰 화면이 번쩍인다. 스피너는 쓰지 않는다.

## 7. 수동 검증 체크리스트

- [ ] 장비 있는 배낭 상세 하단 바에 패킹 보조 버튼 노출, 빈 배낭엔 미노출
- [ ] 패킹 버튼이 `수정하기`와 하단 바에 나란히(겹침·장비 행 가림 없음)
- [ ] 행 탭 → 챙김 전환(면 가라앉음 · 본문 낮춤 · 잉크 체크 원 + 라임 체크가 스프링으로 자람), 재탭 → 해제
- [ ] 챙긴 행이 자리를 지킨다(목록 재배열·삭제 없음), 미체크 행은 흰 면 + 그림자로 떠 있다
- [ ] 체크·진행 바 어느 쪽도 목표를 지나쳤다 돌아오지 않는다(오버슈트 없음)
- [ ] 헤더 개수·퍼센트·챙긴 무게가 토글마다 갱신되고, 진행 바가 퍼센트와 어긋나지 않는다
- [ ] 홈 히어로·배낭 목록 카드·패킹 헤더의 `{n}/{m}`이 같은 값
- [ ] 라임 면이 화면에 하나뿐이다(퍼센트 알약) — 체크 원·완료 표식은 잉크 면 + 라임 글리프
- [ ] 목록 끝까지 스크롤 → 마지막 행이 화면 밑단에 붙지 않는다
- [ ] 초기화 중 → 흰 화면 번쩍임 없이 지면(지형 + 베일)이 먼저 보인다
- [ ] 빈 배낭 URL 직접 진입 → `담긴 장비가 없어요` + `배낭에 장비를 담고 다시 시작해요` 두 줄
- [ ] VoiceOver: 행이 체크박스로 읽히고 챙김 여부가 함께 읽힌다. 헤더는 `패킹 {n}/{m}, {p}%` + `챙긴 무게 {n}kg, 총 무게 {m}kg`
- [ ] 중간 이탈 → 재진입 시 상태 복원, 하단 패킹 버튼 라벨 `패킹 n/m`
- [ ] 전체 체크 → 완료 카드(무게·남은 일수), `닫기`는 카드만 닫힘(패킹 화면 유지)
- [ ] 완료 카드가 뜬 동안 막이 상단 헤더·하단 인셋까지 덮고, 헤더 `처음부터 다시`가 사라진다(닫으면 복귀)
- [ ] 완료 후 1개 해제 → 완료 해제
- [ ] `처음부터 다시` → 확인 후 전체 초기화
- [ ] 배낭 복사 → 복사본에 패킹 상태 없음
- [ ] 비행기 모드에서 토글 → 재접속 후 Firestore 반영
- [ ] 웹에서 전 기능 동작(진동 없음), iOS/Android/Web 레이아웃 확인
- [ ] AN-3 패킹 이벤트 4종이 DebugView에 수신

## 8. 확장 로드맵 / 미해결 질문

**이 구조가 여는 확장 (스키마 변경 없이 가능)**

- **자주 빠뜨리는 장비**: 과거 배낭들의 `gears − packedGears` 빈도 집계.
- **지난 여행 대비 누락**: 직전 배낭 `packedGears`와 이번 `gears` 비교.
- **출발 준비율 지표**: `packingCompletedAt` 유무 + `click_packing_exit`의 진행률.
- **useless 연계**: `packedGears ∩ useless` = "챙겼는데 안 쓴 장비" — 앱 정체성 지표 정밀화.

**미해결**

- NT-2 알림의 딥링크를 `/bag/{id}/packing` 직행으로 바꿀지 — 예약 시점에 payload가 고정되므로 변경해도 기존 예약분은 옛 경로 유지. 패킹 모드 안착 후 재논의.
- 항목별 `packedAt`(챙긴 시각) 기록 — v1 미포함. 필요 시 맵 필드로 추가(마이그레이션 불필요).
- **완료 판정 소스 불일치 가능성**: 패킹 완료 후 배낭 편집으로 장비를 추가하면, 목록(BAG-1)은 교집합 퍼센트 기준이라 `패킹 {percent}%`로 되돌아가지만 상세 하단 패킹 버튼(PK-1)은 `packingCompletedAt` 존재 기준이라 `패킹 완료`로 남는다. 실사용 빈도가 낮아 수용 — 거슬리면 gears 변경 시 `packingCompletedAt` 해제 또는 버튼도 퍼센트 기준으로 통일을 검토.
