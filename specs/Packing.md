## 1. 개요

여행 출발 직전, 배낭에 계획해 둔 장비를 실제로 챙겼는지 하나씩 확인하는 **패킹 모드**.
단순 할 일 목록이 아니라 "배낭이 무게로 차오르는" 경험을 제공한다 — 진행률을 개수와 함께
**챙긴 무게(kg)** 로 보여주는 것이 핵심 차별점. D-1 알림([Notification.md](Notification.md) NT-2)이
유도하는 "여행 전날 앱을 다시 여는" 행동의 랜딩 경험이다.

## 2. 화면 및 진입

```
app/bag/[id]/packing.tsx → BagPackingWrapper → BagPackingView
                                               ├─ BagPackingHeaderView (진행률·무게)
                                               ├─ BagPackingCategorySectionView → BagPackingGearRowView
                                               └─ BagPackingCompleteView (완료 카드)
```

- 진입 경로: 배낭 상세(`/bag/[id]`)의 `패킹 시작` CTA ([BagDetail.md](BagDetail.md) BD-9) → `/bag/[id]/packing` push.
- 도메인 객체: `BagPacking.from(router, bagId)` — `app` 싱글톤에서 `BagStore`·`AnalyticsManager`를 주입받고 `BagDetailFilterManager`로 카테고리 그룹핑 (장비 로드는 `BagStore.getBagWithAllFilter`가 담당하므로 `GearStore` 불필요).

## 3. 요구사항

### PK-1 패킹 시작 진입

사용자는 배낭 상세에서 패킹 모드로 들어갈 수 있다.

**수용 기준**

- 배낭 상세 **하단 고정 액션 바의 보조 버튼**으로 진입한다(주 버튼 `수정하기` 왼쪽, 회색 `surfaceMuted`). 스크롤과 무관하게 항상 보인다. ([BagDetail.md](BagDetail.md) BD-9. 기존 우하단 플로팅 버튼은 폐기 — 장비 행을 가리던 문제 해소.)
- **장비가 1개 이상 담긴 배낭에서만** 노출한다 (빈 배낭은 미노출).
- 라벨은 패킹 상태에 따라 달라진다:
  - 패킹 기록 없음 → `패킹 시작`
  - 진행 중(챙긴 장비 1개 이상, 미완료) → `패킹 {n}/{m}`
  - 완료(`packingCompletedAt` 존재) → `패킹 완료` (재진입 가능)
- 탭 → `/bag/[id]/packing` 이동. 터치 타깃 44pt 이상.

### PK-2 패킹 모드 화면

사용자는 배낭의 장비를 카테고리별로 보며 하나씩 "챙김" 처리할 수 있다.

**수용 기준**

- 배낭 상세(BD-1)와 동일한 규칙으로 장비를 카테고리별 그룹핑해 표시한다 (비어 있지 않은 카테고리만, 동일 정렬).
- **행 전체가 탭 타깃**이다 — 체크박스 모양의 별도 컨트롤을 두지 않는다. 탭하면 챙김 ↔ 해제 토글.
- 챙긴 장비는 **제자리에서** 시각적으로 가라앉는다(dim + 체크 표시). 리스트 순서를 재배열하지 않는다 — 물건을 찾을 때 위치 기억이 깨지면 안 된다.
- 토글 시 스프링 기반 전환 애니메이션을 준다 (햅틱·진동 없음. 신규 네이티브 의존성 금지 — OTA 배포 가능 범위 유지).
- 화면은 push로 열리는 전체 화면이며, 뒤로가기로 언제든 이탈 가능하다 (블로킹 아님).

### PK-3 진행률 표시

사용자는 얼마나 쌌는지 개수·퍼센트·무게로 확인할 수 있다.

**수용 기준**

- 상단 고정 헤더에 다음을 표시한다:
  - 개수: `{챙긴 수} / {전체 수}`
  - 진행 바(퍼센트에 비례, 스프링 트래킹)와 퍼센트 텍스트
  - **챙긴 무게**: `{챙긴 장비 무게 합}kg / {배낭 총 무게}kg` (kg, 소수점 둘째 자리 반올림 — BD-5 `usedWeight` 표기 규칙과 동일)
- 무게 합산은 기존 규칙(DM-3 `weight` g 단위, `parseInt`/`Number` 변환 후 합산)을 따른다.

### PK-4 패킹 상태 저장·복원

패킹 진행 상태는 배낭에 저장되어 이탈 후 재진입해도 이어진다.

**수용 기준**

- 챙긴 장비 ID 배열을 `bag.packedGears`에 저장한다 ([DataModel.md](DataModel.md) DM-5).
- 토글은 로컬에 즉시 반영(옵티미스틱)하고, 쓰기는 **디바운스(약 800ms) 후 배열 통째로 1회** 수행한다. 화면 이탈·완료 시점에는 미저장분을 즉시 플러시한다.
- 최초 패킹 시작(패킹 기록이 없는 배낭에서 패킹 모드 진입) 시 `packingStartedAt`을 기록한다.
- 재진입 시 `packedGears`를 읽어 체크 상태를 복원한다.
- 헤더 메뉴에 `처음부터 다시`를 제공한다 — 확인 다이얼로그 후 `packedGears`를 비우고 `packingCompletedAt`을 제거한다.
- 저장 실패는 앱 동작을 막지 않는다 (Firestore 오프라인 persistence로 오프라인에서도 동작, 재접속 시 동기화).

### PK-5 패킹 완료

모든 장비를 챙기면 완료 상태가 된다.

**수용 기준**

- 전체 장비를 챙기면 완료 전환을 표시한다: 진행 바 100% 채움 애니메이션 + 완료 카드.
- 완료 카드에는 `패킹 완료`, 배낭 총 무게, 출발까지 남은 일수(출발일 지났으면 미표시)를 표시하고 `닫기` 액션만 제공한다:
  - `닫기` → **완료 카드(오버레이)만 닫는다** — 패킹 화면에 남으며, 상세 복귀는 헤더 뒤로가기로 한다
  - (레디샷 만들기 버튼은 제거됨. 배낭 상세의 진입 타일도 같은 시기 제거되어 기능이 도달 불가가 되었고, 2026-07-21 코드·스펙을 함께 제거했다)
- 카드를 닫은 뒤 항목을 해제했다가 다시 전체를 챙기면 완료 카드가 다시 표시된다.
- 완료 시 `packingCompletedAt`을 기록한다.
- 완료 후 항목을 해제해 전체 미만이 되면 완료 상태를 해제한다 (`packingCompletedAt` 제거, 완료 카드 닫힘).

### PK-6 클릭 로그

- [Analytics.md](Analytics.md) AN-3의 "패킹" 표에 정의된 이벤트를 각 트리거에서 전송한다. 화면 조회(`bag/[id]/packing`)는 AN-2가 자동 수집.

### PK-7 준비물 체크리스트 `[제안 · v1.5 — 이번 구현 범위 제외]`

장비 외 소모품·필수 준비물(물, 음식, 지갑, 차량 키, 보조배터리 등)을 함께 챙길 수 있다.

**설계 방향 (구현 시 상세화)**

- 창고(장비 모델)에 넣지 않는다 — 소유·무게 관리 대상이 아니다. 배낭 문서의 `checklist` 배열(`{ id, name, isPacked }`)로 배낭 단위 저장.
- 패킹 모드 하단에 `준비물` 별도 섹션: 프리셋 칩(물/음식/지갑/차량 키/보조배터리) 탭 추가 + 자유 입력.
- 진행률 **개수에는 포함**, **무게 표시에는 미포함** (장비=무게, 준비물=개수).

## 6. 엣지 케이스

- **빈 배낭**: 진입 CTA 미노출. URL 직접 진입 시 빈 상태 문구 + 뒤로가기.
- **삭제된 장비 참조**: `packedGears`에 남은 stale ID는 무시한다 — 진행률·완료 판정은 **현재 로드된 장비 기준**으로만 계산 (BD 상세와 동일 원칙).
- **여행이 끝난 배낭**: CTA·패킹 모드 모두 정상 동작 (남은 일수 표기만 생략).
- **오프라인**: 로컬 반영 + Firestore persistence, 재접속 동기화. 에러 알럿 금지.
- **로딩**: 초기화 전 미렌더 (BD 편집/useless와 동일).

## 7. 수동 검증 체크리스트

- [ ] 장비 있는 배낭 상세 하단 바에 패킹 보조 버튼 노출, 빈 배낭엔 미노출
- [ ] 패킹 버튼이 `수정하기`와 하단 바에 나란히(겹침·장비 행 가림 없음)
- [ ] 행 탭 → 챙김 전환(dim·체크·애니메이션), 재탭 → 해제
- [ ] 헤더 개수·퍼센트·챙긴 무게가 토글마다 갱신
- [ ] 중간 이탈 → 재진입 시 상태 복원, 하단 패킹 버튼 라벨 `패킹 n/m`
- [ ] 전체 체크 → 완료 카드(무게·남은 일수), `닫기`는 카드만 닫힘(패킹 화면 유지)
- [ ] 완료 후 1개 해제 → 완료 해제
- [ ] `처음부터 다시` → 확인 후 전체 초기화
- [ ] 배낭 복사 → 복사본에 패킹 상태 없음
- [ ] 비행기 모드에서 토글 → 재접속 후 Firestore 반영
- [ ] 웹에서 전 기능 동작(진동 없음), iOS/Android/Web 레이아웃 확인
- [ ] AN-3 패킹 이벤트 4종이 DebugView에 수신

## 8. 확장 로드맵 / 미해결 질문

**이 구조가 여는 확장 (스키마 변경 없이 가능)**

- **자주 빠뜨리는 장비**: 과거 배낭들의 `gears − packedGears` 빈도 집계.
- **지난 여행 대비 누락**: 직전 배낭 `packedGears`와 이번 `gears` 비교.
- **출발 준비율 지표**: `packingCompletedAt` 유무 + `click_packing_exit`의 진행률.
- **useless 연계**: `packedGears ∩ useless` = "챙겼는데 안 쓴 장비" — 앱 정체성 지표 정밀화.

**미해결**

- NT-2 알림의 딥링크를 `/bag/{id}/packing` 직행으로 바꿀지 — 예약 시점에 payload가 고정되므로 변경해도 기존 예약분은 옛 경로 유지. 패킹 모드 안착 후 재논의.
- 항목별 `packedAt`(챙긴 시각) 기록 — v1 미포함. 필요 시 맵 필드로 추가(마이그레이션 불필요).
- **완료 판정 소스 불일치 가능성**: 패킹 완료 후 배낭 편집으로 장비를 추가하면, 목록(BAG-1)은 교집합 퍼센트 기준이라 `패킹 {percent}%`로 되돌아가지만 상세 하단 패킹 버튼(PK-1)은 `packingCompletedAt` 존재 기준이라 `패킹 완료`로 남는다. 실사용 빈도가 낮아 수용 — 거슬리면 gears 변경 시 `packingCompletedAt` 해제 또는 버튼도 퍼센트 기준으로 통일을 검토.
