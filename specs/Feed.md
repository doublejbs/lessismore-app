## 1. 개요

탐색 탭을 "찾으러 오는 도구"에서 **"구경하러 오는 피드"**로 바꾼다. 인스타그램처럼 장비 카드가 세로로 이어지는 무한 피드를 제공하고, 사용자의 창고 구성(카테고리·브랜드 취향)에 맞춰 관심 있을 만한 장비를 우선 노출한다. 카테고리·브랜드 필터로 피드를 좁힐 수 있다.

- 서버/ML 없이 **클라이언트 개인화**: 관심 신호는 사용자의 창고 보유 장비 분포에서 추출하고, 후보는 Algolia(정렬 replica + facet, [DataModel.md](DataModel.md) DM-10)에서 소싱한다.
- 탐색 홈(Search.md SR-6)을 대체한다 — 피드 출시 시 SR-6은 `[폐기]` 처리. SR-7(목록)·SR-8(브랜드 디렉토리)·SR-9(신제품)의 데이터 계층(browse/BrandRankStore)은 피드가 재사용한다.

## 3. 요구사항

### FD-1 피드 구성과 개인화

**수용 기준**

- 피드는 다음 4개 버킷을 섞어 구성한다(기본 비율 4:2:2:2, 노출 순서는 인터리브):
  1. **관심 카테고리** — 사용자 창고(카탈로그 출신 장비)의 카테고리 분포 상위 2개 카테고리의 인기순(count desc)
  2. **관심 브랜드** — 창고 브랜드 분포 상위 2개 브랜드의 장비 (인기순, companyKorean·company OR facet)
  3. **전체 인기** — count desc
  4. **신제품** — createDate desc
- **제외 규칙**: 내 창고에 이미 있는 장비, 중복(같은 id는 1회). (구 `imageUrl` 유효성 제외는 장비 이미지 미제공 원칙([DataModel.md](DataModel.md) §1)으로 삭제 — 카탈로그 전체가 피드 후보가 된다.)
- **콜드스타트**(비로그인 또는 창고 비어 있음): 버킷 3+4만으로 구성(비율 6:4).
- 버킷 소싱은 Algolia 정렬 replica + facet을 사용한다. 각 버킷은 자신의 다음 페이지를 `Promise.all`로 병렬 요청하며(큐가 비었고 페이지가 남은 버킷만), 버킷별 페이지를 독립 진행해 무한 스크롤을 지원한다. 요청 경합은 요청 토큰(`requestId`)으로 방어해 늦게 도착한 이전 요청 결과를 폐기한다.
- **셔플**: 새로고침 시점의 시드로 인터리브 순서를 흔들되, 스크롤 중에는 순서가 바뀌지 않는다(세션 내 안정).
- 개인화 신호(카테고리·브랜드 분포)는 앱 내 데이터만 사용하고 외부로 전송하지 않는다.

### FD-2 피드 카드

**수용 기준**

- 피드는 **2컬럼 그리드**로 표시한다(`FlatList numColumns={2}`, 컬럼 간 균등 간격). 마지막 홀수 카드는 좌측 정렬(빈 칸 우측).
- **텍스트 카드** — 장비 이미지 미제공 원칙([DataModel.md](DataModel.md) §1)에 따라 이미지 없이 카드 면을 만든다: 카드 배경 `inputBg` + radius 8의 텍스트 블록. 구성(위→아래): 브랜드(`Gear.getDisplayCompany()` — **제품명과 동일한 타이포**, [Warehouse.md](Warehouse.md) WH-1 공통 규칙) → 이름(`getDisplayName()`, 2줄까지) → **색상**(있을 때만) → **무게(`n g`)가 카드의 시각 앵커**(카드에서 가장 큰 활자 — 이미지가 하던 위계를 무게가 대신한다). 카드 높이는 콘텐츠 기준(정방형 강제 없음), 그리드 리듬은 카드 면(배경)이 유지한다.
  - **색상**: `Gear.getDisplayColor()`(= `colorKorean || color`)를 이름 아래 한 줄(1줄 말줄임, `textSecondary`)로 표시하고, 값이 비면 줄 자체를 렌더하지 않는다 — 같은 제품의 컬러 배리언트가 카드로 나란히 뜨는 경우가 많아 색상 없이는 서로 구분되지 않는다. 창고 목록([Warehouse.md](Warehouse.md) WH-1)과 **위치는 같고**(이름 아래) **톤은 각 화면 규칙을 따른다**(피드 12/`textSecondary`, 창고 목록 13/`textTertiary`).
  - **표시 접근자는 두 화면 모두 `getDisplayColor()`로 통일한다** — 창고 목록이 쓰던 `getColor()`는 원본 값이라 같은 장비가 창고에서 `BLACK`, 피드에서 `블랙`으로 갈렸다.
  - 이 카드는 검색 결과([Search.md](Search.md) SR-2)도 그대로 재사용하므로, 색상은 두 화면에 동시에 반영된다.
- **창고 담기 CTA**: 카드 우상단 원형 버튼(2컬럼에 맞게 크기 축소하되 터치 타깃 확보). 기존 SR-2/SR-3 규칙 재사용 — 미보유 `+` → 창고 등록 + 배낭 담기 모달, 보유 체크 배지 → 제거 경고. 비로그인 `+` → 로그인 모달.
- `coupangUrl`이 있는 장비는 카드 하단에 **`쿠팡 최저가 ›`**(2컬럼 폭에 맞춘 축약 라벨) 텍스트 링크 노출. 수수료 고지는 카드마다 반복하지 않고 **리스트 푸터에서 1회** 노출한다(GD-5 고지 취지 유지).
  - **쿠팡 링크가 실제로 붙은 카드가 하나라도 있을 때만 고지를 노출한다.** 링크가 하나도 없는 목록에까지 문구가 뜨면 무엇에 대한 고지인지 알 수 없다.
  - `coupangUrl`은 Algolia hit·`Gear`에 없고 `/gear` 문서에만 있어 **카드가 마운트 후 지연 로드**한다. 부모가 미리 알 수 없으므로 **카드가 링크를 얻으면 부모에 알리고**, 부모가 그 신호로 고지를 켠다.
  - **한 번 켜지면 되돌리지 않는다.** 필터·검색어를 바꿔 링크 없는 목록이 와도 고지는 남는다 — 이미 제휴 링크를 노출한 화면이고, 추가 로드(페이지네이션)마다 초기화하면 이미 마운트된 카드가 다시 알려주지 않아 고지가 사라진다. 과다 고지가 미고지보다 안전하다.
  - 같은 규칙을 **검색 결과 화면(SR-2)** 도 따른다 — 같은 카드 컴포넌트를 쓴다.
- 카드 탭 → `/gear-detail/{id}`.
- 담기/제거 후에도 피드 스크롤 위치는 유지된다(전체 리로드 금지).

### FD-3 필터 (카테고리 칩 + 브랜드·정렬 컨트롤)

피드 **상단에 고정 필터 바**를 둔다. 위계상 **카테고리**를 주 축(칩 행)으로 노출하고, 보조 축인 **브랜드**(진입 버튼)·**정렬**(드롭다운)은 그 아래 컨트롤 행에 둔다. 정렬은 카테고리보다 덜 바꾸는 축이라 칩 행 대신 우측 드롭다운으로 강등해 위계를 분명히 한다.

**수용 기준**

- **상단 필터 바**(피드 리스트 위 고정, 항상 노출) — 카테고리 칩 행(주) + 컨트롤 행:
  - **카테고리 칩 행**: `전체` + 11개 카테고리 칩(가로 스크롤) — 단일 선택, 탭 시 **즉시 적용**(스테이징 없음), 재탭/`전체`로 해제.
  - **컨트롤 행**(카테고리 행 아래, 좌우 정렬): 좌측 `브랜드` 진입 버튼(아이콘 + 선택 브랜드 수 표기, 예 `브랜드 2`) → 브랜드 시트 / 우측 `정렬` 드롭다운(현재 정렬 라벨 + `⌄`, 예 `가벼운순 ⌄`) → 정렬 시트.
- **정렬 시트**(우측 드롭다운 탭 → 오픈, **공용 네이티브 formSheet 라우트 `/sort-sheet`**): `추천`(기본) · `인기순` · `최신순` · `가벼운순` · `무거운순` 목록 — 단일 선택, 현재 정렬 **체크(✓)**. 항목 탭 = **즉시 적용 후 닫힘**(스테이징 없음). 세 화면(피드·탐색·창고)이 같은 라우트를 공유하며, 트리거가 `router.push` 직전 옵션·현재값·onSelect 콜백을 모듈 핸드오프에 넣고 라우트가 그걸 렌더한다(뷰 스코프 인스턴스라 props 대신 콜백 위임). 그래버·드래그 닫기·높이(`fitToContents`)는 OS가 처리(배낭 추가 시트와 동일). `추천`은 개인화 믹스(기본), 나머지는 해당 정렬 replica로 **단일 정렬 목록**(개인화·6:4 믹스 대신). 정렬 시 카테고리·브랜드 facet은 함께 적용.
- **`가벼운순`은 `1,000건 상한까지 실제 무게 오름차순, 그 뒤에 0g`으로 노출한다.** 카탈로그의 `weight: 0`은 "가장 가벼움"이 아니라 **무게 미입력**이고(대부분 의류 — 오히려 무거운 제품이라 무게가 판단에 큰 의미다), 0g 비중이 커서 replica를 그대로 쓰면 페이지 상한 안이 전부 0g으로 채워져 정렬이 사실상 동작하지 않는다(수치는 §8 실측 참고).
  - 구현: `가벼운순`만 **2단 페이지네이션**으로 조회한다. 1단은 `weight > 0`(numericFilter)으로 실제 무게 오름차순을 **페이지 상한까지** 넘기고, 상한에 닿으면 2단으로 `weight = 0`을 이어 붙인다. 즉 0g은 목록 맨 뒤가 아니라 **가장 가벼운 1,000건 뒤**에 온다(상한이 인덱스 전체보다 작아 1단을 "끝까지" 넘길 수는 없다). 0g끼리의 순서는 의미가 없어 별도 정렬을 두지 않는다.
  - `page`는 두 단계를 관통하는 연속 인덱스이며, 호출자(피드 버킷·SR-7 목록)는 단계를 모른다. **1단/2단 경계는 요청 page와 무관하게 필터 조합(카테고리+브랜드)별로 한 번만 계산해 재사용한다** — 페이지 응답의 `nbPages`로 잡거나 매 요청 다시 세면 상한 밖 응답(빈 결과)·비exhaustive 건수 추정 때문에 경계가 밀려, 목록이 빈 채로 끊기거나 같은 장비가 중복으로 붙는다.
  - `weight` 속성이 아예 없는 레코드는 두 단계 모두에 걸리지 않는다(실측상 극소수 — 전제로 기록한다).
  - `무거운순`은 0g이 자연히 뒤로 가므로 손대지 않는다. Algolia 인덱스 설정(replica·custom ranking) 변경은 admin 키가 필요해 클라이언트 조회로 해결한다.
- **브랜드 시트**(`브랜드` 버튼 탭 → 오픈, **iOS 네이티브 pageSheet 프레젠테이션**): RN `Modal presentationStyle='pageSheet'`로 표시한다 — 카드 슬라이드·스와이프 다운 닫기·라운드 코너·백드롭은 OS가 처리하므로 커스텀 딤/제스처/reanimated는 두지 않는다. **단 핸들바와 닫기는 둔다**(2026-07-31 정정) — pageSheet는 `formSheet`와 달리 **OS 그래버를 그리지 않아** 스와이프로 닫히는데도 어포던스가 안 보였고, 하단이 `확인` 하나뿐이라 **적용하지 않고 나가는 길이 스와이프뿐**이었다. 상단에 공용 `SheetGrabberView` + 헤더 우측 닫기(×, `초기화` 옆)를 두며, 닫기는 스와이프 닫힘과 같은 취소 경로(스테이징 폐기)다. 스와이프 닫힘 시 `onDismiss`(iOS)로 부모 `visible`을 초기화한다(취소 경로 = 스테이징 폐기). 브랜드명 검색 입력 + brand-rank 인기순 목록(SR-8 로직 재사용) — **복수 선택**(행 탭 토글, 선택 행은 **체크(✓) 아이콘**으로 강조). 행에는 브랜드명만 노출하고 **제품 수(`제품 n`)는 표시하지 않는다**(브랜드 디렉토리 SR-8과 달리 필터 맥락에선 불필요 — `BrandRowView`의 `showCount={false}`). 선택은 시트 안에서 **스테이징**되고 하단 고정 `확인`으로 일괄 적용된다:
  - **선택 브랜드 요약 칩**: 검색 입력 아래에 선택된 브랜드를 제거(✕) 가능한 칩으로 나열 — 검색 중 목록에서 선택 브랜드가 사라져도 선택 상태를 항상 확인·해제할 수 있다.
  - 헤더 우측 `초기화`: 브랜드 스테이징 전체 해제(적용은 `확인` 시점).
  - **하단 고정 `확인` 버튼**(잉크 알약, 전체 폭 — 공용 `LiquidPillButton` `primary`/`block`): 스테이징을 적용하고 닫는다. 선택이 있으면 라벨에 개수 표기(`확인 (3)`), 변경 없으면 그냥 닫힘.
  - 브랜드 검색 입력 포커스 시 키보드가 목록·확인 버튼을 덮지 않도록 키보드 회피 처리(배낭 담기 모달과 동일).
  - 스와이프 다운 닫기/뒤로가기 = **취소**(스테이징 폐기, 기존 적용 브랜드 유지).
  - **시트 문법**(2026-08-11 개정, Liquid Depth): 시트 면은 **지면(`canvas`)**이고 브랜드 행이 각자 종이 카드로 놓인다(유리 면 위에 흰 카드를 얹으면 두 면이 겹쳐 카드 경계가 사라진다 — 배낭 선택 시트 [CampSite.md](CampSite.md) CS-5와 같은 판단). 제목은 `title3`, 검색 입력은 공용 **유리 검색 필드**(`LiquidSearchField` — 창고 검색 WH-8·브랜드 디렉토리 SR-8과 같은 컴포넌트), 선택 행 표식은 **체크 원**(잉크 면 + 라임 `checkmark`)이다([Search.md](Search.md) SR-8 행 문법).
  - **선택 요약 칩**은 선택 칩과 같은 **잉크 채움**(높이 32 · 완전한 알약)에 지우기 글리프를 붙인다 — 칩 자체가 해제 버튼이라 스크린리더 롤은 `button`이고, 44pt는 세로 `hitSlop`으로 채운다.
  - 로딩은 **브랜드 행 스켈레톤**이다([Search.md](Search.md) SR-8) — 장비 행 스켈레톤을 쓰면 도착 후 목록이 통째로 줄어든다. 이 시트의 행은 `제품 n` 줄이 없으므로 스켈레톤도 한 줄이다(`showMeta={false}`).
  - 목록 빈 상태는 사실 + 다음 걸음 두 줄이며 원인마다 갈린다(브랜드 디렉토리 SR-8과 같은 두 갈래): 검색어가 있으면 `찾는 브랜드가 없어요` / `이름을 다시 확인해볼까요?`, 아직 아무 브랜드도 못 받았으면(로드 실패 포함 — `brand-rank` 실패도 빈 배열로 온다) `아직 브랜드가 없어요` / `잠시 뒤에 다시 열어볼까요?`.
- 필터 적용 시 피드 재구성: 정렬 지정 시 단일 정렬 버킷, 미지정(추천)+필터 시 인기순 6 : 신제품 4, 개인화 버킷 비활성. 카테고리+브랜드 동시 적용 가능. **복수 브랜드는 OR** — Algolia facetFilters의 같은 내부 배열에 모든 선택 브랜드의 `companyKorean`·`company` 값을 나열해 매칭.
- `브랜드` 진입 버튼 개수 = 선택 브랜드 수(카테고리는 칩 선택 상태로, 정렬은 드롭다운 라벨로 표시하므로 개수에 미포함).
- **검색 승계**: 탐색 검색어 입력 시에도 현재 카테고리·브랜드 필터가 검색 결과에 같은 facet 규칙으로 적용된다([Search.md](Search.md) SR-1). 이를 위해 피드 도메인 객체는 탐색 탭(검색 화면) 수준에서 생성·공유되어, 검색어 입력으로 피드가 화면에서 내려가도 필터 상태가 유지되고 검색어를 지우면 같은 필터의 피드로 돌아온다. 검색 결과 화면에도 필터 바(카테고리 칩 + 브랜드 버튼)를 유지 노출하고 변경 즉시 재검색하며, 정렬 드롭다운은 검색 중 숨긴다.
- 필터 결과 없음: `장비가 없습니다`.
- **필터·정렬 변경 시 스켈레톤 + 스크롤 리셋**: 카테고리·브랜드·정렬을 바꿔 피드를 재구성할 때는 기존 목록을 즉시 비워 스켈레톤을 노출한다(`reload()`가 로딩 시작과 함께 items를 비움 → 리스트가 최상단부터 리마운트). 이로써 리스트를 아래로 내려 보던 중 필터를 바꿔도 스크롤이 항상 최상단으로 리셋된다. 담기/제거·당겨서 새로고침(`refresh()`)은 이 경로를 타지 않아 스크롤 위치가 유지된다(FD-2).
- **인기 순위 진입점**([Search.md](Search.md) SR-4): 피드 하단 플로팅 버튼 `인기 순위` → 인기 장비 순위 화면(기존 SR-4 화면 재사용). **현재 선택된 카테고리 필터를 승계**해 그 카테고리 순위를 바로 보여준다(라우트 파라미터 `?category=<GearFilter>`; 순위 화면 8개 탭에 없는 카테고리·전체·미선택은 `전체`로 진입 — SR-4). 구 하단 중앙 플로팅 `필터` 버튼은 상단 바로 대체되어 **제거**한다.
  - **스켈레톤 중에는 숨긴다**: 최초 진입 스켈레톤 위에는 플로팅 `인기 순위` 버튼을 렌더하지 않고, 피드가 로드된 뒤에만 노출한다. 탭이 막 마운트된 첫 프레임에는 네이티브 탭바 몫이 반영되기 전이라 `insets.bottom`이 작게 잡혀 버튼이 탭바 뒤로 내려가기 때문이며, 로드 시점엔 inset이 정착해 위치가 정확하다.

### FD-4 새로고침·페이지네이션

**수용 기준**

- **pull-to-refresh**: 시드 재생성 + 버킷 페이지 초기화 → 새 믹스. 스피너는 RN 기본 RefreshControl.
- **무한 스크롤**: 하단 근접 시 버킷별 다음 페이지 로드·인터리브 이어붙임. 모든 버킷 소진 시 중단(별도 "끝" UI 없음).
- 로딩: 최초 진입은 도착할 카드와 같은 2열 스켈레톤(`FeedSkeletonView` — 검색 결과와 공유), 추가 로드는 하단 스피너. 목록형 행 스켈레톤(`SearchSkeletonView`)은 탐색 목록(SR-7)의 것이라 여기 쓰지 않는다 — 골격이 달라 로드 후 레이아웃이 튄다.
- 요청 경합: 늦게 도착한 이전 요청 폐기(요청 토큰 — browse와 동일 패턴).

### FD-5 애널리틱스

**수용 기준**

- 카드 탭(`click_feed_card`), 담기(`click_feed_add`), 쿠팡 링크(`click_feed_coupang`), 브랜드 시트 진입(`click_feed_brand`), 정렬 시트 진입(`click_feed_sort`), 필터 적용(`click_feed_filter_apply` — 카테고리 칩 즉시 적용, 브랜드 시트 `확인`, 정렬 시트 항목 선택, 파라미터 `category`·`brand_count`·`sort`), 브랜드 초기화(`click_feed_filter_reset`), 인기 순위 진입(`click_feed_ranking`), 새로고침(`click_feed_refresh`)을 [Analytics.md](Analytics.md) AN 규약(스네이크 케이스·40자·식별정보 금지)으로 계측하고 AN-3 표에 등록한다.
- 카테고리는 칩에서 즉시, 브랜드는 시트 `확인`으로, 정렬은 시트 항목 선택으로 적용된다. 모든 적용은 공통 `click_feed_filter_apply`(파라미터 `category`·`brand_count`·`sort`)로 관찰하며, 개별 선택 이벤트는 두지 않는다. 시트 진입만 `click_feed_brand`·`click_feed_sort`로 계측한다.

## 6. 엣지 케이스

- **비로그인**: 피드 노출(콜드스타트 믹스), 담기만 로그인 모달.
- **Algolia 실패**: 빈 배열 + 재시도 없이 조용히(SR 엣지 정책). 최초 로드 실패 시 빈 상태 문구.
- **창고 5개 미만**: 관심 분포가 빈약 — 콜드스타트 믹스로 폴백(임계값: 카탈로그 출신 3개 미만).
- **색상 없는 장비**: 카드에서 색상 줄 자체를 렌더하지 않는다(빈 줄·플레이스홀더 없음, FD-2).
- **무게 미입력(0g)**: 카드에서 무게 줄을 노출하지 않고, `가벼운순`에서는 1단(실제 무게) 뒤 2단 구간에 붙는다(FD-3).

## 8. 결정 사항 / 미해결 질문

**결정됨 (2026-07-07)**

- 피드 위치: **탐색 탭 키워드-빈 화면 교체** (검색 전환은 현행 유지).
- 카드 구성: 기본(이미지·브랜드·이름·무게) + 창고 담기 CTA + 쿠팡 최저가 링크.
- SR-7 목록·SR-8 브랜드 디렉토리 화면: **일단 유지** (피드 반응을 보고 폐기 여부 재결정).
- 버킷 비율 4:2:2:2, 관심 상위 카테고리/브랜드 2/2: **초기값으로 확정** — 사용 데이터 보고 조정.

**결정됨 (2026-07-28)**

- **장비 이미지 미제공**([DataModel.md](DataModel.md) §1): 카드를 텍스트 카드로 개편(FD-2), `imageUrl` 제외 규칙 삭제(FD-1). 쿠팡 링크·담기 CTA·개인화 믹스는 그대로 유지 — **커머스는 이미지와 분리해 계속 간다**(고의도 동선은 장비 상세 GD-5).

**실측 (2026-07-29)** — 아래 수치는 실측값이라 카탈로그·인덱스 설정이 바뀌면 낡는다. FD-3의 동작 규칙은 수치에 의존하지 않게 서술한다.

- Algolia 인덱스 `useless-gear-search`: 전체 **37,423건**, `weight = 0`(무게 미입력) **7,887건**(둘 다 exhaustive). `weight > 0`은 쿼리에 따라 `nbHits` 약 **20,921~29,644**로 보고된다(비exhaustive 추정치라 요청마다 흔들린다 — FD-3 경계를 조합별로 한 번만 계산하는 이유).
- `paginationLimitedTo` = **1,000**. `hitsPerPage: 100`이면 `nbPages`가 **10으로 클램프**되고, 상한을 넘는 page 요청은 에러가 아니라 `hits: []`·`nbHits: 0`·`nbPages: 0`을 반환한다. 그래서 FD-3 2단 경계는 응답의 `nbPages`가 아니라 코드 상수(`ALGOLIA_PAGINATION_LIMIT / 페이지 크기`)로 계산한다.
- `weight` 속성이 아예 없는 레코드는 위 세 수치 차이만큼(최대 몇 건 수준) 존재할 수 있고, 1단·2단 어디에도 걸리지 않는다.
