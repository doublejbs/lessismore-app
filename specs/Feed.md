## 1. 개요

탐색 탭을 "찾으러 오는 도구"에서 **"구경하러 오는 피드"**로 바꾼다. 인스타그램처럼 장비 카드가 세로로 이어지는 무한 피드를 제공하고, 사용자의 창고 구성(카테고리·브랜드 취향)에 맞춰 관심 있을 만한 장비를 우선 노출한다. 카테고리·브랜드 필터로 피드를 좁힐 수 있다.

- 서버/ML 없이 **클라이언트 개인화**: 관심 신호는 사용자의 창고 보유 장비 분포에서 추출하고, 후보는 Algolia(정렬 replica + facet, [DataModel.md](DataModel.md) DM-10)에서 소싱한다.
- 탐색 홈(Search.md SR-6)을 대체한다 — 피드 출시 시 SR-6은 `[폐기]` 처리. SR-7(목록)·SR-8(브랜드 디렉토리)·SR-9(신제품)의 데이터 계층(browse/BrandRankStore)은 피드가 재사용한다.

## 3. 요구사항

### FD-1 피드 구성과 개인화

**수용 기준**

- 피드는 다음 4개 버킷을 섞어 구성한다(기본 비율 4:2:2:2, 노출 순서는 인터리브):
  1. **관심 카테고리** — 사용자 창고(카탈로그 출신 장비)의 카테고리 분포 상위 2개 카테고리의 인기순(count desc)
  2. **관심 브랜드** — 창고 브랜드 분포 상위 2개 브랜드의 장비 (인기순, companyKorean·company OR facet)
  3. **전체 인기** — count desc
  4. **신제품** — createDate desc
- **제외 규칙**: 내 창고에 이미 있는 장비, 중복(같은 id는 1회). (구 `imageUrl` 유효성 제외는 장비 이미지 미제공 원칙([DataModel.md](DataModel.md) §1)으로 삭제 — 카탈로그 전체가 피드 후보가 된다.)
- **콜드스타트**(비로그인 또는 창고 비어 있음): 버킷 3+4만으로 구성(비율 6:4).
- 버킷 소싱은 Algolia 정렬 replica + facet을 사용한다. 각 버킷은 자신의 다음 페이지를 `Promise.all`로 병렬 요청하며(큐가 비었고 페이지가 남은 버킷만), 버킷별 페이지를 독립 진행해 무한 스크롤을 지원한다. 요청 경합은 요청 토큰(`requestId`)으로 방어해 늦게 도착한 이전 요청 결과를 폐기한다.
- **셔플**: 새로고침 시점의 시드로 인터리브 순서를 흔들되, 스크롤 중에는 순서가 바뀌지 않는다(세션 내 안정).
- 개인화 신호(카테고리·브랜드 분포)는 앱 내 데이터만 사용하고 외부로 전송하지 않는다.

### FD-2 피드 목록 행

**수용 기준** (2026-08-11 레퍼런스 이식 이후. 이 이전 세대는 아래 `[이력]` 참고)

- **지면은 순백**(`Acg.paper`)이고 텍스처가 없다. 탐색 탭은 공통 지면(`AcgScreenBackground` — 회색 + 그레인 + 지형 마크)을 쓰지 않고 흰 면을 직접 깐다.
- **검색 필드**는 화면 최상단, 좌우 여백 16. **연회색 채움 알약**(`Acg.controlFill`, 최소 높이 56, radius full, **테두리·유리·그림자 없음**) 안에 좌측 돋보기 24pt(잉크) → 플레이스홀더 17pt(`Acg.textMuted`) 순. 입력값도 17pt 잉크. 장비 추가 검색 시트는 기존 유리 면을 유지하므로 필드 톤은 `SearchBarVariant`로 갈린다(기본 `Glass`, 탐색 탭만 `Plain`).
- 목록은 **2열 그리드**다(`FlatList numColumns={2}`). 화면 좌우 여백 16, 열 사이 16, 행 사이 24. 레퍼런스가 단일 컬럼인 이유는 사진이 세로를 다 먹기 때문이고, 사진이 없는 이 앱에서는 같은 세로에 두 배가 들어가면서 이름·무게 비교도 쉬워 **문법만 가져오고 열 수는 2로 둔다**.
- **셀의 정보는 면 하나 안에 다 담는다.** 레퍼런스에서 사진이 차지하던 자리를 연회색 면(`Acg.controlFill`, `AcgRadius.thumb` 12, 패딩 12, 최소 높이 150, 같은 행끼리 `flex: 1`로 등높이)이 물려받고 그 안에 브랜드·제품명·색상·무게·담기 버튼이 들어간다.
  - **면 안팎으로 정보를 나누지 않는다.** 나누면 셀 경계가 흐려지고, 밖으로 나간 값은 순백 지면에서 다시 약해진다 — 브랜드를 지면 위 회색 14pt로 뒀을 때 실제로 안 보였다.
  - **카테고리 썸네일을 쓰지 않는다.** 저작권 문제는 없지만 같은 카테고리 항목이 전부 같은 그림이 되어, 시선은 끌면서 항목을 **구분해주지 못해** 스캔을 방해한다. 사진이 앵커로 작동하는 건 항목마다 다르기 때문이다.
- 면 안 구성은 위→아래로:
  - 상단 행: 좌측 **브랜드 14pt medium 잉크**(`getDisplayCompany()`, 1줄 말줄임), 우측 **담기 버튼**. 브랜드는 작지만 회색이 아니라 잉크다 — 제품명과는 색이 아니라 크기·굵기로 갈린다.
  - **제품명 15pt semibold 잉크**(`getDisplayName()`, 3줄까지) 뒤에 **색상 14pt**(`Acg.textMuted`)를 중첩 Text로 **이어 붙인다**. 색상은 이름의 변종 표기라 줄을 따로 두지 않고, 이름이 접히면 같이 접힌다.
  - 면 바닥에 **무게 26pt 콘덴스드**(`AcgFont.condensed`)를 둔다. 사진이 없는 이 앱에서 **무게가 셀의 숫자 앵커**다 — 항목마다 다르고 사람들이 탐색하는 이유인 값이라, 훑는 동안 눈에 걸려야 하는 쪽은 이름이 아니라 무게다.
  - **무게가 없는 항목도 그 줄 높이를 차지한다**(값 대신 대시). 비우면 두 열의 면 높이가 어긋나 그리드가 톱니처럼 보인다. 값을 지어내지는 않는다.
  - **색상**은 `Gear.getDisplayColor()`(= `colorKorean || color`). 같은 제품의 컬러 배리언트가 나란히 뜨는 경우가 많아 색상 없이는 서로 구분되지 않는다. **표시 접근자는 창고 목록과 `getDisplayColor()`로 통일한다** — 창고 목록이 쓰던 `getColor()`는 원본 값이라 같은 장비가 창고에서 `BLACK`, 피드에서 `블랙`으로 갈렸다.
- **창고 담기 CTA**: 면 우상단 **흰 원 36pt + 잉크 아이콘**(hitSlop으로 44pt 확보). 레퍼런스의 흰 원을 그대로 쓸 수 있다 — 연회색 면 위라 보인다. 담김 상태는 **잉크 채움 + 라임 체크**. 동작은 기존 SR-2/SR-3 규칙 그대로 — 미보유 `+` → 창고 등록 + 배낭 담기 모달, 보유 체크 → 제거 경고, 비로그인 `+` → 로그인 모달.
- **쿠팡 최저가 링크를 셀에 두지 않는다**(2026-08-11). `coupangUrl` 실데이터 커버리지가 **0.1%(27건)** 뿐이라([DataModel.md](DataModel.md) DM-3) 셀 문법에 자리를 잡아 두면 대부분의 셀에서 빈 줄이 되고, 링크 하나 때문에 목록 푸터의 수수료 고지·지연 로드 신호까지 따라온다. **커머스 동선은 고의도 화면인 장비 상세(GD-5)에만 둔다** — 링크가 사라졌으니 피드 푸터의 파트너스 고지도 함께 없앤다.
  - 검색 결과 화면(SR-2)은 아직 옛 2컬럼 카드라 링크·고지를 그대로 갖고 있다. 그 화면을 이식할 때 같은 판단을 적용한다.
- 셀 탭 → `/gear-detail/{id}`.
- 담기/제거 후에도 피드 스크롤 위치는 유지된다(전체 리로드 금지).
- **스켈레톤은 목록과 같은 덩어리다** — 셀마다 같은 비율·모서리의 면 하나만 두고(면 안 텍스트 막대를 그리지 않는다) 열·행 간격을 목록과 같게 맞춰 로딩→렌더 점프를 없앤다.
- **동작은 표현과 분리해 둔다** — 담기·제거·상세 이동은 `useGearRowState` 훅 하나가 갖고, 피드와 검색 결과(SR-2)가 **같은 셀 컴포넌트**(`FeedGridCellView`)로 이를 쓴다. 애널리틱스 이벤트 이름(FD-5)도 이 훅에서만 정해진다. 쿠팡 지연 로드는 훅에서 제거했다 — 링크가 사라져 쓰이지 않는데도 **보이는 항목마다 `/gear` 문서를 한 번씩 읽고 있었다**.

> **[이력] 2026-08-11 (단일 컬럼 텍스트 행)**: 레퍼런스를 처음 이식할 때는 단일 컬럼이었고 행 구성은 [이름 24 + 담기] / 브랜드 19 / 메타 17(`무게 · 색상`) / 쿠팡 링크였다. 두 번 고쳤다. ① 크기가 1.3~1.4배 컸다 — 레퍼런스 스크린샷의 **픽셀을 pt로 읽은 실수**(923px ÷ 393pt ≈ 2.35배). ② 크기를 바로잡고 2열로 바꾸니 **텍스트만으로는 시선이 걸리는 데가 없었다**(이름 19·브랜드 15·메타 14가 크기·톤이 비슷). 무게를 앵커로 올리고, 다시 브랜드·제품명까지 사진 자리 면 안으로 넣어 지금 형태가 됐다.

> **[이력] 2026-07-28 ~ 2026-08-10 (2컬럼 텍스트 카드)**: 피드는 `FlatList numColumns={2}` 2컬럼 그리드였고(마지막 홀수 카드는 좌측 정렬), 각 셀은 종이 면(`Acg.paper`, 각진 모서리, `AcgShadow.paper`) 위에 브랜드(14) → 이름(14, 2줄) → 색상(12) → **무게 30pt 콘덴스드**를 쌓은 텍스트 카드였다. 이미지가 하던 시각 위계를 **무게가 앵커로** 대신했고 담기 CTA는 카드 우상단 36pt 원형(hitSlop으로 44 확보), 쿠팡 링크는 카드 하단 축약 라벨(12pt)이었다. 지면은 공통 회색 지면(`AcgScreenBackground`)이었다.

### FD-3 필터 (칩 한 줄 + 정렬 줄)

피드 **상단에 고정 필터 바**를 둔다. 필터·카테고리를 **한 줄 가로 스크롤 칩**으로 모으고(주 축), 정렬은 그 아래 **우측 정렬 줄**에 둔다. 정렬은 카테고리보다 덜 바꾸는 축이라 칩 행에서 빼 위계를 분명히 한다.

**수용 기준** (2026-08-11 레퍼런스 이식 이후)

- **칩 행**(피드 리스트 위 고정, 항상 노출, 가로 스크롤 — 우측에서 그냥 잘리며 페이드 마스크를 두지 않는다):
  - 칩은 **연회색 채움**(`Acg.controlFill`) + radius full, 최소 높이 **48**, 좌우 패딩 20, 라벨 **17pt semibold 잉크**, 칩 사이 12, 좌우 여백 16. **선택 상태는 잉크 채움 + 흰 글자**(레퍼런스에 선택 상태가 없어 이 앱의 기존 규칙을 유지).
  - **브랜드 시트를 여는 칩이 맨 앞**이고 라벨 좌측에 필터 아이콘(`options-outline` 22pt)을 단다. 선택 브랜드가 있으면 라벨에 개수를 붙이고(`브랜드 2`) 선택 상태(잉크 채움)로 보인다.
  - 그 뒤로 `전체` + 11개 카테고리 칩 — 단일 선택, 탭 시 **즉시 적용**(스테이징 없음), 재탭/`전체`로 해제.
  - 2차(세분) 카테고리 옵션이 있으면 **같은 톤의 한 단계 작은 칩 행**(최소 높이 40, 라벨 15pt)을 그 아래 둔다 — 레퍼런스에 대응 요소가 없어 위계만 낮춰 유지한다.
- **정렬 줄**(칩 행 아래, **면·테두리·구분선 없음**, 좌우 여백 16): 우측에 현재 정렬 라벨 **17pt 잉크 + 셰브론 18pt**(예 `가벼운순 ⌄`) → 정렬 시트. 터치 타깃 최소 높이 44.
  - 레퍼런스는 이 줄 좌측에 결과 개수(`497 trails`)를 두지만, **피드는 총 건수를 알 수 없어 개수를 표시하지 않는다** — 버킷을 인터리브하는 무한 스크롤이라 모델에 총량이 없고, 로드된 개수는 총량이 아니다. 추측한 수를 표시하지 않는다.
  - 정렬 줄은 검색 승계 상태(SR-1, 정렬 미적용)에서는 렌더하지 않는다.
- **정렬 시트**(우측 드롭다운 탭 → 오픈, **공용 네이티브 formSheet 라우트 `/sort-sheet`**): `추천`(기본) · `인기순` · `최신순` · `가벼운순` · `무거운순` 목록 — 단일 선택, 현재 정렬 **체크(✓)**. 항목 탭 = **즉시 적용 후 닫힘**(스테이징 없음). 세 화면(피드·탐색·창고)이 같은 라우트를 공유하며, 트리거가 `router.push` 직전 옵션·현재값·onSelect 콜백을 모듈 핸드오프에 넣고 라우트가 그걸 렌더한다(뷰 스코프 인스턴스라 props 대신 콜백 위임). 그래버·드래그 닫기·높이(`fitToContents`)는 OS가 처리(배낭 추가 시트와 동일). `추천`은 개인화 믹스(기본), 나머지는 해당 정렬 replica로 **단일 정렬 목록**(개인화·6:4 믹스 대신). 정렬 시 카테고리·브랜드 facet은 함께 적용.
- **`가벼운순`은 `1,000건 상한까지 실제 무게 오름차순, 그 뒤에 0g`으로 노출한다.** 카탈로그의 `weight: 0`은 "가장 가벼움"이 아니라 **무게 미입력**이고(대부분 의류 — 오히려 무거운 제품이라 무게가 판단에 큰 의미다), 0g 비중이 커서 replica를 그대로 쓰면 페이지 상한 안이 전부 0g으로 채워져 정렬이 사실상 동작하지 않는다(수치는 §8 실측 참고).
  - 구현: `가벼운순`만 **2단 페이지네이션**으로 조회한다. 1단은 `weight > 0`(numericFilter)으로 실제 무게 오름차순을 **페이지 상한까지** 넘기고, 상한에 닿으면 2단으로 `weight = 0`을 이어 붙인다. 즉 0g은 목록 맨 뒤가 아니라 **가장 가벼운 1,000건 뒤**에 온다(상한이 인덱스 전체보다 작아 1단을 "끝까지" 넘길 수는 없다). 0g끼리의 순서는 의미가 없어 별도 정렬을 두지 않는다.
  - `page`는 두 단계를 관통하는 연속 인덱스이며, 호출자(피드 버킷·SR-7 목록)는 단계를 모른다. **1단/2단 경계는 요청 page와 무관하게 필터 조합(카테고리+브랜드)별로 한 번만 계산해 재사용한다** — 페이지 응답의 `nbPages`로 잡거나 매 요청 다시 세면 상한 밖 응답(빈 결과)·비exhaustive 건수 추정 때문에 경계가 밀려, 목록이 빈 채로 끊기거나 같은 장비가 중복으로 붙는다.
  - `weight` 속성이 아예 없는 레코드는 두 단계 모두에 걸리지 않는다(실측상 극소수 — 전제로 기록한다).
  - `무거운순`은 0g이 자연히 뒤로 가므로 손대지 않는다. Algolia 인덱스 설정(replica·custom ranking) 변경은 admin 키가 필요해 클라이언트 조회로 해결한다.
- **브랜드 시트**(`브랜드` 버튼 탭 → 오픈, **iOS 네이티브 pageSheet 프레젠테이션**): RN `Modal presentationStyle='pageSheet'`로 표시한다 — 카드 슬라이드·스와이프 다운 닫기·라운드 코너·백드롭은 OS가 처리하므로 커스텀 딤/제스처/reanimated는 두지 않는다. **단 핸들바와 닫기는 둔다**(2026-07-31 정정) — pageSheet는 `formSheet`와 달리 **OS 그래버를 그리지 않아** 스와이프로 닫히는데도 어포던스가 안 보였고, 하단이 `확인` 하나뿐이라 **적용하지 않고 나가는 길이 스와이프뿐**이었다. 상단에 공용 `SheetGrabberView` + 헤더 우측 닫기(×, `초기화` 옆)를 두며, 닫기는 스와이프 닫힘과 같은 취소 경로(스테이징 폐기)다. 스와이프 닫힘 시 `onDismiss`(iOS)로 부모 `visible`을 초기화한다(취소 경로 = 스테이징 폐기). 브랜드명 검색 입력 + brand-rank 인기순 목록(SR-8 로직 재사용) — **복수 선택**(행 탭 토글, 선택 행은 **체크(✓) 아이콘**으로 강조). 행에는 브랜드명만 노출하고 **제품 수(`제품 n`)는 표시하지 않는다**(브랜드 디렉토리 SR-8과 달리 필터 맥락에선 불필요 — `BrandRowView`의 `showCount={false}`). 선택은 시트 안에서 **스테이징**되고 하단 고정 `확인`으로 일괄 적용된다:
  - **선택 브랜드 요약 칩**: 검색 입력 아래에 선택된 브랜드를 제거(✕) 가능한 칩으로 나열 — 검색 중 목록에서 선택 브랜드가 사라져도 선택 상태를 항상 확인·해제할 수 있다.
  - 헤더 우측 `초기화`: 브랜드 스테이징 전체 해제(적용은 `확인` 시점).
  - **하단 고정 `확인` 버튼**(검정, 전체 폭 — 배낭 담기 모달의 `닫기` 버튼과 동일 스타일): 스테이징을 적용하고 닫는다. 선택이 있으면 라벨에 개수 표기(`확인 (3)`), 변경 없으면 그냥 닫힘.
  - 브랜드 검색 입력 포커스 시 키보드가 목록·확인 버튼을 덮지 않도록 키보드 회피 처리(배낭 담기 모달과 동일).
  - 스와이프 다운 닫기/뒤로가기 = **취소**(스테이징 폐기, 기존 적용 브랜드 유지).
- 필터 적용 시 피드 재구성: 정렬 지정 시 단일 정렬 버킷, 미지정(추천)+필터 시 인기순 6 : 신제품 4, 개인화 버킷 비활성. 카테고리+브랜드 동시 적용 가능. **복수 브랜드는 OR** — Algolia facetFilters의 같은 내부 배열에 모든 선택 브랜드의 `companyKorean`·`company` 값을 나열해 매칭.
- `브랜드` 칩 개수 = 선택 브랜드 수(카테고리는 칩 선택 상태로, 정렬은 정렬 줄 라벨로 표시하므로 개수에 미포함).
- **검색 승계**: 탐색 검색어 입력 시에도 현재 카테고리·브랜드 필터가 검색 결과에 같은 facet 규칙으로 적용된다([Search.md](Search.md) SR-1). 이를 위해 피드 도메인 객체는 탐색 탭(검색 화면) 수준에서 생성·공유되어, 검색어 입력으로 피드가 화면에서 내려가도 필터 상태가 유지되고 검색어를 지우면 같은 필터의 피드로 돌아온다. 검색 결과 화면에도 칩 행(브랜드 칩 + 카테고리 칩)을 유지 노출하고 변경 즉시 재검색하며, 정렬 줄은 검색 중 숨긴다.
- 필터 결과 없음: `장비가 없습니다`.
- **필터·정렬 변경 시 스켈레톤 + 스크롤 리셋**: 카테고리·브랜드·정렬을 바꿔 피드를 재구성할 때는 기존 목록을 즉시 비워 스켈레톤을 노출한다(`reload()`가 로딩 시작과 함께 items를 비움 → 리스트가 최상단부터 리마운트). 이로써 리스트를 아래로 내려 보던 중 필터를 바꿔도 스크롤이 항상 최상단으로 리셋된다. 담기/제거·당겨서 새로고침(`refresh()`)은 이 경로를 타지 않아 스크롤 위치가 유지된다(FD-2).
- **인기 순위 진입점**([Search.md](Search.md) SR-4): 피드 하단 중앙 플로팅 버튼 `인기 순위` → 인기 장비 순위 화면(기존 SR-4 화면 재사용). **현재 선택된 카테고리 필터를 승계**해 그 카테고리 순위를 바로 보여준다(라우트 파라미터 `?category=<GearFilter>`; 순위 화면 8개 탭에 없는 카테고리·전체·미선택은 `전체`로 진입 — SR-4). 구 하단 중앙 플로팅 `필터` 버튼은 상단 바로 대체되어 **제거**한다.
  - **이 버튼이 화면의 유일한 액센트 면이다**(2026-08-11 이식): **라임 채움 + 잉크 아이콘·라벨**(최소 높이 48, radius full, 라벨 17pt semibold, 아이콘 `trending-up` 20pt). 그림자도 화면에서 이 버튼에만 둔다 — 목록·컨트롤에는 없다. `[이력]` 이전에는 공용 `FloatingPillButton`의 흰 면 + 잉크 테두리(`secondary`)였다. 다른 화면은 아직 공용 알약을 쓰므로 공용 컴포넌트는 그대로 두고 이 화면만 자체 알약을 그린다.
  - **스켈레톤 중에는 숨긴다**: 최초 진입 스켈레톤 위에는 플로팅 `인기 순위` 버튼을 렌더하지 않고, 피드가 로드된 뒤에만 노출한다. 탭이 막 마운트된 첫 프레임에는 네이티브 탭바 몫이 반영되기 전이라 `insets.bottom`이 작게 잡혀 버튼이 탭바 뒤로 내려가기 때문이며, 로드 시점엔 inset이 정착해 위치가 정확하다.

### FD-4 새로고침·페이지네이션

**수용 기준**

- **pull-to-refresh**: 시드 재생성 + 버킷 페이지 초기화 → 새 믹스. 스피너는 RN 기본 RefreshControl.
- **무한 스크롤**: 하단 근접 시 버킷별 다음 페이지 로드·인터리브 이어붙임. 모든 버킷 소진 시 중단(별도 "끝" UI 없음).
- 로딩: 최초 진입 스켈레톤(기존 SearchSkeletonView 패턴), 추가 로드는 하단 스피너.
- 요청 경합: 늦게 도착한 이전 요청 폐기(요청 토큰 — browse와 동일 패턴).

### FD-5 애널리틱스

**수용 기준**

## 6. 엣지 케이스

- **비로그인**: 피드 노출(콜드스타트 믹스), 담기만 로그인 모달.
- **Algolia 실패**: 빈 배열 + 재시도 없이 조용히(SR 엣지 정책). 최초 로드 실패 시 빈 상태 문구.
- **창고 5개 미만**: 관심 분포가 빈약 — 콜드스타트 믹스로 폴백(임계값: 카탈로그 출신 3개 미만).
- **색상 없는 장비**: 메타 줄에서 색상을 빼고 구분자(`·`)도 붙이지 않는다(빈 줄·플레이스홀더 없음, FD-2).
- **무게 미입력(0g)**: 메타 줄에서 무게를 빼고(둘 다 없으면 줄 자체를 렌더하지 않는다), `가벼운순`에서는 1단(실제 무게) 뒤 2단 구간에 붙는다(FD-3).

## 7. 수동 검증 체크리스트

- [ ] 로그인+창고 보유 상태: 피드 상위에 관심 카테고리/브랜드 장비가 섞여 나옴, 보유 장비 미노출
- [ ] 비로그인: 인기+신제품 믹스 노출, 담기 → 로그인 모달
- [ ] 지면이 순백이고 텍스처·그레인이 없다. 목록 행에 면·테두리·그림자·구분선이 없다 (FD-2)
- [ ] 셀에 사진·사진 플레이스홀더가 없고, **무게가 셀의 앵커**로 가장 크게 읽힘 (FD-2)
- [ ] 메타 줄이 `무게 · 색상`으로 이어 붙고, 색상이 없으면 구분자 없이 무게만, 둘 다 없으면 줄 자체 미노출(같은 장비가 창고 목록과 같은 표기)
- [ ] 메타 줄의 무게 숫자만 콘덴스드로 보이고 **한글이 깨지지 않는다**(색상·구분자는 Pretendard)
- [ ] 검색 필드가 연회색 알약(테두리·유리 없음)이고 좌측 돋보기가 보인다. 장비 추가 검색 시트는 기존 유리 필드 그대로 (FD-2)
- [ ] 칩 행 맨 앞이 필터 아이콘 달린 `브랜드` 칩이고, 그 뒤로 `전체`+카테고리 칩이 이어진다. 칩 즉시 적용·해제, 브랜드 시트 `확인` 적용, 카테고리+브랜드 동시 적용 (FD-3)
- [ ] 정렬은 칩 행 아래 **우측 정렬 줄**에서 열리고, 그 줄에 결과 개수가 없다. 검색어 입력 시 정렬 줄이 사라진다
- [ ] 플로팅 `인기 순위` 버튼이 라임 채움 + 잉크 글자이고, 화면에서 라임 면·그림자가 이 버튼 하나뿐이다
- [ ] `가벼운순`에서 1단(1,000건) 끝까지 스크롤 → 0g 구간으로 이어지고 빈 목록으로 끊기지 않는다

**결정됨 (2026-08-11)** — 레퍼런스 탐색 화면 이식

- **사진 대신 이름이 행의 앵커다.** 장비 이미지 미제공 원칙([DataModel.md](DataModel.md) §1)은 그대로다. 무게는 앵커에서 내려와 메타 줄의 첫 항목이 됐다.
- 공용 컴포넌트(`CategoryChipView`·`FloatingPillButton`)는 **고치지 않고** 탐색 탭 전용 대응물(`FeedChipView`·자체 라임 알약)을 뒀다. 목록 셀은 예외로, 검색 결과까지 `FeedGridCellView` 하나로 합치고 옛 `FeedCardView`를 지웠다 — 같은 탭에서 키워드 유무로 두 세대가 갈리는 상태를 남길 수 없었다. 검색 필드만 예외로 공용 `SearchBarView`에 옵셔널 `variant`(기본 `Glass`)를 더해 기존 화면 동작을 그대로 남겼다.

**실측 (2026-07-29)** — 아래 수치는 실측값이라 카탈로그·인덱스 설정이 바뀌면 낡는다. FD-3의 동작 규칙은 수치에 의존하지 않게 서술한다.

- Algolia 인덱스 `useless-gear-search`: 전체 **37,423건**, `weight = 0`(무게 미입력) **7,887건**(둘 다 exhaustive). `weight > 0`은 쿼리에 따라 `nbHits` 약 **20,921~29,644**로 보고된다(비exhaustive 추정치라 요청마다 흔들린다 — FD-3 경계를 조합별로 한 번만 계산하는 이유).
- `paginationLimitedTo` = **1,000**. `hitsPerPage: 100`이면 `nbPages`가 **10으로 클램프**되고, 상한을 넘는 page 요청은 에러가 아니라 `hits: []`·`nbHits: 0`·`nbPages: 0`을 반환한다. 그래서 FD-3 2단 경계는 응답의 `nbPages`가 아니라 코드 상수(`ALGOLIA_PAGINATION_LIMIT / 페이지 크기`)로 계산한다.
- `weight` 속성이 아예 없는 레코드는 위 세 수치 차이만큼(최대 몇 건 수준) 존재할 수 있고, 1단·2단 어디에도 걸리지 않는다.

## 9. 레퍼런스 화면 문법 (탭 확장 기준)

탐색 탭을 이식하며 레퍼런스 스크린샷에서 뽑은 **화면 문법 7개**다. 다른 탭으로 넓힐 때 이 목록을 기준으로 판단한다(값의 정본은 `constants/DesignTokens.ts`의 `Acg`·`AcgType`).

1. **지면은 순백, 텍스처 없음.** 회색 지면·그레인·지형 마크를 깔지 않는다.
2. **면은 컨트롤에만.** 검색 필드·칩·아이콘 버튼만 연회색 채움(`Acg.controlFill`)을 갖고, **목록·콘텐츠는 면을 갖지 않는다** — 카드·테두리·그림자·구분선 없이 흰 지면에 콘텐츠가 직접 놓인다.
3. **모서리는 알약이거나 없다.** 컨트롤은 radius full(높이 이상 값으로 지정해 Dynamic Type에서도 알약 유지), 콘텐츠 블록은 모서리 자체가 없다.
4. **타입 4단**: 목록 행 제목 24 semibold 잉크 / 부제(브랜드) 19 `textMuted` / 메타·칩 라벨·정렬·검색 입력 17. 숫자만 콘덴스드를 허용하고 **한글에는 쓰지 않는다**(글리프 없음).
5. **컨트롤 치수**: 검색 필드 최소 높이 56, 칩 최소 높이 48(좌우 패딩 20, 칩 사이 12), 아이콘 버튼 44. 화면 좌우 여백 **16**, 목록 행 사이 24. 가로 스크롤은 화면 끝에서 그냥 잘리고 페이드 마스크를 두지 않는다.
6. **액센트 면은 화면당 하나** — 하단 중앙 플로팅 알약(라임 채움 + 잉크 글자). 라임을 글자색으로 쓰지 않는다.
7. **그림자는 플로팅 요소에만.** 목록·컨트롤·시트 트리거에는 그림자를 두지 않는다.

**선택 상태는 이 앱 규칙을 유지한다** — 레퍼런스에는 선택된 칩이 없어 참조할 값이 없다. 칩 선택은 잉크 채움 + 흰 글자, 담긴 항목은 잉크 채움 + 라임 체크다.
