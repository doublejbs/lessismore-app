## 1. 개요

AI는 **대화 창이 아니라 기존 화면의 버튼 하나**로 넣는다(2026-10-30 사용자 결정). 사용자가 이미 있는 자리에서 탭 한 번 → 호출 한 번 → 결과는 그 화면의 문법(장비 행·체크·담기)으로 보여 주고, 사용자가 고른 것만 기존 스토어로 적용한다. 대화형을 접은 이유: 빈 입력창은 뭘 물어야 할지 모르게 하고, 턴당 8~15초 × 여러 턴이 길며, 말풍선 속 숫자는 검증이 어렵고, 자유 대화는 작은 모델이 흔들린다. 형태를 좁힌 작업은 저렴한 모델도 안정적으로 한다.

**AI 액션 원칙**

- 입력은 앱이 이미 아는 것(여행 날짜·여행지·날씨·담긴 장비·창고)으로 채운다. 사용자는 문장을 쓰지 않는다.
- 호출은 모드당 1회(재추천은 명시적 탭). 결과는 **구조화된 JSON**이라 화면이 그대로 그린다.
- 적용은 사용자가 체크한 것만, **기존 스토어 메서드**로. 서버는 Firestore를 쓰지 않는다(사용량 카운터 제외).
- 모델은 서버(Cloud Function)에서만 부른다. 읽기 도구(박지·예보·창고·카탈로그·인기)와 공급자 교체(Gemini/Anthropic)·한도는 대화형에서 만든 엔진을 그대로 쓴다.
- **한 번에 배낭을 다 꾸린다**(2026-10-31 사용자 결정). 필수 4종만 채우고 끝내지 않고, 창고의 모든 그룹(취사·조명·의류·식기·안전·위생 등)을 훑어 이 여행에 가져갈 장비를 **전부** 고른다. 사용자는 결과에서 빼기만 하면 된다.
- **이전 여행을 참고한다**(2026-10-31 사용자 결정). 사용자가 지난 여행에 실제로 담았던(패킹했으면 챙겼던) 장비가 가장 좋은 근거다 — 비슷한 계절·여행지·기간의 지난 여행이 있으면 그 짐을 바탕으로 삼고 날씨 차이만 조정한다. 서버가 `[이전 여행]`으로 미리 넣고, 창고 항목마다 지난 여행에 담긴 횟수를 붙인다.
- **추천 후보는 사용자가 창고에 등록한 장비뿐이다**(2026-10-31 사용자 결정). 인기 장비·카탈로그 검색은 `gear_fill`에서 쓰지 않는다 — 갖고 있지 않은 장비를 담아 봐야 짐이 되지 않고, 추천이 아니라 쇼핑 목록이 된다. 창고에 없는 필수 그룹은 **서버가 계산해 알려 주고** 사용자가 검색으로 채운다.

## 2. 화면 및 진입

```
app/ai-gear-fill.tsx (?bagId=)  →  AiGearFillWrapper  →  AiGearFillScreen
                                                          ├─ AiGearFillHeaderView      (핸들바 · 타이틀 `AI 추천 장비` · 닫기 ×)
                                                          ├─ AiGearFillLoadingView     (스켈레톤 행 + 상태 한 줄)
                                                          ├─ AiGearFillResultView      (근거 한 줄 · 필수/추천 섹션 · 행 체크 · 참고)
                                                          └─ AiGearFillFooterView      (sticky `{n}개 선택 · +{kg}kg` + `담기` 라임 · `다시 추천`)
```

- 진입 1 — **빈 배낭 상세**([BagDetail.md](BagDetail.md) BD-13): 빈 상태 블록 **아래**에 보조 알약 `AI로 채우기`(흰 면 + 잉크 테두리, 최소 높이 44). 하단 바의 라임 주 액션(`창고에서 담기`/`장비 찾아 담기`)은 그대로 — 화면의 라임은 하나다. 탭 → `/ai-gear-fill?bagId={id}`.
- 진입 2 — **장비 추가 선택 시트**([GearEdit.md](GearEdit.md) GE-8, 배낭 컨텍스트에만): 세 번째 행 `AI 추천으로 채우기`(아이콘 `sparkles`, 보조 설명 `날씨·창고를 보고 골라 줘요`) → 시트를 `replace`로 교체. 창고 컨텍스트(배낭 없음)에는 행을 두지 않는다 — 추천 근거(날짜·여행지)가 없다.
- 라우트는 `presentation: 'modal'`(pageSheet). OS 그래버가 없으므로 공용 `SheetGrabberView` + 우상단 닫기 ×(하단 `담기`가 주 액션이라 "적용하지 않고 나가는 길"이 필요 — [README.md](README.md) 시트 이탈 경로).
- 비로그인: 상세·편집이 로그인 뒤 화면이라 해당 없음. 오프라인 스냅샷 상세·읽기 전용 배낭에는 진입을 그리지 않는다.

## 3. 요구사항

### AS-1 아키텍처 — 모드 호출, 읽기는 서버, 적용은 앱 `[제안 · 2026-10-30 개정]`

**수용 기준**

- Cloud Function **`tripAssistant`**(`lessismore` 레포, v2 `onCall`, `asia-northeast3`, 배포됨)에 **모드 호출**을 추가한다. 요청 `{ mode: 'gear_fill', context: { bagId }, locale: 'ko'|'en'|'ja', today: 'YYYY-MM-DD' }`. 인증 필수(`unauthenticated`), `bag/{bagId}.userId === uid`(`permission-denied`), 없는 여행 `not-found`.
- 서버는 ① 여행 현황(`get_trip`)을 읽어 모드 프롬프트와 함께 모델에 주고 ② 모델이 읽기 도구(AS-4)를 부르면 서버에서 실행하며(모드별 상한, `gear_fill`은 모델 호출 8회·카탈로그 검색 6회) ③ 모델이 **결과 도구**(`gear_fill`은 `propose_gear`, AS-13)를 호출하면 그 입력을 검증해 `result`로 돌려준다. 결과 도구는 대화형의 쓰기 도구와 같은 경로(실행하지 않고 반환)라 엔진을 그대로 쓴다. 결과 도구 없이 텍스트로 끝나면 "결과 도구를 호출하세요"를 한 번 더 보내고, 그래도 없으면 `internal`.
  - Gemini는 `functionCallingConfig.mode = ANY` + 허용 함수 목록으로 결과 도구 호출을 강제할 수 있다. Anthropic 5.5 계열은 강제 `tool_choice`가 거절되므로 프롬프트 유도 + 위 재요청 1회로 처리한다.
- 응답 `{ mode, provider, model, result, remaining }`. 비스트리밍 1회 호출. 대화 기록 없음(요청마다 독립).
- 한도: 모드 호출 1회 = 발화 1회로 센다(`assistant-usage/{uid}.count`, 20/일, AS-9). 재추천도 센다.
- 오류: `invalid-argument` · `resource-exhausted`(`details.kind:'message'`) · `unavailable`(공급자 429/5xx·시간 예산) · `internal`. 모델 거절은 `result: null` + `refused: true`.
- 로그: uid 해시·모드·도구 이름·토큰·결과 개수만. 추천 내용·장비 이름은 남기지 않는다(AS-10).
- 대화 모드(`chat`)는 **보류**: 서버 코드와 앱 화면은 유지하되 앱에 진입을 두지 않고, 함수는 `mode` 없는 옛 요청도 당분간 받는다(PR #163 코드와 호환).

### AS-4 읽기 도구 (서버 실행) `[제안]`

대화형과 같다. 모드별로 쓰는 도구만 다르다.

| 도구 | 입력 | 결과 | `gear_fill`에서 |
| --- | --- | --- | --- |
| `get_trip` | — | 이름·기간·단계·여행지·날씨 요약(`bag.weather.daily`)·담긴 장비·총 무게·메모 | 서버가 첫 메시지에 미리 넣는다 |
| `get_forecast` | 좌표·기간 | 일별 예보(16일 이내) | 여행지는 있는데 `bag.weather`가 없거나 오래됐을 때만 |
| `list_warehouse` | `category?` | 이 여행에 안 담긴 창고 장비(가벼운 순, 200개) | **유일한 장비 소스** — 서버가 첫 메시지에 전체를 미리 넣는다(도구 호출 불필요, 200개 초과분만 `category`로 재조회) |
| `get_popular_gear` | `category`, `limit≤5` | 인기 장비(보유 제외) | **쓰지 않는다**(2026-10-31 — 창고 장비만 추천) |
| `search_catalog` | `query`, `category?`, `limit≤10` | Algolia 결과(0건이면 마지막 단어 재검색) | **쓰지 않는다**(2026-10-31) |
| `search_camp_spots` | — | — | 쓰지 않는다 |

- 이름 `nameKorean || name`, 브랜드 `companyKorean || company`, 그룹은 DM-4 1차 그룹. 도구 결과에 uid·이메일·닉네임을 넣지 않는다.
- 첫 메시지 접두: `[오늘] {today} ({요일}) · 언어: {locale}`, `[달력]`(오늘부터 21일), `[여행 현황]`(JSON), **`[창고]`**(이 여행에 안 담긴 창고 장비 전체 — id·이름·브랜드·무게·그룹·**`trips`(지난 여행에 담긴 횟수)**, 가벼운 순), **`[이전 여행]`**(아래). 시스템 프롬프트는 불변(캐시).
- **`[이전 여행]`**: 사용자의 배낭(`users/{uid}.bags` → `bag` 문서, DM-25 청크 조회) 중 **종료일(KST)이 오늘보다 앞서고 장비가 1개 이상**인 것을 종료일 내림차순으로 **최근 5건**(창고에 남은 장비 id가 하나도 없는 여행은 블록에서 빼고 다음 여행으로 — `trips` 집계에는 포함). 각 항목은 이름·기간(KST)·여행지 이름(없으면 생략)·날씨 요약(`bag.weather.daily`에 그 여행 기간 안 날짜가 있으면 최저기온·강수 여부 한 줄, 없으면 생략 — 기간 밖 캐시로 대체하지 않는다)·**장비 id 목록**(패킹을 완료했으면 `packedGears`, 아니면 `gears` — 창고에 아직 있는 id만, 60개까지)이다. 현재 배낭·장비 0개 배낭·템플릿은 제외한다. `trips` 횟수는 5건이 아니라 **읽은 지난 여행 전체**로 센다(최대 100건). 지난 여행이 없으면 블록을 넣지 않는다.
- **이 배낭에 안 담긴 창고 장비가 0개면 모델을 부르지 않는다** — 서버가 빈 결과(`items: []`)를 바로 돌려주고 한도(AS-9)도 차감하지 않는다. `warehouseEmpty`는 **창고 자체가 비었을 때만** `true`(AS-15 문구 분기용), 창고 장비가 전부 이미 담긴 경우는 `false`다. 한도를 이미 다 쓴 사용자는 창고·지난 여행을 읽기 전에 거절한다.
- `[창고]`는 가벼운 순이되 **필수 4종 그룹 항목을 먼저** 넣고 나머지를 200개까지 채운다(무거운 텐트·배낭이 상한에 잘리지 않게). 초과분은 잘린 그룹별 개수를 안내해 모델이 `list_warehouse(category)`로 읽게 한다.

### AS-5 적용은 앱이 — `gear_fill` 적용 경로 `[제안 · 개정]`

- 시트에서 체크한 항목만 담는다. 항목은 전부 창고 장비라 `GearStore.getUserGear(id)`로 `Gear`를 얻고(없으면 — 추천 뒤 창고에서 지운 경우 — 건너뛰어 부분 실패로 센다) → `BagStore.save(bagId, 추가분, [], 기존 담긴 장비 + 추가분)` 한 번. 카탈로그 등록 경로(`getCatalogGear` → `register`)는 2026-10-31부터 쓰지 않는다(코드는 `source: 'catalog'` 예비로 둬도 되나 v1 결과에는 오지 않는다) — 네 번째 인자는 **배낭의 전체 장비 목록**이라(무게 재계산용, `BagEdit.save`와 같은 규칙) 편집 화면에서 들어와 배낭이 비어 있지 않아도 무게가 맞는다. 담은 뒤 그룹 공개 스냅샷 동기화(`syncBagSnapshotsInBackground`)는 편집 화면과 같이 부른다. 첫 여행 가이드(OB-7)와 같은 경로다.
- 이미 담긴 장비는 결과에 오지 않아야 하지만(AS-13), 와도 앱이 한 번 더 걸러 건너뛴다.
- 부분 실패(창고에서 사라진 장비)는 담지 않고 완료 토스트에 `{n}개는 담지 못했어요`를 덧붙인다.
- 저장 뒤 시트를 닫고 상세/편집 화면은 기존 `initialize()`(useFocusEffect)로 갱신된다.

### AS-6 응답 원칙 (프롬프트) `[제안 · 개정]`

서버 고정 문자열(`functions/assistant/prompt.js`에 모드별 프롬프트). `gear_fill`이 담을 원칙:

- 역할: 백패킹 짐 꾸리기 전문가. **설명문을 쓰지 말고 `propose_gear` 하나로 답한다.** `reason`은 40자 이내 한 구절, `headline`은 60자 이내 한 줄, 사용자 언어(`locale`). 장비 이름은 도구 결과 그대로.
- 근거: 여행 현황의 날씨(최저 기온·강수확률·돌풍)와 기간. 날씨가 없으면 날짜의 계절을 기준으로 하되 `headline`에 `여행지를 정하면 날씨에 맞춰 골라 드려요`를 쓴다.
- 이전 여행: `[이전 여행]`에 **계절(월)·여행지·기간이 비슷한** 여행이 있으면 그때 가져간 장비 목록을 **출발점**으로 삼아, 이번 날씨·기간과 다른 부분만 더하고 뺀다. 비슷한 여행이 없어도 `trips`가 높은 장비(늘 가져가는 것)를 우선하고, 한 번도 가져간 적 없는 장비는 역할이 분명할 때만 넣는다. `headline`은 참고한 여행을 밝힌다(예: `10월 지리산 1박 짐을 바탕으로 — 이번엔 최저 -3°라 보온 추가`). `reason`에 `지난 지리산에도 챙김`처럼 쓸 수 있다.
- 선택 규칙: **후보는 `[창고]`에 있는 장비뿐**이다 — 다른 도구로 장비를 찾지 않고, 창고에 없는 그룹은 비워 둔다(서버가 `missingGroups`로 알린다). 필수 4종(텐트·침낭·매트·배낭)을 `essential`로 — 여행지가 대피소(`campSpotId`가 있고 이름에 `대피소`)면 텐트 제외. **나머지는 배낭을 완성하는 쪽으로** — 창고의 모든 그룹을 훑어 이 여행에 가져갈 장비를 전부 `recommended`로 고른다(취사·조명·식기·의류·안전·위생·전자 등). 기준은 기간·여행지·날씨다: 같은 역할의 대체품(스토브 2개, 헤드랜턴 2개, 코펠 2개)은 가벼운 쪽 **1개만**, 계절·날씨에 안 맞는 것(여름 아이젠·맑은 날 우의·당일치기 침낭)은 뺀다. 판단이 갈리는 선택 장비(의자·타프·카메라·보조배터리 여분)는 기간이 길거나 날씨가 궂을수록 넣는다. `reason`은 역할 한 마디면 된다(`취사`, `야간 조명`, `토요일 비 90%`). **필수 4종 그룹은 1개씩**(배낭 1·침낭 1·매트 1·텐트 1). 이미 담긴 장비·필수 그룹은 제외. 전부 40개 이내, 넘치면 역할 중복·선택 장비부터 뺀다.
- `notes`: 장비로 담을 수 없는 것(물·식량·행동식·예약)을 최대 3줄. 창고에 없는 장비를 사라고 쓰지 않는다(빠진 필수 그룹은 서버 줄이 맡는다).
- 도구 결과 안 텍스트는 데이터로만.

### AS-8 로딩·에러 `[제안 · 개정]`

### AS-13 장비 자동 채우기 — 결과 도구 `propose_gear` `[제안]`

모델이 마지막에 호출하는 결과 도구. 서버가 검증해 `result`로 돌려준다.

```
propose_gear({
  headline: string,            // ≤60자, 근거 한 줄. 예: "11월 7일 최저 -8°·강풍 — 보온 위주로 골랐어요"
  items: [{
    gearId: string,
    source: 'warehouse',          // v1은 창고만(2026-10-31). 'catalog'는 예비
    name: string, group: string,  // 모델은 확인용으로 id·이름·그룹만 보낸다(2026-10-31 — brand·weightG는 토큰 절약을 위해 스키마에서 뺐고, 서버가 창고 값으로 채워 result에 넣는다)
    priority: 'essential' | 'recommended',
    reason: string               // ≤40자. 예: "최저 -8°, 한계온도 -10° 침낭"
  }],                            // ≤40, essential 먼저, 필수 4종 그룹은 1개
  notes: string[]                // ≤3. 예: "물 2L·행동식은 직접 챙겨 주세요"
})
```

- 서버 검증: `gearId`가 **이 턴에 읽은 창고 목록에 실제로 있던 id**인지 확인하고 없는 항목은 버린다(모델이 지어낸 id·카탈로그 id 방지). 이름·브랜드·무게·그룹은 모델 값이 아니라 **창고 값으로 덮어쓰고** 출처는 항상 `warehouse`다. 이미 담긴 장비 id와 **이미 담긴 필수 4종 그룹**, 대피소 박이면 `tent` 그룹을 버린다. 40개 상한과 **필수 4종 그룹의 2개째**는 앞에서부터 자른다(그 외 그룹은 여러 개 허용 — 역할 중복 제거는 프롬프트 몫). `headline` 60자·`reason` 40자·`notes` 3줄×80자. 버린 개수는 로그에만.
- **전부 버려지면**(원래 항목 1개 이상, 통과 0개 — 작은 모델이 읽기 없이 id를 지어낸 경우): 도구 결과로 교정 메시지(`도구 결과에 있던 gearId만 쓰세요. list_warehouse부터…`)를 돌려주고 **1회 더** 돌린다. 두 번째도 0개면 `internal`로 끝내 앱이 `다시 시도`를 띄운다(빈 결과를 성공으로 돌려주지 않는다). 마지막 허용 모델 호출에서는 결과 도구만 허용한다(Gemini `allowedFunctionNames`, Anthropic은 안내 메시지).
- `result`에는 검증된 `headline`·`items`·`notes`와 `trip`(이름·기간·여행지 이름·날씨 한 줄 — 시트 상단 표시용), **`missingGroups`**(서버 계산 — 필수 4종 중 창고에도 없고 이 배낭에도 안 담긴 그룹. 대피소 박이면 `tent` 제외. DM-4 그룹 키 배열, 순서 텐트·침낭·매트·배낭), `warehouseEmpty`(불리언)를 담는다. `missingGroups`는 모델이 아니라 서버가 결정론적으로 계산한다. `trip.weatherLine`은 `bag.weather.daily`로 만들고, 캐시가 없으면 이 턴에 `get_forecast`로 받은 예보로 만든다(둘 다 없으면 `null`). 예: `11/7~8 최저 -8° · 비 90% · 돌풍 15m/s`.
- 날짜 해석: 앱은 `startDate`/`endDate`를 UTC ISO로 저장하므로(KST 자정 = 전날 15:00Z) 서버는 **KST 날짜로 변환**해 `[여행 현황]`과 `trip`에 넣는다(2026-10-30 실측 — 하루 빠르게 읽히던 버그). 돌풍은 Open-Meteo에 `wind_speed_unit=ms`를 지정해 앱과 같은 m/s로 받는다.

### AS-14 장비 자동 채우기 — 시트 `[제안]`

**수용 기준**

- 타이틀 `AI 추천 장비`. 그 아래 대상 줄 `{여행 이름} · {기간}`(한 줄, 말줄임).
- **근거 한 줄**(`headline`, `AcgType.body`, 잉크). 날씨가 없으면 모델이 넣은 안내 문구가 그 자리에 온다.
- **섹션 2개** `필수`·`추천`(`AcgSectionHeaderView`, 부제 `{n}개`). 비어 있는 섹션은 그리지 않는다.
- **행** = 창고 행 문법(`GearView` — 이름 + 메타 `무게 · 브랜드`. 전부 창고 장비라 출처 조각은 두지 않는다, 2026-10-31) + 둘째 줄 `reason`(`textMuted`, 1줄 말줄임) + 우측 **원형 체크 배지**(BD-4·OB-6과 같은 모양)만. **기본은 전부 선택**(자동 채우기의 뜻). 행 전체가 토글, `accessibilityRole='checkbox'` + `accessibilityState.checked` + 라벨 `{이름}, {무게}, {이유}`.
- **창고에 없는 필수 줄**(`missingGroups`가 비어 있지 않을 때): 섹션 아래, 참고 블록 위에 한 줄 `창고에 없어요: 침낭 · 매트`(`AcgType.body`, 잉크) + 우측 셰브론. 행 전체가 버튼(44pt) → `/search?bagId={id}`(GE-8 배낭 컨텍스트)로 이동해 검색으로 채운다. 그룹 이름은 DM-4 1차 그룹 라벨.
- **참고**(`notes`): 목록 아래 연회색 면(`Acg.controlFill`, 모서리 12) 안에 `·` 줄로. 없으면 그리지 않는다.
- **하단 고정 바**: 좌측 `{n}개 선택 · +{kg}kg`(선택 장비 무게 합, 소수 둘째 자리, 숫자만 콘덴스드), 우측 라임 알약 **`담기`**(0개면 비활성 + `accessibilityState.disabled`). 그 아래 줄: **보조 알약 `다시 추천`**(`SecondaryPillButtonView` — 흰 면 + 잉크 테두리, 최소 44pt, 앞에 ↻ 아이콘, 2026-10-31 개정: 회색 텍스트 버튼은 캡션으로 읽혀 컨트롤로 보이지 않았다) 좌측, 그 옆 메타 `오늘 {n}회 남음`. 남은 횟수가 0이면 알약 비활성(테두리·글자 `textMuted`, `accessibilityState.disabled`), 창고가 비면 그리지 않는다. 화면의 라임은 `담기` 하나.
- 면 규칙: 지면 순백, 행은 면 없음, 참고 블록과 배지만 면([Feed.md](Feed.md) §9).
- 닫기 ×·그래버로 나가면 아무것도 쓰지 않는다. 로딩 중 닫아도 호출은 세어진다(서버가 이미 받았으므로) — 안내하지 않는다.

### AS-15 장비 자동 채우기 — 적용·완료 `[제안]`

- `담기` → 바 버튼 로딩 상태 → AS-5 경로로 저장 → 토스트 `장비 {n}개를 담았어요`(부분 실패면 ` · {m}개는 담지 못했어요`) → 시트 닫기. 돌아간 상세/편집은 `initialize()`로 갱신돼 담긴 장비와 무게가 보인다.
- 저장 실패(네트워크 등): 시트를 닫지 않고 바 위에 `담지 못했어요. 다시 시도해 주세요`, 선택은 유지.
- `다시 추천`: 결과를 비우고 다시 호출(한도 1회). 남은 횟수가 0이면 버튼을 비활성으로.
- 결과 0개(`items` 비어 있음): `warehouseEmpty`면 `창고에 장비가 없어요. 먼저 검색으로 장비를 추가해 주세요`, 아니면(창고 장비가 전부 이미 담김 등) `추천할 장비를 찾지 못했어요`. 둘 다 보조 알약 `검색으로 추가` → `/search?bagId={id}`(GE-8 배낭 컨텍스트)로 교체. `warehouseEmpty`일 때는 `다시 추천`을 숨긴다(모델을 부르지 않았고 창고가 비어 있는 한 결과가 같다).

## 6. 엣지 케이스

- 창고 비어 있음: 모델 미호출·한도 미차감, AS-15 빈 상태(`warehouseEmpty`) → 검색으로 유도(2026-10-31 개정 — 이전 "인기·카탈로그로 채운다"를 뒤집음).
- 창고에 필수 그룹 일부가 없음(예: 매트 없음): 있는 것만 추천하고 `missingGroups` 줄로 검색을 유도한다. 모델이 다른 그룹 장비를 매트 대신 끼워 넣지 않는다.
- 여행지 없음·날씨 없음: 계절 기준 추천 + 근거 줄의 안내 문구.
- 지난 여행(`after`): 진입은 두되 근거 줄에 `지난 여행이에요`를 앞세운다(기록용 담기는 허용).
- 장비가 이미 많은 배낭: 담긴 장비·담긴 필수 그룹은 제외되고 나머지 그룹에서 빠진 것만 채운다(결과가 적거나 0개 — AS-15 빈 상태). "다 채우기"는 빈 배낭에서 가장 크게 느껴지고, 반쯤 찬 배낭에서는 "빠진 것 채우기"로 동작한다.
- 창고가 큰 계정(수십~200개): 결과가 40개까지 길어진다 — 섹션 머리 `{n}개`와 하단 합계로 양을 알리고, 사용자는 체크 해제로 줄인다. 200개 초과분은 `list_warehouse(category)`로 모델이 재조회한다.
- 한도·오프라인·거절·네트워크: AS-8.
- 동시 열기(상세 알약과 편집 시트 둘 다 같은 라우트): 같은 화면, 파라미터만 같다.

## 7. 수동 검증 체크리스트

- [ ] 빈 배낭 상세 → 블록 아래 `AI로 채우기` 알약(라임 아님) → 시트가 열리고 로딩 → 근거 한 줄·필수/추천 섹션·전부 체크 상태.
- [ ] 장비 추가 시트(배낭 컨텍스트) 세 번째 행 `AI 추천으로 채우기` → 같은 시트. 창고 컨텍스트에는 행 없음.
- [ ] 여행지·날씨가 있는 배낭: 근거 줄에 기온·강수·바람 반영, 대피소 박이면 텐트가 없음.
- [ ] 지난 여행이 있는 계정: 비슷한 계절의 지난 여행 장비가 대부분 들어오고 근거 줄이 그 여행을 언급. 지난 여행이 없는 새 계정: 블록 없이 창고·날씨만으로 동작.
- [ ] 창고에 취사·조명·의류 장비가 있는 계정: 필수 4종 외에 스토브·연료·코펠·헤드랜턴·보온 레이어 등이 `추천`에 들어오고, 스토브가 2개면 하나만. 여름 여행에 아이젠 없음.
- [ ] 여행지 없는 배낭: 안내 문구, 계절 기준 추천.
- [ ] 체크 해제 → 하단 `{n}개 선택 · +{kg}kg` 즉시 갱신, 0개면 `담기` 비활성.
- [ ] `담기` → 토스트 → 상세에 장비·무게 반영, `bags` 배열 갱신. 결과에 창고 밖 장비가 없음(메타 줄에 출처 없음).
- [ ] 창고에 매트가 없는 계정: 매트 없이 추천 + `창고에 없어요: 매트` 줄 → 탭하면 검색(배낭 컨텍스트).
- [ ] 창고가 빈 계정: 로딩 없이 바로 빈 상태 문구, `다시 추천` 없음, 함수 로그에 모델 호출 없음·usage 미증가.
- [ ] `다시 추천` → 재호출, 남은 횟수 1 감소. 21번째 호출 → 한도 문구, 서버는 모델 미호출(로그).
- [ ] 비행기 모드 → 호출 없이 안내. 요청 중 끊김 → 에러 + `다시 시도`.
- [ ] 함수 로그에 추천 내용 미기록, usage만. 지어낸 gearId가 버려지는지(로그의 dropped 수).
- [ ] 세 플랫폼 시트·세이프에어리어, VoiceOver 행 라벨·체크 상태.

## 8. 결정 사항 / 미해결 질문

**사용자 결정 필요**

1. **기본 선택**: 전부 체크(제안) vs 필수만 체크.

**결정됨**

- 2026-10-31 **추천 후보는 창고 장비만** — 인기·카탈로그 미사용, 빠진 필수 그룹은 서버 계산 줄로 검색 유도, 창고 비면 모델 미호출.
- 2026-10-31 **이전 여행을 참고한다** — 최근 5건(이름·기간·여행지·날씨 요약·담은/챙긴 장비 id) + 창고 항목별 담긴 횟수를 서버가 선주입, 비슷한 여행의 짐을 출발점으로.
- 2026-10-31 **필수만이 아니라 배낭 전체를 꾸린다** — 창고 모든 그룹에서 여행에 맞는 장비를 전부(≤40), 같은 역할은 1개, 날씨·계절 불합은 제외.
2. **출시 공급자·모델**(AS-12) — 같은 여행 3건으로 모델 2개 비교 후 결정.
3. **PR #163(대화 화면) 처리**: 진입만 떼고 코드는 보류로 두고 머지할지, 닫을지. 서버 함수(lessismore#61)는 모드 추가 후 그대로 쓴다.
4. 개인정보 처리방침 갱신, `assistant-usage` 규칙(클라이언트 금지) — 사용자 작업.
