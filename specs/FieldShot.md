# 필드샷 (여행 사진 공유 이미지)

| 항목 | 내용 |
| --- | --- |
| 상태 | **기획 초안** (2026-07-10 — 구현 전, diff 승인 후 착수) |
| ID 프리픽스 | `FS` |
| 주요 코드 (예정) | `app/field-shot/[id]/`, `components/bag-detail/field-shot/`, `model/track/` |
| 관련 스펙 | [BagDetail.md](BagDetail.md), [ShareImage.md](ShareImage.md), [Weather.md](Weather.md), [DataModel.md](DataModel.md) |

## 1. 개요

사용자가 올린 **여행 사진** 위에 배낭·트래킹 데이터를 그래픽으로 얹어 인스타그램 공유용 이미지를 만든다.
레디샷([ShareImage.md](ShareImage.md))이 "내 장비"를 보여준다면, 필드샷은 **"내 여행(성취)"** 을 자랑한다.

핵심 포맷은 **팩 무게 × 코스 거리 듀얼 히어로** — "3.84kg으로 22.4km". 코스(거리)만 있는 Strava류와도,
무게만 있는 기존 레디샷과도 구별되는 UL 백패커 고유의 플렉스 공식이다.

## 2. 화면 및 진입

- 배낭 상세 카드 그리드의 레디샷 카드 옆에 `필드샷` 카드 → `/field-shot/{bagId}`.
- 여행 완료(endDate < 오늘) 또는 여행 중 배낭에서 진입을 유도한다(완료 시 카드에 강조 배지 등 — 디테일은 구현 시).
- 레디샷과 동일하게 `BagDetail`을 초기화해 배낭 데이터를 읽는다.

## 3. 요구사항

### FS-1 편집 플로우

**수용 기준**

- 흐름: 사진 선택(갤러리/카메라, 기존 ImagePicker 패턴) → 트래킹 데이터 확인/가져오기(FS-2) → 오버레이 미리보기 → 공유(FS-4).
- 사진은 9:16으로 크롭해 배치한다(캔버스 1080×1920, 인스타그램 스토리 규격).
- 오버레이 요소 토글: 트래킹 블록 / 팩 무게 / 하단 정보줄(배낭명·박지·날씨) 각각 켜고 끌 수 있다. `useless` 워드마크는 항상 표시(위치 고정).
- 오버레이 색은 사진 명도 자동 감지로 화이트/블랙을 선택하고(레디샷 로고 카드 밝기 감지 로직 재사용), 수동 토글을 제공한다.
- 텍스트 가독성을 위해 하단에 은은한 다크 그라디언트 스크림을 기본 적용한다(끌 수 있음). 듀오톤 등 필터는 v2.

### FS-2 트래킹 데이터

**수용 기준**

- **자동(우선, iOS)**: HealthKit에서 배낭 여행 기간(`startDate` 00:00 ~ `endDate` 24:00, 로컬 기준)의 하이킹·걷기 워크아웃을 조회해 매칭한다.
  - 복수 워크아웃이면 거리·시간·상승고도를 **합산**한다.
  - 경로 좌표(`HKWorkoutRoute`)는 **가장 거리가 긴 워크아웃 1개**의 것을 사용한다(v1 단순화).
  - 권한 거부/기록 없음 → 수동 입력 폴백을 안내한다.
- **수동(폴백)**: 거리(km)·소요 시간·상승고도(m)를 직접 입력한다. 경로 라인은 장식용 기본 라인으로 대체한다.
- 가져온/입력한 값은 `bag.track`([DataModel.md](DataModel.md) DM-16)으로 저장해 재진입 시 재사용하고, 배낭 상세에서도 여행 로그로 노출할 수 있게 한다(상세 노출 위치는 별도 태스크).
- 박지 라벨 기본값은 `bag.location.name`(DM-15, 카카오 지오코딩 지명)이며 필드샷 편집에서 수정 시 `track.campsiteName`으로 저장한다.
- Android는 v1에서 **수동 입력만** 제공한다(Health Connect 연동은 v2).

### FS-3 캔버스·템플릿 (G″ 하단 좌우 분할)

**수용 기준**

- 캔버스 1080×1920(9:16). 구성:
  - 상단 좌: `useless` 워드마크 / 상단 우: 여행 기간(`YYYY.MM.DD – DD`).
  - **하단 좌 트래킹 블록**: 경로 라인아트(SVG) → 거리(대형 타이포, `22.4 km`) → 상승고도·시간(소형 2줄).
  - **하단 우 팩 무게**: `PACK` 레이블 + 무게(대형 타이포, `3.84 kg`) — 거리와 **동일한 타이포 스케일**.
  - 최하단 정보줄(헤어라인 위): 좌 배낭명, 우 `박지 · 기온범위 날씨상태`(DM-15 날씨 스냅샷 사용, 없으면 생략).
- 그래픽 요소는 전부 `react-native-svg`로 렌더한다(해상도 무관 선명). 경로 라인은 좌표를 정규화·단순화해 블록 영역에 맞춘다.
- 폰트·팔레트는 레디샷 내보내기 캔버스 예외 규칙을 따른다(CLAUDE.md — 캔버스는 Inter/전용 팔레트 허용, 주변 편집 UI는 디자인 토큰).
- 무게 표기는 kg 소수 둘째 자리(`getWeight()` 표기 규칙과 동일), 거리는 km 소수 첫째 자리.

### FS-4 캡처·공유

**수용 기준**

- `react-native-view-shot`으로 JPG(품질 0.9) 캡처, 캡처 직전 편집용 UI를 숨긴다(레디샷 SI-4와 동일 파이프라인).
- iOS `Share.share`, Android `expo-sharing`. 갤러리 직접 저장은 공유 시트에 위임.
- 분석 이벤트: 진입/공유 완료를 각각 로깅한다(이벤트명은 [Analytics.md](Analytics.md) 규칙으로 구현 시 확정).

## 4. 데이터

- 읽기: `bag/{bagId}`(이름·기간·무게), `bag.location`/`bag.weather`(DM-15), HealthKit 워크아웃(기기 로컬).
- 쓰기: `bag.track`(DM-16) — `updateDoc` 단독 갱신, 배낭 복사 시 제외(location/weather와 동일 규칙).
- 사진은 서버에 업로드하지 않는다(로컬에서 합성·공유만).

## 6. 엣지 케이스

- **트래킹 데이터 없음**(권한 거부·기록 없음·수동 미입력): 트래킹 블록을 숨기고 무게 단독 히어로로 렌더한다(기존 D 템플릿 형태로 degrade).
- **날씨/박지 없음**: 정보줄에서 해당 항목 생략.
- **여행 시작 전 배낭**: 진입은 허용하되 트래킹 자동 매칭은 건너뛴다(기간이 미래).
- **경로 좌표 과다**(수만 포인트): Douglas-Peucker 단순화로 상한(예: 300pt) 적용.

## 7. 수동 검증 체크리스트

- [ ] 여행 기간 내 워크아웃이 있으면 거리·시간·상승고도가 합산돼 프리필된다
- [ ] 권한 거부 시 수동 입력 폴백으로 진행 가능
- [ ] 트래킹 없음 배낭 → 무게 단독 히어로로 렌더
- [ ] 결과물이 1080×1920 JPG, 편집 UI 미포함
- [ ] 밝은/어두운 사진에서 오버레이 색 자동 전환
- [ ] `bag.track` 저장 후 재진입 시 재조회 없이 프리필
- [ ] 배낭 복사 시 track 미복사

## 8. 미해결 질문

- **네이티브 모듈**: HealthKit 라이브러리 선정(`@kingstinct/react-native-healthkit` 후보) + config plugin. **새 네이티브 모듈이므로 OTA 불가 — 새 바이너리 릴리스에 묶어야 한다**(CLAUDE.md 버전 관리 규칙).
- 배낭 상세에서 `track`을 여행 로그로 노출하는 위치/형태(사용 기록 카드 확장?).
- 다박 여행에서 일자별 워크아웃을 나눠 보여줄지(v1은 합산만).
- 템플릿 I(사이드 레일)·피드 4:5 규격·듀오톤 필터는 v2 백로그.
