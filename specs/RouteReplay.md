## 1. 개요

코스(GPX)와 운동 기록(GPS 경로)은 지금 **평면 지도 위의 선**이다. 산행은 높낮이가 본질인데 평면에서는 그것이 고도 그래프로만 보인다. 이 화면은 **3D 지형 위에 경로를 놓고 카메라가 경로를 따라 날아가는** 리플레이를 보여 준다 — 다녀온 길을 다시 보고(운동 기록), 갈 길을 미리 본다(코스).

**엔진은 MapLibre GL JS(웹)를 웹뷰에 띄운다.** 네이티브 MapLibre는 2026-10 현재 3D 지형이 없고(개발 중), 웹 버전은 지원한다. 지도 데이터는 오프라인 지도([Offline.md](Offline.md) OF-6)와 **같은 스타일(`useless-outdoor`)·같은 고도 타일**이라 비용이 없고 공급자도 늘지 않는다. **온라인 전용**이다 — 웹뷰가 타일을 서버에서 받는다. 네이티브 MapLibre에 3D 지형이 들어오면 이 화면을 네이티브로 옮기고 오프라인에서도 연다(§8).

**범위**: 코스 화면·운동 기록 상세의 진입 버튼, 3D 지형 + 경로 + 시작·끝 + 포인트, 자동 비행(재생·정지·진행 바·배속), 전체 보기. **제외**: 오프라인, 공유 영상 내보내기(후속), 웹.

## 2. 화면 및 진입

```text
app/bag/[id]/route.tsx (코스 화면, BD-11) ─ 지도 우상단 보조 알약 `3D` → RouteReplayStore.open(코스) → /route-replay   (RR-1)
app/bag/[id]/activity (운동 기록 상세, HA-4) ─ 경로 지도 아래 보조 알약 `3D로 보기` → /route-replay            (RR-1)
app/route-replay.tsx ─ RouteReplayWrapper ─ RouteReplayView (헤더 + 웹뷰 + 상태)                                (RR-2)
```

진입 데이터는 라우트 파라미터가 아니라 **`RouteReplayStore`**(앱 싱글톤)에 담아 넘긴다 — 운동 기록 경로는 서버에 없고 기기 메모리에만 있어(HA-5) id로 다시 읽을 수 없다. 코스도 같은 길로 넘겨 화면이 출처를 모르게 한다.

## 3. 요구사항

### RR-1 진입점 `[제안]`

**수용 기준**

- **코스 화면**(BD-11, 네이티브·온라인·네이버 지도일 때): 지도 우상단, `내 위치` 버튼 위에 보조 알약 **`3D`**(아이콘 `cube-outline` + 라벨, 흰 면·잉크 글자 — 라임이 아니다, 이 화면의 주 액션은 `코스 추가`). **선택된 코스가 있을 때만** 보인다(코스가 없으면 보여 줄 것이 없다). 탭하면 선택 코스의 축약 좌표(`simplified`, 고도 포함)·이름·그 배낭의 포인트 전체를 스토어에 담고 `/route-replay`를 연다. 조준 모드(BD-14)·오프라인 지도(OF-6)에서는 숨긴다.
- **운동 기록 상세**(HA-4): 경로 지도 밴드 바로 아래 보조 알약 **`3D로 보기`**. 경로가 있는 운동만(없으면 지도도 버튼도 없다). 운동이 여러 개면 **모든 경로를 시간순으로 이어** 한 리플레이로 넘긴다(1박 2일이 날짜별로 나뉜 기록이 흔하다 — HA-3). 고도는 `altitudeMeters`가 있으면 쓰고 없으면 지형 위에 그대로 올린다.
- **오프라인이면** 두 버튼 모두 탭 시 토스트 `온라인에서 볼 수 있어요`(OF-5와 같은 문구) — 버튼은 보이되 비활성 모양이 아니다(연결이 돌아오면 바로 된다).
- 웹에는 진입점이 없다(APP-5).

### RR-2 리플레이 화면 `[제안]`

**수용 기준**

- 전체 화면(모달 스택). 헤더: 제목 = 코스 이름(운동 기록이면 `운동 기록`), 우상단 닫기 `×`(`accessibilityLabel` `닫기`). iOS는 네이티브 헤더, Android는 커스텀 헤더(코스 화면과 같은 관례 LG-1).
- 본문은 **웹뷰**(`react-native-webview`)에 앱이 가진 HTML 문서(`RouteReplayHtml.ts`, 인라인 문자열 — 호스팅 없이 OTA로 고칠 수 있다)를 `baseUrl` `https://lessismore-7e070.web.app`로 띄운다. 문서는 `maplibre-gl` 5.x를 cdnjs에서 받고, 스타일 `useless-outdoor`(OF-6과 같은 URL), 지형 `terrain`(스타일의 raster-dem, 과장 **1.3**), 하늘(`sky`)을 켠다. 상단 안전영역·헤더 아래부터 지도다.
- **그리는 것**: 경로 폴리라인(코스 파랑 `#2F6BFF` + 흰 테두리 — RoutePathOverlayView와 같다), 시작·끝 마커(`출발`/`도착` 글자 말풍선 — GRP-8 문구), 포인트 마커(유형색 원 + 이름), **진행 마커**(재생 중 경로 위를 움직이는 흰 테두리 잉크 점). 등고선은 그리지 않는다(3D 지형이 높낮이를 말한다).
- **자동 비행**: 문서가 준비되면 경로 전체가 보이게 맞춘 뒤(기울기 0 → 55°로 2초에 걸쳐), 재생을 누르면 카메라가 경로를 **따라간다** — 중심은 진행 지점 조금 앞, 방향은 진행 방향(짧은 창 평균으로 떨림 제거), 기울기 55~60°, 줌 약 14.5. 전체 재생 시간은 **거리 1km당 4초**(최소 20초·최대 120초), 배속 ×1·×2·×4. 끝에 닿으면 멈추고 다시 전체 보기로 돌아간다.
- **컨트롤**(문서 안, 하단 안전영역 위, 반투명 흰 면 + 모서리 12): 재생/정지(라임 알약 — 이 화면의 주 액션), 진행 바(드래그로 이동, 진행 지점의 고도 `1,204m` · 누적 거리 `3.2km` 표시), 배속 칩, `전체 보기`(카메라 리셋). 글꼴은 시스템 산세리프(웹뷰에 Pretendard를 싣지 않는다 — 네트워크 글꼴 로드 없이 바로 뜨는 쪽이 낫다).
- **제스처**: 재생 중이 아닐 때 드래그·핀치·회전·기울이기 전부 허용. 재생 중 사용자가 지도를 만지면 **재생은 계속하되 카메라 따라가기만 풀린다**(한 번 더 재생을 누르면 다시 따라간다) — 방향 모드의 "손으로 움직이면 따라가기만 풀림"(BD-11)과 같은 규칙.
- **메시지**: RN → 웹 `postMessage({ type: 'load', title, coordinates: [[lng, lat, ele?]], points: [{ lng, lat, title, type, color }] })`는 웹이 `ready`를 보낸 뒤 1회. 웹 → RN `ready` · `error(message)` · `play` · `finished`. 타입은 `RouteReplayMessage.ts`에 둔다.
- **출처 표기**는 MapLibre GL JS 기본 attribution(우하단 ⓘ)을 그대로 둔다(OF-6과 같은 의무).

### RR-3 상태 `[제안]`

**수용 기준**

- **로딩**: 웹뷰가 `ready`를 보낼 때까지 지도 자리에 로딩 뷰(`LoadingView`)를 겹친다(웹뷰는 뒤에서 뜬다 — 흰 깜빡임 방지).
- **실패**: `ready`가 **15초** 안에 오지 않거나 웹이 `error`를 보내거나 웹뷰 자체가 로드 실패(`onError`·`onHttpError`)하면 빈 상태 `3D 지도를 불러오지 못했어요` + `다시 시도`(웹뷰 재마운트). 지형 타일 하나가 늦는 것은 실패가 아니다(MapLibre가 비어 있는 채로 그린다).
- **연결 끊김(열려 있는 동안)**: 이미 받은 타일로 계속 돌아간다. 새 영역은 빈 지면이다. 앱이 막지 않는다.
- **진입 데이터 없음**(딥링크·새로고침으로 스토어가 비어 있을 때): 빈 상태 `코스 화면에서 3D를 열어 주세요` + 닫기만.
- 좌표가 **2점 미만**이면 진입 버튼 자체를 그리지 않는다(선이 되지 않는다).

### RR-4 측정 `[제안]`

[Analytics.md](Analytics.md) AN-3 표에 추가: `click_route_replay_open`(`source`: `route` | `activity`, `point_count`, `distance_m`), `route_replay_ready`(`logEvent`, `load_ms`), `route_replay_play`(`logEvent`, `speed`), `route_replay_finished`(`logEvent`), `route_replay_failed`(`logEvent`, `reason`: `timeout` | `web_error` | `http_error`).

## 4. 데이터

- 서버 변경 없음. 스토어는 메모리뿐이다(`RouteReplayStore`: `open(request)` · `getRequest()` · `clear()`). 화면을 닫으면 비운다.
- 지도 스타일·고도 타일은 [Offline.md](Offline.md) §4의 것과 같다. 웹뷰 문서는 앱 번들 안의 문자열이라 서버에 없다. `maplibre-gl`은 cdnjs(`https://cdnjs.cloudflare.com/ajax/libs/maplibre-gl/{version}/maplibre-gl.js`·`.css`)에서 받고 버전을 문서에 고정한다.

## 5. 플랫폼 분기

- iOS·Android 동일(`react-native-webview` 13.x, 이미 있음 — **네이티브 변경 없음**, 2.0.2에도 OTA 가능하지만 OF-6과 함께 2.0.3 묶음으로 낸다). 웹은 진입점 없음(APP-5).
- iOS 웹뷰는 WebGL이 기본으로 켜져 있다. Android 웹뷰는 기기 Chrome 버전에 따라 WebGL이 꺼진 경우가 있다 → 웹이 `error('webgl')`을 보내고 RR-3 실패 상태로 간다(문구는 같다).
- 안전영역: 하단 컨트롤은 `env(safe-area-inset-bottom)`을 더한다(`viewport-fit=cover`).

## 6. 엣지 케이스

- 고도가 없는 코스(GPX에 `ele` 없음, BD-11) → 경로를 지형 위에 그대로 올린다(MapLibre가 지형에 입힌다). 진행 바의 고도는 지형에서 읽는다(`queryTerrainElevation`).
- 운동 기록 경로가 수천 점(HA-4 GPS 1초 샘플) → 넘기기 전에 **500점으로 축약**(코스와 같은 상한, `simplifyRoute`)한다. 웹뷰 메시지 크기와 선 렌더 비용을 묶는다.
- 재생 중 앱 백그라운드 → 웹뷰가 멈추고 돌아오면 그 자리에서 이어진다(웹뷰 기본 동작). 따로 처리하지 않는다.
- 화면 회전은 세로 고정(앱 전체 설정)이다.

## 7. 수동 검증 체크리스트

- [ ] 코스 화면(온라인)에서 코스 선택 → `3D` 알약 → 화면 열림 → 로딩 → 3D 지형 위 경로·출발/도착·포인트, 기울어진 전경
- [ ] 재생 → 카메라가 경로를 따라 날아감, 진행 바·고도·거리 갱신, ×2·×4 배속, 끝에서 멈추고 전체 보기로 복귀
- [ ] 재생 중 지도를 드래그 → 따라가기만 풀림, 재생 다시 누르면 복귀
- [ ] 운동 기록 상세(경로 있는 운동) → `3D로 보기` → 실제 GPS 경로가 3D로 재생, 복수 운동이면 이어서
- [ ] 비행기 모드에서 `3D` 탭 → 토스트 `온라인에서 볼 수 있어요`; 열어 둔 채 연결 끊김 → 받은 영역은 그대로
- [ ] 코스 없는 배낭의 코스 화면 → `3D` 알약 없음; 조준 모드 → 숨김; 웹 → 진입점 없음
- [ ] 스크립트 로드 차단(네트워크 느리게) → 15초 뒤 `3D 지도를 불러오지 못했어요` + `다시 시도`

## 8. 미해결 질문

- **네이티브 MapLibre 3D 지형 출시 시** 이 화면을 네이티브로 옮겨 오프라인 지도(OF-6)와 합친다 — 그때 웹뷰 문서는 폐기. 출시 시점 미정(2026-10 기준 개발 중).
- 리플레이를 **영상·GIF로 내보내기**(SNS 공유 — BagShare와 연결) — 웹뷰 캔버스 캡처가 필요해 후속.
- 운동 기록의 **시간 축 재생**(실제 걸린 시간 비율로 느리고 빠르게) — 지금은 거리 기준 등속.
- 그룹 코스(GRP-8)에도 진입점을 둘지 — 그룹 지도 화면에 같은 알약을 두면 된다(후속).
