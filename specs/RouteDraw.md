## 1. 개요

지금 코스는 **다른 앱에서 만든 GPX를 가져오는 것**만 된다. 처음 쓰는 사람에게는 이것이 가장 큰 벽이다 — GPX가 뭔지 모르고, 만들 도구도 없다. 이 기능은 **지도를 눌러 점을 찍고 직선으로 이어** 코스를 만든다. 만든 코스는 가져온 GPX와 **똑같은 코스**다(같은 데이터 계약·같은 Storage 원본·같은 고도 그래프·3D·그룹 공유·오프라인 저장).

**범위**: 점 찍기 → 직선 연결 → 지형 타일로 고도 보강 → 이름 → 저장(배낭 코스·그룹 코스). **제외**(2026-10-13 사용자 결정): 등산로를 따라 자동으로 잇기(라우팅 서버), 점 드래그 이동, 기존 코스 편집, 웹.

## 2. 화면 및 진입

```text
/bag/[id]/route (BD-11) ─ 시트 푸터 `코스 추가` ─▶ 메뉴 시트 ─ `GPX 파일 가져오기` │ `지도에서 그리기` ─▶ 그리기 모드(같은 화면)   (RD-1·RD-2)
/group/[id]/map (GRP-10) ─ 시트 푸터 `코스 추가` ─▶ 같은 메뉴 ─▶ 그리기 모드                                                     (RD-1·RD-2)
그리기 모드 ─ `저장` ─▶ 이름 입력 시트 ─▶ 고도 보강 → GPX 생성 → 기존 업로드 경로(디스패처) ─▶ 코스 선택·카메라 맞춤               (RD-3)
```

## 3. 요구사항

### RD-1 진입 `[제안]`

**수용 기준**

- 배낭 코스 화면·그룹 지도의 **`코스 추가`**(시트 푸터)를 누르면 바로 파일 선택기가 뜨지 않고 **메뉴 시트**(`BottomMenuModalView`)가 뜬다: `GPX 파일 가져오기`(아이콘 `document-outline`, 메타 `다른 앱에서 만든 코스`) · `지도에서 그리기`(`create-outline`, 메타 `점을 찍어 직선으로 이어요`). 가져오기는 지금 흐름(GRP-8·BD-11) 그대로다.
- 상한(5)·웹(APP-5)·오프라인 지도(OF-6, 편집 UI 숨김) 규칙은 `코스 추가` 버튼이 이미 따르므로 메뉴에도 그대로 적용된다 — 상한이면 메뉴 자체가 뜨지 않는다(버튼이 비활성).
- 메뉴 시트가 **다 내려간 뒤** 그리기 모드로 들어간다(시트 위에 모드 전환이 겹치지 않게 — `BottomMenuModalView`의 닫힘 완료 뒤 `onPress` 관례).

### RD-2 그리기 모드 `[제안]`

**수용 기준**

- **같은 지도 화면 안의 모드**다(포인트 조준 모드 BD-14·GRP-9와 같은 방식 — 별도 라우트가 아니다). 들어가면: 바텀 시트 숨김, 포인트 카드·끝점 카드 닫기, `3D`·`포인트 추가`·상단 유형 칩 숨김, **기존 코스는 모두 옅게**(선택 코스도 — 그리는 선이 주인공이다), 포인트 마커는 그대로(물보급지 옆으로 지나가게 그리는 참고가 된다), `내 위치` 버튼은 남긴다(지금 있는 자리에서 그리는 것이 흔하다).
- **상단 안내 줄**(`MapNoticeLineView` 문법): `지도를 눌러 점을 찍으세요 · 직선으로 이어져요`. 첫 점을 찍으면 `계속 눌러 이어 가세요 · 저장은 2점부터`로 바뀐다. 안내 줄 아래에 **위치 검색 인풋**(RD-5).
- **지도 탭 = 점 추가**(끝에 붙인다). 롱프레스는 이 모드에서 받지 않는다(포인트 추가와 섞이지 않게). 마커 탭도 받지 않는다.
  - 점 마커: 코스 파랑(`ROUTE_COLOR`) 채움 + 흰 테두리 2 원(지름 14). 첫 점은 `출발` 말풍선(GRP-8 끝점 라벨과 같은 이미지), 마지막 점은 2점 이상일 때 `도착`. 선: 기존 코스와 같은 선(파랑 + 흰 테두리, `MapRoutePathLayersView` 문법) — 가져온 코스와 다르게 보일 이유가 없다.
  - 직전 점과 **5m 미만**이면 무시한다(두 번 눌림). 찍은 점은 **100개**까지 — 상한에 닿으면 토스트 `점은 100개까지 찍을 수 있어요`.
  - 찍은 직후 카메라는 움직이지 않는다(손가락 아래에서 지도가 움직이면 다음 점을 못 찍는다).
- **하단 바**(시트 자리, 순백 면 + 위 헤어라인 + 세이프에어리어): 왼쪽 메타 한 줄 `{n}점 · {거리}`(거리 = 직선 거리 합, `formatRouteDistance`; 숫자 조각은 콘덴스드 — HM-8), 오른쪽에 `되돌리기`(아이콘 `arrow-undo-outline`, 44pt, 점이 없으면 비활성) · `취소`(흰 알약) · **`저장`**(라임 알약 — 이 모드의 주 액션 하나, **2점 이상**일 때만 활성). 상승은 저장 때 계산하므로 바에는 적지 않는다.
- **취소**: 점이 2개 이상이면 확인 알럿 `그리던 코스를 버릴까요?`(`버리기` destructive) 뒤 모드를 나간다. 1개 이하면 바로 나간다. Android 뒤로가기도 취소와 같다.
- 모드 중 화면을 떠나면(뒤로가기·앱 종료) 그리던 점은 버린다 — 기기 저장은 하지 않는다(§8).

### RD-5 위치 검색 `[제안]`

그리는 동안 **지명을 검색해 지도를 그 자리로 옮긴다**(2026-10-14 사용자 요청 "코스 그리기일 때 위치 검색해서 이동할 수 있게"). 산 이름·봉우리·들머리를 찾아가 그리기 시작하는 것이 흔한 흐름이라, 손으로 지도를 끌어 찾게 두지 않는다.

**수용 기준**

- 그리기 모드 상단, 안내 줄(RD-2) **아래**에 검색 인풋을 둔다(여행지 선택기 DST-4·박지 지도 CS-6의 검색창 문법 — 돋보기 + 인풋 + 지우기 ×, 순백 면·모서리 `Radius.input`·44pt; 지도 위에 떠 있으므로 그림자 허용 — HM-8). 플레이스홀더 `지명·산 이름 검색`. 접근성 라벨 `위치 검색`, 지우기 `검색어 지우기`.
- 검색은 **카카오 로컬 키워드 검색 모듈을 그대로 쓴다**(`model/bag-destination/GeocodeService.ts`, 2자 이상 · 400ms 디바운스 · 실패 시 조용히 빈 결과 — DST-4·CS-6과 같은 규칙, 새로 구현하지 않는다). 등록 박지 통합 검색은 이 단계에서 하지 않는다(§8).
- 결과는 인풋 아래 **드롭다운 카드**(장소명 + 주소 한 줄, 최대 8행, 검색 중 스피너, 없으면 `검색 결과가 없어요`). 행은 `accessibilityRole='button'`.
- **행 탭 → 카메라만 옮긴다**(그 좌표, 줌 15, 애니메이션). **점은 찍지 않는다** — 점은 사용자가 지도를 눌러 찍는다. 결과 드롭다운과 키보드를 닫고 검색어는 유지한다. 그 자리에 **임시 핀**(회색 핀 + 장소명 캡션, 박지 핀 `MapSpotPinMarkerView` 문법·비대화형)을 띄운다 — 다음 검색 결과를 고르면 교체되고, 점을 찍거나 그리기 모드를 나가면 사라진다. 핀은 저장에 들어가지 않는다.
- **결과가 열려 있는 동안 지도를 탭하면 결과·키보드만 닫고 점을 찍지 않는다**(닫으려는 탭이 점이 되지 않게 — DST-4의 같은 규칙). 지우기 ×는 검색어·결과·임시 핀을 모두 비운다.
- 인풋에 포커스가 있는 동안 하단 바(RD-2)는 그대로다(키보드가 가려도 저장·취소는 키보드를 내린 뒤 누를 수 있다). 되돌리기·저장은 검색 상태와 무관하게 동작한다.
- 카카오 키(`EXPO_PUBLIC_KAKAO_REST_KEY`)가 없는 빌드에서는 인풋을 그리지 않는다 — 그리기 검색은 카카오가 유일한 원천이다(여행지 선택기는 박지 검색이 있어 키가 없어도 인풋을 숨기지 않는다).
- 측정: `click_route_draw_search_select`(`source`) — 결과를 골라 이동했을 때.

### RD-3 저장 `[제안]`

**수용 기준**

- `저장` → **이름 입력 시트**(포인트 입력 시트와 같은 문법, 1~40자, `RouteValidator.toRouteName` 절단). 기본값: 배낭이면 `{여행지 이름} 코스`(여행지가 없으면 `{배낭 이름} 코스`), 그룹이면 `{그룹 이름} 코스`. 같은 이름의 코스가 이미 있어도 막지 않는다(가져오기와 같다).
- 확인하면 **진행 표시**(시트 버튼 `저장 중…`)와 함께 순서대로:
  1. **선분 보간** — 각 선분을 **약 100m 간격**으로 나눠 샘플 좌표를 만든다(끝점 포함). 전체 샘플이 **500점**을 넘으면 간격을 늘려 500점 이하로 맞춘다(DM-29·DM-30 `simplified` 상한과 같은 수). 찍은 점은 모두 샘플에 남긴다.
  2. **고도 보강** — 샘플마다 지형 타일(Terrarium, OF-6과 같은 출처 `TERRAIN_TILE_URL_TEMPLATE`, **줌 13**)에서 고도를 읽어 `ele`에 넣는다. 타일은 키별로 한 번만 받고, 디코딩 직후 필요한 픽셀만 뽑고 버퍼는 버린다(선 하나가 보통 타일 1~4장). 타일 수가 상한(24장)을 넘으면 줌을 낮춰 다시 세고, 줌 10에서도 넘으면 고도 없이 간다. **전체 10초 타임아웃** — 넘으면 중단하고 고도 없이 저장한다(산에서 망이 불안정해도 `저장 중…`이 끝나지 않는 일이 없어야 한다). 픽셀은 가장 가까운 값(보간 없음 — 등고선 격자와 같은 정밀도면 충분하다). **타일을 하나라도 못 받으면 고도 없이 저장**하고 토스트 `고도를 읽지 못해 그래프 없이 저장했어요`(실패가 저장을 막지 않는다 — 코스 자체는 유효하다).
  3. 상승·하강은 샘플의 `ele`로 `measureElevationGain`/`measureElevationLoss`(그래프가 쓰는 같은 함수). 고도가 없으면 키를 생략한다(DM-30 규칙).
  4. **GPX 생성** — `<gpx version="1.1" creator="useless">` + `<metadata><time>` + `<trk><name>{이름}</name><desc>useless에서 지도에 점을 찍어 만든 코스 · 직선으로 이어졌어요</desc><trkseg>` + 샘플마다 `<trkpt lat lon><ele>`. 좌표는 소수 6자리, 고도는 정수 m. XML 특수문자는 이스케이프한다. 파일은 `expo-file-system` 캐시 디렉토리에 `{이름}.gpx`로 쓴다(이름의 파일 금지 문자는 `_`).
  5. `RouteDraft` = `{ name, fileSize(생성 파일 바이트), distance(샘플 직선 합), pointCount(샘플 수), bounds, simplified(샘플 — 500점 이하라 그대로), elevationGain?, elevationLoss? }` → **기존 `addRoute` 디스패처**(배낭 `BagRouteDispatcher.addRoute(bagId, draft, uri)`, 그룹 `GroupRouteDispatcher.addRoute(groupId, draft, uri)`)로 올린다. 검증·Storage 업로드·Firestore 쓰기·고아 회수·상한 검사 모두 가져오기와 **같은 코드**다 — 데이터 계약(DM-29·DM-30)과 보안 규칙은 바뀌지 않는다.
- 성공하면 **모드를 먼저 나간 뒤** 그 코스를 선택해 카메라를 맞춘다(배낭 `focusEntry` — 선택이 기기에 기억되는 부수효과 포함(BD-11 선택 기억), 그룹 `focusRoute`). 모드를 나간 뒤에 맞춰야 카메라 아래 여백이 하단 바가 아니라 시트 기준으로 계산된다. 토스트는 없다(화면이 바뀌는 것이 응답이다). 실패하면 가져오기와 같은 문구(`getRouteErrorMessage`)로 토스트하고 **모드에 남는다**(찍은 점이 사라지지 않는다 — 다시 저장할 수 있다).
- 캐시 파일은 업로드가 끝나면 지운다(성공·실패 모두).

### RD-4 측정 `[제안]`

[Analytics.md](Analytics.md) AN-3 표에 추가: `click_route_draw_start`(`source`: `route` | `group`), `click_route_draw_search_select`(`source` — RD-5 검색 결과로 이동), `click_route_draw_save`(**저장 성공 시**; `source`, `point_count` 찍은 점, `sample_count`, `distance` m, `has_elevation`), `click_route_draw_cancel`(`source`, `point_count`). 저장이 끝나면 기존 `click_bag_route_upload`/`click_group_route_upload`도 그대로 난다(코스가 하나 늘었다는 사실은 같다) — 두 이벤트를 합산하지 않도록 대시보드에서 `draw_save`는 "그리기로 만든 비율"로만 읽는다.

## 4. 데이터

- **서버·보안 규칙 변경 없음.** 그린 코스는 DM-29·DM-30 문서 + Storage GPX 원본으로 저장되며 가져온 코스와 구분하는 필드를 두지 않는다(2026-10-13 — "직접 그림" 표시는 §8 후속). GPX `<desc>`에만 출처를 남긴다.
- 지형 타일은 OF-6과 같은 공급자(AWS Terrain Tiles, 무료·키 없음). 저장 한 번에 타일 1~4장(각 ~100KB) — 비용 영향 없음.

## 5. 플랫폼 분기

- iOS·Android 동일(MapLibre 탭 좌표 `onPress`, 네이티브 변경 없음 — OTA 가능). 웹은 지도가 없어 메뉴·모드 모두 없다(APP-5). 오프라인 지도 모드(OF-6)에서는 `코스 추가`가 이미 숨겨져 있어 진입할 수 없다.

## 6. 엣지 케이스

- 그리는 중 네트워크가 끊김 → 점 찍기·되돌리기는 계속 된다(지도 타일만 비어 보인다). 저장 시 고도 보강이 실패하면 RD-3의 "고도 없이 저장"으로 간다. Storage 업로드가 실패하면 토스트 후 모드에 남는다.
- 점 2개가 **같은 자리**(5m 미만) → 두 번째를 무시. 모든 점이 한 자리면 저장이 활성화되지 않는다(2점 이상 규칙은 서로 다른 점 기준).
- 상한(배낭·그룹 5개)에 도달한 채 그리기 모드에 있다가(다른 기기에서 추가) 저장 → 디스패처가 거절 → 토스트 `코스는 5개까지…` → 모드에 남는다.
- 찍은 점이 100개(상한)이고 선분이 길어 샘플이 500을 넘음 → 간격을 늘려 맞춘다(찍은 점은 모두 유지).
- 매우 긴 선분(수십 km 직선) → 100m 간격 샘플이 수백 개가 되어 500 상한에 걸림 → 간격 자동 확대. 그래프는 성기게 그려진다.
- 지도 탭이 마커(포인트·박지 핀·출발/도착 말풍선) 위에서 일어남 → 그리기 모드에서는 마커 뷰가 터치를 받지 않게(`pointerEvents='none'`) 두어 지도 탭으로 들어와 점이 찍힌다(핸들러만 빼면 네이티브 마커 뷰가 터치를 먹는다).
- 저장 중(`저장 중…`) 화면을 떠남(iOS 스와이프 뒤로가기) → 업로드는 끝까지 진행돼 코스가 저장된다. 떠난 화면의 토스트·선택은 보이지 않는다. 막지 않는다.

## 7. 수동 검증 체크리스트

- [ ] 배낭 코스 화면 `코스 추가` → 메뉴 두 항목, `GPX 파일 가져오기`는 기존과 같이 파일 선택기
- [ ] `지도에서 그리기` → 시트·3D·포인트 추가·칩이 사라지고 안내 줄 + 하단 바(0점 · 0m, 저장 비활성)
- [ ] 지도 탭마다 점·선이 늘고 메타가 `n점 · 거리`로 갱신, 첫 점 `출발`·마지막 `도착` 말풍선, 되돌리기로 마지막 점 제거
- [ ] 그리기 모드 상단 검색: 2자 입력 → 드롭다운(장소명·주소) → 행 탭 → 카메라 이동 + 회색 임시 핀, 점은 안 찍힘, 검색어 유지. 결과 열린 채 지도 탭 → 닫히기만(점 없음). 점을 찍으면 임시 핀 사라짐. × → 모두 비움
- [ ] 2점부터 `저장` 활성 → 이름 시트(기본 `{여행지} 코스`) → 저장 중 → 모드 종료 + 새 코스 선택·카메라 맞춤, 목록 행·고도 그래프·3D가 가져온 코스와 같이 동작
- [ ] 비행기 모드에서 저장 → 고도 없이 저장 토스트 또는 업로드 실패 토스트(모드 유지)
- [ ] 취소(2점 이상) → 확인 알럿 → 버리기 → 원래 화면 복귀, 기존 코스 선명도 복원
- [ ] 그룹 지도에서 같은 흐름, 저장 후 다른 멤버 기기에 코스 표시
- [ ] 같은 자리 두 번 탭 → 점 1개, 100점 상한 토스트
- [ ] 저장된 GPX 내보내기(`⋯` → GPX 내보내기) → 다른 앱에서 열림
