## 1. 개요

지금 코스는 **다른 앱에서 만든 GPX를 가져오는 것**만 된다. 처음 쓰는 사람에게는 이것이 가장 큰 벽이다 — GPX가 뭔지 모르고, 만들 도구도 없다. 이 기능은 **지도를 눌러 점을 찍고 직선으로 이어** 코스를 만든다. 만든 코스는 가져온 GPX와 **똑같은 코스**다(같은 데이터 계약·같은 Storage 원본·같은 고도 그래프·3D·그룹 공유·오프라인 저장).

**범위**: 점 찍기 → 직선 또는 **등산로 따라** 연결(RD-6) → 지형 타일로 고도 보강 → 이름 → 저장(배낭 코스·그룹 코스), 그린 코스 수정(RD-7), 무료 1개·플러스(RD-8). **제외**: 점 드래그 이동·중간 삽입, 가져온 GPX 편집, 웹, 오프라인 길 따라 잇기. `[이력]` 2026-10-13에는 등산로 따라가기를 제외했다가 2026-10-14 RD-6으로 넣었다.

## 2. 화면 및 진입

```text
/bag/[id]/route (BD-11) ─ 시트 푸터 `코스 추가` ─▶ 메뉴 시트 ─ `GPX 파일 가져오기` │ `지도에서 그리기` ─▶ 그리기 모드(같은 화면)   (RD-1·RD-2)
/group/[id]/map (GRP-10) ─ 시트 푸터 `코스 추가` ─▶ 같은 메뉴 ─▶ 그리기 모드                                                     (RD-1·RD-2)
그리기 모드 ─ `저장` ─▶ 이름 입력 시트 ─▶ 고도 보강 → GPX 생성 → 기존 업로드 경로(디스패처) ─▶ 코스 선택·카메라 맞춤               (RD-3)
```

## 3. 요구사항

### RD-1 진입 `[제안]`

**수용 기준**

- 배낭 코스 화면·그룹 지도의 **`코스 추가`**(시트 푸터)를 누르면 바로 파일 선택기가 뜨지 않고 **메뉴 시트**(`BottomMenuModalView`)가 뜬다: `GPX 파일 가져오기`(아이콘 `document-outline`, 메타 `다른 앱에서 만든 코스`) · `지도에서 그리기`(`create-outline`, 메타 `점을 찍어 등산로나 직선으로 이어요`). 가져오기는 지금 흐름(GRP-8·BD-11) 그대로다.
- 상한(5)·웹(APP-5)·오프라인 지도(OF-6, 편집 UI 숨김) 규칙은 `코스 추가` 버튼이 이미 따르므로 메뉴에도 그대로 적용된다 — 상한이면 메뉴 자체가 뜨지 않는다(버튼이 비활성).
- 메뉴 시트가 **다 내려간 뒤** 그리기 모드로 들어간다(시트 위에 모드 전환이 겹치지 않게 — `BottomMenuModalView`의 닫힘 완료 뒤 `onPress` 관례).

### RD-2 그리기 모드 `[제안]`

**수용 기준**

- **같은 지도 화면 안의 모드**다(포인트 조준 모드 BD-14·GRP-9와 같은 방식 — 별도 라우트가 아니다). 들어가면: 바텀 시트 숨김, 포인트 카드·끝점 카드 닫기, `3D`·`포인트 추가`·상단 유형 칩 숨김, **기존 코스는 모두 옅게**(선택 코스도 — 그리는 선이 주인공이다), 포인트 마커는 그대로(물보급지 옆으로 지나가게 그리는 참고가 된다), `내 위치` 버튼은 남긴다(지금 있는 자리에서 그리는 것이 흔하다).
- **상단 안내 줄**(`MapNoticeLineView` 문법): `지도를 눌러 점을 찍으세요 · 등산로를 따라 이어져요`(RD-6 토글 켬) / `… · 직선으로 이어져요`(끔). 첫 점을 찍으면 `계속 눌러 이어 가세요 · 저장은 2점부터`로 바뀐다. 안내 줄 아래에 **위치 검색 인풋**(RD-5).
- **지도 탭 = 점 추가**(끝에 붙인다). 롱프레스는 이 모드에서 받지 않는다(포인트 추가와 섞이지 않게). 마커 탭도 받지 않는다.
  - 점 마커: 코스 파랑(`ROUTE_COLOR`) 채움 + 흰 테두리 2 원(지름 14). 첫 점은 `출발` 말풍선(GRP-8 끝점 라벨과 같은 이미지), 마지막 점은 2점 이상일 때 `도착`. 선: 기존 코스와 같은 선(파랑 + 흰 테두리, `MapRoutePathLayersView` 문법) — 가져온 코스와 다르게 보일 이유가 없다.
  - 직전 점과 **5m 미만**이면 무시한다(두 번 눌림). 찍은 점은 **100개**까지 — 상한에 닿으면 토스트 `점은 100개까지 찍을 수 있어요`.
  - 찍은 직후 카메라는 움직이지 않는다(손가락 아래에서 지도가 움직이면 다음 점을 못 찍는다).
- **하단 바**(시트 자리, 순백 면 + 위 헤어라인 + 세이프에어리어): 왼쪽 메타 한 줄 `{n}점 · {거리}`(거리 = 구간 좌표 길이 합 — 길 따라 구간이면 실제 길 거리(RD-6), `formatRouteDistance`; 숫자 조각은 콘덴스드 — HM-8), 오른쪽에 `되돌리기`(아이콘 `arrow-undo-outline`, 44pt, 점이 없으면 비활성) · `취소`(흰 알약) · **`저장`**(라임 알약 — 이 모드의 주 액션 하나, **2점 이상**일 때만 활성). 상승은 저장 때 계산하므로 바에는 적지 않는다.
- **취소**: 점이 2개 이상이면 확인 알럿 `코스를 저장하지 않고 나갈까요?`(`저장 안 함` destructive — 2026-10-15 사용자 피드백: "버리기"보다 "저장하지 않는다"가 하는 일을 정확히 말한다) 뒤 모드를 나간다. 1개 이하면 바로 나간다. Android 뒤로가기도 취소와 같다.
- 모드 중 화면을 떠나면(뒤로가기·앱 종료) 그리던 점은 버린다 — 기기 저장은 하지 않는다(§8). 대기 중이던 길 찾기 요청도 함께 버린다(토스트·측정을 남기지 않는다, RD-6).

### RD-5 위치 검색 `[제안]`

그리는 동안 **지명을 검색해 지도를 그 자리로 옮긴다**(2026-10-14 사용자 요청 "코스 그리기일 때 위치 검색해서 이동할 수 있게"). 산 이름·봉우리·들머리를 찾아가 그리기 시작하는 것이 흔한 흐름이라, 손으로 지도를 끌어 찾게 두지 않는다.

**수용 기준**

- 그리기 모드 상단, 안내 줄(RD-2) **아래**에 검색 인풋을 둔다(여행지 선택기 DST-4·박지 지도 CS-6의 검색창 문법 — 돋보기 + 인풋 + 지우기 ×, 순백 면·모서리 `Radius.input`·44pt; 지도 위에 떠 있으므로 그림자 허용 — HM-8). 플레이스홀더 `지명·산 이름 검색`. 접근성 라벨 `위치 검색`, 지우기 `검색어 지우기`.
- 검색은 **카카오 로컬 키워드 검색 모듈을 그대로 쓴다**(`model/bag-destination/GeocodeService.ts`, 2자 이상 · 400ms 디바운스 · 실패 시 조용히 빈 결과 — DST-4·CS-6과 같은 규칙, 새로 구현하지 않는다). 등록 박지 통합 검색은 이 단계에서 하지 않는다(§8).
- 결과는 인풋 아래 **드롭다운 카드**(장소명 + 주소 한 줄, 최대 8행, 검색 중 스피너, 없으면 `검색 결과가 없어요`). 행은 `accessibilityRole='button'`.
- **행 탭 → 카메라만 옮긴다**(그 좌표, 줌 15, 애니메이션). **점은 찍지 않는다** — 점은 사용자가 지도를 눌러 찍는다. 결과 드롭다운과 키보드를 닫고 검색어는 유지한다. 그 자리에 **임시 핀**(회색 핀 + 장소명 캡션, 박지 핀 `MapSpotPinMarkerView` 문법·비대화형)을 띄운다 — 다음 검색 결과를 고르면 교체되고, 점을 찍거나 그리기 모드를 나가면 사라진다. 핀은 저장에 들어가지 않는다.
- **결과가 열려 있는 동안 지도를 탭하면 결과·키보드만 닫고 점을 찍지 않는다**(닫으려는 탭이 점이 되지 않게 — DST-4의 같은 규칙). 지우기 ×는 검색어·결과·임시 핀을 모두 비운다.
- 인풋에 포커스가 있는 동안 하단 바(RD-2)는 그대로다(키보드가 가려도 저장·취소는 키보드를 내린 뒤 누를 수 있다). 되돌리기·저장은 검색 상태와 무관하게 동작한다.
- 카카오 키(`EXPO_PUBLIC_KAKAO_REST_KEY`)가 없는 빌드에서는 인풋을 그리지 않는다 — 그리기 검색은 카카오가 유일한 원천이다(여행지 선택기는 박지 검색이 있어 키가 없어도 인풋을 숨기지 않는다).
- 측정: `click_route_draw_search_select`(`source`) — 결과를 골라 이동했을 때.

### RD-6 등산로 따라 잇기 `[제안]`

점과 점을 직선 대신 **실제 등산로를 따라** 잇는다(2026-10-14 사용자 결정 — 엔진은 BRouter 자체 호스팅, 토글 기본 켬). 직선은 능선·계곡을 가로질러 실제 길과 다르고 거리·상승이 작게 나온다.

**수용 기준**

- 하단 바(RD-2) **안 첫 줄**에 **`등산로 따라` 스위치 행**(아이콘 `trail-sign-outline` + 라벨 왼쪽, iOS 스위치 오른쪽, 켬 트랙 = 잉크·끔 = 연회색; 라임 아님. 바 높이에 함께 잡혀 출처 ⓘ·`내 위치`가 그 위로 올라간다). `[이력]` 2026-10-15까지 칩 문법(켬 = 잉크 채움)이었으나 "고르는 것"으로 읽혀 켜짐·꺼짐이 드러나지 않아(사용자 피드백 "토글 형식이 맞지 않을까") 스위치로 바꿨다. **기본 켬**, 세션 동안 기억(기기 저장 안 함). 접근성 `accessibilityRole='switch'` + 상태.
- 켬일 때 새 점을 찍으면 **직전 점 → 새 점 구간**을 라우팅 함수(§4 `routeTrail`)에 요청한다. 응답 전까지 그 구간은 **점선 회색 직선**으로 그리고 하단 메타에 `길 찾는 중…`. 응답이 오면 길 좌표로 바꾼다.
  - 길을 못 찾음(`found: false`)·실패·**8초 초과**·오프라인 → 그 구간은 **직선**으로 확정하고 토스트 `이 구간은 길을 찾지 못해 직선으로 이었어요`(같은 세션에서 3회 이상 연속이면 `길 정보가 없는 지역이에요 · 등산로 따라를 꺼 보세요`로 한 번만).
  - 두 점 사이 직선이 **20km 초과**면 요청하지 않고 직선(라우팅이 의미 없는 거리이고 서버 부하를 막는다). 오프라인·20km 초과도 실패와 같이 토스트·`route_trail_fail`을 남기고 연속 실패에 센다. 연속 실패 안내(`길 정보가 없는 지역이에요…`)는 **앱 세션에서 한 번**만.
  - 서버는 찍은 점에서 길까지 300m를 넘거나, 길 거리가 직선의 3배 + 3km를 넘게 돌면 `found:false`로 본다(바다·논 한가운데를 찍으면 BRouter가 멀리 떨어진 도로로 붙어 수십~수백 km 우회 경로를 내기 때문 — 2026-10-14 실측).
  - 요청은 **찍은 순서대로 하나씩** 처리한다(빨리 연달아 찍어도 구간 순서가 꼬이지 않게). 대기 중 구간이 있어도 점은 계속 찍을 수 있다.
- 끔일 때는 지금처럼 직선. 토글을 바꿔도 **이미 그린 구간은 그대로**다(다음 구간부터 적용).
- **모델은 구간 목록**이다: 찍은 점 `n`개 → 구간 `n−1`개, 각 구간 = `{ mode: 'trail' | 'straight', coordinates, pending }`. 선은 구간 좌표를 이어 그린다. 길 따라 구간은 기존 코스 선 문법, 직선 구간도 같은 선(완료 후 구분하지 않는다 — 저장 데이터에 모드를 남기지 않는다).
- **되돌리기** = 마지막 점과 그 점으로 들어온 구간을 함께 지운다(대기 중이면 요청 결과를 버리고, 다음 구간이 그 요청을 기다리지 않게 바로 다음 차례로 넘어간다).
- 하단 메타 거리 = 구간 좌표 길이 합(길 따라면 실제 길 거리).
- 저장(RD-3) 변경: 선분 보간(①)은 **구간 좌표 전체**를 대상으로 하고, 고도(②)는 길 따라 구간 좌표에 서버가 준 `ele`가 있으면 그대로 쓰고 **직선 구간 샘플만** 지형 타일로 채운다. 대기 중 구간이 있으면 `저장`을 비활성(`길 찾는 중…`).
- 그리기 모드에 들어가면 함수에 **깨우기 요청**(`warmup: true`)을 한 번 보낸다 — 서버 콜드 스타트(수 초)를 첫 점 전에 치른다. 결과는 무시한다.
- GPX `<desc>` 끝에 길 따라 구간이 하나라도 있으면 ` · 경로 데이터 © OpenStreetMap 기여자, BRouter`를 덧붙인다(ODbL 출처 표기).
- 측정: `click_route_draw_save`에 `trail_segment_count`, `straight_segment_count` 추가. `route_trail_fail`(`logEvent`, `reason`: `not_found` | `timeout` | `error` | `offline` | `too_far`).

### RD-3 저장 `[제안]`

**수용 기준**

- `저장` → **이름 입력 시트**(포인트 입력 시트와 같은 문법, 1~40자, `RouteValidator.toRouteName` 절단). 기본값: 배낭이면 `{여행지 이름} 코스`(여행지가 없으면 `{배낭 이름} 코스`), 그룹이면 `{그룹 이름} 코스`. 같은 이름의 코스가 이미 있어도 막지 않는다(가져오기와 같다).
- 확인하면 **진행 표시**(시트 버튼 `저장 중…`)와 함께 순서대로:
  1. **선분 보간** — 각 선분을 **약 100m 간격**으로 나눠 샘플 좌표를 만든다(끝점 포함). 전체 샘플이 **500점**을 넘으면 간격을 늘려 500점 이하로 맞춘다(DM-29·DM-30 `simplified` 상한과 같은 수). 찍은 점은 모두 샘플에 남긴다.
  2. **고도 보강** — 샘플마다 지형 타일(Terrarium, OF-6과 같은 출처 `TERRAIN_TILE_URL_TEMPLATE`, **줌 13**)에서 고도를 읽어 `ele`에 넣는다. 타일은 키별로 한 번만 받고, 디코딩 직후 필요한 픽셀만 뽑고 버퍼는 버린다(선 하나가 보통 타일 1~4장). 타일 수가 상한(24장)을 넘으면 줌을 낮춰 다시 세고, 줌 10에서도 넘으면 고도 없이 간다. **전체 10초 타임아웃** — 넘으면 중단하고 고도 없이 저장한다(산에서 망이 불안정해도 `저장 중…`이 끝나지 않는 일이 없어야 한다). 픽셀은 가장 가까운 값(보간 없음 — 등고선 격자와 같은 정밀도면 충분하다). **타일을 하나라도 못 받으면 고도 없이 저장**하고 토스트 `고도를 읽지 못해 그래프 없이 저장했어요`(실패가 저장을 막지 않는다 — 코스 자체는 유효하다).
  3. 상승·하강은 샘플의 `ele`로 `measureElevationGain`/`measureElevationLoss`(그래프가 쓰는 같은 함수). 고도가 없으면 키를 생략한다(DM-30 규칙).
  4. **GPX 생성** — `<gpx version="1.1" creator="useless">` + `<metadata><time>` + `<trk><name>{이름}</name><desc>useless에서 지도에 점을 찍어 만든 코스</desc><trkseg>` + 샘플마다 `<trkpt lat lon><ele>`. 좌표는 소수 6자리, 고도는 정수 m. XML 특수문자는 이스케이프한다. 파일은 `expo-file-system` 캐시 디렉토리에 `{이름}.gpx`로 쓴다(이름의 파일 금지 문자는 `_`).
  5. `RouteDraft` = `{ name, fileSize(생성 파일 바이트), distance(구간 좌표 길이 합 — 하단 바에서 본 거리와 같다, RD-6), pointCount(샘플 수), bounds, simplified(샘플 — 500점 이하라 그대로), elevationGain?, elevationLoss? }` → **기존 `addRoute` 디스패처**(배낭 `BagRouteDispatcher.addRoute(bagId, draft, uri)`, 그룹 `GroupRouteDispatcher.addRoute(groupId, draft, uri)`)로 올린다. 검증·Storage 업로드·Firestore 쓰기·고아 회수·상한 검사 모두 가져오기와 **같은 코드**다 — 데이터 계약(DM-29·DM-30)과 보안 규칙은 바뀌지 않는다.
- 성공하면 **모드를 먼저 나간 뒤** 그 코스를 선택해 카메라를 맞춘다(배낭 `focusEntry` — 선택이 기기에 기억되는 부수효과 포함(BD-11 선택 기억), 그룹 `focusRoute`). 모드를 나간 뒤에 맞춰야 카메라 아래 여백이 하단 바가 아니라 시트 기준으로 계산된다. 토스트는 없다(화면이 바뀌는 것이 응답이다). 실패하면 가져오기와 같은 문구(`getRouteErrorMessage`)로 토스트하고 **모드에 남는다**(찍은 점이 사라지지 않는다 — 다시 저장할 수 있다).
- 캐시 파일은 업로드가 끝나면 지운다(성공·실패 모두).

### RD-7 그린 코스 수정 `[제안]`

지도에서 그린 코스를 다시 열어 점을 더하거나 되돌리고 다시 저장한다(2026-10-14 사용자 결정 "첫 코스는 수정도 가능하게").

**수용 기준**

- **그린 코스만** 수정할 수 있다(DM-29·DM-30 `source == 'drawn'`). 가져온 GPX는 원본 파일이 따로 있어 수정하지 않는다.
- 진입: 코스 행 `⋯` 메뉴에 `코스 수정`(아이콘 `create-outline`, 뒤집기 다음·삭제 위). 배낭 코스는 소유자, 그룹 코스는 올린 사람만. 권한(RD-8)이 없으면 항목은 보이되 누르면 구독 화면(코스 그리기 진입점 변형)을 연다.
- 누르면 같은 화면의 그리기 모드(RD-2)로 들어가 **그 코스를 이어서 편집**한다: 찍었던 점(`drawnPoints`)과 구간을 복원한다 — 구간 좌표는 저장된 `simplified`를 찍은 점 위치로 잘라 되살린다(다시 라우팅하지 않는다 — 서버 호출·결과 변동 없이 열린다). 복원 구간은 모두 완료 상태다.
- 편집 중에는 끝에 점을 더하고(RD-6 토글 적용), 되돌리기로 끝에서부터 지운다. 중간 점 이동·삽입은 하지 않는다(§8).
- 안내 줄 첫 문구는 `코스 수정 중 · 끝에 점을 더하거나 되돌리세요`. 하단 바 `저장`은 **바뀐 것이 있을 때만** 활성.
- 저장: 이름 시트에 지금 이름이 채워져 있다 → RD-3 ①~④ 그대로 → **같은 문서·같은 Storage 경로를 덮어쓴다**(`createdAt` 유지, `updatedAt` 갱신, `storagePath` 불변). 그룹에 복사된 사본(`sourceBagRouteId`)은 따라 바뀌지 않는다(복사이므로 — GRP-8).
- 취소: 바뀐 것이 있으면 `수정한 내용을 저장하지 않고 나갈까요?`(`저장 안 함`) 확인 뒤 원래 코스 그대로 나간다.
- GPX `<desc>` 출처(RD-6): 수정 저장은 복원 구간이 원래 길 따라였는지 알 수 없으므로 **출처를 항상 붙인다**(빠뜨리는 쪽이 ODbL 위반이고, 붙여서 생기는 해는 없다).
- 하단 바 거리: 수정을 열 때는 저장된 `distance`를 구간 길이 비율로 나눠 두어 원래 거리와 같게 시작한다(축약 좌표로 다시 재면 조금 짧다).
- 찍은 점(`drawnPoints`)이 없는 그린 코스는 수정할 수 없다 — 토스트 `이 코스는 수정할 수 없어요`.
- 측정: `click_route_draw_edit_start`(`source`), 저장 성공은 `click_route_draw_save`에 `mode: 'edit'`(새로 그림은 `'new'`). 수정 저장은 `*_route_upload`를 남기지 않는다(코스 수가 늘지 않는다). `click_route_draw_save`의 구간 수는 새로 그린 구간만 `trail_segment_count`·`straight_segment_count`로 세고, 수정으로 되살린 구간은 `restored_segment_count`로 따로 센다. 덮어쓰기 실패 후 이전 파일 되돌리기마저 실패하면 `route_update_restore_failed`(`logEvent`, `kind`: `bag` | `group`).

### RD-8 무료 1회와 플러스 `[제안]`

코스 그리기는 **useless 플러스 혜택**이다. 무료 사용자는 계정당 **평생 1개**를 그릴 수 있고, 그 1개는 **계속 수정**할 수 있다(2026-10-14 사용자 결정 — 지우고 다시 그려 횟수를 되살리지 못하게 "남은 개수"가 아니라 "평생 횟수"로 센다).

**수용 기준**

- 권한 판단(앱): 플러스(`premium` 활성, 체험 포함) → 그리기·수정 모두 가능. 아니면 서버의 무료 기록(DM-36 `route-draw-quota/{uid}`)을 읽어:
  - `freeRoute`가 없거나 **아직 확정되지 않았다**(`confirmed != true` — 저장이 실패해 코스가 생기지 않은 경우) → **새로 그리기 1회 가능**(그리기 메뉴 항목 메타에 `첫 코스는 무료예요`). 최종 판단은 서버 `claimFreeRouteDraw`가 한다.
  - `freeRoute`가 확정됐다(`confirmed == true`) → 새로 그리기 불가(메뉴 항목 메타 `useless 플러스`), **그 코스 수정만 가능**.
  - **확정 대기 창(2분)**: 방금 정해 서버 확정을 기다리는 미확정 기록(`claimedAt`으로부터 2분 안)은 "썼음"으로 본다 — 새로 그리기를 막아, 다 그리고 저장하다 거절되는 일을 없앤다. **그 코스 수정은 확정 전에도 연다**(목록에 그 코스가 있다는 것이 생성됐다는 뜻이다). 창이 지난 미확정은 저장이 실패한 것으로 보고 1회를 되돌린다.
  - 무료 기록을 못 읽음(오프라인 등) → 안전하게 "새로 그리기 불가·수정 불가"로 보고, 누르면 `온라인에서 확인할 수 있어요` 토스트.
- 새로 그리기 불가 상태에서 `지도에서 그리기`를 누르면 구독 화면(SUB-2)을 **코스 그리기 진입점 변형**(SUB-12)으로 연다. 권한을 얻어 닫히면 그리기 모드로 바로 들어간다.
- **무료 1회 쓰기**: 저장 전 검사(코스 상한 5개 등 — 업로드가 거절될 이유)를 **먼저** 통과한 뒤, 무료 사용자가 처음 그린 코스를 저장할 때 업로드 **직전**에 함수 `claimFreeRouteDraw({ kind: 'bag'|'group', parentId, routeId })`를 부른다. 서버가 `freeRoute`를 그 코스로 정한다(이미 다른 코스가 있으면 거절 → 저장 중단 + 구독 화면). 업로드가 실패해 그 코스가 실제로 생기지 않았으면(서버 트리거가 생성을 확인하기 전 — DM-36 `confirmed`), 다음 저장에서 다른 코스로 다시 정할 수 있다.
- 그 코스를 **지워도 무료 기록은 남는다**(다시 그리기 1회가 생기지 않는다). 수정할 코스가 없어질 뿐이다.
- 플러스가 끝나면: 이미 그린 코스는 그대로 보이고 쓰인다(그래프·3D·오프라인 저장은 각자의 규칙). 새로 그리기·수정은 무료 규칙으로 돌아간다(무료 1회를 아직 안 썼으면 1회 가능, 썼으면 그 코스만 수정).
- **서버도 확인한다**: `routeTrail`(RD-6)은 플러스이거나, 무료 1회를 아직 안 썼거나, 요청에 실린 수정 대상(`editing: { kind, parentId, routeId }`)이 그 사용자의 `freeRoute`일 때만 길을 찾아 준다. 아니면 `{ found: false, reason: 'not_entitled' }` → 앱은 그 구간을 직선으로 잇고 구독 화면을 연다(앱 세션에 한 번 — 이후엔 토스트 `등산로 따라는 useless 플러스 기능이에요`). 직선 그리기는 서버를 거치지 않으므로 앱 게이트만 있다(조작된 앱의 우회는 서버 비용이 없어 허용 범위). **강제 수준(2026-10-15 리뷰 결론)**: 무료 1회의 서버 확인은 "정상 앱" 기준이다 — 조작된 앱이 `claimFreeRouteDraw`를 건너뛰고 `source`를 빼고 올리면 기록이 확정되지 않아 길 따라 잇기를 계속 받을 수 있다. 막으려면 그린 코스 생성을 함수 경유로만 열어야 해 비용이 크다. 서버 호출에는 사용자별 분 60·일 2,000회 상한이 있어 비용은 묶여 있으므로 **이 수준을 받아들인다**. 탈퇴 후 재가입은 새 uid라 무료 1회가 새로 생긴다(의도된 동작).
- GPX 가져오기·보기·고도 그래프·3D·뒤집기·내보내기는 계속 무료다.

### RD-9 노출과 진입 `[제안]`

## 4. 데이터

**라우팅 서버(RD-6)** — 코스 문서에 `source`·`drawnPoints`·`updatedAt`이 더해지고(RD-7, DM-29·DM-30), 무료 기록 컬렉션이 생긴다(RD-8, DM-36).

```text
앱 ─ httpsCallable('routeTrail', { from:{lat,lng}, to:{lat,lng} } | { warmup:true })
      └▶ Cloud Function routeTrail (asia-northeast3, 로그인 필수, uid당 분당 60·일 2,000회)
           └▶ Cloud Run `brouter` (asia-northeast3, 비공개 — 함수 서비스 계정만 invoker, 최소 인스턴스 0, 메모리 2GiB)
                 GET /brouter?lonlats={lng},{lat}|{lng},{lat}&profile=hiking-mountain&alternativeidx=0&format=geojson
```

- 응답(함수 → 앱): `{ found: true, coordinates: [{lat,lng,ele}], distance(m), ascent(m) }` 또는 `{ found: false }`. 좌표는 소수 6자리, 최대 2,000점(넘으면 함수가 균등 샘플링).
- **데이터**: BRouter가 매주 배포하는 세그먼트 타일 중 한국을 덮는 4장(`E120_N35`·`E125_N30`·`E125_N35`·`E130_N35`, 약 100MB)을 이미지에 굽는다. 갱신은 **월 1회** 이미지 재빌드(웹 레포 `infra/brouter/` 스크립트) — 등산로는 자주 바뀌지 않는다. 엔진은 BRouter 릴리스(현재 1.7.10)를 고정한다.
- 비용: Cloud Run 최소 0이면 무료 한도 안, Artifact Registry 이미지 ~0.3GB.
- 출처·라이선스: BRouter MIT, 데이터 ODbL(OpenStreetMap) — 지도 출처 ⓘ와 GPX `<desc>`에 표기(RD-6).


- 그린 코스는 DM-29·DM-30 문서 + Storage GPX 원본으로 저장된다. **2026-10-14 개정**: 문서에 `source: 'drawn'`과 찍은 점 `drawnPoints`(최대 100, `{lat,lng}`)를 남긴다 — 수정(RD-7)에서 다시 열고 무료 1회(RD-8)를 가리기 위해서다. 가져온 코스는 `source`가 없다(= `gpx`). 보안 규칙: 두 코스 컬렉션에 이 키를 허용하고, **그린 코스만** 소유자(배낭)·올린 사람(그룹)이 수정할 수 있게 연다(`storagePath`·`createdAt`·`source` 불변). `[이력]` 2026-10-13에는 구분 필드를 두지 않았다.
- 지형 타일은 OF-6과 같은 공급자(AWS Terrain Tiles, 무료·키 없음). 저장 한 번에 타일 1~4장(각 ~100KB) — 비용 영향 없음.

## 6. 엣지 케이스

- 그리는 중 네트워크가 끊김 → 점 찍기·되돌리기는 계속 된다(지도 타일만 비어 보인다). 저장 시 고도 보강이 실패하면 RD-3의 "고도 없이 저장"으로 간다. Storage 업로드가 실패하면 토스트 후 모드에 남는다.
- 점 2개가 **같은 자리**(5m 미만) → 두 번째를 무시. 모든 점이 한 자리면 저장이 활성화되지 않는다(2점 이상 규칙은 서로 다른 점 기준).
- 상한(배낭·그룹 5개)에 도달한 채 그리기 모드에 있다가(다른 기기에서 추가) 저장 → 디스패처가 거절 → 토스트 `코스는 5개까지…` → 모드에 남는다.
- 찍은 점이 100개(상한)이고 선분이 길어 샘플이 500을 넘음 → 간격을 늘려 맞춘다(찍은 점은 모두 유지).
- 매우 긴 선분(수십 km 직선) → 100m 간격 샘플이 수백 개가 되어 500 상한에 걸림 → 간격 자동 확대. 그래프는 성기게 그려진다.
- 지도 탭이 마커(포인트·박지 핀·출발/도착 말풍선) 위에서 일어남 → 그리기 모드에서는 마커 뷰가 터치를 받지 않게(`pointerEvents='none'`) 두어 지도 탭으로 들어와 점이 찍힌다(핸들러만 빼면 네이티브 마커 뷰가 터치를 먹는다).
- 저장 중(`저장 중…`) 화면을 떠남(iOS 스와이프 뒤로가기) → 업로드는 끝까지 진행돼 코스가 저장된다. 떠난 화면의 토스트·선택은 보이지 않는다. 막지 않는다.

- [ ] 배낭 코스 화면 `코스 추가` → 메뉴 두 항목, `GPX 파일 가져오기`는 기존과 같이 파일 선택기

- [ ] 지도 탭마다 점·선이 늘고 메타가 `n점 · 거리`로 갱신, 첫 점 `출발`·마지막 `도착` 말풍선, 되돌리기로 마지막 점 제거
- [ ] 그리기 모드 상단 검색: 2자 입력 → 드롭다운(장소명·주소) → 행 탭 → 카메라 이동 + 회색 임시 핀, 점은 안 찍힘, 검색어 유지. 결과 열린 채 지도 탭 → 닫히기만(점 없음). 점을 찍으면 임시 핀 사라짐. × → 모두 비움
- [ ] `등산로 따라`(기본 켬): 북한산 우이동 근처 → 백운대 근처를 찍으면 점선 회색 → 길을 따라 굽은 선으로 바뀜, 거리가 직선보다 길게 표시. 길 없는 바다·논 한가운데 찍으면 직선 + 토스트. 끄면 다음 구간부터 직선. 되돌리기는 구간째로. 길 찾는 중엔 저장 비활성. 비행기 모드 → 직선 + 토스트
- [ ] 무료 계정: 첫 코스 그리기·저장 → 메뉴 메타가 `useless 플러스`로 바뀜, `지도에서 그리기` → 구독 화면(코스 그리기 변형). 그 코스 `⋯` → `코스 수정` → 점 추가·되돌리기·저장 → 같은 코스가 바뀜(새 코스 안 생김). 지워도 다시 무료로 못 그림. 다른 그린 코스는 `코스 수정` → 구독 화면
- [ ] 플러스(체험 포함): 그리기·수정 무제한, 만료 후엔 무료 규칙
- [ ] 2점부터 `저장` 활성 → 이름 시트(기본 `{여행지} 코스`) → 저장 중 → 모드 종료 + 새 코스 선택·카메라 맞춤, 목록 행·고도 그래프·3D가 가져온 코스와 같이 동작
- [ ] 비행기 모드에서 저장 → 고도 없이 저장 토스트 또는 업로드 실패 토스트(모드 유지)
- [ ] 취소(2점 이상) → 확인 알럿 `코스를 저장하지 않고 나갈까요?` → `저장 안 함` → 원래 화면 복귀, 기존 코스 선명도 복원
- [ ] 그룹 지도에서 같은 흐름, 저장 후 다른 멤버 기기에 코스 표시
- [ ] 같은 자리 두 번 탭 → 점 1개, 100점 상한 토스트
- [ ] 저장된 GPX 내보내기(`⋯` → GPX 내보내기) → 다른 앱에서 열림
