## 1. 개요

장비 카탈로그 검색(Algolia)과 인기 장비 순위(`gear-rank`)를 제공하고,
검색 결과에서 바로 창고 추가·배낭 담기를 지원한다. 비로그인 사용자도 같은 네이티브 검색 UI를 쓴다.

### 2.1 화면 문법 (as-built, 2026-08-11 — Liquid Depth)

SR-7 목록·SR-8 브랜드 디렉토리의 시각만 서술한다. 무엇을 언제 보여주는지는 SR-7·SR-8이 정의한다.
(검색 결과·인기 순위 화면의 문법은 SR-2·SR-4에 있다.)

- 지면은 **지형 없이 `canvas` + 우상단 라임 글로우**다 — 훑어 비교·검색하는 목록이라 산세를 깔지 않는다([Warehouse.md](Warehouse.md) §2와 같은 판단).
- 크롬은 지면 위에 뜬 **유리**다: iOS는 네이티브 투명 헤더가 원형 글래스 back을 내주고(LG-1), Android·Web은 같은 그림을 공용 프리미티브(`LiquidGlassCircleButton`)로 직접 그린다. 좌우 여백은 크롬 12 · 콘텐츠 20이다.
- 화면 대상은 **제목 블록**이 든다(32/38): SR-7은 카테고리·브랜드 이름 + 우측 정렬 드롭다운, SR-8은 `브랜드별 탐색` + 그 아래 한 줄(`124개`, 13/500 — **지금 목록에 보이는 브랜드 수**라 검색어를 넣으면 함께 줄어든다)과 유리 검색 필드. **네이티브 바 타이틀은 비운다** — 같은 말을 두 곳에 두지 않는다.
- **제목 블록·검색 필드는 스크롤하지 않고 그 아래 목록만 스크롤한다** — 창고와 같은 as-built 이탈이며(핸드오프의 "유리 밑으로 흐르는 콘텐츠"와 다르다), iOS 상단 인셋도 automatic content inset이 아니라 수동 `paddingTop`(세이프에어리어 + 44 + 6)이다([LiquidGlassNavigation.md](LiquidGlassNavigation.md) LG-3).
- **행 하나가 곧 카드**다(모서리 20 · `LiquidShadow.tile` · 카드 사이 10). SR-7 목록이 **무한 스크롤로 자라기** 때문이다 — 카드가 리스트 컨테이너와 같아지면 스크롤 프레임 안에 갇혀 마지막 행이 카드 밑단에서 잘린다(카드 안에 헤어라인으로 나누는 문법은 길이가 고정된 목록, 창고·인기 순위의 것이다). SR-8은 단발 쿼리(`ownerCount desc` 상한 200)라 길이가 고정이지만 **같은 행 문법을 쓴다** — 두 화면이 브랜드 행 컴포넌트를 공유하고(`BrandRowView`), 한쪽만 카드 하나로 묶으면 같은 행이 두 모양이 된다.
- 라임은 **담기 CTA 하나**뿐이다(SR-7). SR-8에는 라임 면이 없다 — 담기 같은 주 액션이 없고 행 선택이 곧 이동이다.
- 숫자(무게)는 **콘덴스드(Archivo Narrow)**, 단위까지 한 덩어리(`907g`)로 쓴다. 한글이 섞인 값(개수·`제품 n`)은 본문 서체다.
- 각진 면은 쓰지 않는다(카드 20, 검색 필드·칩 height/2, 썸네일 12).
- 로딩은 스켈레톤이다(스피너 금지) — 도착할 목록과 같은 카드·행 골격에 셔머만 얹는다. 장비 행과 브랜드 행은 골격이 다르므로 **스켈레톤도 갈라 둔다**(SR-8).

## 3. 요구사항

### SR-1 검색 실행

**수용 기준**

- 입력 300ms 디바운스 후 Algolia `useless-gear-search` 인덱스를 검색한다([DataModel.md](DataModel.md) DM-10).
- 페이지 크기 100, 무한 스크롤(`onEndReached` 임계 0.1)로 다음 페이지를 누적 로드, `nbPages` 도달 시 중단.
- 키워드 클리어 버튼(X) 제공. 플레이스홀더는 하드코딩된 제안 키워드 9종 중 무작위 + 조사 처리.
- 검색 화면 포커스 복귀 시 현재 키워드로 즉시 재검색한다(보유 상태 동기화 목적).
- **탐색 탭에서의 검색은 현재 피드 필터를 승계한다**: 피드에 적용된 카테고리·브랜드 필터가 검색 결과에도 동일한 facet(카테고리 + 브랜드 OR — [Feed.md](Feed.md) FD-3 매칭 규칙)으로 적용된다. 정렬(추천/인기순 등)은 검색 관련도를 우선해 적용하지 않는다. 피드가 없는 검색 화면(비로그인 검색 등)은 필터 없이 기존대로 동작한다.
- **검색 결과 화면에도 필터 바를 유지 노출한다**: 카테고리 칩 행 + `브랜드` 진입 버튼은 검색 중에도 그대로 보이고 조작 가능하며, 변경 즉시 현재 키워드로 재검색한다. 정렬 드롭다운은 검색에 적용되지 않으므로 검색 중에는 숨긴다.

### SR-2 검색 결과 표시와 보유 배지

**수용 기준**

- 검색 결과는 피드 카드와 동일한 **2컬럼 그리드**([Feed.md](Feed.md) FD-2 텍스트 카드 `FeedCardView` 재사용 — 브랜드 → 이름 → 색상(있을 때만) → 무게 앵커, 우상단 담기 CTA, 장비 이미지 없음)로 표시한다. 마지막 홀수 카드는 좌측 정렬. 제조사 표시는 **`companyKorean || company`** (브랜드 디렉토리·미리보기와 동일 규칙 — 니모/NEMO/nemo 혼재 방지).
- **결과 화면 상단**(2026-08-10 개정, Liquid Depth): 검색어가 있으면 필드 위 `탐색` 타이틀을 내리고 — 화면 대상이 `검색 결과`로 바뀌므로 두 타이틀이 겹치면 위계가 갈린다 — **채워진 검색 필드 → `검색 결과` + 개수 → 필터 칩 줄 → 그리드** 순으로 쌓는다.
- **결과 개수는 Algolia `nbHits`(총 히트 수)를 쓴다.** 누적 수신 건수(`result.length`)를 쓰면 무한 스크롤마다 숫자가 커져 틀린 수처럼 읽히고, 로딩 상태로 가리면 개수가 깜빡인다. 첫 응답부터 총량이 확정되며, 값이 0이면(아직 미수신·결과 없음) 자리를 비운다. 개수는 콘덴스드 서체(라틴 전용).
- 내 창고에 있는 장비(`users/{uid}/gears`와 ID 매칭)는 **담김 CTA(잉크 면 + 라임 체크)**, 없으면 **담기 CTA(라임 면 + `add`)** 를 표시한다 — 상태·위계 규칙은 SR-4의 담기 CTA 항목과 같다(같은 컴포넌트).
- 비로그인 시 모든 결과가 미보유로 표시된다.
- 행 클릭 → `/gear-detail/{objectID}`.
- 로딩 자리는 스피너가 아니라 **도착할 카드와 같은 모양의 2열 스켈레톤**이다(`FeedSkeletonView` 공용 — 목록형 행 스켈레톤을 쓰면 로드 후 레이아웃이 튄다).

### SR-3 결과에서 창고 추가 / 배낭 담기

**수용 기준**

- `+` 클릭(로그인 필수): 창고에 등록(`GearStore.register`, `isCustom: false`) 후 **배낭 담기 모달**이 열린다.
- 모달 옵션: `새 배낭`(오늘 날짜로 생성 후 담기) / 기존 배낭 목록(이미 담긴 배낭은 중복 체크로 구분).
- 체크 배지 클릭: `모든 배낭에서 장비가 제거됩니다` 경고 확인 후 창고에서 제거(`GearStore.remove`).
- 추가/제거 시 `gear-rank` count 증감([DataModel.md](DataModel.md) DM-6) 후 현재 검색을 재실행해 배지를 갱신한다.
- **장비 추가 검색 컨텍스트(GearEdit GE-8)** — `+` 클릭 동작이 진입 컨텍스트에 따라 갈린다:
  - **탐색 탭 검색**(기본): 위 기본 동작 — 창고 등록 후 배낭 담기 모달.
  - **창고 장비 추가(`/search`, bagId 없음)**: 창고 **등록만** 하고 배낭 담기 모달은 **띄우지 않는다**. 보유 배지로 반영.
  - **배낭 장비 추가(`/search?bagId=`)**: `+` 탭 시 창고에 없으면 등록한 뒤 **그 배낭에 바로 담는다**(배낭 재선택 모달 없음, 완료 토스트). 이미 창고 보유 장비도 재등록 없이 그 배낭에 담는다(창고 제거 동작은 노출하지 않는다). **이미 그 배낭에 담긴 장비**는 비파괴 체크 배지로 표시하고 중복 담기를 막는다.

### SR-4 인기 장비 순위

> 진입 경로 변경(2026-07-07): 키워드-빈 상태는 피드([Feed.md](Feed.md))가 대체했고, 인기 순위는 **피드 하단 `인기 순위` 플로팅 버튼 → 전용 화면**(신규 라우트)으로 진입한다(FD-3).

**수용 기준**

- 피드의 `인기 순위` 버튼 탭 → 인기 장비 순위 화면(뒤로가기 헤더 포함).
- **진입 시 카테고리 승계**: 피드에서 카테고리 필터가 선택돼 있으면 그 카테고리의 순위를 **바로** 보여준다(해당 카테고리 탭이 선택된 상태로 진입). 진입 카테고리는 라우트 파라미터(`?category=<GearFilter>`)로 넘긴다. 선택 카테고리가 이 화면의 8개 탭에 없으면(의류/전자기기/음식/기타) `전체`로 진입한다. 피드가 `전체`거나 필터 미선택이면 `전체`로 진입한다.
- **승계 카테고리 칩 노출 스크롤**: 승계된 카테고리 칩이 가로 스크롤 영역의 화면 밖(오른쪽)에 있을 수 있으므로, 진입 시 그 칩이 보이도록 카테고리 칩 행을 **1회 가로 스크롤**한다(칩 `onLayout`의 x 오프셋 기준, 좌측에 약간의 여백을 두고 노출; `전체` 진입은 이미 좌측이라 스크롤 없음).
- 카테고리 탭 8개: 전체/텐트/침낭/배낭/매트/가구/랜턴/조리.
- `gear-rank`를 `count desc limit 10`으로 조회하고(카테고리 선택 시 `where('category'==…)`), 상위 3위는 강조 배지.
- **순위 배지 위계**(2026-08-10 개정, Liquid Depth): 상위 3위는 **잉크 면 + 흰 숫자**, 4위 이하는 **가라앉은 면(`surfaceSunken`) + 보조 잉크 숫자**. 숫자는 콘덴스드(Archivo Narrow, 라틴 전용).
  - **1위에 라임 면을 주지 않는다.** 이 화면에서 라임은 담기 CTA의 "아직 내 것이 아님"을 뜻하므로, 같은 색을 순위 강조에도 쓰면 두 의미가 겹친다(라임은 화면당 한 자리).
- **4위 이하 배지도 행 배경과 구분되게 한다.** 상위 3위 강조는 유지하되, 나머지가 "배지 없음"처럼 보이면 순위 목록이라는 것 자체가 흐려진다.
- 순위 행은 창고 목록과 **같은 목록 문법**(`LiquidMetricRow`)을 쓰고 순위 배지를 좌측 슬롯에 끼운다 — 브랜드 → 이름, 우측 콘덴스드 무게, 그 오른쪽에 담기 CTA. 행들은 한 장의 흰 카드 안에 헤어라인(좌측 16 들여쓰기)으로 나뉜다.
  - **무게 단위는 값과 같은 스팬이다**(Archivo 20 · `ink`, 2026-08-11) — `907g`이 한 덩어리로 읽혀야 하고(카피 규칙: 숫자는 단위까지 한 덩어리), 단위만 작거나 흐리면 다른 값의 일부처럼 읽힌다. 창고 목록 행([Warehouse.md](Warehouse.md) WH-1)·배낭 상세·패킹과 같은 문법이다.
- **순위 기준(보유 수)은 화면에 노출하지 않는다** — 수치도, 기준을 설명하는 문구도 두지 않는다. SR-8 브랜드 디렉토리와 같은 정책이며, 화면 이름(`인기 장비 순위`)만으로 충분하다고 본다.
- 순위 행 클릭 → 장비 상세.
- **행의 주 액션은 `창고에 담기`다.** 담기 CTA는 피드·검색 결과와 **같은 컴포넌트**(`components/liquid/LiquidAddCta.tsx`)를 쓴다 — 32pt 원, **미담김 = 라임 면 + `add`(잉크 아이콘) / 담김 = 잉크 면 + 라임 `checkmark`**, 인플라이트 = 잉크 면 + 라임 스피너. 두 상태 전환은 **150ms 크로스페이드**다(핸드오프 Interactions).
  - **면이 뒤집히는 것이 위계다**(2026-08-10 개정 — 이전 "보유 배지 검정 채움 금지" 서술을 대체한다). 라임은 "아직 내 것이 아님"을 뜻하므로 담긴 항목에서 라임 면이 사라져야 목록을 훑을 때 **남은 것만** 눈에 걸린다. 담김 상태가 잉크 면인 것은 강조가 아니라 **채도를 뺀 완료 표시**이며, 눌러야 할 자리가 화면에서 유일하게 라임이라 시선이 뒤집히지 않는다.
- **보유(담김) 배지 탭 = 창고에서 제거**이며 확인 알럿을 거친다. 아이콘만으로는 파괴적 동작이 드러나지 않으므로 `accessibilityLabel`로 명시한다(`… 창고에서 빼기`).
- **아이콘 전용 컨트롤(추가·보유·뒤로가기)** 은 `accessibilityLabel`·`accessibilityRole`을 갖고 **44×44pt 터치 타깃**을 확보한다. 시각 크기를 키우는 대신 `hitSlop`으로 확보해도 된다.

### SR-5 비로그인 검색

**수용 기준**

- 비로그인 사용자도 **네이티브 검색 UI를 그대로 쓴다** — 검색·탐색 자체에 로그인을 요구하지 않는다. 과거의 웹뷰 분기(`/not-login-search`)는 2026-07-28 제거됐다([Auth.md](Auth.md) AU-6 폐기).
- 네이티브 검색 UI에서 비로그인 상태로 `+`를 누르면 로그인 모달을 띄운다.

> **참고(코드 실태)**: `/not-login-search`로 이동하는 네비게이션 호출이 현재 코드에 없다(탐색 탭은 로그인·비로그인 모두 네이티브 `SearchPageView`). 아래 탐색 기능(SR-6~9)도 네이티브로 구현하고, 비로그인은 `+`만 로그인 모달로 게이트한다(SR-3 패턴).

### SR-6 탐색 홈 (키워드 없음 상태) `[폐기]`

피드([Feed.md](Feed.md) FD-1~5)가 탐색 홈을 대체함 (2026-07-07). 카테고리·브랜드·신제품 진입은 피드 필터로 흡수, SR-7/SR-8 화면·라우트는 유지.

### SR-7 카테고리·브랜드 장비 목록 + 정렬

**수용 기준**

- 진입: 카테고리 또는 브랜드 선택(둘 조합 가능). Algolia `useless-gear-search` 조회 — 카테고리는 `category`, 브랜드는 `companyKorean` **또는** `company` facet(OR — 두 값을 같은 facetFilters 내부 배열로 묶어 매칭)로 필터한다. `companyKorean`이 없는 영문 브랜드도 매칭되도록 하기 위함이다([DataModel.md](DataModel.md) DM-10).
- 무한 스크롤·페이지네이션은 SR-1 방식을 재사용한다.
- **정렬 옵션**: `무게순(가벼운순/무거운순)` · `최신순`(createDate desc) · `인기순`(보유수 count desc). Algolia 정렬 replica 사용([DataModel.md](DataModel.md) DM-10).
- 정렬 선택 UI는 **공용 네이티브 formSheet 라우트 `/sort-sheet`**로 표시한다(피드·창고와 공유). 선택된 옵션은 체크로 강조하고, 옵션 탭 시 즉시 적용 후 닫힌다. 그래버·드래그 닫기·높이(`fitToContents`)는 OS가 처리. (플로팅 드롭다운·커스텀 바텀시트는 폐기 — 시트 위 시트 좌표 문제 회피)
- **행 문법**(2026-08-11 개정, Liquid Depth): 창고 목록·인기 순위와 **같은 목록 문법**(`LiquidMetricRow`)을 쓴다 — 좌측은 정체(브랜드 12 → 이름 15 → 색상·사용률 한 줄), 우측은 콘덴스드 무게(단위까지 한 덩어리), 그 오른쪽에 담기 CTA. 행 하나가 곧 종이 카드다(§2.1).
  - **[이력] ~2026-08-10**: 각진 ACG 종이 면 + 라임 텍스트 무게(`components/warehouse/GearView.tsx`). 그 행은 이 화면이 마지막 소비처였고 이식과 함께 삭제했다 — 같은 장비가 창고와 이 목록에서 다르게 읽히던 문제도 그때 끝났다.
- 담기 CTA는 피드·검색 결과·인기 순위와 **같은 컴포넌트**(`components/liquid/LiquidAddCta.tsx`)다 — 미담김 = 라임 면 + `add` / 담김 = 잉크 면 + 라임 `checkmark`, 상태·접근성 규칙은 SR-4와 같다. 보유 배지 탭 = 창고에서 제거(확인 알럿).
- `+` 창고추가/배낭담기 동작은 SR-3을 그대로 재사용한다. 비로그인 `+`는 로그인 모달.
- **정렬 버튼은 제목 블록 우측**에 둔다(2026-08-11 개정) — iOS `headerRight` 바 버튼에서 옮겨, 두 플랫폼이 같은 자리에 같은 그림(현재 정렬 라벨 + `⌄`)을 두고 44pt 터치를 확보한다. **결과가 비어 있거나 로딩 중에도 내리지 않는다** — 정렬은 결과를 바꾸는 컨트롤이라 결과가 없을 때가 오히려 필요하다. 피드 필터 줄의 정렬 버튼과 같은 문법이다([Feed.md](Feed.md) FD-3).
- 빈 결과(2026-08-11 개정): 두 줄 — `장비가 없어요` / `다른 카테고리나 브랜드를 둘러볼까요?`. 빈 상태는 **사실 + 다음 걸음** 두 줄로 쓴다(Liquid Depth 카피 규칙).

### SR-8 브랜드 디렉토리

**수용 기준**

- `brand-rank`([DataModel.md](DataModel.md) DM-14)를 **`ownerCount desc`(실제 사용자 보유수 합계 = 인기순)**로 조회해 브랜드 목록을 표시한다. 각 항목에 브랜드명 + **제품 수**(보유 수는 정렬 키로만 쓰고 노출하지 않음).
- 항목 탭 → SR-7(해당 브랜드 목록, 기본 정렬 인기순).
- **행 문법**(2026-08-11 개정, Liquid Depth): 행 하나가 곧 종이 카드이며 좌측은 정체(브랜드명 15 + `제품 n` 12.5), 우측은 표식 하나다 — 디렉토리는 **쉐브론**(다음 화면으로 이동), 브랜드 필터 시트([Feed.md](Feed.md) FD-3)는 **체크 원**(잉크 면 + 라임 `checkmark` / 빈 원은 `inkFaint` 테두리)이다. 같은 컴포넌트(`BrandRowView`)가 `selectable`로 갈리며, 스크린리더 롤도 `button`/`checkbox`로 함께 갈린다 — 다음 화면으로 가는 것과 값을 고르는 것은 다른 약속이다.
- **브랜드명 검색 필터**: 디렉토리 상단 검색 입력으로 이미 로드된 목록을 로컬 필터한다(서버 재조회 없음). `companyKorean`·`company` 모두 대상, 대소문자 무시 부분 일치. 키워드 클리어(X) 제공.
  - 필드는 **유리 검색 필드**(공용 `components/liquid/LiquidSearchField.tsx` — 블러 + 유리 채움 + 0.5px 흰 보더, 값이 들어오면 채움을 한 단계 진하게)다. 창고 검색(WH-8)·브랜드 필터 시트가 같은 컴포넌트를 쓴다 — 세 곳이 각자 그리면 값이 갈린다. 유리 면 자체는 한 겹 아래 셸(`components/liquid/LiquidGlassField.tsx`, 높이 48)이 그리며 리뷰·답글 입력 바([Reply.md](Reply.md) §2.1)도 같은 셸을 공유한다.
  - 키보드가 올라온 채로 행을 누를 수 있어야 하므로 목록은 `keyboardShouldPersistTaps='handled'`다.
- **로딩은 브랜드 행 스켈레톤**이다(2026-08-11 신설 `components/browse/BrandRowSkeletonView.tsx`) — 이름 줄 + `제품 n` 줄 + 우측 표식 자리. 줄 수는 도착할 행과 같게 맞춘다(`showMeta` — 디렉토리는 두 줄, `showCount={false}`인 브랜드 필터 시트는 한 줄). 예전에는 장비 행 스켈레톤(무게·CTA 자리까지 있는 3줄 골격)을 그대로 써서 브랜드 행이 도착하는 순간 목록이 통째로 줄어들었다.
- 필터 결과 없음(2026-08-11 개정): 두 줄 — `찾는 브랜드가 없어요` / `이름을 다시 확인해볼까요?`. 아직 아무 브랜드도 못 받았으면 `아직 브랜드가 없어요` / `잠시 뒤에 다시 열어볼까요?`.
- (후순위) 가나다 인덱스.
- 빈/실패: 빈 배열, 에러 UI 없음(SR 엣지 케이스 정책).

### SR-9 신제품 (최근 추가)

**수용 기준**
