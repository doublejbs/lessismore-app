## 1. 개요

산에서는 데이터가 끊긴다. 지금 앱은 Firestore 메모리 캐시만 쓰므로(RN 환경의 Firebase JS SDK 기본값 — 영속 캐시 없음) 네트워크가 없으면 여행 상세·코스·포인트가 열리지 않는다. 여행 하나를 **기기에 통째로 저장**해 두면 오프라인에서도 **장비 목록·총무게·패킹 체크, 코스(경로·고도·내 위치), 지도 포인트, 여행지·날씨 스냅샷, 박지 주의사항**을 볼 수 있게 한다.

**지도 타일은 저장하지 않는다.** 네이버 지도 SDK는 오프라인 타일을 지원하지 않고, 타일을 긁어 두는 것은 약관 위반이다. 대신 오프라인에서는 지도 자리에 **코스 캔버스**(흰 바탕 위 경로 폴리라인 + 포인트 마커 + 내 위치 + 축척)를 그린다. GPS는 데이터 없이도 동작하므로 "지금 코스의 어디쯤인가"는 캔버스로도 답할 수 있다 — 이것이 산에서 가장 필요한 한 가지다.

**이 기능은 유료다**(2026-10-10 사용자 결정). 구독 `useless 플러스`([Subscription.md](Subscription.md))의 **유일한 혜택**이며 7일 무료 체험으로 시작할 수 있다. 저장·갱신·열람 모두 구독 중(체험 포함)에만 할 수 있고, **구독이 끝나면 저장본 열람도 잠긴다**(OF-7, 2026-10-10 사용자 결정). 저장본은 기기에 남겨 두어 다시 구독하면 바로 열린다.

**범위**: 저장·갱신·삭제, 저장된 여행 목록, 오프라인 상세(읽기 + 패킹 체크), 오프라인 코스 캔버스, 저장 용량 표시. **제외**: 지도 타일, 오프라인에서 장비·메모·포인트 편집(읽기 전용), 그룹 화면 오프라인, 웹.

## 2. 화면 및 진입

```text
app/bag/[id].tsx (배낭 상세) ─ 액션 그리드 `오프라인` 타일 (BD-10, OF-2)
   ├─ 미저장 → 탭: 구독 중이면 바로 저장 / 아니면 구독 화면(SUB-11)
   └─ 저장됨 → 부제 `저장됨 · {용량} · {갱신 시각}` → 탭: 시트(갱신 · 삭제)
app/(tabs)/bag.tsx (여행 탭) ─ 오프라인이면 상단 배너 `오프라인 · 저장된 여행만 볼 수 있어요` + 저장된 여행만 목록 (OF-4)
app/bag/[id].tsx 오프라인 분기 ─ 로컬 스냅샷으로 상세 렌더 (OF-5)
app/bag/[id]/route.tsx 오프라인 분기 ─ 지도 대신 OfflineRouteCanvasView (OF-6)
```

## 3. 요구사항

### OF-1 저장 단위와 내용 `[제안]`

**수용 기준**

- 저장 단위는 **여행(배낭) 1건**이다. 저장하면 다음을 한 스냅샷으로 기기에 쓴다.
  - 배낭 문서(이름·기간·여행지·날씨 스냅샷·메모·패킹 상태·장비 참조) + **장비 문서 전체**(이름·브랜드·무게·카테고리 — 창고 문서를 복사해 두어 오프라인에서 창고를 읽지 않아도 된다)
  - 코스(DM-30) 문서 전체 — 축약 좌표·고도·거리·상승이 문서 안에 있어 그래프·캔버스를 그릴 수 있다. **원본 GPX 파일(Storage)도 내려받아 둔다**(내보내기·정밀 경로용).
  - 지도 포인트(DM-33) 전체
  - 여행지 박지 문서(`camp-spot`) — 이름·유형·좌표·설명·**주의사항(CS-4)**·접근 정보. 사진은 받지 않는다.
  - 연결된 그룹의 코스·포인트는 저장하지 **않는다**(그룹 화면은 범위 밖. 배낭 코스 화면에 읽기 전용으로 섞여 보이던 그룹 코스도 오프라인에서는 빠진다 — 캔버스에 `그룹 코스는 오프라인에서 보이지 않아요` 한 줄).
- 위치: `expo-file-system` 문서 디렉터리 `offline/{bagId}/` 아래 `snapshot.json` + `routes/{routeId}.gpx`. 목록은 `AsyncStorage`의 매니페스트(`offline.manifest`: bagId·이름·기간·용량·`savedAt`·`schemaVersion`).
- 스냅샷에는 **다른 사용자의 데이터·개인 식별 정보가 들어가지 않는다**(본인 배낭·본인 창고·공개 박지뿐). `schemaVersion`을 적어 두고, 앱이 더 새 스키마를 요구하면 그 스냅샷은 `갱신 필요`로 표시한다(온라인에서 갱신하면 풀린다).
- 저장 용량은 보통 1~3MB(GPX 포함)다. 매니페스트에 바이트를 적고 타일 부제·목록에 사람이 읽는 단위(`1.8MB`)로 보여 준다. 저장된 여행은 **10개까지** — 11번째를 저장하려 하면 `저장된 여행이 10개예요. 지난 여행을 삭제하고 다시 시도해 주세요`.

### OF-2 저장·갱신·삭제 (배낭 상세 타일) `[제안]`

**수용 기준**

- 배낭 상세 액션 그리드(BD-10)에 `오프라인` 타일을 둔다(아이콘 `cloud-download-outline`). 그리드 규칙(연회색 면·아이콘+제목+부제)을 그대로 따른다.
  - 미저장 부제: `오프라인 저장` · 구독이 아니면 부제 뒤에 자물쇠 없이 그대로 두고, 탭했을 때 게이트(SUB-11)가 설명한다 — 타일에 유료 표시를 박아 두면 그리드에 배지가 생긴다(HM-8 "행 안 배지 금지").
  - 저장됨 부제: `저장됨 · 1.8MB · 10.09 갱신`. 스냅샷이 서버 최신보다 오래됐는지는 앱이 알 수 없으므로(변경 추적 없음) 갱신 시각만 보여 준다.
  - `갱신 필요`(스키마 구버전) 부제: `갱신이 필요해요`.
- **미저장 탭**: 구독 중(체험 포함)이면 **바로 저장을 시작**한다(확인 알럿 없음 — 되돌릴 수 있는 동작이다). 타일 부제가 `저장 중…`으로 바뀌고 끝나면 `저장됨 …`. 실패하면 토스트 `오프라인 저장에 실패했어요`(부분 저장본은 지운다 — 반쪽 스냅샷을 남기지 않는다). 구독이 아니면 구독 화면을 연다(SUB-11, 오프라인 진입점 문구).
- **저장됨 탭**: 바텀 메뉴 `지금 갱신` · `오프라인 저장 삭제`(destructive). 갱신은 저장과 같은 절차이고 성공 전까지 기존 스냅샷을 유지한다(갱신 실패 시 이전 것이 남는다). 삭제는 확인 알럿(`저장된 오프라인 데이터를 지울까요?`)을 거친다.
- **자동 갱신**: 저장된 여행의 상세를 **온라인에서 열 때마다** 조용히 갱신한다(배낭 편집·패킹 토글·코스 추가가 모두 상세를 지나므로 사실상 최신을 유지한다). 조용한 갱신은 실패해도 알리지 않는다. 사용자가 명시적으로 `지금 갱신`을 눌렀을 때만 실패 토스트를 띄운다.
- 저장·갱신은 **온라인에서만**. 오프라인 상태에서 타일을 누르면 토스트 `온라인에서 저장할 수 있어요`.
- 배낭을 삭제하면 스냅샷·GPX·매니페스트 항목을 함께 지운다. 로그아웃·탈퇴 시 **저장된 모든 오프라인 데이터를 지운다**(다른 사람이 같은 기기로 로그인했을 때 남의 여행이 보이면 안 된다).
- 웹에서는 타일을 렌더하지 않는다.

### OF-3 네트워크 상태 판단 `[제안]`

**수용 기준**

- `@react-native-community/netinfo`로 연결 상태를 구독한다(`isInternetReachable`이 `false`이거나, `null`이면서 Firestore 첫 읽기가 실패하면 오프라인으로 본다). 네이티브 의존성이므로 **2.0.2 바이너리**부터다.
- 오프라인 판단은 `NetworkStatus` 하나가 갖고, 화면은 그 값을 읽기만 한다. 연결이 돌아오면 2초 안에 온라인으로 전환되고 상세는 서버 데이터로 다시 로드한다(스냅샷 → 서버 전환 때 스크롤 위치를 유지한다).
- "오프라인"은 **연결 없음**이지 "구독 아님"이 아니다. 연결이 있으면 구독 여부와 무관하게 늘 서버 데이터를 쓴다.

### OF-4 오프라인에서의 여행 탭 `[제안]`

**수용 기준**

- 오프라인이면 여행 탭 상단에 배너 `오프라인이에요 · 저장해 둔 여행만 볼 수 있어요`(연회색 면, 아이콘 `cloud-offline-outline`, 닫기 없음 — 연결되면 사라진다).
- 목록은 **매니페스트의 저장된 여행만** 보여 준다(이름·기간·`저장됨 · 1.8MB`). 저장된 여행이 하나도 없으면 빈 상태 `저장해 둔 여행이 없어요. 온라인에서 여행 상세의 오프라인 타일로 저장할 수 있어요.`
- 템플릿·그룹 세그먼트는 오프라인에서 비활성(탭하면 토스트 `온라인에서 볼 수 있어요`). 여행 추가·복사 버튼도 숨긴다.
- 로그인 상태 자체가 없을 때(로그아웃 상태)는 저장된 것도 없으므로 기존 비로그인 화면 그대로다.

### OF-5 오프라인 상세 (읽기 + 패킹 체크) `[제안]`

**수용 기준**

- 오프라인에서 저장된 여행 상세를 열면 **스냅샷으로 렌더**한다: 요약(총무게·D-day·여행지·날씨), 카테고리별 장비 목록·무게, 메모, 액션 그리드 중 `코스`·`여행지`·`오프라인`만(사용 기록·운동 기록 타일은 숨긴다). 화면 상단에 얇은 띠 `오프라인 · 10.09 저장본`.
- **편집은 막는다**: 장비 추가/빼기, 메모 수정, 여행지 변경, 공유, 복사, 포인트·코스 추가는 버튼을 비활성하거나 숨기고, 누르면 토스트 `온라인에서 할 수 있어요`. 하단 바(BD-9)의 `수정`은 비활성, `패킹`은 활성.
- **패킹 체크(PK-2)는 오프라인에서도 토글할 수 있다.** 체크 상태는 스냅샷에 즉시 쓰고(앱을 껐다 켜도 남는다), **연결이 돌아오면 서버의 `bag.gears[].packed`에 반영한다**(마지막 토글 기준으로 덮어쓴다 — 산에서 체크한 사람이 한 명이라 충돌이 없다). 반영 전에는 매니페스트에 `pendingPacking: true`를 두고, 반영이 끝나면 지운다. 반영 실패는 다음 온라인 진입에서 다시 시도한다.
- 저장되지 않은 여행을 오프라인에서 열려 하면(딥링크·알림 등) 빈 상태 `이 여행은 저장되지 않았어요`.

### OF-6 오프라인 코스 캔버스 `[제안]`

**수용 기준**

- 오프라인에서 `/bag/{id}/route`를 열면 **네이버 지도 대신 캔버스**를 그린다: 흰 바탕(`Acg.paper`), 코스 폴리라인(잉크, 시작 라임 점·끝 잉크 점 — GRP-8 마커 규칙), 포인트 마커(유형색, BD-14), **내 위치**(파란 점 + 방향 부채꼴, BD-11 방향 모드와 같은 소스), 좌하단 **축척 막대**, 우상단 북쪽 표시. 등고선·지명은 없다 — 있어 보이게 꾸미지 않는다(가짜 지형은 산에서 위험하다).
- 화면 안에 코스 전체가 들어오게 맞추고, 핀치·드래그로 확대·이동할 수 있다(`react-native-gesture-handler`, 지도와 같은 제스처). `내 위치` 버튼은 지도와 같은 세 상태(이동·방향 모드·끄기)를 돈다.
- 고도 그래프·훑기·포인트 탭 시 그래프 표시(GRP-8)는 **그대로 동작한다** — 축약 좌표에 고도가 들어 있다.
- 코스 목록·뒤집기·GPX 내보내기(저장해 둔 원본 파일에서)는 동작한다. 추가·삭제·그룹에 올리기는 비활성(OF-5 규칙).
- 캔버스 상단에 한 줄 `오프라인 · 지도는 연결되면 보여요`. 연결이 돌아오면 같은 카메라(코스 전체)로 지도를 다시 그린다.
- 온라인에서도 지도 로드가 실패하면(지도 키 오류·SDK 오류) 같은 캔버스를 **폴백**으로 쓴다 — 캔버스는 오프라인 전용 뷰가 아니라 "지도가 없을 때의 코스 뷰"다.

### OF-7 구독과의 관계 `[제안]`

**수용 기준**

- **저장·갱신(수동·자동)·오프라인 열람(OF-4·OF-5·OF-6) 모두 권한 `premium`이 살아 있을 때만** 한다(SUB-11, 체험 포함). 2026-10-10 사용자 결정 — 구독이 끝나면 오프라인 기능은 없다.
- **권한 판단은 오프라인에서도 해야 한다.** RevenueCat SDK가 기기에 캐시한 마지막 `customerInfo`의 `premium` 만료 시각(`expirationDate`)을 기준으로, 지금이 그 전이면 살아 있는 것으로 본다. 캐시가 아예 없으면(한 번도 온라인에서 확인 못 함) 잠긴 것으로 본다. 결제 실패 유예(billing issue) 기간은 스토어가 권한을 유지하므로 그대로 따른다. 해지 예약은 종료일까지 살아 있다.
- **만료 시**: 여행 탭 오프라인 배너가 `구독이 끝나 저장된 여행을 볼 수 없어요 · useless 플러스 다시 시작`으로 바뀌고 목록은 비운다(온라인이면 평소 목록). 배낭 상세 `오프라인` 타일 부제는 `저장됨 · 구독 후 다시 볼 수 있어요`, 탭하면 구독 화면(SUB-11). 오프라인 상세·캔버스는 열리지 않는다.
- **저장본은 지우지 않는다.** 재구독하면 즉시 다시 열리고 다음 온라인 상세 진입 때 갱신된다. 삭제는 사용자(OF-2)·로그아웃·탈퇴·배낭 삭제 때만이다.
- 환불·취소로 권한이 사라져도 같다.

### OF-8 측정 `[제안]`

[Analytics.md](Analytics.md) AN-3 표에 추가: `click_offline_save`(저장 시작, `source`: `tile`), `offline_saved`(성공, `bytes`·`route_count`·`point_count`), `click_offline_refresh`, `click_offline_remove`, `offline_trip_open`(오프라인 상세 열람), `offline_route_canvas_open`, `offline_packing_synced`(복귀 반영 성공, `count`). 게이트 노출·전환은 SUB-8이 센다(`entry_point: offline`).

## 4. 데이터

- 서버에 새 컬렉션은 없다. 기기 로컬: `offline/{bagId}/snapshot.json`(OF-1 내용, `schemaVersion`, `savedAt`, `pendingPacking`), `offline/{bagId}/routes/{routeId}.gpx`, `AsyncStorage` `offline.manifest`.
- 스냅샷은 Firestore 문서를 그대로 직렬화하되 Timestamp는 ISO 문자열로 바꾼다. 읽을 때 기존 모델(`BagDetail`·`Gear`·`BagRoute`·`BagPoint`)의 정적 팩토리로 되돌린다 — 오프라인용 모델을 따로 만들지 않는다.

## 5. 플랫폼 분기

- iOS·Android 동일. 웹은 타일·배너·캔버스 모두 없다(APP-5 — 웹에는 지도도 파일 선택도 없다).
- `netinfo`·`expo-file-system`(이미 있음) 외 새 네이티브 의존성은 없다. **2.0.2 바이너리** 묶음이다.

## 6. 엣지 케이스

- 저장 중 앱 종료 → 부분 저장본 삭제(다음 진입 때 매니페스트에 없는 디렉터리를 정리).
- 저장 후 장비를 삭제(창고에서) → 스냅샷에는 남아 있다. 자동 갱신으로 다음 온라인 상세 진입 때 맞춰진다.
- 디스크 부족 → 저장 실패 토스트에 `저장 공간이 부족해요`.
- 같은 계정 두 기기 → 각 기기가 따로 저장한다(스냅샷은 기기 로컬).
- 체험 중 저장 → 체험 종료(미전환) 시 잠김, 저장본은 유지(OF-7).

## 7. 수동 검증 체크리스트

- [ ] 구독(체험) 중 타일 탭 → `저장 중…` → `저장됨 · 용량 · 시각`; 비행기 모드 → 여행 탭 배너 + 저장된 여행만 → 상세 열림(장비·무게·날씨·메모·주의사항)
- [ ] 비행기 모드에서 코스 화면 → 캔버스(폴리라인·포인트·내 위치·축척), 고도 그래프 훑기 동작, 추가·삭제 비활성
- [ ] 비행기 모드에서 패킹 체크 토글 → 앱 재시작 후 유지 → 연결 복귀 후 서버 반영(다른 기기에서 확인)
- [ ] 미구독 타일 탭 → 구독 화면(오프라인 문구, `7일 무료로 시작`); 구독 만료 후(샌드박스 만료) 비행기 모드에서 저장본이 열리지 않고 배너가 구독 유도로 바뀜; 재구독 시 즉시 다시 열림
- [ ] 저장 10개 상한, 삭제 확인 알럿, 로그아웃 시 전부 삭제, 웹에서 타일 없음

## 8. 미해결 질문

- 자동 갱신을 Wi-Fi에서만 할지(GPX 포함 1~3MB, 셀룰러에서도 부담은 작다 — 기본은 제한 없음).
- 만료 후 저장본 보관 기간(지금은 무기한 — 디스크를 차지하므로 90일 뒤 정리 등을 검토).
- 오프라인에서 메모 수정을 허용할지(패킹과 같은 "마지막 쓰기 우선"으로 가능하지만 범위를 늘린다 — 후속).
- 그룹 코스·포인트의 오프라인 저장(그룹 화면 오프라인화와 함께 — 후속).
