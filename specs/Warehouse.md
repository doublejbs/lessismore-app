## 1. 개요

창고는 사용자가 보유한 장비(`users/{uid}/gears`)의 목록 화면이다. 홈 미리보기(`전체 보기`)에서
들어오는 **푸시 화면**이며([Home.md](Home.md) HM-0·HM-4), 카테고리 필터·정렬·장비 추가/수정/삭제의
진입점을 제공한다.

## 2. 화면 및 진입

```
app/warehouse/index.tsx → WarehouseWrapper → WarehouseScreen
                                              ├─ WarehouseChromeView (Android·Web 유리 크롬: back + [검색][+])
                                              ├─ 제목 블록 (`창고` + `{n}개 · {w}kg` + 정렬 OrderButtonView=formSheet)
                                              ├─ WarehouseSearchFieldView (Android·Web 검색 모드, WH-8)
                                              ├─ WarehouseFiltersView (1차 칩 + 세분 칩 + 안 쓴 장비 알림 칩)
                                              ├─ 흰 카드 하나 안에 WarehouseGearView × n (행 + 삭제 스와이프 액션)
                                              └─ WarehouseSkeletonView / 빈 상태 2줄
```

- `WarehouseWrapper`는 Firebase 초기화 완료까지 **지면만** 렌더하고(스피너 없음), 이후 `Warehouse` 도메인 객체를 1회 생성한다.
- 화면 포커스 시(`useFocusEffect`) `warehouse.refresh()`로 목록을 다시 읽고 검색 상태를 초기화한다. pull-to-refresh는 없다.

### 화면 문법 (as-built, 2026-08-11 — Liquid Depth)

창고의 시각만 서술한다. 무엇을 언제 보여주는지는 WH-1~WH-8이 정의한다.

- 지면은 **지형 없이 `canvas` + 우상단 라임 글로우**다 — 여기는 읽을 지형이 아니라 훑어 비교하는 목록이라 산세를 깔지 않는다(목업 §8).
- 크롬은 지면 위에 뜬 **유리**다: iOS는 네이티브 투명 헤더가 원형 글래스 back + 글래스 바 버튼(검색·추가)을 내주고(LG-1·LG-3), Android·Web은 같은 그림을 공용 프리미티브(`LiquidGlassCircleButton`·`LiquidGlassCapsule`)로 직접 그린다 — 배낭 상세·패킹 헤더와 같은 문법이다.
- 화면 대상은 제목 블록이 든다: `창고` 32/38 + 그 아래 규모 한 줄(`42개 · 18.6kg`, 13/500) · 우측 정렬 드롭다운. **네이티브 바 타이틀은 비운다** — 같은 말을 두 곳에 두지 않는다.
- 좌우 여백은 블록마다 다르다: 크롬 12 · 콘텐츠 20 · **칩 줄은 화면 끝까지 블리드**(스크롤이 가장자리에서 끊기지 않게).
- **목록은 흰 카드 하나**이고 행은 좌측 16 들여쓴 헤어라인으로만 갈린다 — 행마다 면을 두면 목록이 카드 더미로 보인다. 카드 모서리 22, 그림자는 껍데기가 들고 클리핑은 안쪽이 맡는다(스와이프 액션 면이 카드 밖으로 새지 않게).
- **라임은 알림 칩의 틴트 하나뿐**이다(`안 쓴 장비 n`). 원색 라임 면이 아니라 35% 틴트라 액센트 면 하나 규칙과 자리를 다투지 않으며, 글자·아이콘은 라임 계열 잉크(`limeOnQuiet`)를 쓴다 — 라임을 글자색으로 직접 쓰지 않는다(대비 근거는 WH-2-1).
- **상단 고정 블록**: 제목 블록과 칩 줄은 스크롤하지 않고, 그 아래 목록만 스크롤한다 — **콘텐츠가 유리 크롬 아래로 흐르지 않는다.** 핸드오프 Interactions(유리 밑으로 흐르는 콘텐츠)와 다른 as-built이며, 이식 전(HEAD)의 화면 구조를 그대로 유지한 결과다. 규모 줄·필터가 항상 보이는 쪽이 훑어 비교하는 목록에 맞다고 보고 남겼다. iOS 상단 인셋도 그래서 automatic content inset이 아니라 수동 `paddingTop`(세이프에어리어 + 44 + 6)이다([LiquidGlassNavigation.md](LiquidGlassNavigation.md) LG-3).
- 숫자(무게)는 **콘덴스드(Archivo Narrow)**, 단위까지 한 덩어리(`907g`)로 쓴다. 한글이 섞인 값(개수·요약 줄)은 본문 서체다 — 콘덴스드에 한글 글리프가 없다.
- 각진 면은 쓰지 않는다(카드 22, 칩 height/2, 썸네일 12).
- 로딩은 스켈레톤이다(스피너 금지) — 도착할 목록과 같은 카드·행 골격에 셔머만 얹는다.

## 3. 요구사항

### WH-1 장비 목록 표시

로그인한 사용자는 창고에서 자신의 장비 목록을 볼 수 있다.

**수용 기준**

- 각 장비 행에 제조사, 이름, 색상, 무게를 표시한다.
- **행 사이는 헤어라인으로 가른다**(2026-08-11 개정 — 목록 전체가 흰 카드 하나이고 그 안에서 좌측 16 들여쓴 0.5px 헤어라인이 행을 나눈다). 여백만으로 행을 가르면 줄 수가 다른 행(1~3줄)이 섞일 때 경계가 잡히지 않아, 정보가 적은 행이 목록의 일부가 아니라 떠 있는 문자열처럼 읽힌다.
  - **[이력] 2026-07-29~2026-08-10**: 행마다 각진 흰 종이 면(ACG) 또는 행 하단 1px 구분선(`Color.divider`). 카드 하나로 묶는 지금 문법에서는 카드 경계가 목록의 바깥 테두리를, 헤어라인이 행 경계를 맡는다.
  - **행 사이에 gap이 없는 목록에만 적용한다.** 창고 목록은 행이 맞붙어 있고 패딩으로만 간격을 만들어 헤어라인이 정확히 행 사이에 놓인다. 배낭 상세([BagDetail.md](BagDetail.md) BD-1)·패킹([Packing.md](Packing.md) PK-2)은 각자의 문법을 따른다(카테고리 카드 / 행 하나가 곧 카드).
- **값이 없는 줄은 렌더하지 않는다** — 제조사·색상 모두 같은 규칙이다. 빈 텍스트를 두면 행에 죽은 공백이 생겨 이름이 아래로 밀려 보이고, 브랜드·색상이 없는 직접 등록 장비(예: 이름만 있는 `테스트`)가 행이 아니라 떠 있는 문자열처럼 읽힌다(2026-07-29 실측). 행 높이는 썸네일 기준 `minHeight`로 이미 균일하므로 줄이 줄어도 목록 리듬은 유지된다.
  - **세로 스택에만 해당한다.** 브랜드가 CTA와 같은 **가로 행**에 놓이는 피드 카드(FD-2)는 브랜드 텍스트가 `flex: 1` 스페이서 역할을 겸하므로, 값이 없어도 요소를 유지한다 — 지우면 CTA가 왼쪽으로 딸려온다.
  - 같은 규칙이 배낭 상세 장비 행([BagDetail.md](BagDetail.md) BD-1)과 장비 상세 정체 줄([GearDetail.md](GearDetail.md) GD-1)에도 적용된다.
- **썸네일은 사용자가 올린 본인 사진이 있을 때만 표시한다**([DataModel.md](DataModel.md) §1, 2026-07-29 개정 · 업로드는 [GearDetail.md](GearDetail.md) GD-13). `users/{uid}/gears/{id}.imageUrl`이 있으면 행 좌측에 정사각 썸네일(한 변 44 · 모서리 12 · 자리색은 가라앉은 면)을 두고, **없으면 빈 썸네일 박스·플레이스홀더를 남기지 않고** 텍스트 우선 행 레이아웃을 그대로 쓴다. 카탈로그 크롤 이미지로 **폴백하지 않는다**.
  - 같은 목록에서 이미지 있는 행과 없는 행이 섞이므로, **썸네일 유무와 무관하게 우측 무게의 세로 정렬이 유지돼야 한다** — 무게를 세로로 스캔해 비교하는 것이 이 행 레이아웃의 목적이다(아래 2열 규칙). 행 높이는 썸네일 한 변을 최소 본문 높이로 걸어 균일하게 묶는다.
  - 이미지 로드 실패는 이미지 없음과 동일하게 처리한다(깨진 아이콘 금지, GD-13).
- **행 안의 세 줄은 브랜드 → 이름 → 메타 순이다**(2026-08-11 개정): 브랜드 12/600(`inkMuted`) → 이름 15/600(`ink`) → `{색상} · 사용률 {n}%` 12(`inkSubtle`). 이름이 시각 앵커이고 브랜드는 그 위를 여는 작은 라벨이다.
  - **[이력] 2026-07-28~2026-08-10**: 브랜드를 제품명과 동일한 타이포로 표시했다(이미지 없는 레이아웃에서 브랜드가 식별의 첫 축이라는 근거). Liquid Depth의 행 문법에서는 같은 크기의 두 줄이 어느 쪽이 제품명인지 갈리지 않아, 크기로 위계를 준다 — 이식이 끝난 화면(홈 HM-4·배낭 상세 BD-1·패킹 PK-2·검색 순위 SR-4·창고)이 이 문법을 공유한다.
  - **사용률은 배지가 아니라 메타 줄의 텍스트다**(2026-08-11 개정) — 배지가 무게 위에 놓이면 우측 컬럼이 두 층이 되어 무게의 세로 정렬이 흔들린다. 사용 기록이 없으면 그 조각째 빼서 ` · `가 홀로 남지 않게 한다.
- **행은 좌 정체 · 우 무게의 2열로 나눈다**(2026-07-28 사용자 결정 · 2026-08-11 지표 컬럼 단일화) — 좌측은 정체(브랜드·이름·메타), 우측은 **무게 하나**(콘덴스드 20, 단위까지 한 덩어리). 무게가 행마다 같은 자리에 오므로 세로 스캔으로 비교할 수 있다(iOS leading/trailing 리스트 관습). 이름·브랜드가 길면 말줄임해 우측 컬럼을 침범하지 않는다. **장비 리스트 행 전체**(창고·패킹·배낭 편집·배낭 상세·공유 배낭)에 공통 적용하되, **피드 카드(FD-2)는 예외** — 무게가 카드의 시각 앵커인 현재 구조를 유지한다.
- 이름은 `Gear.getDisplayName()`(= `nameKorean || name`)으로 표시한다 — `getName()` 직접 표시 금지.
- 무게는 `{weight}g` 형식으로 표시한다. 무게가 없으면(0g 미입력) 우측 자리를 비운다.
- 사용 기록이 있는 장비는 메타 줄에 `사용률 XX%`(`used`/`useless` 기록 기반)를 표시한다.
- **상단 크롬 액션은 `[검색][+ 장비 추가]` 둘이다**(2026-07-31 · 2026-08-11 유리 크롬으로 이식). 플로팅 `장비 추가` pill은 폐기 — 창고가 푸시 화면이 되며 헤더에 자리가 생겼고, 하단 플로팅 하나로 주 액션을 대표하던 이유가 사라졌다.
  - iOS 검색은 네이티브 검색 바가 맡는다([LiquidGlassNavigation.md](LiquidGlassNavigation.md) LG-3). Android·Web은 **유리 캡슐 안 아이콘 두 개**로 같은 순서·같은 자리에 두고, 검색을 탭하면 제목 블록 자리에 검색 필드가 열린다(WH-8). 캡슐 안 아이콘 칸은 시스템 바 버튼과 같은 34/38이라 44에 못 미친다 — **현 프리미티브 구조상의 제약**이며(`LiquidGlassCapsule`의 겉면이 알약으로 클리핑해 그 밖의 히트 영역이 전달되지 않는다), 클리핑을 안쪽 레이어로 내리면 넓힐 수 있다. 배낭 상세·패킹 헤더가 같은 자리에 있다.
  - **화면 제목은 크롬이 아니라 본문 제목 블록이 든다**(2026-08-11 개정): `창고` 32/38 좌측 정렬 + 아래 규모 줄(WH-2) + 우측 정렬 드롭다운(WH-3). iOS 네이티브 바 타이틀은 비운다 — 같은 말을 두 곳에 두지 않는다.
  - **[이력] 2026-07-31**: Android·Web은 [back + `창고` 20pt + 버튼 둘]을 한 행에 두었다(탭 루트 시절 32pt large title이 푸시 화면에서 과했다는 실기기 근거). 제목이 크롬에서 본문으로 내려가며 한 행에 몰리는 문제가 사라져 32pt로 돌아왔다.
- 목록은 전체 일괄 로드한다 (페이지네이션/무한 스크롤 없음).
- 스크롤 끝에는 공통 하단 여백을 비운다 — 마지막 행이 화면 밑단에 붙지 않는다.

### WH-2 카테고리 필터

사용자는 카테고리 칩으로 목록을 필터링할 수 있다.

**수용 기준**

- 필터는 `전체` + 11개 카테고리([DataModel.md](DataModel.md) DM-4)로 구성되고 기본값은 `전체`다.
- 칩 UI는 Liquid Depth 공용 `LiquidChip`(완전한 알약 h34 · 비선택 = 흰 유리 톤 채움 + 0.5px 보더 + `inkSecondary` · 선택 = 잉크 채움 + 흰 글자 600)을 쓴다(2026-08-11 이식). 고정 높이 없이 `minHeight`+패딩으로 큰 글씨(Dynamic Type)에서도 잘리지 않으며, `hitSlop`으로 44pt 터치를 확보한다. 홈 미리보기(HM-4)와 같은 컴포넌트다. (2026-08-11: 구세대 `CategoryChipView`는 참조가 끊겨 삭제했다 — 선택형 칩은 이제 이 컴포넌트 하나뿐이다.)
- 한 번에 하나만 선택된다 — 다른 필터 선택 시 기존 선택은 해제된다.
- 이미 선택된 필터를 다시 눌러도 **해제되지 않고 그대로 유지**된다(선택 칩 재탭은 무시). `전체`로 돌아가려면 `전체` 칩을 누른다.
- **1차 필터는 그룹 쿼리**: 선택한 그룹의 세분 카테고리 배열(DM-4 매핑, 레거시 키 포함)로 `where('category','in', 멤버들)` 조회한다. `전체`는 전체 조회.
- **2차(세분) 필터**: 세분 카테고리가 2개 이상인 그룹(텐트/매트/배낭/의류/가구/랜턴/조리/기타)을 선택하면 1차 칩 행 아래에 **세분 칩 행**이 나타난다 — `전체` + 그 그룹의 세분 카테고리(한글 라벨, DM-4). 단일 선택, 기본 `전체`, 이미 선택된 칩 재탭은 무시(해제 안 됨) — `전체` 칩으로 해제(1차 필터와 동일). 세분 선택 시 이미 로드된 그룹 목록을 **클라이언트에서 `category === 세분키`로 필터**한다(추가 쿼리 없음). 1차 필터 변경 시 세분 선택은 초기화. 세분이 1개뿐인 그룹(침낭/전자기기/음식)은 세분 행을 렌더하지 않는다.
- 세분 칩도 같은 `LiquidChip`을 쓰되 2차 크기(h28)로 낮추고 1차 줄에 붙여 보조적으로 배치한다.
- **칩 줄은 화면 좌우로 블리드시킨다** — 가로 스크롤이 화면 가장자리에서 끊기면 목록이 잘린 것처럼 읽힌다.

### WH-2-1 사용 여부 필터 `[제안]`

사용자는 **안 쓴 장비만** 골라 볼 수 있다 (2026-08-05).

**배경** — 이 앱의 이름값(`useless`)은 "안 쓴 장비를 덜어낸다"인데, 그 인사이트가 장비 상세 안에만 흩어져 있었다. 사용률 배지·미기록 태그·덜어내기 배너 모두 장비를 하나씩 열어야 보인다. 창고에서 한 번에 걸러내는 수단이 없어 "덜어낼 후보"를 찾으려면 전 장비를 훑어야 했다.

**수용 기준**

- 카테고리 칩(WH-2)과 **별개 축**의 토글 칩 `안 쓴 장비`를 둔다. 카테고리 필터와 **함께** 적용된다(예: `텐트` + `안 쓴 장비`).
  - 시각은 **라임 톤 알림 칩**이다(2026-08-11 이식, 목업 §8): h30 · 라임 35% 틴트 면 + 라임 테두리 + 라임 계열 글자·아이콘(`alert-circle-outline`). 카테고리 칩(34)보다 낮아 별개 축임이 크기로 드러난다. 이 화면에서 라임이 쓰이는 자리는 여기 하나뿐이다.
  - **글자·아이콘 색은 `limeOnQuiet`다** — 목업은 `limeInk`지만 이 틴트 면 위에서 4.16:1이라 12.5px 글자에 필요한 AA 4.5에 못 미쳐 한 단계 어둡게 조정했다(라임 계열은 유지).
  - **켜면 다른 필터 칩과 같은 잉크 채움**이 되고 아이콘만 라임으로 남는다 — 틴트를 진하게 하는 방식은 켠 건지 아닌지 한눈에 갈리지 않았다(2026-08-05 결정 승계).
- 판정은 **사용률 0%** 다 — 배낭에 담긴 적이 있고 그중 `사용`으로 기록된 여행이 하나도 없는 장비. 담긴 적이 아예 없는 장비는 **포함하지 않는다**(쓸 기회가 없었던 것과 쓰고도 안 쓴 것은 다르다).
- 켜면 결과 수를 함께 보여준다 — 몇 개가 걸러졌는지 모르면 덜어낼 판단을 못 한다.
- 결과가 0건이면 `안 쓴 장비가 없어요` + `담아 간 장비를 모두 쓰고 있어요` 두 줄 빈 상태를 낸다(전체가 비었을 때의 WH-6과 구분).
- 추가 쿼리를 만들지 않는다 — 이미 로드된 목록을 클라이언트에서 거른다(WH-2 세분 필터·WH-5 검색과 같은 방식).
- **검색 토글 시 아래 콘텐츠가 밀리지 않아야 한다.** 검색 행은 평소 제목 블록과 **같은 높이를 차지**해야 하며, 이는 계산이 아니라 구조로 보장한다(2026-08-11 개정).
  - Android·Web: 제목 블록 ↔ 검색 행이 **같은 최소 높이 상수**(제목 32/38 + 4 + 요약 18 = 60)를 참조해 맞교환된다. 유리 필드(48)는 그 안에서 가운데 놓인다.
  - iOS: 검색은 네이티브 검색 바가 맡으므로 본문이 바뀌지 않는다 — 헤더를 감추지 않고(`hideNavigationBar: false`) 제목 블록도 그대로 남는다.
  - Android·Web 검색 모드에서는 `창고` 타이틀·요약·정렬이 사라진다. 화면이 검색 상태임이 드러나야 하고, 그때 제목은 군더더기다. 유리 크롬의 뒤로가기는 검색 중에도 남는다.
- **선택된 1차 칩이 가로 스크롤 밖이면 보이도록 스크롤한다**(2026-07-31). 홈 미리보기에서 카테고리를 좁힌 채 들어오면([Home.md](Home.md) HM-4) 선택 칩이 화면 밖이라 **필터가 걸린 줄 모른 채 목록이 적게 나온 것처럼 읽혔다.**
  - 이미 보이는 칩은 건드리지 않는다 — 탭할 때마다 행이 흔들리면 거슬린다.
  - **진입 시 첫 정렬은 애니메이션 없이** 한다. 열자마자 칩이 흐르면 사용자가 건드린 것처럼 보인다. 이후 선택 변경은 애니메이션.
  - 가장자리에 여백(16pt)을 남긴다 — 딱 붙으면 잘린 것처럼 보인다.
- **필터 변경 시 스켈레톤 + 스크롤 리셋**: 1차 필터는 재조회 로딩 중 스켈레톤이 뜨고, 2차(세분) 필터는 추가 쿼리가 없어도 짧게 로딩 상태를 두어(약 200ms) 스켈레톤을 노출한다. 스켈레톤 스왑으로 목록 스크롤뷰가 리마운트되어, 목록을 아래로 내려 보던 중 필터를 바꿔도 스크롤이 항상 최상단으로 리셋된다.
- **규모는 제목 블록의 요약 줄이 든다** — `{개수}개 · {총 무게}kg`(예: `42개 · 18.6kg`, 소수점 한 자리) 한 덩어리이며, 필터(1·2차)+검색어(WH-8) 적용 결과를 반영한다(2026-08-11 개정).
  - **[이력] 2026-07-13~2026-08-10**: 필터 영역에 `총 N개`만 표시(총 무게는 제거된 상태였다). 목업 §8이 개수와 총 무게를 화면 대상 바로 아래 한 줄로 되살렸다 — 창고에서 알고 싶은 규모는 "몇 개"와 "얼마나 무거운가" 둘이고, 둘을 갈라 놓으면 어느 것도 눈에 남지 않는다.
  - 무게가 전부 미입력이면 `0.0kg`은 뜻이 없어 개수만 남긴다.
- 창고가 완전히 빈 상태(WH-6)에서는 필터 영역·요약 줄·정렬을 렌더하지 않는다.

### WH-3 정렬

사용자는 정렬 순서를 선택할 수 있고, 선택은 기기에 저장된다.

**수용 기준**

- 옵션은 4개: `이름순`(기본) / `가벼운순` / `무거운순` / `최근 추가순`.
- 각 옵션은 Firestore `orderBy`에 매핑된다: `name asc` / `weight asc` / `weight desc` / `createDate desc`.
- **`가벼운순`은 실제 무게 오름차순 뒤에 무게 미입력(0g)을 붙인다.** `weight: 0`은 "가장 가벼움"이 아니라 무게 미입력이고([Feed.md](Feed.md) FD-3과 같은 전제 — 대부분 의류라 오히려 무거운 제품이다), 그대로 두면 목록 맨 앞이 0g으로 채워져 정작 가벼운 장비를 볼 수 없다.
  - 구현: 이 목록은 결과를 페이지네이션 없이 한 번에 다 읽으므로, `orderBy('weight','asc')` 결과에서 **0g을 뒤로 미는 안정 분할**로 끝낸다(서버가 준 상대 순서는 유지). 피드(FD-3)가 2단 조회를 쓰는 건 Algolia 페이지 상한 때문이라 여기선 필요 없다.
  - 0g끼리의 순서는 의미가 없어 별도 정렬을 두지 않는다.
  - `무거운순`은 0g이 자연히 뒤로 가므로 손대지 않는다.
  - **적용 대상은 `GearStore.getList`를 쓰는 두 화면 — 창고 목록과 배낭 편집의 창고 리스트**([BagDetail.md](BagDetail.md) BD-4)다. 정렬 UI가 있는 화면이 이 둘뿐이다. 배낭 상세·사용 기록·공유 배낭은 `BagStore.getBag`/`getSharedBag`로 배낭에 담긴 장비를 읽는데, 이 화면들에는 정렬 선택 자체가 없어 규칙이 적용되지 않는다(BD-1).
- 선택 시 즉시 목록을 다시 읽고, `LocalStorageManager`에 `selectedOrderType_{key}`로 저장되어 재실행 후에도 유지된다.
- 정렬 진입 버튼은 **제목 블록 우측**에 둔다(2026-08-11 개정 — 필터 줄 하단에서 올라왔다): 현재 옵션 이름 13.5/600 + `chevron-down`, 시각 높이 32에 44pt 터치를 확보한다. 배낭 목록(BAG-1)·피드와 같은 문법이다.
- 정렬 선택 UI는 **공용 네이티브 formSheet 라우트 `/sort-sheet`**로 표시한다(타이틀 `정렬` + 옵션 행, 선택 옵션은 체크·볼드; 그래버·드래그 닫기·높이는 OS 처리, `fitToContents`). 옵션 탭 시 즉시 적용 후 닫힘. 피드·탐색과 같은 라우트를 공유한다. (구 앵커드 드롭다운·커스텀 Animated 바텀시트는 폐기.)
- 정렬 기준 `name`은 캐논컬 값이다(표시 이름과 다를 수 있음) — [DataModel.md](DataModel.md) DM-3.

### WH-4 장비 상세/수정 진입

- 장비 행을 누르면 `/gear-detail/{id}`로 이동한다 → [GearDetail.md](GearDetail.md)
- 장비 **수정**은 장비 상세 화면 헤더 우상단 `수정하기`(GD-1)에서 진입한다 → `/gear-edit/{id}` → [GearEdit.md](GearEdit.md). 목록 행에는 별도 수정 진입점을 두지 않는다. `[제안]`

### WH-5 장비 삭제

사용자는 창고에서 장비를 삭제할 수 있다.

**수용 기준**

- 목록 행을 **왼쪽으로 스와이프**하면 트레일링 액션으로 `삭제`(red 배경)가 노출된다(배낭 리스트 BAG-4와 동일한 `ReanimatedSwipeable` 패턴). 스와이프 액션 버튼은 44pt 이상 히트 영역과 `accessibilityLabel`(`{이름} 삭제`)을 가진다. `[제안]`
- `삭제` 탭 → 확인 다이얼로그(`{이름}을 삭제하시겠습니까?`, 확인 버튼 `삭제하기`, 이름은 `getDisplayName()`)를 거친다. 취소하거나 스와이프를 닫으면 아무 일도 일어나지 않는다.
- 확인 시 장비 문서 삭제와 함께: 장비가 담긴 모든 배낭의 `gears`에서 제거 + 배낭 `weight` 차감 + 카탈로그 장비면 `gear-rank` count 감소([DataModel.md](DataModel.md) DM-6, DM-11).
- 완료 후 토스트 `삭제 되었습니다.`를 표시하고 목록을 갱신한다.
- 행의 기존 `⋮` 더보기 메뉴(수정/삭제 모달)는 제거한다 — 삭제는 스와이프로, 수정은 상세 화면(WH-4)으로 대체. `[제안]`

### WH-6 빈 상태

**수용 기준**

빈 상태는 **사실 + 다음 걸음 두 줄**이다(2026-08-11 개정 — 핸드오프 Interactions). 원인마다 다음 걸음이 다르다.

- 장비가 0개이고 `전체` 필터이고 로딩 중이 아니면: 흰 카드에 `창고가 비어 있어요` / `가진 장비를 하나씩 담아보세요` + 보조 알약 `첫 장비 담기`(WH-7과 같은 경로). 상단 크롬의 `+`와 같은 곳으로 가므로 **잉크 주 액션으로 두지 않는다** — 주 액션은 화면에 하나다.
- 검색어가 있고 결과가 0개면: `검색 결과가 없어요` / `이름이나 브랜드로 다시 찾아볼까요?`.
- 검색어가 없고 특정 필터 선택 결과가 0개면: `{필터명}이(가) 없어요` / `다른 카테고리를 골라볼까요?` (josa 라이브러리로 조사 처리).
- 안 쓴 장비 필터(WH-2-1) 결과가 0개면: WH-2-1의 두 줄.

### WH-7 장비 추가 진입

- 추가 버튼(상단 크롬의 `+`, WH-1): 로그인 상태면 **장비 추가 선택 시트(`gear-add-options`)** 를 연다([GearEdit.md](GearEdit.md) GE-8), 비로그인이면 로그인 모달(`LogInAlertManager`)을 띄운다.
- 선택 시트는 배낭 추가 시트(BAG-2, `bag-add-options`)와 동일한 네이티브 formSheet 패턴을 쓰며 두 갈래를 제공한다: **`검색으로 추가`**(→ **탐색 탭**으로 이동, 둘러보기+검색으로 창고 담기, GE-8) / **`직접 입력`**(`/custom` 수동 폼, GE-1/GE-3). 항목 선택 시 시트를 다음 화면으로 `replace`한다(중간 탭 리로드 노출 방지).

### WH-8 장비 검색

사용자는 창고에서 장비를 이름/브랜드로 검색할 수 있다.

**수용 기준**

- 검색 인풋은 **기본으로 감춰져 있고**, 상단 크롬의 **검색 버튼**(돋보기, `accessibilityLabel='장비 검색'`)을 눌러야 노출된다. iOS는 이 버튼과 필드를 네이티브 검색 바가 내주고(LG-3), Android·Web은 아래 유리 필드를 쓴다.
  - Android·Web 검색 모드 진입 시: 제목 블록이 **유리 검색 필드**(h48 · 알약 · 블러 + 유리 채움 + 0.5px 흰 보더, placeholder `장비 검색`, 자동 포커스) + `취소` 버튼 행으로 바뀐다. 값이 들어오면 채움을 한 단계 진하게 덮어 입력 상태를 드러내고 돋보기도 잉크로 올린다(탐색 필드와 같은 문법). 검색 버튼은 이 동안 숨긴다.
  - `취소`를 누르면 검색 인풋을 닫고 **검색어를 초기화**한다(제목 블록 복귀).
  - 검색 버튼·인풋 모두 창고가 완전히 빈 상태(WH-6)에서는 렌더하지 않는다. 카테고리 필터 칩(WH-2)은 검색 모드와 무관하게 계속 노출된다.
- 입력값으로 **현재 로드된 목록을 클라이언트에서 필터**한다(추가 Firestore 조회 없음): `getDisplayName()` 또는 `getDisplayCompany()`에 검색어 포함(대소문자 무시). 카테고리 필터(WH-2)와 함께 적용된다.
- 검색 결과가 제목 블록의 요약 줄(개수·총 무게, WH-2)에 반영된다. 결과 0개면 WH-6의 검색 두 줄.
- 인풋 우측 클리어(X) 버튼으로 검색어를 지운다(커스텀 버튼 1개 — 네이티브 `clearButtonMode` 미사용, 크로스플랫폼 일관).

## 4. 데이터

- 읽기: `users/{uid}/gears` — 필터/정렬 쿼리는 WH-2, WH-3.
- 쓰기: 삭제(WH-5)만. 필드 계약은 [DataModel.md](DataModel.md) DM-3.
- 로컬: 정렬 선택 `selectedOrderType_{key}` (AsyncStorage).

## 6. 엣지 케이스

- **비로그인**: 목록을 비우고 빈 상태 표시. 로그인 상태 변화는 MobX reaction으로 감지해 자동 갱신.
- **로딩**: 초기 로드·필터/정렬 변경 시 `WarehouseSkeletonView`(흰 카드 안 6행 셔머) 표시 — 도착할 목록과 같은 골격이라 로드 후 자리가 튀지 않는다. Firebase 초기화 전에는 **지면만** 깐다(스피너 금지, 흰 화면 번쩍임 방지).
- **에러**: Firestore 조회 실패 시 빈 배열 처리(별도 에러 UI 없음). 삭제 실패는 콘솔 로그만.
- **무게 미입력(0g)**: `가벼운순`에서 실제 무게 항목 뒤로 밀린다(WH-3). `weight` 필드가 아예 없는 문서는 Firestore `orderBy('weight')` 자체에 걸리지 않아 무게 정렬에서는 목록에 나오지 않는다 — 기존 동작이며 이번 규칙의 대상이 아니다.

## 7. 수동 검증 체크리스트

- [ ] 로그인 → 창고 진입 시 장비 목록이 정렬 기본값(이름순)으로 보인다
- [ ] 필터 단일 선택 → 다른 필터로 전환, 선택 칩 재탭은 무시(해제 안 됨), `전체` 칩으로 전체 복귀
- [ ] 검색어 입력 → 이름/브랜드 필터, 요약 줄(개수·총 무게) 반영, 결과 없으면 두 줄 빈 상태, X로 초기화(X 1개)
- [ ] Android·Web 검색 열기/닫기 → 제목 블록 ↔ 유리 필드가 맞교환되고 아래 칩 줄·목록이 밀리지 않는다. 검색 중에도 뒤로가기가 남는다
- [ ] iOS 검색 버튼(네이티브) 탭 → 필드가 상단 바에서 펼쳐지고(하단 툴바로 내려가지 않음) 뒤로가기가 사라지지 않는다
- [ ] 제목 블록 → `창고` 32pt + `{n}개 · {w}kg` + 우측 정렬. iOS 네이티브 바에 `창고` 타이틀이 중복되지 않는다
- [ ] 정렬 탭 → 하단 바텀시트(딤 페이드·시트 슬라이드업), 옵션 선택 체크 / 앱 재시작 후 선택 유지
- [ ] `가벼운순` → 무게가 있는 장비가 가벼운 순서로 먼저 나오고, 무게 미입력(0g) 장비는 목록 맨 뒤에 모인다 (배낭 편집의 창고 리스트도 동일)
- [ ] `무거운순` → 무거운 순서로 나오고 0g은 맨 뒤 (기존 동작 유지)
- [ ] 장비 삭제 → 담겨 있던 배낭 상세의 총 무게가 줄어든다
- [ ] 비로그인에서 추가 버튼 → 로그인 모달
- [ ] 한글 이름(`nameKorean`) 장비와 영문만 있는 장비가 모두 올바르게 표시된다
- [ ] 사진 올린 장비 → 행 좌측 썸네일 표시 / 안 올린 장비 → 빈 썸네일 칸 없이 기존 텍스트 행. 두 행이 섞여도 우측 무게 컬럼의 세로 정렬이 유지된다
- [ ] 카탈로그에 크롤 이미지가 있는 장비라도 내가 사진을 안 올렸으면 썸네일이 안 나온다(폴백 없음)
- [ ] 목록이 흰 카드 하나로 보이고 행은 헤어라인으로만 갈린다(행마다 뜬 면·그림자 없음)
- [ ] 행 스와이프 → 삭제 액션 면이 카드 모서리 안에서 끝난다(카드 밖으로 새지 않음)
- [ ] 로딩 → 흰 카드 안 6행 스켈레톤이 도착한 목록과 같은 자리에 서고, 스피너가 없다
- [ ] 안 쓴 장비 칩 → 라임 틴트(끔) ↔ 잉크 채움 + 라임 아이콘(켬). 화면에 라임이 이 칩 하나뿐이다
- [ ] 목록 끝까지 스크롤 → 마지막 행이 화면 밑단에 붙지 않는다
- [ ] 빈 창고 / 필터 0건 / 검색 0건 / 안 쓴 장비 0건 → 각각 두 줄 문구가 원인에 맞게 나온다
