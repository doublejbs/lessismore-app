## 1. 개요

창고는 사용자가 보유한 장비(`users/{uid}/gears`)의 목록 화면이다. 홈 미리보기(`전체 보기`)에서
들어오는 **푸시 화면**이며([Home.md](Home.md) HM-0·HM-4), 카테고리 필터·정렬·장비 추가/수정/삭제의
진입점을 제공한다.

## 2. 화면 및 진입

```
app/warehouse/index.tsx → WarehouseWrapper → WarehouseScreen
                                              ├─ WarehouseChromeView (Android·Web 아이콘 크롬: 뒤로 + [검색][+])
                                              ├─ 페이지 머리 (`창고` / 아래 줄 `{n}개 · {w}kg`)
                                              ├─ WarehouseSearchFieldView (Android·Web 검색 모드, WH-8 — LedgerField)
                                              ├─ WarehouseFiltersView (LedgerTextTabs[전체·안 쓴 장비 n·카테고리] + WarehouseSortView + 1px 구역 경계 / 세분 탭 줄)
                                              ├─ WarehouseGearView × n (LedgerRow + 삭제 스와이프 액션)
                                              └─ WarehouseSkeletonView / 빈 상태 2줄
```

프리미티브는 `components/ledger/`에 있다: `LedgerRow`(목록 한 행) · `LedgerTextTabs`(+ `LedgerTextTabsSize`) · `LedgerField`(입력).

- `WarehouseWrapper`는 Firebase 초기화 완료까지 **지면만** 렌더하고(스피너 없음), 이후 `Warehouse` 도메인 객체를 1회 생성한다.
- 화면 포커스 시(`useFocusEffect`) `warehouse.refresh()`로 목록을 다시 읽고 검색 상태를 초기화한다. pull-to-refresh는 없다.

### 화면 문법 (as-built, Ledger)

창고의 시각만 서술한다. 무엇을 언제 보여주는지는 WH-1~WH-8이 정의한다.

창고는 **Ledger**(장비 원장) 디자인 시스템을 쓰는 유일한 화면이다. 토큰은
`constants/LedgerTokens.ts`, 프리미티브는 `components/ledger/`이며 나머지 화면은 아직
Liquid Depth다([README.md](README.md) 디자인 시스템 절). **한 화면 안에서 두 세대를 섞지 않는다** —
이 화면이 Liquid에서 가져다 쓰는 것은 스켈레톤 셔머 두 개(`useLiquidShimmer`·`LiquidSkeletonBar`)뿐이다.

- 지면은 **흰 종이 하나**(`page` #FFFFFF)다. 지형 이미지·베일·라디얼 글로우·유리가 없다 — `LiquidBackdrop`을 걷었다. `Layout`의 기본 지면(Liquid `canvas`)은 절대 배치 흰 면으로 덮는다.
- 구분은 **`여백 → 글자급 → 정렬 → 헤어라인`** 순서로만 낸다. **카드로 감싸는 자리가 한 곳도 없다** — 목록도, 스켈레톤도, 빈 상태도 면이 없다.
- 그림자는 **실제로 떠 있는 것에만** 쓴다. 이 화면에는 떠 있는 것이 없어 그림자가 0개다(`LedgerElevation`은 정의만 되어 있다).
- 크롬은 **아이콘만**이다: iOS는 네이티브 투명 헤더가 back·바 버튼(검색·추가)을 내주고(LG-1·LG-3), Android·Web은 유리 캡슐 없이 아이콘 상자 3개(뒤로·검색·`+`)만 그린다. 아이콘 상자는 44라 글리프 중심이 22에 놓여 시스템 바와 같은 좌우 축을 갖는다.
- 화면 대상은 페이지 머리가 든다: `창고`(display 24/30 bold) + 그 **아래** 규모(`57개 · 44.7kg`, label 13 `inkTertiary`). 규모를 정렬과 한 행에 묶지 않는다 — 정렬은 컨트롤 줄의 것이고 규모는 제목에 딸린 사실이라, 한 줄에 두면 읽는 값과 조작하는 값이 섞인다. **네이티브 바 타이틀은 비운다.**
- 좌우 거터는 **16 하나**다(`pageX`). 행은 자기 가로 패딩을 갖지 않고 이 거터에 정렬한다 — 행마다 패딩을 주면 헤어라인과 글자의 좌측 축이 갈린다. 탭 줄만 화면 끝까지 블리드한다(스크롤이 가장자리에서 끊기지 않게).
- 컨트롤 줄은 **텍스트 탭 + 정렬 + 1px 구역 경계**다: 좌측에 무엇을 볼지(카테고리 탭 + 사용 여부 탭, WH-2·WH-2-1), 우측에 어떤 순서로 볼지(WH-3). 그 아래 `lineStrong` 1px이 컨트롤과 원장을 가른다 — 선택 탭의 2px 밑줄이 이 선에 앉는다.
- **목록은 카드가 아니라 행**이고 행 사이는 헤어라인 하나다. 헤어라인은 **좌우 인셋 없이 거터에서 거터까지** 긋는다 — 한쪽만 들여쓰면 선이 기울어 보인다. 목록 첫 행 위에는 선을 두지 않는다(컨트롤 줄의 구역 경계가 이미 선을 그었다).
- 아이콘을 블록마다 붙이지 않는다. 이 화면의 글리프는 크롬 3개(뒤로·검색·`+`) + 컨트롤 셰브론 1개 + 검색 필드 2개(돋보기·지우기)뿐이고, 스와이프 삭제는 **글자 `삭제`만** 쓴다.
- **액센트(라임)는 주 액션에 쓰지 않는다** — 선택 상태·활성 지표 전용이다. 이 화면에서 쓰이는 자리는 `안 쓴 장비` 탭의 선택 표시 하나이며, 흰 면 위라 원색 라임(`accent`)이 아니라 라임 계열 잉크(`accentInk`)로 긋는다(2px 원색 라임 선은 흰 면에서 1.4:1로 보이지 않는다).
- 주 액션은 화면당 하나이고 이 화면에서는 크롬의 `+`다. 빈 상태의 `첫 장비 담기`는 같은 곳으로 가는 조용한 안내라 **밑줄 텍스트 버튼**이다(면·알약 없음).
- 숫자(무게)는 **콘덴스드(Archivo Narrow)**, 단위까지 한 덩어리(`907g`)로 쓰고 우측 정렬축에 고정한다 — 무게가 이 앱의 통화라 표처럼 자릿수가 맞아야 한다(Ledger 시그니처 ①). 한글이 섞인 값(개수·요약 줄·`무게 없음`)은 본문 서체다 — 콘덴스드에 한글 글리프가 없다.
- **상단 고정 블록**: 페이지 머리와 컨트롤 줄은 스크롤하지 않고 그 아래 원장만 스크롤한다(이식 전 구조 승계). 규모 줄·필터가 항상 보이는 쪽이 훑어 비교하는 목록에 맞다. iOS 상단 인셋도 그래서 automatic content inset이 아니라 수동 `paddingTop`(세이프에어리어 + 44 + 8)이다(LG-3).
- 로딩은 스켈레톤이다(스피너 금지) — 카드 없이 **행 골격 + 헤어라인**이고, 줄 상자는 도착할 텍스트의 라인박스(이름 22 / 메타 18)와 같은 높이이며 막대는 그 안에서 글자 크기만큼만 차지한다. 셔머는 Liquid 세대의 것을 그대로 쓴다(왕복 로직을 두 벌 만들 이유가 없다).
- 누름은 `activeOpacity 0.7`이다 — 색을 바꾸거나 크기를 줄이지 않는다.

**밀도(as-built 계산, 402×874 / 세이프에어리어 상 62·하 34)**: 상단 고정 블록 219(= 62 + 네이티브 바 44 + 8 + 페이지 머리 52 + 컨트롤 53) → 목록 뷰포트 621. 두 줄 행은 64(세로 패딩 12×2 + 이름 22 + 메타 18)라 **9행 + 10행째 일부**, 한 줄 행은 46이라 13행이 들어온다. 이식 전(74pt 행 · 뷰포트 588)은 8행이었다.

#### [이력] 화면 문법 (2026-08-11 ~ 2026-08-11 — Liquid Depth)

Ledger 이식 전 문법이다. 지금 코드에는 남아 있지 않다.

- 지면은 지형 없이 `canvas` + 우상단 라임 글로우(`LiquidBackdrop screen='none'`).
- 크롬은 지면 위에 뜬 **유리**: Android·Web은 `LiquidGlassCircleButton`(원형 back) + `LiquidGlassCapsule`(검색·추가) 두 겹의 블러 면.
- 제목 블록 `창고` 32/38 + 그 아래 한 행에 규모(13/500)와 **정렬 칩**을 좌우로 앉혔다.
- 좌우 여백이 블록마다 달랐다(크롬 12 · 콘텐츠 20 · 칩 줄 블리드).
- **목록은 흰 카드 하나**(모서리 22 + 2겹 그림자)이고 행은 좌측 16 들여쓴 헤어라인으로 갈렸다. 빈 상태도 `LiquidCard` + `LiquidPillButton` 알약이었다.
- 필터는 완전한 알약 칩(`LiquidChip` h34 / 세분 h28)이고, `안 쓴 장비 n`은 라임 35% 틴트 알림 칩(h30 + `alert-circle-outline`)이었다.
- 검색은 유리 필드(`LiquidSearchField` h48 알약 + 블러), 스와이프 삭제는 휴지통 아이콘 + `삭제`.
- 행은 **세 줄**(브랜드 / 이름 / 메타)에 `minContentHeight` 44를 걸어 74pt였다.

## 3. 요구사항

### WH-1 장비 목록 표시

로그인한 사용자는 창고에서 자신의 장비 목록을 볼 수 있다.

**수용 기준**

- 각 장비 행에 제조사, 이름, 색상, 무게를 표시한다.
- **행 사이는 헤어라인으로 가른다**(2026-08-11 Ledger 개정 — 목록을 감싸는 카드가 없고, 헤어라인이 **좌우 인셋 없이 페이지 거터에서 거터까지** 그어진다). 여백만으로 행을 가르면 줄 수가 다른 행(1~2줄)이 섞일 때 경계가 잡히지 않아, 정보가 적은 행이 목록의 일부가 아니라 떠 있는 문자열처럼 읽힌다.
  - **목록 첫 행 위에는 헤어라인을 두지 않는다** — 컨트롤 줄 아래 `lineStrong` 1px 구역 경계가 이미 선을 그었다. 두 선이 겹치면 첫 행만 두 겹 테두리를 두른 것처럼 보인다.
  - **[이력] 2026-08-11 (Ledger 이식 전)**: 목록 전체가 흰 카드 하나(모서리 22 + 그림자)이고 그 안에서 **좌측 16 들여쓴** 헤어라인이 행을 나눴다. 카드를 걷으면서 인셋도 걷었다 — 감쌀 면이 없으면 들여쓸 기준선도 없다.
  - **[이력] 2026-07-29~2026-08-10**: 행마다 각진 흰 종이 면(ACG) 또는 행 하단 1px 구분선(`Color.divider`).
  - **행 사이에 gap이 없는 목록에만 적용한다.** 창고 목록은 행이 맞붙어 있고 패딩으로만 간격을 만들어 헤어라인이 정확히 행 사이에 놓인다. 배낭 상세([BagDetail.md](BagDetail.md) BD-1)·패킹([Packing.md](Packing.md) PK-2)은 각자의 문법을 따른다(카테고리 카드 / 행 하나가 곧 카드).
- **값이 없는 줄은 렌더하지 않는다** — 제조사·색상 모두 같은 규칙이다. 빈 텍스트를 두면 행에 죽은 공백이 생겨 이름이 아래로 밀려 보이고, 브랜드·색상이 없는 직접 등록 장비(예: 이름만 있는 `테스트`)가 행이 아니라 떠 있는 문자열처럼 읽힌다(2026-07-29 실측). 행 높이는 썸네일 기준 `minHeight`로 이미 균일하므로 줄이 줄어도 목록 리듬은 유지된다.
  - **세로 스택에만 해당한다.** 브랜드가 CTA와 같은 **가로 행**에 놓이는 피드 카드(FD-2)는 브랜드 텍스트가 `flex: 1` 스페이서 역할을 겸하므로, 값이 없어도 요소를 유지한다 — 지우면 CTA가 왼쪽으로 딸려온다.
  - 같은 규칙이 배낭 상세 장비 행([BagDetail.md](BagDetail.md) BD-1)과 장비 상세 정체 줄([GearDetail.md](GearDetail.md) GD-1)에도 적용된다.
- **행에 썸네일을 두지 않는다**(2026-08-11 Ledger 개정 · [DataModel.md](DataModel.md) §1은 장비 이미지 미제공을 정한다). 사진이 있는 행은 극소수인데 그 행만 좌측 축이 밀려, 같은 목록에서 이름의 시작점이 행마다 갈렸다. 사진은 상세에서 본다([GearDetail.md](GearDetail.md) GD-13).
  - **[이력] 2026-07-29~2026-08-11**: 사용자가 올린 본인 사진(`users/{uid}/gears/{id}.imageUrl`)이 있을 때만 행 좌측에 정사각 썸네일(한 변 44 · 모서리 12)을 두고, 행 높이를 그 한 변으로 묶었다. 썸네일이 사라지면서 `minContentHeight` 계약도 함께 걷혔다 — 이제 행 높이는 줄 수가 정한다(2줄 64 / 1줄 46).
- **행 안은 두 줄이다 — 이름 → 메타**(2026-08-11 Ledger 개정): 이름 16/22 semibold(`ink`, 1줄 말줄임) → 메타 13/18(`inkTertiary`)이고, 메타는 **브랜드와 사용률을 ` · `로 이은 한 줄**(`힐레베르그 · 사용률 40%`)이다. 이름이 시각 앵커이고 브랜드는 그 아래 메타의 첫 조각이다.
  - **브랜드가 이름 위 별도 줄에서 메타 줄로 내려왔다.** 세로로 훑어 비교하는 목록에서 줄이 하나 늘면 화면에 들어오는 행 수가 그만큼 줄고, 브랜드는 이름을 여는 라벨이라 메타와 같은 급이다. 행 높이가 74 → 64(두 줄) / 46(한 줄)로 내려가 뷰포트당 8행 → 9행 이상이 된다(§2 밀도 계산).
  - **값이 없는 조각은 통째로 뺀다** — 브랜드도 사용률도 없으면 메타 줄이 사라져 한 줄 행이 되고, 둘 중 하나만 있으면 ` · `를 넣지 않는다.
  - **메타에 담을 값의 종류는 고정이다 — 브랜드와 사용률뿐**(2026-08-11 디자인 리뷰 승계). 색상을 함께 잇던 구 문법(`{색상} · 사용률 {n}%`)에서는 같은 슬롯에 네 종류가 섞였다 — `핑크` · `STONE GREEN`(한글 매핑 없는 크롤 원본) · `라지 [품절]`(이름 뒷부분과 중복) · `Beluga · 사용률 100%`. 종류가 행마다 갈리면 그 줄에서 무엇을 읽어야 하는지 학습되지 않는다.
  - **[이력] 2026-08-11 (Ledger 이식 전)**: 세 줄(브랜드 12/600 `inkMuted` → 이름 15/600 → `사용률 {n}%` 12 `inkSubtle`)에 `minContentHeight` 44를 걸어 행 높이 74로 묶었다.
    - **남길 값의 기준은 "행동을 유발하는가"다.** 색상은 사실이지만 목록에서 할 일을 만들지 않아 상세의 태그 칩으로 내렸고([GearDetail.md](GearDetail.md) GD-1), 창고에는 덜어낼 후보를 고르게 하는 값만 남긴다(WH-2-1과 같은 목적).

    - **이름과 중복되는 문자열은 어느 슬롯에서도 반복하지 않는다** — 위 `라지 [품절]`이 그 사례였다.
  - **[이력] 2026-07-28~2026-08-10**: 브랜드를 제품명과 동일한 타이포로 표시했다(이미지 없는 레이아웃에서 브랜드가 식별의 첫 축이라는 근거). Liquid Depth의 행 문법에서는 같은 크기의 두 줄이 어느 쪽이 제품명인지 갈리지 않아, 크기로 위계를 준다 — 이식이 끝난 화면(홈 HM-4·배낭 상세 BD-1·패킹 PK-2·검색 순위 SR-4·창고)이 이 문법을 공유한다.
  - **사용률은 배지가 아니라 메타 줄의 텍스트다**(2026-08-11 개정) — 배지가 무게 위에 놓이면 우측 컬럼이 두 층이 되어 무게의 세로 정렬이 흔들린다. 사용 기록이 없으면 그 조각째 빼서 ` · `가 홀로 남지 않게 한다.
- **행은 좌 정체 · 우 무게의 2열로 나눈다**(2026-07-28 사용자 결정 · 2026-08-11 지표 컬럼 단일화) — 좌측은 정체(이름·메타), 우측은 **무게 하나**(콘덴스드 15/20, 단위까지 한 덩어리). 무게가 미입력이면 그 자리를 비우지 않고 `무게 없음`(caption 12 `inkQuiet`)을 놓아 우측 정렬축을 지킨다 — Ledger 카피는 짧은 사실이라 아직 이식하지 않은 화면의 `무게 미입력`과 말이 다르다. 무게가 행마다 같은 자리에 오므로 세로 스캔으로 비교할 수 있다(iOS leading/trailing 리스트 관습). 이름·브랜드가 길면 말줄임해 우측 컬럼을 침범하지 않는다. **장비 리스트 행 전체**(창고·패킹·배낭 편집·배낭 상세·공유 배낭)에 공통 적용하되, **피드 카드(FD-2)는 예외** — 무게가 카드의 시각 앵커인 현재 구조를 유지한다.
- 이름은 `Gear.getDisplayName()`(= `nameKorean || name` + 대괄호 접미 스트립)으로 표시한다 — `getName()` 직접 표시 금지.
  - **재고·판매 상태 대괄호 접미(`[품절]`·`[재입고]`)는 표시하지 않는다**(2026-08-11 디자인 리뷰). 카탈로그 크롤 원본의 주석이라 내 창고 목록에서 이미 가진 물건에 남의 재고 상태가 따라다닐 이유가 없다. 스트립은 표시 게터 한 곳에서만 하고(정본 규칙은 [DataModel.md](DataModel.md) DM-3), 창고·배낭·검색이 같은 이름을 쓴다.
- 무게는 항상 g 고정이고 천 단위 구분자를 넣지 않는다(`55g` `7200g` — 표기 정본은 [DataModel.md](DataModel.md) DM-26). 값 크기에 따라 kg으로 바꾸지 않는다 — 이 컬럼은 세로 비교축이다.
- **무게가 미입력(0g·빈 값)이면 그 자리에 `무게 미입력`을 놓는다**(2026-08-11 개정, `inkSubtle` 보조 서체 — 한글이라 콘덴스드를 쓰지 않는다). 예전에는 자리를 비웠는데, 칸이 통째로 사라지면서 그 행만 우측 정렬축이 무너져 **무게가 있는 행끼리도 비교가 안 됐다**. 판정은 `hasWeight()` 하나를 쓰고, 목록 행은 수치 프롭을 빼는 대신 `null`을 넘긴다.
- 사용 기록이 있는 장비는 메타 줄에 `사용률 XX%`(`used`/`useless` 기록 기반)를 표시한다.
- **상단 크롬 액션은 `[검색][+ 장비 추가]` 둘이다**(2026-07-31 · 2026-08-11 유리 크롬으로 이식). 플로팅 `장비 추가` pill은 폐기 — 창고가 푸시 화면이 되며 헤더에 자리가 생겼고, 하단 플로팅 하나로 주 액션을 대표하던 이유가 사라졌다.
  - iOS 검색은 네이티브 검색 바가 맡는다([LiquidGlassNavigation.md](LiquidGlassNavigation.md) LG-3). Android·Web은 **유리 캡슐 안 아이콘 두 개**로 같은 순서·같은 자리에 두고, 검색을 탭하면 제목 블록 자리에 검색 필드가 열린다(WH-8). 캡슐 안 아이콘 칸은 시스템 바 버튼과 같은 34/38이라 44에 못 미친다 — **현 프리미티브 구조상의 제약**이며(`LiquidGlassCapsule`의 겉면이 알약으로 클리핑해 그 밖의 히트 영역이 전달되지 않는다), 클리핑을 안쪽 레이어로 내리면 넓힐 수 있다. 배낭 상세·패킹 헤더가 같은 자리에 있다.
  - **화면 제목은 크롬이 아니라 본문 제목 블록이 든다**(2026-08-11 개정): `창고` 32/38 좌측 정렬 + 아래 규모 줄(WH-2) + 우측 정렬 드롭다운(WH-3). iOS 네이티브 바 타이틀은 비운다 — 같은 말을 두 곳에 두지 않는다.
  - **[이력] 2026-07-31**: Android·Web은 [back + `창고` 20pt + 버튼 둘]을 한 행에 두었다(탭 루트 시절 32pt large title이 푸시 화면에서 과했다는 실기기 근거). 제목이 크롬에서 본문으로 내려가며 한 행에 몰리는 문제가 사라져 32pt로 돌아왔다.
- 목록은 전체 일괄 로드한다 (페이지네이션/무한 스크롤 없음).
- 스크롤 끝에는 공통 하단 여백을 비운다 — 마지막 행이 화면 밑단에 붙지 않는다.

### WH-2 카테고리 필터

사용자는 카테고리 칩으로 목록을 필터링할 수 있다.

**수용 기준**

- 필터는 `전체` + 11개 카테고리([DataModel.md](DataModel.md) DM-4)로 구성되고 기본값은 `전체`다.
- **필터 UI는 알약 칩이 아니라 텍스트 탭이다**(2026-08-11 Ledger 개정 — 공용 `components/ledger/LedgerTextTabs.tsx`). 항목은 label 13이고 **선택 = `ink` + 2px 잉크 밑줄 · 비선택 = `inkTertiary` 밑줄 없음**이다. 항목마다 면·테두리를 만들던 칩 줄은 필터 한 줄이 카드 더미처럼 보였다 — 원장에서 고르는 일은 글자에 밑줄을 옮기는 것이다.
  - 선택 여부로 **글자 굵기를 바꾸지 않는다**(둘 다 medium) — 굵기가 바뀌면 항목 폭이 달라져 줄 전체가 흔들린다. 비선택 항목도 투명한 2px 밑줄을 들어 높이가 갈리지 않는다.
  - 터치 타깃 44pt는 **항목 높이**로 확보한다(`minHeight` 44, 밑줄은 그 밑단). `hitSlop`을 쓰지 않는 이유: Android는 hitSlop이 부모 경계를 넘지 못해 세로로 넓혀도 전달되지 않는다. 가로는 이웃과 겹치므로 넓히지 않는다.
  - **[이력] 2026-08-11 (Ledger 이식 전)**: Liquid Depth 공용 `LiquidChip`(완전한 알약 h34 · 비선택 = 흰 유리 톤 채움 + 0.5px 보더 · 선택 = 잉크 채움 + 흰 글자 600). 홈 미리보기(HM-4)는 지금도 이 컴포넌트를 쓴다.
- 한 번에 하나만 선택된다 — 다른 필터 선택 시 기존 선택은 해제된다.
- 이미 선택된 필터를 다시 눌러도 **해제되지 않고 그대로 유지**된다(선택 칩 재탭은 무시). `전체`로 돌아가려면 `전체` 칩을 누른다.
- **1차 필터는 그룹 쿼리**: 선택한 그룹의 세분 카테고리 배열(DM-4 매핑, 레거시 키 포함)로 `where('category','in', 멤버들)` 조회한다. `전체`는 전체 조회.
- **2차(세분) 필터**: 세분 카테고리가 2개 이상인 그룹(텐트/매트/배낭/의류/가구/랜턴/조리/기타)을 선택하면 1차 칩 행 아래에 **세분 칩 행**이 나타난다 — `전체` + 그 그룹의 세분 카테고리(한글 라벨, DM-4). 단일 선택, 기본 `전체`, 이미 선택된 칩 재탭은 무시(해제 안 됨) — `전체` 칩으로 해제(1차 필터와 동일). 세분 선택 시 이미 로드된 그룹 목록을 **클라이언트에서 `category === 세분키`로 필터**한다(추가 쿼리 없음). 1차 필터 변경 시 세분 선택은 초기화. 세분이 1개뿐인 그룹(침낭/전자기기/음식)은 세분 행을 렌더하지 않는다.
- 세분 줄도 같은 `LedgerTextTabs`를 쓰되 caption 12로 한 급 낮춰(`LedgerTextTabsSize.Sm`) 1차 줄에 붙여 보조적으로 배치한다. 항목 높이는 1차와 같은 44다(글자만 작아진다).
- **탭 줄은 화면 좌우로 블리드시킨다** — 가로 스크롤이 화면 가장자리에서 끊기면 목록이 잘린 것처럼 읽힌다. 단 1차 줄은 **좌측만** 블리드한다 — 우측에는 정렬(WH-3)이 서 있어 거터까지 갈 수 없다. 세분 줄은 우측에 컨트롤이 없어 양쪽 모두 블리드한다.
- **컨트롤 줄 아래에 `lineStrong` 1px 구역 경계를 둔다** — 컨트롤과 원장을 가르는 선이고, 선택 탭의 2px 밑줄이 이 선에 앉아 탭이 경계에 붙어 보인다. 이 선이 있어 목록 첫 행 위에는 헤어라인을 두지 않는다(WH-1).

### WH-2-1 사용 여부 필터 `[제안]`

사용자는 **안 쓴 장비만** 골라 볼 수 있다 (2026-08-05).

**배경** — 이 앱의 이름값(`useless`)은 "안 쓴 장비를 덜어낸다"인데, 그 인사이트가 장비 상세 안에만 흩어져 있었다. 사용률 배지·미기록 태그·덜어내기 배너 모두 장비를 하나씩 열어야 보인다. 창고에서 한 번에 걸러내는 수단이 없어 "덜어낼 후보"를 찾으려면 전 장비를 훑어야 했다.

**수용 기준**

- 카테고리 탭(WH-2)과 **별개 축**의 토글 `안 쓴 장비 {n}`을 둔다. 카테고리 필터와 **함께** 적용된다(예: `텐트` + `안 쓴 장비`).
  - **탭 줄의 두 번째 항목으로 흡수한다**(2026-08-11 Ledger 개정 — `전체` 다음). 별도 시각(알림 칩)으로 줄 안에 앉아 있을 때는 누르면 목록이 걸러지는 **필터**인지 "안 쓴 장비가 4개 있다"는 **배지**인지 갈리지 않았다. 실제로는 필터이므로 다른 필터와 같은 자리·같은 문법(텍스트 탭)을 쓴다.
  - 개수는 라벨 뒤에 caption으로 붙인다 — 몇 개가 걸러지는지 알아야 덜어낼 판단이 선다.
  - **선택 표시만 라임 계열로 가른다**: 선택 시 밑줄이 `accentInk`(라임 계열 잉크)다. 카테고리는 단일 선택이고 이것은 함께 걸리는 토글이라, 같은 잉크 밑줄이면 **카테고리 선택을 대체한 것처럼** 읽히는데 실제로는 카테고리 필터가 그대로 남아 있다. 밑줄 두 개가 동시에 보이는 상태가 곧 "두 필터가 걸렸다"는 사실이다.
    - 원색 라임(`accent`)을 2px 선으로 흰 면에 긋지 않는다 — 대비가 1.4:1이라 보이지 않는다. 흰 면 위 라임은 잉크로 쓴다(Ledger 색 규칙).
  - 탭 스크롤 정렬(아래)의 대상에는 넣지 않는다 — 줄 앞이라 진입 시점(offset 0)에는 항상 보이고, 멀리 있는 카테고리를 골라 줄이 흐른 뒤에는 다른 필터들과 같이 밀린다.
  - **[이력] 2026-08-11 (Ledger 이식 전)**: 라임 35% 틴트 알림 칩(h30 · 라임 테두리 · `alert-circle-outline` · 글자 `limeOnQuiet`)이었고, 켜면 다른 필터 칩과 같은 잉크 채움이 됐다. 그 전(2026-08-05~)에는 칩 줄 **아래 자기 줄**에 혼자 떠 있었다.
- 판정은 **사용률 0%** 다 — 배낭에 담긴 적이 있고 그중 `사용`으로 기록된 여행이 하나도 없는 장비. 담긴 적이 아예 없는 장비는 **포함하지 않는다**(쓸 기회가 없었던 것과 쓰고도 안 쓴 것은 다르다).
- 켜면 결과 수를 함께 보여준다 — 몇 개가 걸러졌는지 모르면 덜어낼 판단을 못 한다.
- 결과가 0건이면 `안 쓴 장비가 없어요` + `담아 간 장비를 모두 쓰고 있어요` 두 줄 빈 상태를 낸다(전체가 비었을 때의 WH-6과 구분).
- 추가 쿼리를 만들지 않는다 — 이미 로드된 목록을 클라이언트에서 거른다(WH-2 세분 필터·WH-5 검색과 같은 방식).
- **검색 토글 시 아래 콘텐츠가 밀리지 않아야 한다.** 검색 행은 평소 페이지 머리와 **같은 높이를 차지**해야 하며, 이는 계산이 아니라 구조로 보장한다(2026-08-11 개정).
  - Android·Web: 페이지 머리 ↔ 검색 행이 **같은 최소 높이 상수**(제목 24/30 + 4 + 요약 줄 18 = 52 — Ledger 이식으로 74에서 줄었다)를 참조해 맞교환된다. 필드(44)는 그 안에서 가운데 놓인다.
  - iOS: 검색은 네이티브 검색 바가 맡으므로 본문이 바뀌지 않는다 — 헤더를 감추지 않고(`hideNavigationBar: false`) 페이지 머리도 그대로 남는다.
  - Android·Web 검색 모드에서는 `창고` 타이틀·요약이 사라진다. 화면이 검색 상태임이 드러나야 하고, 그때 제목은 군더더기다. 크롬의 뒤로가기는 검색 중에도 남는다.
- **선택된 1차 탭이 가로 스크롤 밖이면 보이도록 스크롤한다**(2026-07-31). 홈 미리보기에서 카테고리를 좁힌 채 들어오면([Home.md](Home.md) HM-4) 선택 탭이 화면 밖이라 **필터가 걸린 줄 모른 채 목록이 적게 나온 것처럼 읽혔다.** 정렬 대상 키는 호출부가 넘긴다(`LedgerTextTabs`의 `alignKey`) — 프리미티브가 "무엇이 대표 선택인지" 추측하지 않는다.
  - 이미 보이는 항목은 건드리지 않는다 — 탭할 때마다 줄이 흔들리면 거슬린다.
  - **진입 시 첫 정렬은 애니메이션 없이** 한다. 열자마자 줄이 흐르면 사용자가 건드린 것처럼 보인다. 이후 선택 변경은 애니메이션.
  - 가장자리에 여백(16pt)을 남긴다 — 딱 붙으면 잘린 것처럼 보인다.
- **필터 변경 시 스켈레톤 + 스크롤 리셋**: 1차 필터는 재조회 로딩 중 스켈레톤이 뜨고, 2차(세분) 필터는 추가 쿼리가 없어도 짧게 로딩 상태를 두어(약 200ms) 스켈레톤을 노출한다. 스켈레톤 스왑으로 목록 스크롤뷰가 리마운트되어, 목록을 아래로 내려 보던 중 필터를 바꿔도 스크롤이 항상 최상단으로 리셋된다.
- **규모는 페이지 머리의 요약 줄이 든다** — `{개수}개 · {총 무게}`(예: `57개 · 44.7kg` — 합계라 kg 한 자리이고 뒤의 `.0`은 뗀다, [DataModel.md](DataModel.md) DM-26) 한 덩어리이며, 필터(1·2차)+검색어(WH-8) 적용 결과를 반영한다(2026-08-11 개정).
  - **요약은 타이틀 바로 아래 줄이고 정렬과 같은 행에 두지 않는다**(2026-08-11 Ledger 개정): 정렬은 컨트롤 줄의 것이고 규모는 제목에 딸린 사실이라, 한 행에 묶으면 **읽는 값과 조작하는 값이 한 줄에서 섞인다**. 컨트롤은 컨트롤 줄에 모인다.
  - 로딩 중과 빈 창고에서는 요약을 비운다 — 페이지 머리가 최소 높이(52)를 들고 있어 아래가 밀리지 않는다.
  - **[이력] 2026-08-11 (Ledger 이식 전)**: 요약 줄과 정렬 칩이 한 행이었고 행 높이를 칩(32)이 잡았다.
  - **[이력] 2026-07-13~2026-08-10**: 필터 영역에 `총 N개`만 표시(총 무게는 제거된 상태였다). 목업 §8이 개수와 총 무게를 화면 대상 바로 아래 한 줄로 되살렸다 — 창고에서 알고 싶은 규모는 "몇 개"와 "얼마나 무거운가" 둘이고, 둘을 갈라 놓으면 어느 것도 눈에 남지 않는다.
  - 무게가 전부 미입력이면 `0kg`은 뜻이 없어 개수만 남긴다.
- 창고가 완전히 빈 상태(WH-6)에서는 필터 영역·요약 줄·정렬을 렌더하지 않는다.

### WH-3 정렬

사용자는 정렬 순서를 선택할 수 있고, 선택은 기기에 저장된다.

**수용 기준**

- 옵션은 4개: `이름순`(기본) / `가벼운순` / `무거운순` / `최근 추가순`.
- 각 옵션은 Firestore `orderBy`에 매핑된다: `name asc` / `weight asc` / `weight desc` / `createDate desc`.
- **`가벼운순`은 실제 무게 오름차순 뒤에 무게 미입력(0g)을 붙인다.** `weight: 0`은 "가장 가벼움"이 아니라 무게 미입력이고([Feed.md](Feed.md) FD-3과 같은 전제 — 대부분 의류라 오히려 무거운 제품이다), 그대로 두면 목록 맨 앞이 0g으로 채워져 정작 가벼운 장비를 볼 수 없다.
  - 구현: 이 목록은 결과를 페이지네이션 없이 한 번에 다 읽으므로, `orderBy('weight','asc')` 결과에서 **0g을 뒤로 미는 안정 분할**로 끝낸다(서버가 준 상대 순서는 유지). 피드(FD-3)가 2단 조회를 쓰는 건 Algolia 페이지 상한 때문이라 여기선 필요 없다.
  - 0g끼리의 순서는 의미가 없어 별도 정렬을 두지 않는다.
  - `무거운순`은 0g이 자연히 뒤로 가므로 손대지 않는다.
  - **적용 대상은 `GearStore.getList`를 쓰는 두 화면 — 창고 목록과 배낭 편집의 창고 리스트**([BagDetail.md](BagDetail.md) BD-4)다. 정렬 UI가 있는 화면이 이 둘뿐이다. 배낭 상세·사용 기록·공유 배낭은 `BagStore.getBag`/`getSharedBag`로 배낭에 담긴 장비를 읽는데, 이 화면들에는 정렬 선택 자체가 없어 규칙이 적용되지 않는다(BD-1).
- 선택 시 즉시 목록을 다시 읽고, `LocalStorageManager`에 `selectedOrderType_{key}`로 저장되어 재실행 후에도 유지된다.
- 정렬 진입 버튼은 **컨트롤 줄의 우측 끝**, 즉 카테고리 탭 줄과 같은 행에 둔다(2026-08-11 Ledger 개정 — 제목 블록 요약 행에서 내려왔다): 현재 옵션 이름 label 13/600(`ink`) + `chevron-down` 12(`inkTertiary`), 높이 44로 터치 타깃을 확보한다. 무엇을 볼지(좌)와 어떤 순서로 볼지(우)가 한 행에서 짝지어 읽힌다.
  - **창고는 공용 `OrderButtonView`를 쓰지 않고 `WarehouseSortView`로 직접 그린다**(면 없는 글자 + 셰브론). 원장의 컨트롤 줄에는 면이 없어 칩 면을 깐 공용 버튼이 들어올 수 없고, 공용 버튼은 아직 Liquid Depth를 쓰는 배낭 목록(BAG-1)·배낭 편집(BD-4)이 그대로 쓰고 있어 건드리지 않는다. **시트 진입 경로(`setSortSheetContext` + `/sort-sheet`)와 계측은 동일하다.**
  - **[이력] 2026-08-11 (Ledger 이식 전)**: 제목 블록 요약 행 우측에서 `OrderButtonView chip`(비선택 필터 칩과 같은 알약 면 + 0.5px 보더)을 썼다.
  - **무게 비교가 이 화면의 목적이라 `무거운순`이 칩을 누른 다음 화면에 바로 있어야 한다** — 옵션 4개가 한 시트에 평평하게 놓이고(그룹·중첩 없음) 스크롤도 필요 없다.
- 정렬 선택 UI는 **공용 네이티브 formSheet 라우트 `/sort-sheet`**로 표시한다(타이틀 `정렬` + 옵션 행, 선택 옵션은 체크·볼드; 그래버·드래그 닫기·높이는 OS 처리, `fitToContents`). 옵션 탭 시 즉시 적용 후 닫힘. 피드·탐색과 같은 라우트를 공유한다. (구 앵커드 드롭다운·커스텀 Animated 바텀시트는 폐기.)
- 정렬 기준 `name`은 캐논컬 값이다(표시 이름과 다를 수 있음) — [DataModel.md](DataModel.md) DM-3.

### WH-4 장비 상세/수정 진입

- 장비 행을 누르면 `/gear-detail/{id}`로 이동한다 → [GearDetail.md](GearDetail.md)
- 장비 **수정**은 장비 상세 화면 헤더 우상단 `수정하기`(GD-1)에서 진입한다 → `/gear-edit/{id}` → [GearEdit.md](GearEdit.md). 목록 행에는 별도 수정 진입점을 두지 않는다. `[제안]`

### WH-5 장비 삭제

사용자는 창고에서 장비를 삭제할 수 있다.

**수용 기준**

- 목록 행을 **왼쪽으로 스와이프**하면 트레일링 액션으로 `삭제`(`danger` 면 · 각진 면 그대로 · 폭 88)가 노출된다(배낭 리스트 BAG-4와 동일한 `ReanimatedSwipeable` 패턴). 스와이프 액션 버튼은 44pt 이상 히트 영역과 `accessibilityLabel`(`{이름} 삭제`)을 가진다. `[제안]`
  - **글자 `삭제`만 두고 휴지통 아이콘은 쓰지 않는다**(2026-08-11 Ledger 개정). 액션이 하나뿐인 자리에서 글리프는 `삭제`가 말하는 것을 반복할 뿐이다 — 이 화면에서 아이콘은 크롬(뒤로·검색·`+`)의 것이다.
  - 액션 면은 행과 같은 좌우 거터 안에서 끝난다 — 행이 가로 패딩을 갖지 않고 페이지 거터에 정렬하므로, 액션도 그 컬럼의 일부다.
- `삭제` 탭 → 확인 다이얼로그(`{이름}을 삭제하시겠습니까?`, 확인 버튼 `삭제하기`, 이름은 `getDisplayName()`)를 거친다. 취소하거나 스와이프를 닫으면 아무 일도 일어나지 않는다.
- 확인 시 장비 문서 삭제와 함께: 장비가 담긴 모든 배낭의 `gears`에서 제거 + 배낭 `weight` 차감 + 카탈로그 장비면 `gear-rank` count 감소([DataModel.md](DataModel.md) DM-6, DM-11).
- 완료 후 토스트 `삭제 되었습니다.`를 표시하고 목록을 갱신한다.
- 행의 기존 `⋮` 더보기 메뉴(수정/삭제 모달)는 제거한다 — 삭제는 스와이프로, 수정은 상세 화면(WH-4)으로 대체. `[제안]`

### WH-6 빈 상태

**수용 기준**

빈 상태는 **사실 + 다음 걸음 두 줄**이다. 원인마다 다음 걸음이 다르다.

- **카드로 감싸지 않고 가운데 정렬하지도 않는다**(2026-08-11 Ledger 개정) — 페이지 거터의 좌측 축에 그대로 붙인다. 가운데 정렬하면 이 화면에서 유일하게 축이 다른 블록이 되어, 원장의 정렬 규칙(좌측 정체 / 우측 수치)이 여기서만 풀린다.
- 장비가 0개이고 `전체` 필터이고 로딩 중이 아니면: `창고가 비어 있어요`(title 19/600) / `가진 장비를 하나씩 담아보세요`(body 14 `inkTertiary`) + **밑줄 텍스트 버튼** `첫 장비 담기`(WH-7과 같은 경로, 높이 44). 상단 크롬의 `+`와 같은 곳으로 가므로 **잉크 면 주 액션으로 두지 않는다** — 주 액션은 화면에 하나다.
  - **[이력] 2026-08-11 (Ledger 이식 전)**: `LiquidCard` 흰 카드 안에 가운데 정렬 두 줄 + `LiquidPillButton quiet` 알약.
- 검색어가 있고 결과가 0개면: `검색 결과가 없어요` / `이름이나 브랜드로 다시 찾아볼까요?`.
- 검색어가 없고 특정 필터 선택 결과가 0개면: `{필터명}이(가) 없어요` / `다른 카테고리를 골라볼까요?` (josa 라이브러리로 조사 처리).
- 안 쓴 장비 필터(WH-2-1) 결과가 0개면: WH-2-1의 두 줄.

### WH-7 장비 추가 진입

- 추가 버튼(상단 크롬의 `+`, WH-1): 로그인 상태면 **장비 추가 선택 시트(`gear-add-options`)** 를 연다([GearEdit.md](GearEdit.md) GE-8), 비로그인이면 로그인 모달(`LogInAlertManager`)을 띄운다.
- 선택 시트는 배낭 추가 시트(BAG-2, `bag-add-options`)와 동일한 네이티브 formSheet 패턴을 쓰며 두 갈래를 제공한다: **`검색으로 추가`**(→ **탐색 탭**으로 이동, 둘러보기+검색으로 창고 담기, GE-8) / **`직접 입력`**(`/custom` 수동 폼, GE-1/GE-3). 항목 선택 시 시트를 다음 화면으로 `replace`한다(중간 탭 리로드 노출 방지).

### WH-8 장비 검색

사용자는 창고에서 장비를 이름/브랜드로 검색할 수 있다.

**수용 기준**

- 검색 인풋은 **기본으로 감춰져 있고**, 상단 크롬의 **검색 버튼**(돋보기, `accessibilityLabel='장비 검색'`)을 눌러야 노출된다. iOS는 이 버튼과 필드를 네이티브 검색 바가 내주고(LG-3), Android·Web은 아래 필드를 쓴다.
  - Android·Web 검색 모드 진입 시: 페이지 머리가 **`LedgerField`**(공용 `components/ledger/LedgerField.tsx` — 면·모서리 없이 **하단 헤어라인만**, 높이 44, 좌측 돋보기 16 `inkQuiet`, placeholder `장비 검색` `inkQuiet`, 자동 포커스) + `취소` 버튼 행으로 바뀐다. 검색 버튼은 이 동안 숨긴다.
  - `취소`를 누르면 검색 인풋을 닫고 **검색어를 초기화**한다(페이지 머리 복귀).
  - 검색 버튼·인풋 모두 창고가 완전히 빈 상태(WH-6)에서는 렌더하지 않는다. 카테고리 탭(WH-2)은 검색 모드와 무관하게 계속 노출된다.
  - **[이력] 2026-08-11 (Ledger 이식 전)**: 공용 `LiquidSearchField`(h48 · 알약 · 블러 + 유리 채움 + 0.5px 흰 보더). 브랜드 디렉토리([Search.md](Search.md) SR-8)·브랜드 필터 시트([Feed.md](Feed.md) FD-3)는 지금도 이 컴포넌트를 쓴다.
- 입력값으로 **현재 로드된 목록을 클라이언트에서 필터**한다(추가 Firestore 조회 없음): `getDisplayName()` 또는 `getDisplayCompany()`에 검색어 포함(대소문자 무시). 카테고리 필터(WH-2)와 함께 적용된다.
- 검색 결과가 페이지 머리의 요약 줄(개수·총 무게, WH-2)에 반영된다. 결과 0개면 WH-6의 검색 두 줄.
- 인풋 우측 클리어(`close` 글리프) 버튼으로 검색어를 지운다(커스텀 버튼 1개 — 네이티브 `clearButtonMode` 미사용, 크로스플랫폼 일관). 버튼 상자는 44지만 글리프는 상자 안에서 **우측에 붙여** 페이지 우측 축을 지킨다.

## 6. 엣지 케이스

- **비로그인**: 목록을 비우고 빈 상태 표시. 로그인 상태 변화는 MobX reaction으로 감지해 자동 갱신.
- **로딩**: 초기 로드·필터/정렬 변경 시 `WarehouseSkeletonView`(카드 없이 8행 셔머 + 행 사이 헤어라인) 표시 — 도착할 원장과 같은 골격이라 로드 후 자리가 튀지 않는다. Firebase 초기화 전에는 **흰 지면만** 깐다(스피너 금지, 배경색 번쩍임 방지).
- **에러**: Firestore 조회 실패 시 빈 배열 처리(별도 에러 UI 없음). 삭제 실패는 콘솔 로그만.
- **무게 미입력(0g)**: `가벼운순`에서 실제 무게 항목 뒤로 밀린다(WH-3). `weight` 필드가 아예 없는 문서는 Firestore `orderBy('weight')` 자체에 걸리지 않아 무게 정렬에서는 목록에 나오지 않는다 — 기존 동작이며 이번 규칙의 대상이 아니다.

## 7. 수동 검증 체크리스트

- [ ] 로그인 → 창고 진입 시 장비 목록이 정렬 기본값(이름순)으로 보인다
- [ ] 필터 단일 선택 → 다른 필터로 전환, 선택 탭 재탭은 무시(해제 안 됨), `전체` 탭으로 전체 복귀. 선택 탭에만 2px 잉크 밑줄이 있다
- [ ] 검색어 입력 → 이름/브랜드 필터, 요약 줄(개수·총 무게) 반영, 결과 없으면 두 줄 빈 상태, 우측 글리프로 초기화(버튼 1개)
- [ ] Android·Web 검색 열기/닫기 → 페이지 머리 ↔ 필드가 맞교환되고 아래 탭 줄·목록이 밀리지 않는다. 검색 중에도 뒤로가기가 남는다
- [ ] iOS 검색 버튼(네이티브) 탭 → 필드가 상단 바에서 펼쳐지고(하단 툴바로 내려가지 않음) 뒤로가기가 사라지지 않는다
- [ ] 페이지 머리 → `창고` 24pt 아래 줄에 `{n}개 · {w}kg`. 정렬은 그 아래 컨트롤 줄 우측 끝에 있다. iOS 네이티브 바에 `창고` 타이틀이 중복되지 않는다
- [ ] 행 메타 → 브랜드·사용률만 ` · `로 이어지고, 둘 다 없으면 줄 자체가 없다(색상·대문자 영문 색·`[품절]` 같은 값이 섞이지 않는다)
- [ ] 카탈로그 이름에 `[품절]`이 붙은 장비 → 목록·상세·검색 어디서도 대괄호 접미가 보이지 않는다
- [ ] 안 쓴 장비 탭 → 카테고리 `전체` **바로 다음 자리**에 있고, 진입 직후 스크롤 위치에서 보인다
- [ ] 정렬 탭 → 하단 바텀시트(딤 페이드·시트 슬라이드업), 옵션 선택 체크 / 앱 재시작 후 선택 유지
- [ ] `가벼운순` → 무게가 있는 장비가 가벼운 순서로 먼저 나오고, 무게 미입력(0g) 장비는 목록 맨 뒤에 모인다 (배낭 편집의 창고 리스트도 동일)
- [ ] `무거운순` → 무거운 순서로 나오고 0g은 맨 뒤 (기존 동작 유지)
- [ ] 장비 삭제 → 담겨 있던 배낭 상세의 총 무게가 줄어든다
- [ ] 비로그인에서 추가 버튼 → 로그인 모달
- [ ] 한글 이름(`nameKorean`) 장비와 영문만 있는 장비가 모두 올바르게 표시된다
- [ ] 어느 행에도 썸네일이 없고, 모든 행의 이름이 같은 좌측 축에서 시작한다
- [ ] 무게 미입력 장비 → 우측에 `무게 없음`이 놓여 무게 컬럼의 세로 정렬이 유지된다
- [ ] 화면 전체에 카드·그림자·유리·gradient·알약이 하나도 없다. 지면이 순백 하나다
- [ ] 행 사이 헤어라인이 **좌우 인셋 없이 거터에서 거터까지** 그어지고, 목록 첫 행 위에는 선이 없다(컨트롤 줄 아래 1px 경계가 그 자리)
- [ ] 행 스와이프 → 삭제 액션이 **글자 `삭제`만**이고(휴지통 아이콘 없음) 행과 같은 거터 안에서 끝난다
- [ ] 로딩 → 카드 없이 8행 스켈레톤이 도착한 목록과 같은 자리에 서고, 스피너가 없다
- [ ] 안 쓴 장비 탭을 켠 뒤 카테고리를 바꾼다 → 밑줄 두 개(카테고리 = 잉크 / 안 쓴 장비 = 라임 계열)가 동시에 보이고 두 필터가 함께 걸린다
- [ ] 화면에서 라임 계열이 쓰이는 자리가 안 쓴 장비 탭의 선택 밑줄 하나뿐이다
- [ ] 목록 끝까지 스크롤 → 마지막 행이 화면 밑단에 붙지 않는다
- [ ] 빈 창고 / 필터 0건 / 검색 0건 / 안 쓴 장비 0건 → 각각 두 줄 문구가 원인에 맞게 나오고, 카드 없이 좌측 축에 붙는다
- [ ] 밀도 → iPhone 16 Pro(402×874)에서 두 줄 행이 9행 + 10행째 일부까지 보인다(이식 전 8행)
