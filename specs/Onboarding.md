## 1. 개요

여행(배낭)이 하나도 없는 로그인 사용자에게 **첫 진입 때 한 번**, 날짜 → 여행지 → 장비 → 완료 네 단계로 첫 여행을 만들게 돕는다.

근거(2026-10-08 지표): 가입자 중 59%가 여행을 만들지만 그중 1/3은 장비를 담지 않고 떠난다. 두 번째 여행까지 가는 사용자는 15%다. 재방문 알림(D-1 패킹 NT-2, 다음 여행 NT-7, 주말 박지 NT-8)은 **날짜가 있는 여행**을 전제로 한다 — 첫 여행을 날짜·장비와 함께 만들어야 이후의 알림이 돌아간다.

가이드는 새 데이터 구조를 만들지 않는다. 마지막에 기존 생성 경로(BAG-2 `BagStore.add`) → 여행지 저장(DST-6) → 장비 담기(BD-4 `BagStore.save`)를 순서대로 부른다.

## 2. 화면 및 진입

```
app/_layout.tsx  ─(로그인·약관 완료 + 탭 첫 도착 + 대상 판정 OB-1)→ router.push('/onboarding-trip')
app/onboarding-trip.tsx (fullScreenModal, 제스처 닫기 없음)
  → components/onboarding/OnboardingTripWrapper.tsx   (OnboardingTrip.new() 1회 생성)
    → OnboardingTripView.tsx                           (머리: 뒤로·진행 표시·닫기 / 본문 / 하단 액션)
       ├─ OnboardingTripDateStepView.tsx         1/4 언제 가세요?
       ├─ OnboardingTripDestinationStepView.tsx  2/4 어디로 가세요?  → /bag-destination-picker (DST-3, 핸드오프)
       ├─ OnboardingTripGearStepView.tsx         3/4 어떤 장비를 챙기세요?  → /search?category=… (GE-8 창고 등록)
       └─ OnboardingTripDoneStepView.tsx         4/4 완료 → 생성 → router.replace('/bag/{id}')
```

- 전역 상태(대상 판정·노출 기록)는 `model/onboarding/OnboardingTripManager.ts`(`app.getOnboardingTripManager()`), 단계·입력·생성은 화면 도메인 `model/onboarding/OnboardingTrip.ts`가 가진다.
- 딥링크로는 열지 않는다(공개 진입점 없음). 조건이 맞을 때 레이아웃이 한 번 띄운다.

## 3. 요구사항

### OB-1 대상과 1회 노출 `[제안]`

**수용 기준**

- 대상 = **로그인 + 필수 약관 동의 완료(AU-3) + 여행 0개**인 사용자. 신규 가입자와 기존 사용자를 가리지 않는다. 비로그인 사용자는 대상이 아니다.
- 여행 개수는 노출 직전에 `users/{uid}.bags` 길이로 **새로 읽는다**(1회 읽기, `BagStore.getBagCountOrThrow`). 다른 기기·딥링크(박지 상세 `새 여행 만들기` 등)로 이미 여행을 만들었다면 이 읽기에서 걸러진다.
- 노출 기록은 **기기 로컬 AsyncStorage**에 사용자별로 저장한다 — 키 `onboarding-first-trip_{uid}`, 값 `{ status, at }`(APP-6). `status`는 `presented`(띄움) · `dismissed`(닫음) · `completed`(만듦) · `not_needed`(판정 때 이미 여행 있음).
  - **기록이 하나라도 있으면 다시 띄우지 않는다.** 띄우는 순간 `presented`를 먼저 쓴다 — 도중에 앱이 종료돼도 다음 실행에 다시 뜨지 않는다(한 번만 노출).
  - 판정 때 여행이 1개 이상이면 `not_needed`를 남긴다 — 나중에 여행을 모두 지워 0개가 돼도 다시 띄우지 않는다("다른 방법으로 여행을 만든 적이 있으면 다시 보지 않는다").
- 판정은 **세션당 uid마다 1회**다. 로그아웃 후 다른 계정으로 로그인하면 그 uid로 다시 판정한다(키가 uid별이라 서로 섞이지 않는다).
- 여행 개수 읽기가 실패하면(오프라인 등) **이번 세션에는 띄우지 않고 기록도 남기지 않는다** — 다음 실행에 다시 판정한다. 빈 목록으로 오인해 여행이 있는 사용자에게 가이드를 띄우지 않는다.
- 웹도 같다(아래 플랫폼 분기). 웹은 알림이 없어 완료 단계의 권한 요청만 빠진다.

### OB-2 진입 시점과 오버레이 우선순위 `[제안]`

**수용 기준**

- 판정·노출은 초기화(APP-1) 이후, **로그인 + 약관 동의 상태로 메인 탭(`(tabs)`)에 처음 도착했을 때** 일어난다. 약관 화면(`/terms-agreement`)·딥링크로 연 다른 화면 위에서는 띄우지 않고, 그 사용자가 탭으로 돌아오면 그때 판정한다.
- 우선순위(한 번에 하나만):

  ```
  강제 업데이트 게이트(APP-7)  >  약관 동의(AU-3)  >  첫 여행 가이드(OB)  >  신기능 팝업(FP)  >  텍스트 공지(AN)
  ```

  - 게이트는 absolute 전체 화면이지만 가이드는 네이티브 모달이라 게이트를 덮을 수 있다. 그래서 **게이트 판정이 끝난 뒤**(`ForceUpdateManager.isResolved()` — 성공·실패·웹 no-op 모두 true)에만 판정하고, 게이트 대상이면(`getNeedsUpdate()`) 띄우지 않는다.
  - 약관 미동의 로그인 사용자는 가이드 판정 자체를 하지 않는다(위 조건). **약관 화면에서는 신기능 팝업·공지도 띄우지 않는다**(`OnboardingTripManager.isBlockingPopups()` — 로그인 + 미동의면 true).
  - 신기능 팝업(FP-2)·공지(AN-2)는 **가이드 판정이 끝나기 전**(로그인·동의 사용자가 아직 탭에 도착하지 않았거나 판정 중)과 **가이드가 떠 있는 동안** 표시하지 않는다. 가이드를 닫거나 끝내면 다음 렌더에 원래 규칙대로 뜬다(공지·팝업의 닫음 정책은 그대로).
  - 비로그인 사용자에게는 영향이 없다(팝업·공지 기존 동작 그대로).

### OB-3 단계 구조와 이탈 `[제안]`

**수용 기준**

- 화면은 `fullScreenModal` 라우트다. 배경 순백(`Acg.paper`), 좌우 패딩 24(`AcgLayout.screenPadding`), 세이프에어리어를 지킨다. iOS 스와이프 닫기는 끈다(`gestureEnabled: false`) — 입력이 쌓인 화면이 실수로 닫히지 않게 한다.
- **머리(고정)**: 왼쪽 `뒤로`(2~4단계, chevron, `accessibilityLabel='이전 단계'`), 가운데 **진행 표시**(4칸 막대 — 지난·현재 칸은 잉크, 남은 칸은 `Acg.controlFill`; 접근성 라벨 `4단계 중 {n}단계`), 오른쪽 **닫기 ×**(`accessibilityLabel='가이드 닫기'`). 버튼은 모두 44×44 이상.
- **본문**: 단계 제목 22/28 semibold(`AcgType.screenTitle`) + 부제 한 줄(`AcgType.body`, `Acg.textMuted`) + 단계 내용.
- **하단(고정)**: 주 액션 라임 알약 **하나**(`Acg.lime` 면 + 잉크 글자, 높이 52 이상, `minHeight`) + 그 아래 보조 텍스트 버튼 하나(그 단계의 `건너뛰기`). 라임은 단계마다 이 버튼 하나뿐이다(HM-8).
- **건너뛰기**는 1~3단계 모두에 있다 — 그 단계 입력 없이 다음 단계로 간다. 1단계는 건너뛰기와 `아직 미정`이 같은 결과라 버튼 문구를 `아직 미정이에요`로 쓴다(OB-4). 4단계의 보조 버튼은 권한 요청을 건너뛰는 `알림 없이 만들기`다(OB-7).
- **닫기 ×**: 1단계에서 아무것도 고르지 않았으면 바로 닫는다. 그 밖에는 확인 알럿(`가이드를 닫을까요?` / `지금까지 고른 내용으로 여행이 만들어지지 않아요.` · `계속하기` / `닫기`(destructive)) 뒤 닫는다. 닫으면 `dismissed`를 기록한다(OB-1).
- **안드로이드 하드웨어 뒤로**: 2~4단계는 이전 단계, 1단계는 닫기 ×와 같다. 생성 중에는 무시한다.
- 뒤로 갔다 다시 와도 이전 단계 입력(날짜·여행지·선택한 장비)은 유지된다.

### OB-4 1단계 — 언제 가세요? `[제안]`

**수용 기준**

- 제목 `언제 가세요?` / 부제 `날짜를 정하면 출발 하루 전에 패킹을 알려 드려요`.
- 기존 범위 선택 캘린더(`DateRangeCalendarView`, BAG-2 선택 규칙 그대로)를 **펼친 채로** 쓴다(`alwaysOpen` — 이 단계의 유일한 입력이라 접을 이유가 없다). 기본값은 없음(시작·종료 모두 미선택). 오늘 이전 날짜도 막지 않는다(기존 캘린더와 같다).
- 시작일만 고른 상태는 하루 여행으로 보지 않는다 — 종료일까지 골라야(같은 날을 두 번 누르면 당일) `다음`이 켜진다. 꺼진 동안은 비활성 표시 + `accessibilityState.disabled`.
- 보조 버튼 `아직 미정이에요` = 이 단계의 건너뛰기. 여행은 **날짜가 필수**라(BAG-2·DM-5 — `BagStore.add`가 기간을 받는다) 미정이면 **기존 즉시 생성 기본값(다가오는 주말 1박, `getUpcomingWeekend`)** 으로 만든다. 완료 단계에서 이 사실과 "날짜를 바꾸면 그 날짜 기준으로 알려 드린다"를 알린다(OB-7).

### OB-5 2단계 — 어디로 가세요? `[제안]`

**수용 기준**

- 제목 `어디로 가세요?` / 부제 `여행지를 정하면 그 기간 날씨를 함께 보여 드려요`.
- 본문은 여행지 면 하나(연회색 채움 + 모서리 12, 그림자 없음, 최소 높이 72, 우측 셰브론):
  - 미선택: `여행지를 골라 주세요`(잉크) + 메타 `박지 검색 · 지도에서 고르기`.
  - 선택됨: `{여행지명}` + 메타(박지 연결이면 `박지`, 자유 위치면 `직접 고른 위치`). 탭하면 다시 고를 수 있다.
- 면 탭 또는 주 액션 → **공용 여행지 선택기(DST-3, `/bag-destination-picker`)** 를 핸드오프로 연다. `currentLocation`은 이 단계에서 고른 값, `onConfirm`은 **값을 가이드 상태에만 담는다**(Firestore 쓰기 없음 — 여행이 아직 없다). 박지 상세 시트의 `여행지로 설정` CTA도 같은 `onConfirm`을 지난다(DST-3).
- 주 액션 문구는 미선택이면 `여행지 고르기`(선택기 열기), 선택됨이면 `다음`.
- 날씨는 생성 시 기존 저장 경로(DST-6 `saveBagDestination`)가 자동으로 조회·저장한다. 날씨 조회 실패는 생성을 막지 않는다(DST-6 — 상세 여행지 화면에서 다시 시도).
- 보조 버튼 `건너뛰기` → 여행지 없이 다음 단계.

### OB-6 3단계 — 어떤 장비를 챙기세요? `[제안]`

**수용 기준**

- 제목 `어떤 장비를 챙기세요?`. 이 단계에 처음 들어올 때 창고(`users/{uid}/gears`, 최근 추가순)를 읽고, 그 결과로 **모드를 한 번 정한다**(단계 안에서 모드가 바뀌지 않는다).
- **창고에 장비가 있으면 — 체크리스트 모드**
  - 부제 `창고에서 이번 여행에 챙길 장비를 골라 주세요`.
  - 창고 장비를 1차 카테고리로 묶어 섹션 머리(`AcgSectionHeaderView`, 카테고리 표시명 + 부제 `{n}개`)를 둔다. 순서는 필수 4종을 먼저 — 텐트·침낭·매트·배낭·의류·조리·랜턴·가구·전자기기·음식·기타. 장비가 없는 카테고리는 섹션을 그리지 않는다.
  - 행은 창고 행(`GearView`, WH-1 — 이름 + `무게 · 브랜드` 메타)을 그대로 쓰고 우측에 원형 체크 배지(편집 화면 BD-4와 같은 모양)를 둔다. 행 전체가 토글 대상이고 `accessibilityRole='checkbox'` + `accessibilityState.checked`.
  - 기본 선택은 없다.
- **창고가 비어 있으면 — 필수 장비 검색 모드**
  - 부제 `백패킹 필수 장비부터 찾아 담아 보세요. 고른 장비는 창고에도 저장돼요`.
  - 필수 카테고리 4행: `텐트` · `침낭` · `매트` · `배낭`. 행 = 카테고리명 + 메타(담은 게 없으면 `검색해서 담기`, 있으면 `{첫 장비 이름} 외 {n}개`) + 우측 셰브론. 연회색 면 행(최소 높이 72).
  - 행 탭 → 장비 검색 모달 `/search?category={그룹 키}`(GE-8 **창고 컨텍스트** — 창고 등록만, 배낭 담기 모달 없음)를 그 카테고리 필터로 연다. `category` 파라미터는 검색 모달 피드의 1차 카테고리 초기값이다(재조회 없이 첫 로드에 적용).
  - 검색 모달을 닫고 돌아오면(포커스) 창고를 다시 읽고, **이 단계 진입 이후 새로 창고에 들어온 장비를 자동 선택**한다. 담은 장비는 해당 카테고리 행 아래에 체크 행으로 보여 빼거나 다시 넣을 수 있다.
  - 검색에서 등록한 장비는 가이드를 닫아도 **창고에 남는다**(GE-8 등록은 즉시 반영) — 여행 생성과 무관한 사용자 데이터라 되돌리지 않는다.
- 상단 요약 한 줄: `{n}개 · {총 무게}kg`(선택이 0이면 숨김). 총 무게 = 선택 장비 `weight`(g) 합 ÷ 1000, 소수 둘째 자리.
- 창고 읽기 실패: 빈 창고로 오인하지 않는다 — 안내(`장비를 불러오지 못했어요`) + `다시 시도`, 건너뛰기는 그대로 가능.
- 주 액션 `다음`(선택 0개여도 켜짐 — 0개로 다음은 건너뛰기와 같은 결과지만 action 값은 `next`), 보조 `건너뛰기`(선택을 비우고 다음 단계).

### OB-7 4단계 — 완료와 생성 `[제안]`

**수용 기준**

- 제목 `여행을 만들 준비가 됐어요`.
- 요약 면(연회색 채움 + 모서리 12): 여행 이름(`AcgType.rowTitle` medium) + 메타 한 줄 `{총 무게}kg · {기간} · {여행지}`(없는 조각은 뺀다 — 숫자 맨 앞, HM-8). 기간은 BAG-1 표시 규칙, 미정이면 `{기간} (임시)`.
- **여행 이름 자동**: 여행지가 있으면 `{여행지명} 백패킹`, 없으면(또는 여행지명이 역지오코딩 폴백 `선택한 위치`면) `첫 백패킹`. 이름은 만든 뒤 상세(BD-1)에서 고친다 — 이 화면에서 입력받지 않는다(BAG-2의 "생성 단계에서 묻지 않는다" 결정과 같다). 보조 문장 `이름과 날짜는 여행에서 언제든 바꿀 수 있어요`.
- 안내 문장:
  - 날짜를 고른 경우 `출발 하루 전에 패킹을 알려 드릴게요` (NT-2).
  - 미정(OB-4)이면 `날짜는 이번 주말로 잡아 뒀어요. 날짜를 바꾸면 그 날짜에 맞춰 알려 드릴게요`.
- **주 액션**(라임):
  - 알림 권한이 **미결정**(네이티브 `getPermissionsAsync().status === 'undetermined'`)이면 `알림 받고 여행 만들기` → OS 권한 요청(OB-8) → 결과와 무관하게 생성.
  - 이미 허용·거부됐거나 웹이면 `여행 만들기` → 바로 생성. **이미 결정된 권한은 다시 묻지 않는다.**
- 보조 버튼 `알림 없이 만들기`(권한 미결정일 때만) → 권한을 묻지 않고 생성.
- **생성은 이 단계의 버튼을 누를 때 한 번에 한다**(중간 단계에서는 Firestore에 아무것도 쓰지 않는다) — 건너뛰기·닫기·앱 종료 어느 경우에도 반쯤 만든 여행이 남지 않는다.
  1. `BagStore.add(이름, 시작일, 종료일)` — BAG-2와 같은 문서(`weight: 0`, `gears: []`) + `users/{uid}.bags` arrayUnion + NT-2·NT-3 예약 + NT-9 동기화. **권한 요청 뒤에 부르므로** 방금 허용한 권한으로 D-1 알림이 바로 예약된다.
  2. 여행지가 있으면 `saveBagDestination`(DST-6) — 위치 저장 + 기간 날씨 조회·저장.
  3. 장비가 있으면 `BagStore.save(id, 선택 장비, [], 선택 장비)`(BD-4 저장과 같은 트랜잭션 — 무게 합·장비의 `bags` 역참조 갱신).
  4. 기록 `completed`(OB-1) → `router.replace('/bag/{id}')`.
- 생성 중에는 두 버튼을 비활성화하고 주 액션에 로딩을 표시한다(연타 방지). 머리의 뒤로·닫기도 막는다.
- **1단계(add)가 실패하면** 알럿(`여행을 만들지 못했어요` / `잠시 후 다시 시도해 주세요.`) 후 이 단계에 머문다 — 다시 누르면 다시 시도한다.
- **add는 성공하고 2·3단계가 실패하면** 이미 만든 여행 ID를 보관하고(재시도해도 여행이 두 개 생기지 않는다) 그 여행 상세로 이동한 뒤 알럿으로 알린다(`여행은 만들었지만 일부를 저장하지 못했어요` / `여행에서 여행지와 장비를 다시 확인해 주세요.`). BAG-2 박지 경로(`bag-new`)와 같은 판단 — 생성된 여행을 두고 폼에 머물면 중복 생성된다.
- 날씨 조회 실패(DST-6 `weatherFailed`)는 오류로 보지 않는다 — 상세 여행지 화면이 `다시 시도`를 제공한다.

### OB-8 알림 권한 — 맥락 요청 `[제안]`

이 가이드의 완료 단계가 **앱의 첫 알림 권한 요청 자리**가 된다. NT-1의 시작 시 요청과 겹치지 않게 다음과 같이 나눈다([Notification.md](Notification.md) NT-1 개정).

**수용 기준**

- 앱 시작 시 일괄 요청(NT-1)은 **로그인 + 약관 동의 + 가이드 판정이 끝난 뒤**에만 일어나고, **이번 세션에 가이드를 띄웠으면 건너뛴다** — 가이드 사용자는 완료 단계에서 처음 묻는다.
- 두 경로 모두 OS 상태가 **미결정(`undetermined`)일 때만** 권한 대화상자를 띄운다. 허용·거부가 이미 정해졌으면 묻지 않는다(안드로이드 13+에서 한 번 거부해도 `canAskAgain`이 true라 다시 뜨던 것을 막는다) — **어떤 사용자도 두 번 묻지 않는다.**
- 가이드에서 권한을 묻지 않고 끝낸 경우(`알림 없이 만들기`·닫기·도중 종료) 다음 콜드 스타트의 시작 시 요청(NT-1)이 그대로 적용된다 — 모든 사용자가 정확히 한 번은 질문을 받는다.
- 가이드에서 허용하면 시작 시 요청이 하던 후속 처리(공지 토픽 `all` 구독 — 설정이 켜져 있으면, NT-9 동기화)를 그 자리에서 한다.
- 웹은 no-op(완료 단계 문구가 `여행 만들기`로 바뀐다).

### OB-9 분석 `[제안]`

**수용 기준** — [Analytics.md](Analytics.md) AN-3 `온보딩` 표가 정본이다.

- `click_onboarding_trip_step` — 각 단계의 주 액션·보조 버튼. `step`: `date` \| `destination` \| `gear` \| `done`, `action`: `next` \| `skip`.
  - 1단계 `아직 미정이에요`는 `skip`, 2단계 미선택 상태의 `여행지 고르기`는 선택기만 열 뿐이라 보내지 않는다(선택 뒤의 `다음`이 `next`).
  - 4단계 주 액션은 `next`, `알림 없이 만들기`는 `skip`.
- `click_onboarding_trip_complete` — 생성 성공(add 성공 기준). `has_dates`(boolean — 미정이면 false), `has_destination`(boolean), `gear_count`(정수), `notification`: `granted` \| `denied` \| `skipped`(묻지 않음) \| `already`(이미 결정됨) \| `unavailable`(웹).
- `click_onboarding_trip_dismiss` — 닫기 확정. `step`: 닫은 단계.
- 화면 조회는 라우트(`onboarding-trip`) `screen_view`로 자연 수집된다(AN-2).
- 여행 이름·여행지명·장비 이름 같은 사용자 입력은 보내지 않는다.

### OB-10 디자인·접근성 `[제안]`

**수용 기준**

- HM-8 문법: 순백 지면, 면은 연회색 채움 + 모서리 12, **그림자 없음**(하단 라임 알약도 화면에 고정된 액션이라 그림자를 두지 않는다 — 콘텐츠 위에 떠 있지 않다), 행 사이 헤어라인, 라임은 단계당 주 액션 하나.
- 텍스트는 모두 `PretendardText`(weight prop) + `AcgType` 세트 토큰. 무게 숫자만 `AcgDisplayText`.
- 글자를 담는 컨트롤은 `minHeight + 세로 패딩`(Dynamic Type). 터치 타깃 44×44 이상.
- 아이콘 전용 컨트롤(뒤로·닫기)에 `accessibilityRole='button'` + `accessibilityLabel`. 단계 제목은 `accessibilityRole='header'`.
- 문구는 존댓말, 짧게. 모든 UI 문구는 `onboarding.*` l10n 키(ko·en·ja 동수)로 둔다(L10N-3).

## 4. 데이터

- Firestore 계약 변경 없음 — 생성은 BAG-2·DST-6·BD-4의 기존 쓰기를 그대로 쓴다([DataModel.md](DataModel.md) DM-5·DM-15).
- 기기 로컬 AsyncStorage `onboarding-first-trip_{uid}` = `{ status: 'presented' | 'dismissed' | 'completed' | 'not_needed', at: ISO 문자열 }`(APP-6). 서버에 동기화하지 않는다.
- 검색 모달 `/search`에 선택 파라미터 `category`(GearFilter 그룹 키) 추가 — 피드 1차 카테고리 초기값(OB-6). 다른 진입점은 영향 없음.

## 6. 엣지 케이스

- **비로그인**: 대상 아님. 로그인하고 약관까지 마친 뒤 탭에 도착하면 그때 판정한다.
- **오프라인**: 판정 읽기 실패 → 이번 세션 미노출·미기록. 생성 실패 → 알럿 후 머무름(OB-7). 창고 읽기 실패 → 3단계 다시 시도(OB-6).
- **도중 중단·앱 종료**: 띄울 때 `presented`를 기록하므로 다시 뜨지 않는다. 중간 단계에서 Firestore에 쓰지 않으므로 반쯤 만든 여행이 남지 않는다. 검색으로 창고에 등록한 장비만 남는다(의도된 동작 — 사용자의 장비다).
- **가이드가 뜬 사이 다른 경로로 여행을 만듦**: 가이드는 전체 화면 모달이라 다른 생성 경로에 닿을 수 없다. 딥링크(알림 탭 등)로 다른 화면이 위에 쌓여 그곳에서 여행을 만들어도, 가이드로 돌아와 완료하면 여행이 하나 더 생길 뿐 데이터는 깨지지 않는다(수용).
- **딥링크 콜드 스타트**: 탭이 아닌 화면으로 열리면 그 화면 위에 가이드를 띄우지 않는다. 사용자가 탭으로 오면 판정한다(그때 이미 여행이 있으면 `not_needed`).
- **여러 기기**: 기록이 기기 로컬이라 A 기기에서 닫아도 B 기기에서 한 번 더 볼 수 있다. A에서 여행을 만들었다면 B는 판정 읽기에서 걸러진다(수용).
- **다른 계정으로 재로그인**: uid별 키라 각 계정이 따로 판정된다. 같은 세션 안에서도 uid가 바뀌면 다시 판정한다.
- **가이드 도중 로그아웃**: 가이드 안에는 로그아웃 경로가 없다. 다른 기기에서 계정을 지우는 등으로 세션이 끊기면 생성이 실패 알럿으로 끝난다.
- **장비가 아주 많은 창고**: 체크리스트는 가상화 목록(`SectionList`)으로 그린다.
- **같은 날 하루 여행**: 캘린더에서 같은 날을 두 번 누르면 당일 여행(시작=종료)이다(기존 캘린더 규칙).

## 7. 수동 검증 체크리스트

- [ ] 여행 0개인 신규 계정으로 로그인 → 약관 동의 → 홈 도착 시 가이드가 뜬다. 여행이 있는 계정은 뜨지 않고 기록이 `not_needed`.
- [ ] 가이드를 닫고 앱 재시작 → 다시 뜨지 않음. 1단계에서 앱을 강제 종료 후 재시작 → 다시 뜨지 않음.
- [ ] 가이드가 떠 있는 동안 신기능 팝업·공지가 뜨지 않고, 닫으면 뜬다. 약관 화면 위에도 팝업·공지가 뜨지 않는다.
- [ ] 강제 업데이트 게이트 대상 버전에서는 가이드가 뜨지 않는다.
- [ ] 1단계: 종료일까지 골라야 `다음`이 켜짐 / `아직 미정이에요` → 4단계에 `(임시)` 기간과 이번 주말 안내.
- [ ] 2단계: 선택기에서 자유 위치·박지(상세 시트 CTA 포함) 선택 → 이 단계로 돌아와 이름 표시, 주 액션이 `다음`으로 바뀜. Firestore에 쓰기 없음.
- [ ] 3단계(창고 있음): 카테고리별 체크리스트, 선택 수·총 무게 갱신. (창고 없음): 4행 → 검색 모달이 해당 카테고리 필터로 열림 → 담고 돌아오면 자동 선택.
- [ ] 4단계: 이름 `{여행지명} 백패킹`/`첫 백패킹`, 메타 무게·기간·여행지. 권한 미결정이면 `알림 받고 여행 만들기` → OS 권한 → 여행 상세로 이동. 상세에서 여행지·날씨·장비·무게 확인.
- [ ] 권한이 이미 결정된 기기에서는 권한 대화상자가 뜨지 않고 버튼 문구가 `여행 만들기`.
- [ ] 가이드를 거친 신규 사용자는 앱 시작 시 권한 대화상자가 **뜨지 않는다**(완료 단계에서만). `알림 없이 만들기` 후 다음 콜드 스타트에 한 번 뜬다.
- [ ] 생성 버튼 연타 → 여행 1개만 생김. 비행기 모드에서 생성 → 실패 알럿 후 머무름.
- [ ] 안드로이드 하드웨어 뒤로: 2~4단계는 이전 단계, 1단계는 닫기.
- [ ] VoiceOver/TalkBack: 뒤로·닫기·진행 표시·체크 행이 라벨로 읽힘. 큰 글자에서 버튼이 잘리지 않음.
- [ ] GA4 DebugView(`EXPO_PUBLIC_ANALYTICS_DEV_COLLECTION=1`): 단계마다 `click_onboarding_trip_step`(step·action), 완료 시 `click_onboarding_trip_complete`, 닫기 시 `click_onboarding_trip_dismiss`.
- [ ] 웹: 가이드가 뜨고 여행지(카카오 검색)·장비 검색·생성이 동작, 권한 문구 없음.

## 8. 결정 사항 / 미해결 질문

**결정됨 (2026-10-08 구현 시 판단)**

- 생성 시점: **완료 단계에서 한 번에**. 단계별로 만들면 건너뛰기·닫기마다 지울지 남길지를 정해야 하고, 남기면 빈 여행이 생긴다(BD-13이 줄이려는 그것).
- 날짜 미정: 여행은 날짜가 필수라 **이번 주말 기본값**(BAG-2와 같은 값)으로 만들고 완료 단계에서 알린다.
- 1단계 건너뛰기 문구는 `아직 미정이에요`(같은 결과의 버튼 둘을 두지 않는다).
- 4단계에는 `건너뛰기`가 아니라 `알림 없이 만들기`를 둔다 — 이 단계에서 건너뛸 수 있는 것은 권한 요청뿐이다. 만들지 않고 나가려면 닫기 ×.
- 노출 기록은 띄우는 순간 남긴다(도중 종료 시 다시 띄우지 않는다 — "한 번만"을 우선).
- 웹 포함.
- 창고 비어 있음 모드의 검색은 **창고 컨텍스트**(배낭 담기 아님)다 — 여행이 아직 없어 배낭 컨텍스트(`bagId`)를 쓸 수 없다. 돌아와서 새 장비를 자동 선택해 같은 결과를 낸다.

**미해결**

- 가이드를 거치지 않은(닫은) 사용자에게 배낭 탭 빈 상태에서 가이드를 다시 열 진입점을 둘지.
- 노출 기록을 사용자 문서(Firestore)로 옮겨 기기 간 1회로 만들지(현재 기기 로컬).
