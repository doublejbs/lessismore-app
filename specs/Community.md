## 1. 개요

커뮤니티는 장비를 고르기 전 궁금한 점을 나누고, 실제 배낭을 사용한 경험을 공유하며, 간단한 선택을 다른 사용자에게 묻는 공간이다. 범용 SNS가 아니라 **아웃도어 장비와 배낭 경험을 중심으로 한 대화**에 집중한다.

MVP의 게시글 유형은 `게시글` · `배낭 후기` · `투표` 세 가지다. 모든 유형은 사진을 선택적으로 첨부할 수 있다. 사진은 커뮤니티 게시글을 설명하는 공개 UGC이며, 본인 장비에만 비공개로 표시하는 장비 사진([DataModel.md](DataModel.md) §1)과 저장·노출 정책을 분리한다.

**MVP에서 제외**: 영상, 익명 게시글, 팔로우·팔로워, 개인 메시지, 해시태그, 북마크, 사용자 프로필 피드, 인기순·개인화 추천, 댓글 사진, 푸시 알림, 게시글 외부 웹 공유, 자동 콘텐츠 필터, 공개 전 사전 검수, 사용자 차단, 별도 운영자 도구.

## 2. 화면 및 진입

```text
app/(tabs)/community.tsx → CommunityWrapper → CommunityView
                                              ├─ 유형 필터: 전체 / 게시글 / 배낭 후기 / 투표
                                              ├─ 최신순 게시글 피드
                                              └─ 작성 버튼

app/community-write-options.tsx → 글쓰기 유형 선택 시트

app/community/write.tsx → CommunityWriteWrapper → CommunityWriteView
                                                    ├─ 게시글 / 배낭 후기 / 투표 입력
                                                    ├─ CommunityWriteImagesView: 사진 선택·순서 변경
                                                    ├─ CommunityWriteBagSelectView: 배낭 스냅샷 선택
                                                    └─ CommunityWritePollOptionsView: 투표 선택지·마감 입력

app/community/[id].tsx → CommunityDetailWrapper → CommunityDetailView
                                                   ├─ 게시글 본문·사진·배낭 스냅샷·투표
                                                   ├─ CommunityDetailPostHeaderView
                                                   ├─ CommunityDetailBagSnapshotView
                                                   ├─ CommunityDetailBagGearListView
                                                   ├─ CommunityDetailPollView
                                                   ├─ CommunityDetailPostActionsView
                                                   ├─ CommunityDetailCommentRowView
                                                   ├─ CommunityDetailCommentComposerView
                                                   └─ CommunityDetailReportMenu

app/community/[id]/edit.tsx → 본인 게시글 수정
```

Expo Router는 정적 세그먼트 `community/write`를 동적 세그먼트 `[id]`보다 우선 매칭하므로 `/community/write`와 `/community/{id}`가 공존해도 작성 라우트가 상세 라우트에 흡수되지 않는다. 루트 `app/_layout.tsx`의 등록 이름은 실제 파일 경로인 `community/write`, `community/[id]`, `community/[id]/edit`와 일치한다.

- 하단 탭은 `홈 / 탐색 / 지도 / 배낭 / 커뮤니티` 다섯 개를 유지한다([AppLifecycle.md](AppLifecycle.md) APP-9).
- 기존 `내 정보`는 홈 우측 상단 프로필 버튼에서 `/info`로 진입한다([Auth.md](Auth.md) AU-9).
- 커뮤니티 열람은 로그인하지 않아도 가능하다. 작성·좋아요·댓글·투표·신고는 로그인 후 가능하다.

## 3. 요구사항

### CM-1 커뮤니티 피드 `[제안]`

사용자는 게시글·배낭 후기·투표를 한곳에서 정렬해 둘러볼 수 있다.

**수용 기준**

- 상단 제목은 `커뮤니티`이고, 아래에 `전체 / 게시글 / 배낭 후기 / 투표` 필터를 둔다. 필터는 공용 `CategoryChipView` 문법을 따른다.
- 기본은 `전체`, 정렬은 `최신순`(`createdAt desc`)이다. `인기순`(`likeCount desc`, 동률은 `createdAt desc`)도 선택할 수 있다.
- 정렬 UI는 배낭 탭(BAG-6)과 같은 필터 칩 행 우측 정렬 드롭다운과 공용 `/sort-sheet`를 사용한다. 선택은 `LocalStorageManager`의 `selectedOrderType_communityFeed`에 저장하며 창고·배낭과 공유하지 않는다. 정렬 변경 시 첫 페이지부터 재조회한다.
- 최초 20개를 읽고 목록 끝에서 다음 20개를 불러온다. 당겨서 새로고침하면 첫 페이지부터 다시 읽는다.
- 카드에는 작성자 닉네임·작성 시각(두 줄), 제목, 본문 미리보기, 대표 사진, 좋아요 수, 댓글 수를 표시한다.
- 배낭 후기는 배낭 이름·총 무게·장비 수 요약을, 투표는 선택지 수·총 참여 수·마감 상태를 카드에 추가한다.
- 사진이 없거나 로드에 실패하면 빈 이미지 자리·깨진 아이콘을 남기지 않고 텍스트 카드로 표시한다.
- `published`가 아닌 게시글은 피드에 나타나지 않는다.
- 조회 오류 상태에서는 빈 상태와 섞지 않고 `게시글을 불러오지 못했어요`와 `다시 시도`만 표시한다. 오류 원인은 개발자 로그에 남기며, 정상적으로 조회된 게시글이 0건인 경우에만 빈 상태 문구 `아직 게시글이 없어요`와 유도 문구 `첫 번째 게시글을 남겨보세요`를 표시한다.
- 게시글이 있거나 정상 빈 상태이거나 조회 오류인 모든 비스켈레톤 상태에서 `글쓰기` 알약을 노출해 첫 글 작성을 유도한다. 글쓰기 알약 위치·크기는 배낭 탭 `배낭 추가`([Bag.md](Bag.md) BAG-1)와 동일하다.

### CM-2 작성 진입과 게시글 유형 `[제안]`

사용자는 커뮤니티에서 주 액션 하나로 새 게시글 작성을 시작할 수 있다.

**수용 기준**

- 커뮤니티 화면에 `글쓰기` 주 액션을 하나만 둔다. 탭하면 `게시글 / 배낭 후기 / 투표`를 고르는 시트를 연다.
- 비로그인 사용자가 작성에 진입하면 전역 로그인 모달을 열고, 로그인 완료 후 선택한 작성 흐름으로 돌아온다.
- 작성자는 익명으로 게시할 수 없고 현재 닉네임이 표시된다. 작성 화면 본문 상단에는 `작성자: <닉네임>` 한 줄만 두고 **게시글 유형 라벨(`게시글`·`배낭 후기`·`투표`)은 표시하지 않는다** — 유형은 폼 구성(배낭 선택·선택지)으로 드러나고, 라벨은 iOS 투명 헤더의 뒤로 버튼과 겹쳐 읽히지 않았다(2026-09-03). Android 커스텀 헤더도 제목 한 줄만 두고 부제를 두지 않는다.
- 모든 유형은 제목이 필수이며 앞뒤 공백을 제거한 뒤 2~80자다.
- 본문은 게시글·배낭 후기에서 필수(10~5,000자), 투표에서는 선택(최대 5,000자)이다.
- 등록 중에는 입력과 등록 버튼을 잠가 중복 생성을 막는다. 실패하면 입력과 선택한 사진을 유지한다.
- 화면을 나갈 때 작성 내용이 있으면 `작성 중인 내용을 버릴까요?` 확인을 거친다.

### CM-3 일반 게시글 `[제안]`

제목과 본문으로 자유롭게 작성하는 기본 유형(질문·정보·잡담 포함)이다.

**수용 기준**

- 제목과 본문으로 작성하며 사진은 선택이다.
- 별점·정답 채택·장비 카탈로그 연결은 MVP에 두지 않는다.
- 일반 게시글은 다른 유형과 같은 댓글·답글·좋아요·신고 기능을 사용한다.

### CM-4 배낭 후기와 스냅샷 `[제안]`

사용자는 자신의 기존 배낭을 선택해 실제 사용 후기를 남길 수 있다.

**수용 기준**

- 로그인 사용자의 배낭 목록에서 배낭 하나를 반드시 선택한다. 배낭이 없으면 `먼저 배낭을 만들어주세요`와 배낭 생성 진입점을 표시한다.
- 등록 시점의 배낭 이름, 여행 날짜, 여행지의 표시 이름, 총 무게, 장비 수, 장비별 브랜드·이름·무게·카테고리를 **텍스트 스냅샷**으로 저장한다([DataModel.md](DataModel.md) DM-28).
- 등록 박지(`bag.location.campSpotId`)로 연결된 여행지는 공개 박지 ID(`campSpotId`)를 함께 저장하고, 날씨 캐시가 있으면 여행 기간 안의 일자만 `locationName`·날씨 코드·최고/최저기온으로 복사한다. 자유 위치의 좌표와 날씨 캐시의 좌표·조회 시각·출처·강수·풍속은 저장하지 않는다.
- 원본 배낭을 나중에 수정·삭제해도 이미 작성한 후기의 스냅샷은 바뀌지 않는다.
- 정확한 좌표, 이동 경로, 건강 활동, 메모, 개인 장비의 `imageUrl`, 사용자 정의 장비 ID는 포함하지 않는다.
- 다른 사용자는 스냅샷의 장비 목록을 볼 수 있지만 원본 배낭 편집 화면으로 이동할 수 없다.
- 스냅샷은 연회색 요약 카드(모서리 12, 패딩 16, 그림자 없음)와 카드 밖 순백 지면의 장비 목록으로 나눠 표시한다. 카드에는 `다녀온 배낭` 라벨, 배낭 이름, `YYYY.MM.DD` 날짜(같은 날은 한 번만)·여행지 메타, 총 무게·장비 수를 표시하고, 장비 목록은 카드 아래 16pt에 둔다.
- 스냅샷 장비 목록은 현행 그룹 순서의 카테고리별 섹션으로 표시한다. 섹션 머리에는 개수·합계 무게를 천 단위 콤마로 표시하고, 각 장비는 이름 한 줄과 `무게 · 브랜드` 메타 줄의 헤어라인 행으로 표시한다(무게 우측 열 없음).
- 작성자가 후기를 수정할 때 배낭을 다시 선택하면 스냅샷 전체를 새 값으로 교체한다. 다시 선택하지 않으면 기존 스냅샷을 유지한다.
- 스냅샷에 `campSpotId`가 있으면 카드 상단에 공개 박지 좌표로 만든 지도 밴드를 표시할 수 있다. 좌표는 스냅샷에 없으며, 지도 미리보기는 등록 박지의 공개 좌표로만 그린다.

### CM-5 간단한 투표 `[제안]`

사용자는 두 개 이상의 선택지를 제시하고 다른 사용자의 의견을 받을 수 있다.

**수용 기준**

- 선택지는 2~4개이며 각 문구는 1~60자다. 중복 문구와 빈 문구는 등록할 수 없다.
- 마감 시각은 선택이며, 설정하지 않으면 작성자가 게시글을 삭제할 때까지 열린다.
- 마감 시각 입력은 MVP에서 `없음`·`1일`·`3일`·`7일` 프리셋으로 제공한다. 정확한 날짜·시각 피커는 후속 범위로 둔다.
- 로그인 계정당 한 표만 행사한다. **투표 후 다른 선택지를 누르면 확인 없이 즉시 그 선택지로 변경**된다. 같은 선택지를 다시 눌러도 변화가 없으며, 취소 기능은 두지 않는다. 마감 후에는 변경할 수 없다.
- 사용자는 투표하기 전에는 총 참여 수만 보고, 투표한 뒤에는 선택지별 표 수와 비율을 본다. 작성자도 자신의 투표에 한 표를 행사할 수 있고 투표 전에도 결과를 볼 수 있다.
- 결과 표시 시 선택지 행은 약 56pt 높이·모서리 12·1px 테두리의 흰색 행으로 표시하고, 행 안쪽 왼쪽에서 비율 폭만큼 채움 면을 자라게 한다. 채움은 행 높이 전체를 덮으며 행 모서리 안에서 잘리고, 문구는 왼쪽·비율은 오른쪽에 일반 컨트롤 글자로 겹쳐 표시한다. 내 선택지는 `ink` 테두리·`inkTint` 채움·잉크 semibold 문구와 비율·비율 왼쪽 체크 아이콘을, 다른 선택지는 `hairline` 테두리·`controlFill` 채움·`textMuted` regular 문구와 비율을 사용한다.
- 투표 전·비로그인·비작성자 미마감 상태에서는 채움과 비율 없이 테두리 행과 잉크 문구만 표시한다. 마감 또는 투표 처리 중인 행은 disabled 시각과 `accessibilityState.selected`를 반영하며, 득표 수는 선택지 행 안에 표시하지 않고 행 아래 `N명 참여` 한 줄만 유지한다.
- 마감 후에는 새 투표를 받지 않고 최종 결과를 표시한다.
- 첫 표가 생기기 전에는 제목·본문·선택지·마감 시각을 수정할 수 있다. 첫 표 이후에는 본문과 사진만 수정할 수 있고 제목·선택지·마감 시각은 잠긴다.
- 투표 생성과 표 수 증가는 원자적으로 처리하며 중복 탭·재시도에도 한 계정의 표가 두 번 반영되지 않는다.

### CM-6 공개 사진 첨부 `[제안]`

사용자는 게시글의 상황과 경험을 설명하는 사진을 첨부할 수 있다.

**수용 기준**

- 모든 게시글 유형에 사진 0~4장을 첨부할 수 있다. 앨범 선택과 카메라 촬영을 지원한다.
- 선택한 사진은 등록 전 미리보기, 삭제, 순서 변경이 가능하고 첫 번째 사진이 대표 사진이다.
- 입력은 JPEG·PNG·HEIC를 허용하되 업로드용 파일은 방향을 보정하고 장축 2,048px 이하의 JPEG로 정규화한다. 파일당 업로드 크기는 5MB 이하로 제한한다.
- 업로드 전에 위치 좌표를 포함한 EXIF 메타데이터를 제거한다.
- 작성 화면에 `직접 촬영했거나 사용할 권리가 있는 사진만 올려주세요` 안내를 표시한다.
- 사진은 커뮤니티 전용 Storage 경로에 저장하며, 본인 장비 사진 경로와 값을 복사하거나 자동 첨부하지 않는다([DataModel.md](DataModel.md) DM-9·DM-28).
- 각 사진의 업로드 진행·실패 상태를 보여준다. 일부 사진이 실패하면 게시하지 않고 실패한 사진의 재시도 또는 제거를 요청한다.
- 게시글 등록 실패·작성 취소·사진 교체로 참조가 끊긴 파일은 정리한다. 게시글 삭제·운영 숨김 확정 시 연결된 사진도 삭제 대상으로 보낸다.
- 사진은 별도 검수 없이 게시글 등록 완료와 함께 공개된다. 공개 후 문제가 있는 사진은 CM-10의 신고 경로로 접수한다.
- 영상·움직이는 GIF·댓글 사진은 MVP에서 지원하지 않는다.

### CM-7 게시글 상세·댓글·답글 `[제안]`

사용자는 게시글 전체 내용을 읽고 대화를 이어갈 수 있다.

**수용 기준**

- 상세에는 작성자 닉네임·작성 시각(두 줄), 제목, 본문, 사진 전체, 유형별 콘텐츠, 좋아요, 댓글을 표시한다.
- 댓글은 1~1,000자이며 답글은 한 단계까지만 허용한다. 답글에 다시 답하면 같은 단계의 답글로 저장하고 대상 닉네임을 표시한다([Reply.md](Reply.md) RP-2의 깊이 규칙 재사용).
- 댓글과 답글에는 사진·별점·좋아요를 두지 않는다.
- 댓글은 오래된 순으로 최초 20개를 표시하고 다음 페이지를 불러올 수 있다.
- 비로그인 사용자가 댓글 입력부를 탭하면 로그인 모달을 연다.
- 삭제되거나 신고 처리로 숨겨진 게시글은 일반 사용자에게 내용을 보여주지 않는다. 단, 답글이 남은 삭제 댓글은 개인정보와 본문을 제거한 자리표시만 읽을 수 있다.
- 스냅샷 장비 목록은 카테고리별 섹션으로 표시하며, 본문 아래 요약 카드·장비 목록을 거쳐 좋아요 액션 행 위에 둔다. 카드 위 여백은 16pt, 목록 아래 액션까지 여백은 20pt이며, 섹션 머리에는 개수·합계 무게를 천 단위 콤마로 표시한다.
- 배낭 스냅샷 요약 카드의 여행지는 날짜와 분리한 `location-outline` 아이콘 줄로 표시한다. `campSpotId`가 있고 공개 박지 문서가 `active`이면 카드 상단에 공개 좌표 지도 밴드를 표시하며, 문서가 없거나 비활성·숨김이거나 지도 URL 생성·로드에 실패하면 밴드를 생략한다. 날씨가 있으면 카드 하단에 여행 기간의 일별 날씨 코드·한글 상태·최저/최고기온을 줄바꿈 가능한 행으로 표시하고, 없으면 날씨 줄 자체를 표시하지 않는다. 기존 스냅샷은 여행지명이 있을 때 위치 줄만 표시한다.

### CM-8 게시글 좋아요 `[제안]`

로그인 사용자는 유용한 게시글에 좋아요를 표시할 수 있다.

**수용 기준**

- 계정당 게시글 하나에 좋아요 하나만 존재하며 다시 탭하면 취소된다.
- 좋아요 문서 생성·삭제와 게시글 `likeCount` 증감은 원자적으로 처리한다.
- 비로그인 사용자가 탭하면 로그인 모달을 연다.
- 작성자는 자신의 게시글에도 좋아요를 누를 수 있다. 자기 좋아요 제한은 두지 않는다.

### CM-9 수정·삭제 `[제안]`

작성자는 자신의 게시글과 댓글을 수정하거나 삭제할 수 있다.

**수용 기준**

- 수정·삭제 메뉴는 작성자에게만 표시한다.
- 게시글 수정 시 유형 자체를 바꿀 수 없다. 투표 수정 제한은 CM-5를 따른다.
- 게시글 삭제는 확인을 거치며 피드·상세에서 즉시 숨긴다. 연결된 댓글·좋아요·투표·사진은 후속 정리 대상이 된다.
- 댓글 삭제는 항상 작성자 소프트 삭제(`deletedReason: author`)로 처리한다. 답글이 있으면 `삭제된 댓글입니다` 자리표시를 남겨 대화 연결을 보존하고, 답글이 없으면 화면에서 자리표시를 숨긴다. 물리 삭제는 서버 스케줄 정리에 위임한다.
- 삭제·수정 실패 시 기존 화면 상태를 유지하고 토스트로 알린다.

### CM-10 신고 `[제안]`

사용자는 문제가 있는 공개 게시글이나 댓글을 신고할 수 있다.

**수용 기준**

- 로그인 사용자는 게시글·댓글 메뉴에서 `스팸`, `욕설·괴롭힘`, `음란·폭력`, `저작권 침해`, `개인정보 노출`, `기타` 중 하나로 신고할 수 있다.
- 같은 사용자가 같은 대상을 반복 신고해도 신고는 하나만 생성된다.
- 신고가 저장되면 `신고가 접수되었어요` 토스트를 표시하고 원래 화면을 유지한다. 신고만으로 콘텐츠를 자동 숨기거나 삭제하지 않는다.
- 신고 내역은 `open` 상태로 저장한다. 초기 MVP에서는 별도 운영 화면을 만들지 않고 Firebase 콘솔에서 확인·처리한다.
- 운영자가 신고를 확인한 뒤 게시글·댓글의 `status`를 `hidden`으로 바꾸면 일반 사용자 화면에서 즉시 제외된다.
- 자동 필터, 공개 전 승인, 사용자 차단은 MVP에서 제공하지 않는다.

### CM-11 화면 문법과 접근성 `[제안]`

커뮤니티는 현재 앱의 탐색·홈 화면 문법과 시스템 접근성 설정을 따른다.

**수용 기준**

- 색·여백·모서리·타이포는 `DesignTokens`와 `PretendardText`를 사용한다.
- 피드 카드는 상세 진입점이며, 좋아요·더보기·투표 선택지 같은 상호작용은 상세 화면의 별도 터치 영역에서 제공한다. 중첩 탭이 상세 진입을 함께 발생시키지 않는다.
- 아이콘 전용 버튼은 44×44pt 터치 영역, `accessibilityLabel`, `accessibilityRole`을 갖는다.
- 사진은 작성자가 입력한 대체 설명을 MVP에서 받지 않으므로 장식이 아닌 경우 `게시글 사진 1/4`처럼 순서 기반 접근성 라벨을 제공한다. 본문만으로 의미를 알 수 없는 사진 게시 기능은 MVP 범위에서 허용하지 않는다.
- Dynamic Type에서 필터·버튼 텍스트가 잘리지 않고, 사진 순서 변경은 VoiceOver의 이동 액션으로도 가능해야 한다.
- 글쓰기 알약 위치·크기는 배낭 탭 `배낭 추가`([Bag.md](Bag.md) BAG-1)와 동일하다.
- 화면마다 주 액션은 하나다. 피드에서는 `글쓰기`, 작성 화면에서는 `등록`, 상세에서는 댓글 입력이다.
- iOS 헤더는 LG-1(네이티브 투명 헤더·글래스 back·`headerRight` 액션)을 사용하고, Android/Web은 커스텀 헤더를 유지한다.

### CM-12 계정 탈퇴와 커뮤니티 데이터 `[제안]`

회원 탈퇴 시 공개 사진과 작성자 식별 정보가 남지 않도록 커뮤니티 데이터를 함께 정리한다.

**수용 기준**

- 탈퇴 시 작성한 커뮤니티 게시글과 연결 사진, 댓글·답글, 좋아요, 투표를 삭제한다.
- 삭제되는 댓글·좋아요·투표 때문에 생기는 비정규화 카운트는 함께 보정한다.
- 다른 사용자의 게시글에 남긴 댓글이 삭제되더라도 그 아래 답글이 있으면 `탈퇴한 사용자의 댓글입니다` 자리만 남긴다. 툼스톤은 경로 정리·감사를 위해 `authorId`를 유지하고 닉네임·본문은 제거한다.
- 클라이언트 중단으로 일부 정리가 실패해도 재시도 가능한 서버 작업으로 이어져야 한다. 공개 사진 삭제를 클라이언트의 일회성 실행에만 의존하지 않는다.

## 4. 데이터

- Firestore·Storage 계약: [DataModel.md](DataModel.md) DM-28, DM-9.
- 게시글의 배낭 정보는 원본 참조가 아니라 공개 가능한 텍스트 스냅샷이다(CM-4).
- 게시글·댓글·사진은 등록 성공 즉시 `published` 상태로 공개한다. `hidden` 상태는 운영자만 쓸 수 있어야 한다.
- 좋아요 수·댓글 수·투표 수는 목록 표시용 비정규화 캐시이며 원본 문서 생성·삭제와 원자적으로 맞춘다.
- 삭제·운영 숨김의 연쇄 정리와 탈퇴 정리(CM-9·CM-12), 고아 사진 정리(CM-6)는 **`lessismore` 레포 `functions/`의 Cloud Functions**가 맡는다(2026-09-02 사용자 결정 — [DataModel.md](DataModel.md) DM-28 서버 정리 작업 항목). 앱은 게시글을 소프트 삭제(`status: deleted`)하고 즉시 화면에서 숨기며, 물리 정리 완료를 기다리지 않는다.
- 탈퇴로 자리표시가 된 댓글은 `deletedReason: withdrawal`로 구분해 `탈퇴한 사용자의 댓글입니다`를 표시한다(작성자 삭제는 `author` → `삭제된 댓글입니다`).

## 6. 엣지 케이스

- **비로그인**: 피드·상세는 열람, 작성·좋아요·댓글·투표·신고는 로그인 유도.
- **빈 피드**: 안내와 글쓰기 진입점을 표시.
- **삭제된 원본 배낭**: 후기 스냅샷은 그대로 표시.
- **투표 동시 참여**: 트랜잭션으로 정확히 한 표만 반영.
- **사진 일부 실패**: 게시 중단, 실패 항목 재시도 또는 제거.
- **오프라인**: 기존에 표시된 목록은 유지할 수 있으나 새 글·댓글·투표를 성공으로 낙관 처리하지 않는다.
- **신고 실패**: 콘텐츠와 화면 상태를 유지하고 재시도 안내를 표시한다.
- **삭제 중 실패**: 화면에서는 먼저 숨기고 서버 정리 작업이 재시도한다.

- [ ] 첫 투표 이후 제목·선택지·마감 시각 수정 불가
- [ ] 댓글·한 단계 답글, 20개 단위 페이지네이션, 삭제 자리 보존
- [ ] 게시글 좋아요 연타·재시도에도 카운트와 문서가 일치

## 8. 미해결 질문

- **출시 심사 위험 — 신고 기능만 제공**: MVP는 사용자 결정으로 자동 필터·사전 검수·사용자 차단을 두지 않는다. Apple App Review Guideline 1.2는 UGC 앱에 유해 콘텐츠 필터링과 사용자 차단도 요구하므로, iOS 심사에서 보완 요청이나 거절 가능성이 있다. 심사 대응이 필요해지면 CM-10을 먼저 개정한다.
- **신고 처리 운영**: 초기에는 Firebase 콘솔에서 `community-reports`를 확인하고 대상 `status`를 수동 변경한다. 실제 운영량이 늘면 별도 신고 관리 화면과 대응 기한을 후속 기획한다.
- **커뮤니티 공개 범위**: MVP는 앱 안 공개만 정의했다. 검색엔진 노출과 웹 공유 링크는 후속 기획에서 개인정보·삭제 전파 정책과 함께 결정한다.
- **알림**: 댓글·답글·투표 마감 알림은 MVP 제외다. 커뮤니티 재방문 지표를 확인한 뒤 [Notification.md](Notification.md)에 별도 제안한다.
