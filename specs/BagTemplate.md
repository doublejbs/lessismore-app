# 배낭 템플릿 (저장 / 목록 / 템플릿에서 생성)

| 항목 | 내용 |
| --- | --- |
| 상태 | 제안 (2026-08-13 초안 — 미구현) |
| ID 프리픽스 | `BT` |
| 주요 코드 | (예정) `app/(tabs)/bag.tsx`, `components/bag/`(세그먼트·템플릿 목록), `model/store/`(템플릿 CRUD 스토어) |
| 관련 스펙 | [DataModel.md](DataModel.md) DM-26, [Bag.md](Bag.md), [BagDetail.md](BagDetail.md), [Home.md](Home.md) HM-8 |

## 1. 개요

배낭 복사([Bag.md](Bag.md) BAG-4)는 날짜 있는 여행 1회를 복제하지만, 템플릿은 **날짜 없는 재사용 장비 구성**이다.
"백패킹 기본 세트"처럼 반복 사용하는 구성을 저장해두고, 새 여행마다 거기서 시작한다.
저장(BT-1) → 목록(BT-2) → 템플릿에서 배낭 생성(BT-3)이 한 사이클이다.

## 2. 화면 및 진입

```
app/(tabs)/bag.tsx → BagView
  ├─ 세그먼트 `배낭`   → 기존 배낭 목록 (Bag.md BAG-1 카드 목록, 변경 없음)
  └─ 세그먼트 `템플릿` → 템플릿 목록 (BT-2)
                          └─ 행 탭 → 템플릿으로 만들기 폼 (BT-3, `BagFormContent` 재사용)
```

- 저장 진입: 배낭 목록 카드 `⋯` 메뉴 → `템플릿으로 저장` (BT-1)
- 목록 진입: 배낭 탭 상단 세그먼트에서 `템플릿` 선택 (BT-2)
- 생성 진입: 템플릿 목록 행 탭 (BT-3) → 확정 시 `/bag/{새 id}` 상세로 이동

## 3. 요구사항

### BT-1 템플릿으로 저장 `[제안]`

사용자는 배낭의 장비 구성을 템플릿으로 저장할 수 있다.

**수용 기준**

- 배낭 목록 카드 `⋯` 메뉴(`BottomMenuModalView` — [Bag.md](Bag.md) BAG-1)에 `템플릿으로 저장` 항목을 추가한다. 순서: `복사` → `템플릿으로 저장` → `삭제`.
- 항목 선택 시 시트를 닫고 **이름 입력 시트**를 띄운다(시트 위에 시트를 겹쳐 쌓지 않는다 — BAG-3이 삭제 다이얼로그를 띄울 때와 같은 규칙).
  - 이름 프리필: `{배낭 이름}`. 빈 문자열은 거부한다(기존 생성/복사 폼과 같은 알럿 규칙).
- 확인 시 템플릿 문서를 저장한다([DataModel.md](DataModel.md) DM-26): `name`(입력값), `gears`(배낭의 `gears` 그대로), `weight`(배낭 `weight` 그대로 — 합계 캐시), `createdAt`/`editDate`(저장 시점 ISO).
- **날짜·메모·패킹·여행지(`location`)·날씨(`weather`)는 저장하지 않는다** — 전부 여행 1회에 종속된 값이다(BAG-4 복사가 `memo`/`packedGears`를 복사하지 않는 것과 같은 원칙).
- **장비 문서의 `bags` 배열은 건드리지 않는다** — 템플릿은 배낭이 아니므로 `gear.bags[]` ↔ `bag.gears[]` 양방향 참조 불변식([DataModel.md](DataModel.md) DM-11) 대상 밖이다. 장비 상세 "배낭 기록"에도 나타나지 않는다.
- 완료 토스트: `템플릿으로 저장됐습니다`.
- 비로그인 상태에서 항목을 누르면 시트를 닫고 **로그인 모달**을 띄운다(배낭 추가·복사와 같은 규칙 — BAG-4).

### BT-2 템플릿 목록 (배낭 탭 세그먼트) `[제안]`

사용자는 배낭 탭 안에서 저장한 템플릿 목록을 볼 수 있다.

**수용 기준**

- 배낭 탭 상단(화면 제목 아래)에 **`배낭` / `템플릿` 세그먼트 칩 2개**를 둔다.
  - 공용 `CategoryChipView` 문법: 비선택 연회색 채움, 선택 잉크 채움 + 흰 글자. 기본 선택 `배낭`.
  - 44pt 터치 타깃, 고정 높이 금지(Dynamic Type), `accessibilityRole`·`accessibilityState` 등 `CategoryChipView`가 제공하는 접근성을 그대로 쓴다.
- 화면 제목은 선택에 따라 `배낭 N개` / `템플릿 N개` (`AcgType.screenTitle` semibold — 기존 제목과 동일).
  - 제목은 **빈 목록에서도 렌더한다**(빈 상태 문구 위) — 세그먼트 도입으로 제목이 현재 세그먼트가 무엇인지 알리는 역할을 겸하므로, `배낭` 세그먼트의 빈 상태에서도 `배낭 0개` 제목이 보인다. [Bag.md](Bag.md) BAG-6의 빈 목록 규칙에서 숨는 것은 **정렬 드롭다운뿐**이다. 로딩 중에는 스켈레톤만 그리고 제목을 렌더하지 않는다(기존과 동일).
- `템플릿` 선택 시 템플릿 목록을 표시한다:
  - 목록은 `createdAt` **내림차순(최근 저장순)** 으로 정렬한다. 서버 `orderBy` 없이 클라이언트에서 정렬하며, 별도 정렬 옵션(드롭다운)은 두지 않는다.
  - 행 = 이름 + 메타 한 줄(`{무게}kg · 장비 {N}개`). **[Home.md](Home.md) HM-8 행 문법**(순백 지면 + 헤어라인 행, 면·그림자 없음, `AcgRow` 치수, 첫 행 헤어라인 없음). 배낭 목록의 카드 문법(BAG-1)은 지도 밴드를 담기 위한 화면별 예외라 템플릿 목록에는 적용하지 않는다 — 템플릿에는 지도·이미지가 없다.
  - 메타 줄은 잉크색(`AcgType.rowSubtitle`), 무게 숫자 조각만 중첩 Text 콘덴스드(HM-8 문법).
  - 행 우측 `⋯` 메뉴 버튼(BAG-1 카드 메뉴 버튼과 같은 치수·접근성: 44pt, `accessibilityLabel='템플릿 메뉴'`) → `BottomMenuModalView`에 `삭제` 항목 → 시트를 닫고 확인 다이얼로그(`{이름} 템플릿을 삭제할까요?`, 확인 버튼 `삭제`) → 삭제.
  - **행 탭(본문 영역) → 템플릿에서 배낭 생성**(BT-3). 메뉴 버튼은 행 터치어블 밖의 형제 컨트롤이다 — 터치어블 안에 중첩하면 행이 하나의 접근성 요소로 묶여 VoiceOver에서 메뉴 버튼에 도달할 수 없다(BAG-1과 같은 이유).
  - 행 본문은 `accessibilityRole='button'` + 라벨 `{이름}, {무게}kg, 장비 {N}개`.
- 빈 상태: `저장한 템플릿이 없어요` + 저장 방법 안내 한 줄(예: `배낭 카드의 ⋯ 메뉴에서 템플릿으로 저장할 수 있어요`).
- 로딩 중에는 배낭 목록과 같은 방식의 로딩 처리(스켈레톤 또는 인디케이터 — 행 골격이면 HM-8 행 골격).
- **`템플릿` 세그먼트에서는 `배낭 추가` 플로팅 버튼을 숨긴다** — 템플릿은 배낭 저장(BT-1)으로만 생기고, 이 화면의 주 액션이 아니다.
- `배낭` 세그먼트는 기존 배낭 목록(BAG-1)과 동일하게 동작한다(정렬 드롭다운 포함). 정렬 드롭다운(BAG-6)은 `배낭` 세그먼트에서만 렌더한다. 기존과 다른 점은 하나다 — 빈 목록에서도 화면 제목이 렌더된다(위 제목 항목, [Bag.md](Bag.md) BAG-6).
- 비로그인: 배낭 목록과 동일 — 빈 목록으로 표시.
- 배낭 추가 바텀시트(BAG-2)는 기존 2항목(`새로 만들기`/`기존 배낭 복사하기`)을 유지한다 — `템플릿에서 만들기` 항목을 추가하지 않는다(템플릿 탭이 그 역할, 진입점 중복 방지).

### BT-3 템플릿에서 배낭 생성 `[제안]`

사용자는 템플릿에서 새 배낭을 만들 수 있다.

**수용 기준**

- 템플릿 행 탭 → 복사 모달(BAG-4)과 동일한 폼(`BagFormContent` 재사용)을 띄운다:
  - 타이틀 `템플릿으로 만들기`(또는 유사 — 복사 모달의 `배낭 복사`와 같은 자리), 확인 버튼 `만들기`.
  - 이름 프리필 `{템플릿 이름}`(수정 가능, 빈 문자열 거부).
  - 날짜 기본값: 시작일 오늘, 종료일 내일(복사 모달과 동일). 캘린더 선택 규칙은 BAG-2와 동일.
  - 확정 처리 중에는 확인 버튼을 비활성화한다(연타로 인한 중복 생성 방지 — BAG-4와 동일).
- 확정 시 새 `bag` 문서를 생성한다(BAG-4 복사와 같은 `writeBatch` 계약 — [DataModel.md](DataModel.md) DM-11 참조):
  - `name`/`startDate`/`endDate`: 폼 입력값. `gears`/`weight`: 아래 stale 제외 후 값.
  - `shared: false`, `editDate`/`createdAt`: 생성 시점, `userId`: 현재 uid. `memo`/`packedGears` 등은 만들지 않는다.
  - 새 배낭 ID를 담긴 각 장비의 `bags`에 추가 + `users/{uid}.bags`에 `arrayUnion`.
- **창고에서 삭제된 장비는 제외한다**: 템플릿의 `gears` 중 현재 `users/{uid}/gears`에 존재하는 장비만 담고, `weight`는 남은 장비의 합으로 재계산한다. 템플릿은 장비 삭제 정리 경로 밖이라 stale ID가 남을 수 있다([DataModel.md](DataModel.md) DM-26) — 존재하지 않는 gear 문서에 배치 update를 걸면 배치 전체가 실패한다.
- 생성 후 `/bag/{새 id}` 상세로 이동 + 토스트(복사와 동일한 흐름). 장비 편집 화면 자동 열기는 복사(BAG-4)의 현행 동작을 따른다.
- 생성 후 템플릿 문서는 그대로 남는다 — 같은 템플릿에서 반복 생성할 수 있다.

## 4. 데이터

- 읽기/쓰기 경로: [DataModel.md](DataModel.md) **DM-26** (`users/{uid}/bagTemplates/{templateId}`) — 필드 계약은 그 문서가 단일 정의처다.
- 템플릿은 `gear.bags[]` 양방향 불변식([DataModel.md](DataModel.md) DM-11) 대상이 아니다. 템플릿 삭제·장비 삭제 어느 쪽도 상대를 갱신하지 않는다 — stale ID는 BT-3 생성 시점에 걸러진다.
- BT-3 확정은 배낭 복사(`BagStore.copy`)와 같은 `writeBatch` 계약을 따른다(DM-11).

## 6. 엣지 케이스

- **비로그인**: 템플릿 목록은 빈 목록. BT-1 항목 탭은 시트를 닫고 로그인 모달(BAG-4와 동일 규칙).
- **빈 상태**: `저장한 템플릿이 없어요` + 저장 방법 안내 한 줄(BT-2).
- **로딩**: 배낭 목록과 같은 방식(스켈레톤/인디케이터 — BT-2).
- **stale 장비**: 템플릿의 `gears`에 창고에서 삭제된 장비 ID가 남아 있어도 BT-3 생성이 실패하지 않는다 — 존재하는 장비만 담고 무게를 재계산한다.
- **빈 템플릿에서 생성**: stale 제외 후 장비가 0개여도 생성은 성공한다(`gears: []`, `weight: 0` — 빈 배낭 생성 BAG-2와 같은 결과).

## 7. 수동 검증 체크리스트

**BT-1 저장**

- [ ] 배낭 카드 `⋯` → 메뉴 시트에 `복사` → `템플릿으로 저장` → `삭제` 순서로 3항목
- [ ] `템플릿으로 저장` → 시트가 닫히고 이름 입력 시트, 이름 `{배낭 이름}` 프리필
- [ ] 이름을 지우고 확인 → 거부(기존 생성/복사 폼과 같은 알럿)
- [ ] 확인 → 토스트 `템플릿으로 저장됐습니다`, `템플릿` 세그먼트에 새 행 표시
- [ ] 저장된 템플릿의 무게·장비 수가 원본 배낭과 동일, 날짜·메모·패킹·여행지·날씨는 저장되지 않음 (Firestore 문서 확인)
- [ ] 템플릿으로 저장해도 장비 문서의 `bags` 배열은 그대로 — 장비 상세 "배낭 기록"에 템플릿이 나타나지 않음
- [ ] 비로그인 → `템플릿으로 저장` 탭 시 시트가 닫히고 로그인 모달

**BT-2 목록**

- [ ] 배낭 탭 상단에 `배낭`/`템플릿` 세그먼트 칩, 기본 `배낭` 선택, 제목이 `배낭 N개`/`템플릿 N개`로 전환
- [ ] 배낭 0개 → `배낭` 세그먼트에서도 제목 `배낭 0개`가 빈 상태 문구 위에 표시, 정렬 드롭다운은 없음
- [ ] `템플릿` 목록이 HM-8 행 문법(순백 지면 + 헤어라인, 카드·지도 밴드 없음, 첫 행 헤어라인 없음)으로 렌더
- [ ] 템플릿 목록이 최근 저장순(`createdAt` 내림차순) — 새로 저장한 템플릿이 맨 위
- [ ] 행 메타 `{무게}kg · 장비 {N}개`가 잉크색, 무게 숫자만 콘덴스드
- [ ] 행 `⋯` → `삭제` → 시트가 닫히고 확인 다이얼로그(`{이름} 템플릿을 삭제할까요?`) → 삭제 후 목록 갱신
- [ ] `템플릿` 세그먼트에서 `배낭 추가` 플로팅 버튼과 정렬 드롭다운이 보이지 않음
- [ ] `배낭` 세그먼트 복귀 → 기존 목록·정렬·플로팅 버튼 그대로
- [ ] 템플릿 0개 → `저장한 템플릿이 없어요` + 안내 한 줄
- [ ] 비로그인 → 템플릿 목록이 빈 목록
- [ ] VoiceOver: 세그먼트 칩의 선택 상태가 읽히고, 행(`{이름}, {무게}kg, 장비 {N}개`) 다음에 `템플릿 메뉴` 버튼이 별도 요소로 읽힘

**BT-3 생성**

- [ ] 템플릿 행 탭 → 폼 타이틀 `템플릿으로 만들기`, 이름 `{템플릿 이름}` 프리필, 날짜 오늘~내일, 확인 버튼 `만들기`
- [ ] 확정 → `/bag/{새 id}` 상세 이동 + 토스트, 배낭 목록에 새 배낭 표시
- [ ] 새 배낭의 장비 목록·총 무게가 템플릿과 동일, 담긴 장비의 상세 "배낭 기록"에 새 배낭 표시
- [ ] 템플릿에 담긴 장비 하나를 창고에서 삭제한 뒤 생성 → 그 장비만 제외되고 무게가 재계산되며 생성이 실패하지 않음
- [ ] 확정 처리 중 확인 버튼 비활성 — 연타해도 배낭이 1개만 생성

- [ ] 이름을 지우고 확정 → 거부(빈 문자열 알럿)

## 8. 미해결 질문

- **Firestore 보안 규칙이 `users/{uid}/bagTemplates` 서브컬렉션 읽기/쓰기를 허용하는지 확인 필요 — 아직 미확인(2026-08-13 구현 시점 기준)** — 규칙 파일은 이 레포에 없다(콘솔 관리). `users/{uid}/gears`와 같은 소유자 전용 규칙이면 충분하다. 구현은 규칙 확인 없이 진행됐으므로, 규칙이 막혀 있으면 BT-1 저장·BT-2 조회가 전부 런타임에 실패한다 — **출시 전 확인 필수.**
- BT-3의 "장비 편집 화면 자동 열기"는 복사(BAG-4)의 현행 동작을 따르기로 했는데, [Bag.md](Bag.md) 안에서 BAG-2는 자동 열기를 제거(2026-07-31)했다고 하고 BAG-4는 "곧바로 장비 편집 화면을 연다"고 서술한다 — 두 서술이 상충하므로 구현 시 현행 코드를 확인해 따르고 Bag.md를 정정한다.
