## 1. 개요

장비별 리뷰 시스템. 최상위 댓글 + 답글(1단계) 구조에 좋아요·@멘션·논리 삭제를 지원한다.
장비 상세의 리뷰 섹션에서 진입한다. **최상위 댓글(리뷰)에는 별점(1~5)이 있으며**(RP-1), 작성/수정은 캠프 후기와 동일한 formSheet 모달(별점+글)을 쓰고, 리뷰 섹션 헤더에 평균 별점을 표시한다(별점은 최상위 리뷰만 — 답글은 별점 없음).

## 2. 화면 및 진입

| 라우트 | 화면 | 역할 |
| --- | --- | --- |
| `/reply/[id]` | ReplyView | 장비의 최상위 댓글 목록 |
| `/reply/[id]/input` | ReplyInputView | 새 최상위 리뷰 작성 (**별점+글 formSheet 모달**) |
| `/reply/[id]/[commentId]` | ReplyDetailView | 댓글 1개 + 답글 목록 + 답글 입력 |
| `/reply/[id]/[commentId]/edit` | ReplyEditView | 리뷰/답글 수정 (최상위는 **별점+글 formSheet**, 답글은 글만) |

`[id]`는 장비 ID. 목록 → 댓글 클릭 → 상세, 목록 하단 입력 버튼 → 작성 화면.

### 2.1 화면 문법 (as-built, 2026-08-11 — Liquid Depth)

리뷰 화면들의 시각만 서술한다. 무엇을 언제 보여주는지는 RP-1~RP-6이 정의한다.

- 지면은 **지형 없이 `canvas` + 우상단 라임 글로우**다(창고·탐색 목록과 같은 판단 — 훑어 읽는 화면에 산세를 깔지 않는다). 크롬은 iOS는 네이티브 투명 헤더, Android·Web은 공용 `LiquidGlassCircleButton` 유리 back이다(LG-1).
- **목록(`/reply/[id]`)**: 화면 대상은 제목 블록(`리뷰` 32/38)이 들고 — 네이티브 바 타이틀은 비운다 — 리뷰는 **흰 카드 하나** 안에 좌측 16 들여쓴 헤어라인으로 갈려 쌓인다([Warehouse.md](Warehouse.md) WH-1과 같은 문법. 첫 페이지 20건으로 길이가 고정돼 무한 스크롤 목록의 카드-당-행 문법을 쓰지 않는다).
- **제목 아래 개수 줄은 두지 않는다**(창고 WH-2와 다른 판단): 목록이 첫 페이지 20건만 로드하므로(RP-3) 여기서 셀 수 있는 값은 총 리뷰 수가 아니고, 장비 상세가 요약 문서로 보여 주는 `리뷰 n`([GearDetail.md](GearDetail.md) GD-3)과 갈린다. 페이지네이션이 생겨 총계를 말할 수 있게 되면 그때 붙인다.
- **상세(`/reply/[id]/[commentId]`)**: 바 타이틀은 `답글`이다(2026-08-11 — 옛 `댓글`. 이 화면의 카피가 전부 답글이라 바에서도 같은 말을 쓴다). 원 리뷰는 **자기 종이 카드** 하나(모서리 22), 답글은 그 아래 **좌측 20 들여쓴 카드 하나** 안에 헤어라인으로 갈려 쌓인다 — 답글마다 면을 두면 화면이 카드 더미로 보이고, 들여쓰기가 원 리뷰와의 종속 관계를 말한다.
- **항목 안 위계**: 작성자 14/600 잉크 · 날짜 12.5 `inkMuted` · 본문 14/22 `inkSecondary`(상세의 **원 리뷰 본문만 15/22** — 그 화면의 주인공이라 한 단계 크다) · 좋아요·답글 수 13 `inkMuted`. 내 리뷰·내 답글은 이름 색을 바꾸는 대신 **중립 배지**(`badgeFill` + `inkSecondary` 11)로 표시한다 — 라임을 글자색으로 쓰지 않고, 박지 후기 카드([CampSite.md](CampSite.md) CS-8)와 같은 표기가 된다.
- **입력 바**(목록의 리뷰 쓰기 진입 · 상세의 답글 입력): 지면 위에 놓인 바라 띠 면을 깔지 않는다 — **필드 자체가 유리**이고 값이 들어오면 채움을 한 단계 진하게 덮는다. 유리 면은 검색 필드와 **같은 셸**(`components/liquid/LiquidGlassField.tsx` — 높이 48 · 블러 + 유리 채움 + 0.5px 흰 보더, 여러 줄로 자라면 모서리를 카드값으로 낮춘다)이 그린다. 답글 저장은 잉크 알약이되 주 액션 높이(54)가 아니라 필드와 같은 48이다 — 바 안에 든 인라인 액션이라 화면의 주 액션 자리를 가져가지 않는다.
- **작성 시트**(`/reply/[id]/input`, formSheet): 시트는 **종이 면**이고 입력만 `surfaceSunken`으로 가라앉힌다. 라벨은 `LiquidFieldLabel`(12.5/600 `inkTertiary`, 대문자화 없음, 필수는 라벨 옆 `*`), 하단은 `취소`(흰 아웃라인) + `확인`(잉크) 알약 두 개다 — 박지 후기 작성([CampSite.md](CampSite.md) CS-8)과 같은 문법이라 두 작성 화면이 한 벌로 읽힌다.
- **수정 화면**(`/reply/[id]/[commentId]/edit`): 지면 위에 **종이 카드 인풋** 하나가 놓인다(회색 채움을 두면 지면과 붙어 입력 영역이 사라진다 — 뒤가 지면이면 종이, 뒤가 종이면 가라앉은 면). 완료는 iOS는 네이티브 `headerRight`, Android·Web은 하단 잉크 알약(`block`)이다.
- **수정·삭제 메뉴**는 공용 바텀 메뉴 시트(`components/ui/BottomMenuModalView.tsx`)가 낸다 — 지면 위 종이 카드에 액션 행을 헤어라인으로 나누고, `닫기`는 **흰 아웃라인 알약**이다(잉크로 채우면 아무것도 하지 않는 쪽이 가장 무거운 버튼이 된다). 박지 후기·장비 상세가 같은 시트를 쓴다.
  - **전환 (as-built 2026-08-11)**: 막 페이드 + slide-up/down은 공용 프리미티브 `components/liquid/LiquidSheetModal.tsx`가 든다(들어올 때 `LiquidMotion.spring`, 나갈 때 200ms timing) — 로그인·공지·박지 배낭 선택 시트와 같은 전환이다. **[이력] 그 전까지 닫힘 애니메이션은 재생되지 않았다**: `<Modal visible={...}>`이 `visible`이 꺼지는 순간 언마운트돼 작성해 둔 slide-down/fade-out이 화면에 닿지 못했고, 프리미티브가 나가는 애니메이션이 끝날 때까지 마운트를 붙잡아 이제 실제로 내려간다.
- 라임 면은 두지 않는다. 라임 계열이 쓰이는 자리는 **@멘션 글자**(`limeInk`)와 체크 글리프뿐이다 — 라임 원색을 글자색으로 쓰지 않는다.
- 빈 상태는 **사실 + 다음 걸음** 두 줄이다: `아직 등록된 리뷰가 없어요` / `첫 리뷰를 남겨볼까요?`.

## 3. 요구사항

### RP-1 리뷰 작성 (별점 + 글)

로그인 사용자는 장비에 **별점(필수)과 글(선택)** 로 리뷰(최상위 댓글)를 남길 수 있다.

**수용 기준**

- 작성 화면은 **캠프 후기와 동일한 formSheet 모달**(별점 입력 `StarRatingView` + 멀티라인 글, 키보드 '완료'/빈 영역 탭으로 닫힘) 톤을 따른다. 공용 별점 컴포넌트(`components/camp-site/StarRatingView.tsx`) 재사용.
- **별점(1~5)은 필수** — 미선택 시 완료 비활성. 글은 선택(최대 1000자). (기존 "내용 있을 때만 활성"은 별점 기준으로 대체.)
- 작성 진입 시 닉네임이 없으면 자동 생성한다(`hiker{난수}` — [Auth.md](Auth.md) AU-2).
- 저장은 트랜잭션으로 댓글 문서(`rating` 포함) + 요약 문서(`totalCount`/`parentCount`/`lastCommentAt` + **별점 집계 `ratingSum`/`ratingCount`/`ratingAvg`**)를 함께 갱신한다([DataModel.md](DataModel.md) DM-7). 별점 집계는 **별점 있는 최상위 댓글만** 포함(답글·레거시 무별점 제외).
- 작성 중에는 버튼 비활성 + **라벨을 유지한 채 앞에 진행 표시**를 붙인다(2026-08-11 개정) — 라벨이 사라지면 무엇을 기다리는지 알 수 없다.
- **진입 바 카피는 `리뷰를 남겨보세요`다**(2026-08-11 개정 — 기존 `댓글을 입력해보세요`). 이 화면이 받는 것은 별점이 딸린 리뷰이고, 같은 것은 같은 말로 부른다(Liquid Depth 카피 규칙). 답글 입력 바는 그대로 `답글을 남겨보세요`다.
- **답글에는 별점이 없다**(RP-2) — 답글 입력은 기존 인라인 방식·글만 유지.

### RP-2 답글과 깊이 제한

**수용 기준**

- 답글은 최상위 댓글 아래 1단계만 가능하다(답글의 답글 UI 없음). 스토어는 `depth > 2`를 예외로 거부한다.
- 답글 입력에는 대상 사용자 @멘션이 자동 삽입되고, 멘션은 **밝은 면 위 라임 계열 잉크**(`Liquid.limeInk`)로 렌더된다(2026-08-11 개정 — 옛 `#9CCC65`·ACG `limeText`를 대체). 라임 원색을 글자색으로 쓰지 않는다. 멘션과 본문은 한 라인박스에 흐르도록 중첩 텍스트로 두고 행간을 같게 잡는다.
- 답글 입력 `maxLength`는 1000자다. 최상위 댓글 입력에는 길이 제한이 없다(현 동작).

### RP-3 정렬과 페이지네이션

**수용 기준**

- 최상위 댓글: `createdAt desc`(최신순). 스토어는 페이지 로드(`limit` + `startAfter`)를 지원하지만, **현재 UI는 첫 페이지(기본 20개)만 로드하고 추가 로드 트리거가 없다** (미해결 질문 참조).
- 답글: `createdAt asc`(오래된순) 전체 로드.

### RP-4 수정/삭제 권한

**수용 기준**

- 수정·삭제 메뉴는 본인 댓글(`authorId === 내 uid`)에만 노출되고, 스토어에서도 `authorId`를 재검증한다.
- 수정 화면의 입력 라벨·플레이스홀더는 무엇을 고치는지 그대로 말한다(2026-08-11) — 최상위는 `별점`(필수 표식) + `리뷰 글`(`장비가 어땠나요?`), 답글은 `답글`(`답글을 남겨보세요`) 하나다.
- **최상위 리뷰 수정 화면에는 별점 입력을 추가**(기존 별점·글 프리필)하고, 별점 변경 시 요약 `ratingSum`/`ratingAvg` 델타를 반영하기 위해 `updateComment`도 **트랜잭션**으로 처리한다. 답글 수정은 글만. (수정 화면 프레젠테이션은 기존 방식 유지 — 작성만 formSheet 모달.)
- 삭제 시 답글이 있으면 **논리 삭제**(`isDeleted: true`, 내용 `'[삭제된 댓글입니다]'`), 없으면 물리 삭제. 삭제 트랜잭션은 요약 카운트·부모 `replyCount`와 함께 **별점 집계**(최상위 리뷰가 별점을 가졌으면 `ratingSum`/`ratingCount`/`ratingAvg` 감소)를 갱신한다. (논리 삭제도 집계에서 제외한다 — 화면에서 안 보이므로.)
- `isDeleted` 댓글은 목록 UI에서 필터링되어 보이지 않는다(현 동작 — 미해결 질문 참조).

### RP-5 좋아요

**수용 기준**

- 좋아요는 토글이며 `comment-likes/{userId}_{commentId}` 문서 생성/삭제 + `likeCount` 증감을 트랜잭션으로 처리한다.
- 비로그인 상태에서 좋아요/삭제를 시도하면 전역 로그인 모달(`LogInAlertManager.show()`)을 띄운다.

### RP-6 별점 표시 (신규)

**수용 기준**

- 장비 상세 리뷰 섹션 헤더에 **평균 별점(★ n.n)과 별점 리뷰 수**를 표시한다(요약 문서 `ratingAvg`/`ratingCount`). 별점 리뷰가 0건이면 평균을 숨긴다.
- 최상위 리뷰 항목(`ReplyItemView`)에 해당 리뷰의 **별점(★, 비편집)** 을 작성자/날짜 근처에 표시한다. `rating`이 없는 레거시 댓글은 별점을 표시하지 않는다.
- **리뷰 상세(`/reply/[id]/[commentId]`)의 원 리뷰에도 같은 별점을 표시한다**(2026-08-11 개정) — 목록에서 별점을 보고 들어왔는데 상세에 없으면 다른 리뷰처럼 읽힌다. `rating`이 없는 레거시 댓글은 그대로 생략.
- 답글에는 별점을 표시하지 않는다.

## 8. 미해결 질문

- 논리 삭제된 댓글(`[삭제된 댓글입니다]`)이 UI에서 완전히 필터링되면 그 아래 답글 접근 경로가 모호하다 — 의도 확인 필요.
- 최상위 댓글 입력에 길이 제한이 없다(답글만 1000자) — 정책 통일 여부.
- **21번째 이후 댓글은 볼 방법이 없다** — 스토어의 `startAfter` 페이지네이션을 UI(`Reply.ts`, `ReplyView`)가 소비하지 않음. 더보기/무한 스크롤 도입 필요.
