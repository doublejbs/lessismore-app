## 1. 개요

장비별 리뷰 시스템. 최상위 댓글 + 답글(1단계) 구조에 좋아요·@멘션·논리 삭제를 지원한다.
장비 상세의 리뷰 섹션에서 진입한다. **최상위 댓글(리뷰)에는 별점(1~5)이 있으며**(RP-1), 작성/수정은 캠프 후기와 동일한 formSheet 모달(별점+글)을 쓰고, 리뷰 섹션 헤더에 평균 별점을 표시한다(별점은 최상위 리뷰만 — 답글은 별점 없음).

## 2. 화면 및 진입

| 라우트 | 화면 | 역할 |
| --- | --- | --- |
| `/reply/[id]` | ReplyView | 장비의 최상위 댓글 목록 |
| `/reply/[id]/input` | ReplyInputView | 새 최상위 리뷰 작성 (**별점+글 formSheet 모달**) |
| `/reply/[id]/[commentId]` | ReplyDetailView | 댓글 1개 + 답글 목록 + 답글 입력 |
| `/reply/[id]/[commentId]/edit` | ReplyEditView | 리뷰/답글 수정 (최상위는 **별점+글 formSheet**, 답글은 글만) |

`[id]`는 장비 ID. 목록 → 댓글 클릭 → 상세, 목록 하단 입력 버튼 → 작성 화면.

## 3. 요구사항

### RP-1 리뷰 작성 (별점 + 글)

로그인 사용자는 장비에 **별점(필수)과 글(선택)** 로 리뷰(최상위 댓글)를 남길 수 있다.

**수용 기준**

- 작성 화면은 **캠프 후기와 동일한 formSheet 모달**(별점 입력 `StarRatingView` + 멀티라인 글, 키보드 '완료'/빈 영역 탭으로 닫힘) 톤을 따른다. 공용 별점 컴포넌트(`components/camp-site/StarRatingView.tsx`) 재사용.
- **별점(1~5)은 필수** — 미선택 시 주 액션(`등록`, RP-7) 비활성. 글은 선택(최대 1000자). (기존 "내용 있을 때만 활성"은 별점 기준으로 대체.)
- 작성 진입 시 닉네임이 없으면 자동 생성한다(`hiker{난수}` — [Auth.md](Auth.md) AU-2).
- 저장은 트랜잭션으로 댓글 문서(`rating` 포함) + 요약 문서(`totalCount`/`parentCount`/`lastCommentAt` + **별점 집계 `ratingSum`/`ratingCount`/`ratingAvg`**)를 함께 갱신한다([DataModel.md](DataModel.md) DM-7). 별점 집계는 **별점 있는 최상위 댓글만** 포함(답글·레거시 무별점 제외).
- 작성 중에는 버튼 비활성 + 로딩 인디케이터를 표시한다.
- **답글에는 별점이 없다**(RP-2) — 답글 입력은 기존 인라인 방식·글만 유지.

### RP-2 답글과 깊이 제한

**수용 기준**

- 답글은 최상위 댓글 아래 1단계만 가능하다(답글의 답글 UI 없음). 스토어는 `depth > 2`를 예외로 거부한다.
- 답글 입력에는 대상 사용자 @멘션이 자동 삽입되고, **멘션은 잉크 semibold로 렌더된다**(RP-7 — 색이 아니라 굵기로 가른다. 옛 강조색 #9CCC65 → 라임 텍스트 → 잉크 semibold로 두 번 바뀌었다).
- 답글 입력 `maxLength`는 1000자다. 최상위 댓글 입력에는 길이 제한이 없다(현 동작).

### RP-3 정렬과 페이지네이션

**수용 기준**

- 최상위 댓글: `createdAt desc`(최신순). 스토어는 페이지 로드(`limit` + `startAfter`)를 지원하지만, **현재 UI는 첫 페이지(기본 20개)만 로드하고 추가 로드 트리거가 없다** (미해결 질문 참조).
- 답글: `createdAt asc`(오래된순) 전체 로드.

### RP-4 수정/삭제 권한

**수용 기준**

- 수정·삭제 메뉴는 본인 댓글(`authorId === 내 uid`)에만 노출되고, 스토어에서도 `authorId`를 재검증한다.
- **최상위 리뷰 수정 화면에는 별점 입력을 추가**(기존 별점·글 프리필)하고, 별점 변경 시 요약 `ratingSum`/`ratingAvg` 델타를 반영하기 위해 `updateComment`도 **트랜잭션**으로 처리한다. 답글 수정은 글만. (수정 화면 프레젠테이션은 기존 방식 유지 — 작성만 formSheet 모달.)
- 삭제 시 답글이 있으면 **논리 삭제**(`isDeleted: true`, 내용 `'[삭제된 댓글입니다]'`), 없으면 물리 삭제. 삭제 트랜잭션은 요약 카운트·부모 `replyCount`와 함께 **별점 집계**(최상위 리뷰가 별점을 가졌으면 `ratingSum`/`ratingCount`/`ratingAvg` 감소)를 갱신한다. (논리 삭제도 집계에서 제외한다 — 화면에서 안 보이므로.)
- `isDeleted` 댓글은 목록 UI에서 필터링되어 보이지 않는다(현 동작 — 미해결 질문 참조).

### RP-5 좋아요

**수용 기준**

- 좋아요는 토글이며 `comment-likes/{userId}_{commentId}` 문서 생성/삭제 + `likeCount` 증감을 트랜잭션으로 처리한다.
- 비로그인 상태에서 좋아요/삭제를 시도하면 전역 로그인 모달(`LogInAlertManager.show()`)을 띄운다.

### RP-6 별점 표시 (신규)

**수용 기준**

- 장비 상세 리뷰 섹션 헤더에 **평균 별점(★ n.n)과 별점 리뷰 수**를 표시한다(요약 문서 `ratingAvg`/`ratingCount`). 별점 리뷰가 0건이면 평균을 숨긴다.
- 최상위 리뷰 항목(`ReplyItemView`)에 해당 리뷰의 **별점(★, 비편집)** 을 작성자/날짜 근처에 표시한다. `rating`이 없는 레거시 댓글은 별점을 표시하지 않는다.
- 답글에는 별점을 표시하지 않는다.

### RP-7 화면 문법 (as-built 2026-08-13)

리뷰 화면 4개(목록 · 답글 상세 · 쓰기 시트 · 수정)는 **[Home.md](Home.md) HM-8 시각 문법**을 그대로
따른다. 값은 전부 `constants/DesignTokens.ts`에서 오고 화면에 리터럴로 쓰지 않는다.

**2026-08-13 사용자 지적으로 이식했다** — 이 화면들만 옛 ACG 세대(각진 면 · 잉크 사각 버튼)에
남아 있어서, 장비 상세에서 `리뷰 남기기`를 누르면 앱의 다른 시트와 다른 문법이 올라왔다.

| 요소 | 규칙 |
| --- | --- |
| 지면 | 순백(`Acg.paper`). 목록·답글 상세는 절대 위치 `ground` 뷰가 깐다(투명 네이티브 헤더 아래로 흐르게) |
| 면 | 리뷰 행 · 원 리뷰 · 답글 · 입력칸 · 입력 유도 바 모두 `Acg.controlFill` + **`AcgRadius.thumb`(12)**, 테두리·그림자 없음 |
| 화면·시트 제목 | `AcgType.screenTitle`(22) semibold — 목록 `리뷰`, 쓰기 시트 `리뷰 쓰기`, 수정 화면 `리뷰 수정`/`답글 수정` |
| 라벨 | `AcgType.sectionSubtitle` + `Acg.textMuted`(`별점`·`리뷰 글`), 글자 수 카운터는 `AcgType.meta` |
| 본문 | **여러 줄이라 `AcgType.body`**(14/21). 옛 값은 `sectionSubtitle`(15)이었는데 그건 한 줄 부제 단이다 |
| 여러 줄 입력 | `AcgType.body` 스프레드 + `fontFamily: 'Pretendard-Regular'`. TextInput은 `PretendardText`를 못 쓰므로 서체를 직접 지정한다(배낭 편집 검색 입력과 같은 방식) |
| 주 액션 | **화면당 라임 알약 하나** — 쓰기 시트 `등록`, 수정 화면 `완료`(Android/Web), 답글 입력 `저장`. `Acg.lime` 채움 + 잉크 semibold + `borderRadius = 높이/2` |
| 보조 액션 | 쓰기 시트 `취소` — `Acg.controlFill` 채움 알약 + 잉크. 형태(알약)로 액션임을 말하고, 색 단계로 주/보조를 가른다 |
| 비활성 | `Acg.controlFill` 채움 + `Acg.textMuted` 글자. **`opacity`·`#CCCCCC` 하드코딩을 쓰지 않는다** — 반투명 라임은 채도가 빠져 다른 색으로 읽힌다 |
| 별점 | `StarRatingView`(#FFB300)는 **의미색 예외**라 그대로 둔다 |
| 아이콘 전용 컨트롤 | 더보기(`ellipsis-horizontal`)·좋아요는 `accessibilityLabel` + `accessibilityRole='button'` + `hitSlop`으로 44pt 확보. 행 높이를 늘리지 않으려 44×44 박스 대신 `hitSlop`을 쓴다 |

**이 화면 고유 결정**

- **라임을 글자색으로 쓰지 않는다** — 내 리뷰 작성자명과 @멘션이 `Acg.limeText`였다. 라임은
  화면당 하나이고 그 하나는 **눌러야 하는 면**의 몫이라, 목록에 라임 글자가 섞이면 그 화면에
  라임이 둘이 된다. 대신:
  - **내 리뷰는 날짜 줄에 ` · 내 리뷰` 조각**으로 밝힌다. 배지·칩을 행 안에 두지 않는 규칙에 따라
    작은 사각형이 아니라 메타 줄의 글자 조각이다.
  - **@멘션은 잉크 semibold** — 굵기로 가른다.
- **더보기 버튼의 `opacity: 0.3`을 걷었다.** 아이콘을 흐리게 만드는 대신 색 토큰(`Acg.textMuted`,
  순백 위 AA 4.5)을 쓴다 — 반투명은 대비를 계산할 수 없다.
- **목록 화면(Android/Web)의 헤더 타이틀을 비웠다.** 헤더 바에 `리뷰`, 콘텐츠에 큰 제목 `리뷰`가
  겹쳐 한 화면에 같은 낱말이 두 번 나왔다(iOS는 이미 `headerTitle: ''`). 화면 제목은 콘텐츠 안
  큰 제목이 맡고 바에는 back만 둔다.
- **수정 화면에 제목을 세웠다** — 이전에는 제목이 아예 없어 무엇을 고치는 화면인지 back 버튼
  말고는 단서가 없었다. `isTopLevel`로 `리뷰 수정`/`답글 수정`을 가른다.
- **쓰기 시트 주 액션 라벨 `확인` → `등록`.** 컨트롤은 실제로 일어나는 일을 말해야 한다(HM-1과
  같은 규칙) — `확인`은 무엇이 확인되는지 말하지 않는다.
- **목록 하단 입력 유도 문구 `댓글을 입력해보세요` → `리뷰를 남겨보세요`.** 이 화면은 `리뷰`이고
  빈 상태도 `첫 리뷰를 남겨보세요`인데 유도 바만 `댓글`이라 같은 것을 두 이름으로 불렀다.
- **iOS 수정 화면의 `완료`는 라임 알약이 아니다** — 네이티브 헤더의 바 버튼이라 시스템 문법
  (텍스트 버튼, 잉크 semibold / 비활성 `Acg.textMuted`)을 따른다. 알약을 헤더에 끼워 넣으면
  시스템 back과 짝이 안 맞는다. Android/Web은 하단 라임 알약 그대로.

## 8. 미해결 질문

- 논리 삭제된 댓글(`[삭제된 댓글입니다]`)이 UI에서 완전히 필터링되면 그 아래 답글 접근 경로가 모호하다 — 의도 확인 필요.
- 최상위 댓글 입력에 길이 제한이 없다(답글만 1000자) — 정책 통일 여부.
- **21번째 이후 댓글은 볼 방법이 없다** — 스토어의 `startAfter` 페이지네이션을 UI(`Reply.ts`, `ReplyView`)가 소비하지 않음. 더보기/무한 스크롤 도입 필요.
- 날짜 포맷 불일치: 답글 상세만 `YYYY. M. D` — 통일 필요.
