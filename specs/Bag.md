## 1. 개요

배낭 탭은 사용자의 배낭(패킹 리스트) 목록과 생성 진입점이다.
배낭 1개 = 여행/산행 1회의 장비 구성 + 날짜 범위.

## 2. 화면 및 진입

```
app/(tabs)/bag.tsx → BagView
  ├─ BagItemView × n  (배낭 행)
  └─ BagAddView       (생성 모달: 이름 + DateRangeCalendarView 날짜 범위)
```

- 배낭 행 클릭 → `/bag/{id}` ([BagDetail.md](BagDetail.md))
- 생성 완료 → `/bag/{id}`로 자동 이동

## 3. 요구사항

### BAG-1 배낭 목록

**수용 기준**

- `users/{uid}.bags` 배열의 ID로 `bag` 컬렉션을 조회하고 선택된 정렬(BAG-6, 기본 `최근 추가순` = `createdAt desc`)로 표시한다.
- **배낭이 30개를 넘어도 전부 표시된다.** 이 조회는 `where('__name__','in', bagIDs)`라 Firestore `in` 30개 상한에 걸리므로 30개 단위로 청크 분할해 병렬 조회한다([DataModel.md](DataModel.md) DM-25). `orderBy`는 청크별로만 걸리므로 **병합 후 클라이언트에서 정렬**한다(BAG-6).
- `startDate`가 없는 배낭은 **날짜 정렬에서** 맨 뒤에 둔다(방향 무관 — BAG-6). 이름·무게 정렬에서는 해당 필드 기준으로 자연 정렬된다. 서버 `orderBy('startDate')`는 이런 문서를 결과에서 제외했으므로, 청크 분할 이후 **이전에는 목록에 안 보이던 레거시 배낭이 새로 나타날 수 있다**(생성·복사 경로가 항상 `toISOString()`을 쓰므로 실제로는 거의 없다 — DM-5).
- 각 행에 이름, 날짜, 총 무게(kg)를 표시한다. 복사·삭제는 상시 노출 버튼이 아니라 **행 트레일링 스와이프 액션**으로 제공한다(BAG-3/BAG-4). (`editDate`는 저장되지만 목록에 표시되지 않는다 — 미해결 질문 참조.)
- **행은 좌 정체 · 우 지표의 2열**(2026-07-28, [Warehouse.md](Warehouse.md) WH-1 공통 행 레이아웃과 동일 문법) — 좌측은 배지·이름·기간, 우측 트레일링 컬럼은 **총 무게(kg)**(우측 정렬, 콘덴스드 큰 숫자 + 작은 단위). 무게가 행마다 같은 자리에 와 배낭 간 비교가 쉬워진다. 이름이 길면 말줄임해 우측 컬럼을 침범하지 않는다.
- **행은 지면 위 카드다**(2026-08-10 개정, Liquid Depth). 구분선으로 나누지 않고 카드 면으로 나눈다 — 예정·여행 중은 **흰 종이 카드**, 지난 여행은 **조용한 면(`surfaceQuiet`) + 0.5px 보더**로 낮춘다. 목록을 훑을 때 앞으로 갈 여행만 눈에 걸려야 하고, 지난 기록은 지우지 않고 자리에 남긴다.
  - 카드 모서리·여백·그림자는 토큰을 따른다(카드 radius 22, 내부 패딩 18, 카드 사이 10). 스와이프 컨테이너가 콘텐츠를 클리핑하므로 **그림자는 바깥 껍데기가 들고** 모서리만 안쪽에서 깎는다.
- **시각 위계**: 이름·무게는 `ink`, 기간은 `inkMuted`로 낮춘다. 지난 카드는 무게까지 `inkSecondary`/단위 `inkSubtle`로 한 단계 내린다.
- **접근성(HIG)**: 행은 `accessibilityRole='button'` + 라벨(`{배지}, {이름}, {날짜}, {무게}[, 패킹 {n}/{m}]`)을 갖는다. 배지·진행 줄은 행 안의 텍스트지만 행 전체가 하나의 버튼이라 라벨에 함께 실어야 읽힌다. 스와이프로 노출되는 복사/삭제 액션 버튼은 각각 `accessibilityLabel`(`배낭 복사` / `배낭 삭제`)을 갖는다.
- **헤더는 2단이다**(2026-08-10 개정): 화면 대상인 `배낭`(32/38)을 제목으로 두고 그 아래 보조 줄에 `{개수}개 · 평균 {무게}`(예 `4개 · 평균 8.4kg`)을 붙인다. 우측은 정렬 드롭다운(BAG-6)이며 두 줄의 아래에 맞춰 앉는다.
  - 평균은 g 저장값의 합을 개수로 나눈 뒤 [DataModel.md](DataModel.md) DM-26 표기로 낸다(표시용 kg 값을 평균하면 반올림 오차가 쌓인다). **총합은 쓰지 않는다** — 여행마다 따로인 무게를 더한 값은 뜻이 없다.
- **로딩 자리는 스피너가 아니라 도착할 화면과 같은 골격의 스켈레톤이다**(제목·요약 → 구간 라벨 → radius 22 카드 3장, 1.2s 셔머). 구조가 그대로여야 데이터가 올 때 덜컥거리지 않는다.
- **플로팅 버튼 비가림(HIG)**: 목록 스크롤 콘텐츠 하단에 `배낭 추가` 플로팅 버튼 높이 이상의 여백을 둬, 끝까지 스크롤하면 마지막 행이 플로팅 버튼에 가리지 않게 한다.
- **여행 중 / 예정 / 지난 세 구간으로 나눈다** `[제안]` (2026-08-05). 목록은 여행마다 한 개씩 쌓이는 축적형이라, 정렬 하나로는 "지금 가 있는 여행"과 "다음에 갈 여행"이 지난 기록 사이에 묻힌다(실사용 31개 기준 확인).
  - 판정은 배낭 상세와 같은 기준을 쓴다(`getTripPhase` — [BagDetail.md](BagDetail.md) BD-1). 오늘이 기간 안이면 `여행 중`, 종료일이 오늘 이후면 `예정`, 그 밖은 `지난`.
  - 종료일이 없으면 시작일로 판정하고, 둘 다 없으면 `지난`으로 본다(날짜 없는 레거시 배낭이 상단을 차지하지 않게).
  - `여행 중`을 예정 안의 배지가 아니라 **별도 구간**으로 두는 이유: 보통 0~1개라 있을 때만 나타나고, 있을 때는 그게 가장 급한 항목이다 — 배지로 표시하면 예정 목록 안에서 스캔해야 찾는다.
  - 각 구간은 **마이크로 섹션 라벨**(`여행 중` / `여행 예정` / `지난 여행`)로 가른다 — 큰 제목이 아니라 11px·자간 .16em 라벨이다(2026-08-10 개정: `예정`·`지난`을 `여행 예정`·`지난 여행`으로 늘렸다. 라벨 한 줄만 보고도 무엇이 묶인 구간인지 읽혀야 한다). 구간 안의 정렬은 BAG-6 선택을 그대로 따른다.
  - 빈 구간은 라벨을 렌더하지 않는다 — 실제로 대부분의 날에는 `여행 예정` + `지난 여행` 두 구간만 보이고, 첫 사용자는 `여행 예정` 하나만 본다.
  - 새 데이터를 만들지 않는다 — 이미 있는 `startDate`/`endDate`에서 파생한다.
- 날짜 표시: 시작일과 종료일이 같으면 `YYYY.MM.DD`, 다르면 `YYYY.MM.DD ~ YYYY.MM.DD`.
- 무게 표시: 저장값(g)에서 **kg 소수 한 자리, 뒤의 `.0`은 뗀다**(`0kg` `3.2kg` `10kg`) — 표기 정본은 [DataModel.md](DataModel.md) DM-26이고 `formatBagWeight()`만 이 문자열을 만든다. `BagItem`은 kg 게터를 노출하지 않는다(`getWeightGram()` 하나) — 정렬·평균·표시가 같은 값에서 나와야 어긋나지 않는다.
- **카드 배지는 구간마다 뜻이 다르다**(2026-08-10 개정 — 이전의 "우측 지표 컬럼 패킹 칩" 배치를 대체한다). 배지는 좌측 정체 컬럼의 첫 줄이며 카드마다 **하나만** 둔다. 예정 카드에 남는 정보는 *언제 떠나는지*, 지난 카드에 남는 정보는 *다 챙겼는지*다 — 둘을 함께 달면 카드마다 배지가 두 줄이 된다.
  - **여행 중 / 여행 예정** → D-day 배지(`D-6` / `오늘 출발` / `여행 중`). 계산은 홈 히어로와 같은 함수를 쓴다([Home.md](Home.md) HM-1 `getDDayLabel`) — 두 화면이 같은 배낭을 다르게 부르면 안 된다.
    - **가장 임박한 배낭 한 장만 라임 면**이고 나머지는 중립 면 + 보조 잉크 글자다. 그 한 장은 홈 히어로가 세우는 배낭과 **같은 계산**(`selectTripPlan`)으로 고른다. 화면당 라임 면은 하나뿐이라는 규칙이 여기서 지켜진다.
    - D-day 라벨이 숫자·라틴(`D-6`)일 때만 콘덴스드 서체를 쓴다. `오늘 출발`·`여행 중`은 한글이라 콘덴스드에 글리프가 없다.
    - 날짜가 없어 D-day를 계산할 수 없으면 배지를 두지 않는다.
  - **지난 여행** → 패킹 배지. 완료(100%)는 `패킹 완료`(잉크 면 + 라임 체크 + 흰 글자), 진행 중(챙긴 장비 ≥1, 미완료)은 `패킹 {percent}%`(중립 면 + 보조 잉크), 기록 없음(챙긴 장비 0)은 미표시다. 지난 카드에 D-day를 쓰지 않는다 — 이미 끝난 여행에 남은 일수는 뜻이 없다.
- **가장 임박한 카드에만 하단 진행 줄**을 둔다(2026-08-10 신설): 진행 바(h6, 트랙 `surfaceSunken` + 라임 채움) + `{n}/{m}` 콘덴스드. 담긴 장비가 0이면 그릴 값이 없어 생략한다.
  - 진행 바는 스프링·오버슈트 없음이다 — 목표를 지나쳤다 돌아오면 값이 틀린 것처럼 보인다.
  - **모든 카드에 진행 줄을 달지 않는다.** 지금 손댈 배낭 하나만 진행을 보여야 목록이 "다음에 할 일"로 읽히고, 나머지는 배지 한 줄로 스캔된다.
- **패킹 값의 단일 소스**([Packing.md](Packing.md)): `{n}/{m}`·완료율은 목록 조회로 받은 `bag` 문서의 `packedGears ∩ gears` 개수 / `gears` 개수에서만 파생한다(정수 반올림, 추가 조회 없음 — [DataModel.md](DataModel.md) DM-5). 교집합 기준이라 배낭에서 뺀 장비의 stale ID는 자연히 제외된다.
  - **홈 히어로(HM-1)·배낭 목록 카드·패킹 헤더(PK-2)가 같은 계산을 읽는다** — 세 곳이 어긋나면 안 된다.
  - 패킹/상세에서 목록으로 복귀 시 갱신된 값이 보인다 (목록 재로드 경로 기준).
- **`배낭 추가`는 우하단 플로팅 알약**(잉크 면 + 라임 `add` 아이콘)이며 탭바 위에 뜬다. 화면의 주 액션은 이것 하나다.

### BAG-2 배낭 생성

**수용 기준**

- `배낭 추가` 버튼 클릭 시:
  - 배낭이 1개 이상이면 **바텀시트**로 `새로 만들기` / `기존 배낭 복사하기` 중 선택하게 한다.
    - `새로 만들기` → **시트 없이 즉시 생성**(아래).
    - `기존 배낭 복사하기` → 원본 선택 목록(BAG-5).
  - 배낭이 0개면 바텀시트 없이 **바로 생성**한다.
  - 비로그인 처리(로그인 모달)는 기존과 동일하게 바텀시트보다 먼저 적용된다.
  - **바텀시트에서 항목을 고르면 시트를 교체한다**(`router.replace`) — 위에 겹쳐 쌓지 않는다(BAG-5의 동일 규칙 참고).
  - **시트 시각 (as-built 2026-08-11 — Liquid Depth)**: 종이 면 + 제목 22/700 → 두 행(아이콘 타일 44 `surfaceSunken` radius 18 → 제목 17/600 + 보조 설명 13.5 → 쉐브론), 행 사이는 헤어라인 하나. 아이콘은 Ionicons로 통일했다(SF Symbols는 탭바만 쓴다). **시트 상단 모서리 20은 앱의 다른 시트와 함께 두고 바꾸지 않는다** — 연달아 뜨는 시트끼리 어긋난다.
- **새로 만들기는 입력을 받지 않고 즉시 배낭을 만든다**(2026-07-31 결정).
  - 이름은 **`이번주`** 고정, 기간은 **다가오는 주말 1박(토~일)**.
  - 기준: **다가오는 토요일**. 오늘이 토요일이면 오늘이 시작일이다. **오늘이 일요일이면 이번 주 토요일은 이미 지났으므로 다음 주 토요일**을 쓴다 — 과거 날짜로 배낭이 만들어지는 것보다 낫다.
  - 이름·기간은 만든 뒤 배낭 상세에서 고친다(BD-1 정보 수정). 생성 단계에서 묻지 않는 것이 이 결정의 핵심이다 — 대부분의 배낭이 "이번 주말에 갈 것"이라 매번 같은 값을 입력하게 된다.
  - ~~생성 시트(이름 입력 + 기간 선택)~~ — 폐기. 시트가 사라지면서 **이름 무작위 기본값·다시 뽑기 버튼**(2026-07-30 도입)도 함께 걷었다. 생성 폼(`BagFormContent`)은 복사(BAG-5)·정보 수정(BD-1)에서 계속 쓴다.
- **아래 입력 규칙은 복사(BAG-5)·정보 수정(BD-1) 시트에만 적용된다** — 생성은 입력을 받지 않는다.
- **폼 시각 (as-built 2026-08-11 — Liquid Depth)**: 종이 면 시트에 제목 22/700 → **필드 라벨**(`배낭 이름`·`여행 기간` — 공용 `LiquidFieldLabel` 12.5/600 · `inkTertiary`. 섹션 머리 라벨의 대문자 마이크로 라벨이 아니다, [GearEdit.md](GearEdit.md) §2 폼 문법) → 가라앉은 **알약 필드**(h54) → 하단 취소(흰 아웃라인)·확정(잉크) 알약 두 개. 저장 중에는 확정 알약이 **라벨을 유지한 채** 앞에 진행 표시를 붙이고 재탭을 막는다([BagDetail.md](BagDetail.md) BD-7과 같은 처리). 여행 기간 필드를 누르면 그 아래로 달력이 펼쳐진다(기본 접힘) — 고른 양 끝은 잉크 원 채움, 사이는 가라앉은 면으로 잇고, 오늘 표식은 라임 계열 잉크 점이다. **달력 요일색(일 `#FF5252`/토 `#2196F3`)은 시맨틱 예외**라 그대로 둔다 — 오늘 표식은 굵기로만 내고 글자색을 덮지 않는다(덮으면 오늘이 토·일일 때 요일색이 사라진다).
  - 입력: 이름(필수, 빈 문자열 거부), 시작일, 종료일. 날짜가 없으면 저장하지 않고 알럿을 띄운다.
  - **여행 기간은 필드 하나**다. `시작일`·`종료일`을 각각 값 박스로 나누면 두 필드처럼 보이는데 실제 컨트롤은 하나이고 열리는 것도 범위 선택기 하나라 기대와 어긋난다. 이름 입력과 **같은 높이·같은 면**을 쓴다.
  - **캘린더는 기본으로 접혀 있고, 기간 필드를 누르면 펼쳐진다.** 접힌 상태에서도 선택된 기간은 보인다. **종료일까지 고르면 자동으로 접는다.**
  - 캘린더 날짜 선택 규칙: 두 날짜가 모두 선택된 상태에서 새로 누르면 범위를 다시 시작한다. 시작일 이전 날짜를 누르면 시작일을 교체, 이후 날짜는 종료일로 설정한다.
  - 시트 상단 여백·타이틀 크기는 앞 단계인 `배낭 추가` 시트와 맞춘다 — 연달아 뜨므로 다르면 화면이 튄 것처럼 보인다.
- 생성 시 `bag` 문서(`weight: 0`, `gears: []`, `shared: false`)를 만들고 `users/{uid}.bags`에 `arrayUnion`, 생성된 **`/bag/{id}` 상세로 이동한다.**
  - ~~생성 직후 장비 편집 화면(`/bag/{id}/edit`)을 자동으로 연다~~ — **2026-07-31 제거(사용자 결정).** 복사(BAG-5)도 같다. 만들자마자 편집 화면이 겹쳐 뜨면 방금 만든 배낭을 확인할 틈이 없고, 장비를 바로 담지 않을 때도 화면을 한 번 닫아야 했다.

### BAG-3 배낭 삭제

**수용 기준**

- 목록 행을 **왼쪽으로 스와이프**하면 트레일링 액션으로 `삭제`(red 배경, 파괴적 액션 시각 구분)가 노출된다. `삭제` 탭 → 확인 다이얼로그(`{이름} 배낭을 삭제할까요?`, 확인 버튼 `삭제`)를 거친다.
- 확인 시 배치로: 담긴 모든 장비의 `bags`/`used`/`useless` 배열에서 해당 배낭 ID 제거 → `bag/{id}` 삭제 → `users/{uid}.bags`에서 제거 ([DataModel.md](DataModel.md) DM-11).

### BAG-4 배낭 복사

사용자는 기존 배낭을 복제해 비슷한 구성의 새 배낭을 빠르게 만들 수 있다.

**수용 기준**

- 복사는 목록 행 **트레일링 스와이프** 액션 `복사`로 노출한다(삭제 액션과 함께 표시되며, 파괴적인 `삭제`와 시각적으로 구분한다). 스와이프 액션 버튼은 44pt 이상의 히트 영역을 갖는다.
- 복사 버튼 → **복사 모달**을 띄운다. 생성 모달(BAG-2)과 동일한 형태(이름 입력 + 날짜 범위 캘린더)에 복사 맥락을 표시한다:
  - 모달 상단에 타이틀 `배낭 복사`를 표시하고, 확인 버튼 문구는 `복사`를 쓴다 (생성 모달은 기존과 동일하게 타이틀 없음/`확인`).
  - 이름: `{원본 이름} 복사본`으로 미리 채운다 (수정 가능, 빈 문자열 거부).
  - 날짜: 생성 기본값과 동일하게 시작일 오늘, 종료일 내일 (캘린더 선택 규칙은 BAG-2와 동일).
  - 복사 확정 처리 중에는 확인 버튼을 비활성화한다 (연타로 인한 중복 생성 방지).
- 확인 시 새 `bag` 문서를 생성한다 ([DataModel.md](DataModel.md) DM-5):
  - `name` / `startDate` / `endDate`: 모달 입력값
  - `gears` / `weight`: 원본 그대로
  - `shared`: `false`, `editDate`: 복사 시점, `userId`: 현재 uid
  - `memo`: 복사하지 않는다 (여행 1회에 종속된 기록이므로)
  - `packedGears` / `packingStartedAt` / `packingCompletedAt`: 복사하지 않는다 — 패킹은 여행 1회에 종속 (`memo`와 동일 원칙, [Packing.md](Packing.md) PK-4)
- 배치로 함께 갱신한다 ([DataModel.md](DataModel.md) DM-11): 새 `bag` 문서 생성 + 담긴 각 장비의 `bags`에 새 배낭 ID 추가 + `users/{uid}.bags`에 추가.
  장비의 `used`/`useless`에는 추가하지 않는다 — **사용 여부 기록은 복사되지 않는다.**
- 복사 완료 후 생성(BAG-2)과 동일하게 `/bag/{새 id}` 상세로 이동한 뒤 **곧바로 장비 편집 화면을 연다**. 완료 토스트(`복사됐습니다`)를 표시한다. 목록 복귀 시 갱신된 목록에 복사본이 표시된다.

### BAG-5 추가 버튼 경유 복사 (원본 선택)

사용자는 배낭 추가 시점에 기존 배낭을 골라 복사할 수 있다.

**수용 기준**

- BAG-2 바텀시트에서 `기존 배낭 복사하기` 선택 → **원본 선택 목록**을 띄운다. 각 행에 배낭 목록(BAG-1)과 동일하게 이름·날짜·무게를 표시한다.
- 원본 선택 시트는 화면 높이의 60%로 뜨고, 위로 끌어 100%까지 키울 수 있다. 배낭이 많아도 **목록은 시트 높이 안에서 스크롤**되며, 마지막 행까지 잘리지 않고 도달할 수 있다(하단 세이프에어리어 여백 확보).
  - **시트 콘텐츠에 `contentStyle: { bottom: 0 }`을 반드시 준다** — 없으면 콘텐츠 래퍼 높이가 무제한이 되어 목록 스크롤이 죽는다. 근거와 상세는 [CampSite.md](CampSite.md) CS-3의 formSheet 스크롤 규칙 참고.
- 시트 제목 `복사할 배낭 선택`은 목록을 스크롤해도 **상단에 고정**된다(HIG: 화면 대상을 항상 식별 가능). 행은 좌우 20pt 여백을 유지한다.
- **로딩·빈 상태**: 목록 조회 중에는 제목 아래에 **로딩 인디케이터**를 표시하고(빈 시트를 보여주지 않는다), 조회 결과가 0건이면 빈 상태를 **사실 + 다음 걸음 두 줄**로 표시한다(`복사할 배낭이 없어요` / `먼저 배낭을 하나 만들어요` — 2026-08-11 as-built). 조회 실패도 빈 배열로 수렴하므로 같은 빈 상태를 쓴다(§6 엣지 케이스).
- **시트 시각 (as-built 2026-08-11 — Liquid Depth)**: 종이 면 + 고정 제목 22/700, 행은 이름(15/600) · 날짜(12.5 보조 잉크) 두 줄 + 우측 무게(콘덴스드 17, 단위까지 한 덩어리) + 쉐브론이며 헤어라인으로만 갈린다.
- **접근성(HIG)**: 행은 BAG-1과 동일하게 `accessibilityRole='button'` + 라벨(`{이름}, {날짜}, {무게}`)을 갖는다. 우측 꺾쇠(chevron)는 장식이라 별도 라벨을 두지 않는다.
- 원본 행 선택 → 원본 선택 시트를 **복사 모달로 교체**한다(시트를 위에 겹쳐 쌓지 않는다). BAG-4의 모달·프리필·확정 동작을 그대로 재사용한다.
  - 시트를 쌓지 않는 이유: formSheet 라우트가 2단으로 쌓인 상태에서 복사 확정 후 상세·편집으로 이동하면 내비게이션 옵션 적용이 무한 리렌더에 빠져 화면이 죽는다(`Maximum update depth exceeded`). `새로 만들기`(BAG-2)가 바텀시트를 교체하는 것과 같은 규칙이다.
  - 교체이므로 복사 모달에서 취소·뒤로가기 시 원본 선택 목록이 아니라 배낭 목록으로 돌아간다.
- 이후 확정·데이터·이동·토스트 동작은 BAG-4와 동일하다.

### BAG-6 배낭 목록 정렬 `[제안]`

사용자는 배낭 목록의 정렬 순서를 선택할 수 있고, 선택은 기기에 저장된다.

**수용 기준**

- 옵션은 6개다. 라벨과 기준:

  | 라벨 | 기준 |
  | --- | --- |
  | `최근 추가순` (기본) | `createdAt` 내림차순 |
  | `최근 여행순` | `startDate` 내림차순 |
  | `오래된 여행순` | `startDate` 오름차순 |
  | `무거운순` | `weight` 내림차순 |
  | `가벼운순` | `weight` 오름차순 |
  | `이름순` | `name` 오름차순 |

- **`최근 추가순`이 기본 정렬이다**(2026-07-31 변경, 이전 기본은 `최근 여행순`). 방금 만든 배낭이 맨 위에 와야 바로 이어서 작업한다. **이미 정렬을 고른 사용자는 저장된 선택이 그대로 유지된다** — 기본값은 저장된 값이 없을 때만 쓰인다.
- **`최근 추가순`은 `createdAt` 기준이다**(2026-07-31 추가). 여행 날짜와 만든 순서는 다르다 — 다음 달 여행을 오늘 만들 수 있다.
  - `createdAt`은 **생성 시 1회만** 쓰고 이후 갱신하지 않는다([DataModel.md](DataModel.md) DM-5). 생성·복사 두 경로 모두에 쓴다.
  - **2026-07-31 이전 문서에는 이 필드가 없다.** 없으면 `editDate`로 대체한다 — 수정한 적 없는 배낭은 두 값이 같아 정확하고, 수정한 배낭은 실제 생성보다 뒤로 잡힌다. `editDate`도 없으면 날짜 정렬과 같은 규칙으로 **맨 뒤**에 둔다(값 없음은 "가장 오래됨"이 아니라 미상이다).
  - 소급 보정(마이그레이션)은 하지 않는다. 옛 배낭의 정확한 생성 시각은 어디에도 남아 있지 않아 만들어 낼 수 없다.

- **정렬은 전부 클라이언트에서 수행한다.** 목록 조회가 청크 분할이라 서버 `orderBy`를 쓸 수 없다(BAG-1, [DataModel.md](DataModel.md) DM-25). 비교 기준은 DM-25을 따른다 — 문자열은 **코드포인트 순**(`localeCompare` 아님), 날짜·무게는 값 비교, **동률은 문서 ID 오름차순** 타이브레이크.
- **`가벼운순`에 [Warehouse.md](Warehouse.md) WH-3의 0g 규칙을 적용하지 않는다.** 창고의 `weight: 0`은 무게 미입력이지만, 배낭의 `weight: 0`은 **장비를 담지 않은 빈 배낭**이라 실제로 가장 가벼운 것이 맞다. 자연 순서대로 맨 앞에 둔다.
- **`startDate`가 없는 배낭은 날짜 정렬에서 방향과 무관하게 맨 뒤**에 둔다(`최근 여행순`·`오래된 여행순` 모두). 값이 없는 것은 "가장 오래됨"이 아니라 미상이다. 이름·무게 정렬에서는 해당 필드 기준으로 자연 정렬된다(BAG-1의 "맨 뒤" 규칙은 날짜 정렬 한정).
- 정렬 선택 UI는 **공용 네이티브 formSheet 라우트 `/sort-sheet`**를 재사용한다(창고 WH-3·피드·탐색과 동일 — 타이틀 `정렬` + 옵션 행, 선택 옵션 체크·볼드, 항목 탭 시 즉시 적용 후 닫힘).
  - 시트 시각은 Liquid Depth로 옮겼다(2026-08-10): 흰 면 + 타이틀 22/700, 옵션 행은 44pt 이상 + 선택 시 semibold·잉크 / 미선택 medium·보조 잉크, 우측 체크는 잉크. **시트 상단 모서리(20)는 앱의 다른 시트와 함께 두고 바꾸지 않는다** — 이 라우트만 28로 올리면 연달아 뜨는 다른 시트들과 어긋난다.
- 진입점은 `배낭` 헤더 행의 **우측 정렬 드롭다운**(현재 정렬 라벨 13.5/600 + 쉐브론, 예 `최근 추가순 ⌄`)이다. 창고의 컨트롤 행·탐색 필터 줄과 같은 문법이며, 시각 높이는 32지만 `hitSlop`으로 44pt 터치 타깃을 채운다.
- 선택 시 즉시 목록을 다시 정렬해 표시하고, `LocalStorageManager`에 `selectedOrderType_bagList`로 저장되어 앱 재실행 후에도 유지된다. **창고(`warehouse`)·배낭 편집(`bag`) 선택값과 공유하지 않는다** — 정렬 대상이 장비가 아니라 배낭이다.
- 빈 목록(§6)에서는 헤더 행과 함께 정렬 드롭다운도 렌더하지 않는다.
- **접근성**: 드롭다운은 공용 `OrderButtonView`가 제공하는 `accessibilityRole='button'` + 라벨(`정렬: {선택 라벨}`)을 그대로 쓴다 — 같은 컴포넌트를 쓰는 창고(WH-3)·배낭 편집(BD-4)과 문구를 맞춘다. (피드·탐색은 `/sort-sheet` 라우트만 공유하고 이 버튼을 쓰지 않아 라벨이 없다.)

## 6. 엣지 케이스

- **비로그인**: 목록은 빈 배열, 추가 버튼은 로그인 모달 표시. 로그인 변화에 reaction으로 자동 갱신.
- **로딩**: 목록 골격 스켈레톤 표시(BAG-1). 스피너는 쓰지 않는다.
- **빈 목록**: **사실 + 다음 걸음 두 줄**로 안내한다 — `아직 만든 배낭이 없어요` / `이번 주말 1박으로 하나 만들어 둘까요?`(2026-08-10 개정). 다음 걸음이 `배낭 추가`가 하는 일(주말 1박 즉시 생성, BAG-2)과 같은 말이어야 버튼을 누를 이유가 생긴다.
- **원본 선택 시트 로딩/조회 실패**(BAG-5): 조회 중에는 로딩 인디케이터를 표시한다. `BagStore.getList()`는 실패를 삼키고 빈 배열을 돌려주므로 실패와 0건을 구분하지 않고 같은 빈 상태 문구(`복사할 배낭이 없어요`)를 표시한다 — 어느 경우든 제목만 있는 빈 시트를 보여주지 않는다.

## 7. 수동 검증 체크리스트

- [ ] 생성 → 상세 위에 장비 편집 화면이 바로 열림, 뒤로가기 → 상세, 목록 복귀 시 최신(시작일 내림차순) 위치에 표시
- [ ] 복사 확정 → 복사본 상세 위에 장비 편집 화면이 바로 열림 (담긴 장비 체크 상태), 뒤로가기 → 복사본 상세
- [ ] 같은 날짜로 생성 → 단일 날짜 표기
- [ ] 배낭 삭제 → 담겨 있던 장비의 상세 "배낭 기록"에서 해당 배낭이 사라짐
- [ ] 비로그인 → 추가 버튼이 로그인 모달
- [ ] 배낭 복사 → 모달 타이틀 `배낭 복사`·이름 `{원본 이름} 복사본` 프리필·날짜 오늘~내일 → `복사` 버튼 → 복사본 상세 이동 + 토스트
- [ ] 복사본 상세 → 장비 목록·총 무게가 원본과 동일, 메모는 비어 있음
- [ ] 복사 모달에서 이름을 지우고 확인 → 거부(생성과 동일한 알럿)
- [ ] 복사본에 담긴 장비의 상세 "배낭 기록"에 복사본 배낭이 추가로 표시
- [ ] 원본에서 사용 여부를 기록한 장비도 복사본에서는 미기록 상태
- [ ] 복사 직후 원본 삭제 → 복사본과 장비 연결은 유지
- [ ] 비로그인 → 복사 버튼 동작이 로그인 모달(추가 버튼과 동일 규칙)
- [ ] 배낭 ≥1개 → 추가 버튼 → 바텀시트(새로 만들기/기존 배낭 복사하기) 표시
- [ ] 배낭 0개 → 추가 버튼 → 바텀시트 없이 바로 생성 모달
- [ ] 행을 왼쪽으로 스와이프 → 트레일링 `복사`/`삭제` 액션 노출, `삭제`는 red로 구분
- [ ] `삭제` 스와이프 액션 → 확인 다이얼로그, `복사` 스와이프 액션 → 복사 모달 (버튼 방식과 동일 동작)
- [ ] VoiceOver: 행(`{배지}, {이름}, {날짜}, {무게}[, 패킹 {n}/{m}]`)·`복사`·`삭제` 라벨이 읽힘
- [ ] 목록 끝까지 스크롤 → 마지막 행이 `배낭 추가` 플로팅 버튼에 가리지 않음
- [ ] 기간 텍스트가 이름·무게보다 옅은 회색(`inkMuted`)으로 표시
- [ ] 예정 배낭이 2개 이상 → **가장 임박한 카드만** 라임 D-day 배지 + 하단 진행 줄, 나머지는 중립 배지 한 줄
- [ ] 홈 히어로에 선 배낭과 목록에서 라임 배지가 붙은 배낭이 같다
- [ ] 홈 히어로·목록 카드·패킹 헤더의 `{n}/{m}`이 같은 값
- [ ] 출발 당일 배낭 → 배지가 `오늘 출발`(한글이라 콘덴스드가 아닌 Pretendard로 정상 렌더)
- [ ] 지난 여행 카드 → 조용한 면 + 보더, 패킹 완료면 잉크 배지 + 라임 체크, 미완료면 `패킹 {N}%`
- [ ] 로딩 → 스피너가 아니라 카드 골격 스켈레톤이 보이고, 목록이 와도 레이아웃이 튀지 않음
- [ ] 빈 목록 → `아직 만든 배낭이 없어요` + `이번 주말 1박으로 하나 만들어 둘까요?` 두 줄
- [ ] 배낭 30개 초과 계정: 목록이 비지 않고 전부 보이며 `startDate` 최신순이 유지된다 (30개 이하 계정도 기존과 동일)
- [ ] 정렬 드롭다운 → 시트에서 5개 옵션 노출, 현재 옵션 체크. 각 옵션 선택 시 목록이 즉시 재정렬 (BAG-6)
- [ ] 정렬 변경 후 앱 재시작 → 선택 유지. 창고에서 고른 정렬과 서로 영향 없음
- [ ] `가벼운순` → 빈 배낭(0kg)이 맨 앞에 온다 (창고와 반대 — 배낭 0g은 미입력이 아니라 빈 배낭)
- [ ] 배낭 30개 초과 계정에서 각 정렬 옵션 → 청크 경계에서 순서가 끊기지 않는다
- [ ] 빈 목록 → 헤더 행과 정렬 드롭다운이 렌더되지 않는다
- [ ] 바텀시트 → 기존 배낭 복사하기 → 원본 선택 → 복사 모달 → 복사본 상세 이동 + 토스트
- [ ] 배낭이 10개 이상인 계정: 원본 선택 시트 → 제목이 첫 행에 가려지지 않고 좌우 여백이 유지되며, 끝까지 스크롤해 마지막 행 선택 가능
- [ ] 원본 선택 시트를 위로 끌어 100%까지 확장 → 제목 고정·좌우 여백·스크롤이 그대로 유지됨
- [ ] 원본 선택 시트 진입 직후 → 제목 아래 로딩 인디케이터 표시, 배낭 0개(또는 조회 실패) → `복사할 배낭이 없어요` 표시
- [ ] 원본 선택 → 복사 모달에서 취소·뒤로가기 → 원본 선택 목록이 아니라 배낭 목록으로 복귀
- [ ] 원본 선택 → 복사 모달 → `복사` → 복사본 상세 + 편집 화면 정상 진입 (흰 화면·크래시 없음)
- [ ] 패킹 진행 중 배낭 → 목록 행에 `패킹 {percent}%`, 완료 배낭 → `패킹 완료`, 기록 없는 배낭 → 미표시
- [ ] 패킹 화면에서 몇 개 체크 후 목록 복귀 → 완료율 갱신 확인
- [ ] 패킹된 장비를 배낭 편집에서 제거 → 완료율이 교집합 기준으로 재계산됨
