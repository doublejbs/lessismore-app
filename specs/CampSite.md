## 1. 개요

전국 백패킹 박지(공식 야영장·대피소·노지 박지)를 **지도 기반**으로 둘러보고 상세 정보를 확인하는 신규 탭.
데이터는 공공 API(고캠핑·국립공원) 스냅샷 + 큐레이션 시드를 Firestore `/camp-spot`(DM-17)에 배치 적재하고,
클라이언트는 Firestore만 읽는다. 지도는 **네이버 지도**(`@mj-studio/react-native-naver-map` v1 — 레거시 아키텍처용, 공식 네이티브 SDK 래퍼)를 사용한다.
네이티브 SDK라 지도 엔진 변경은 새 바이너리에 묶인다. 과금: NCP Mobile Dynamic Map(지도 뷰 생성당 — 단가는 NCP 요금표).

노지 야영은 국립공원·상수원보호구역 등에서 **불법**일 수 있다. 유형 배지와 주의·규제 고지(CS-4)가 이 기능의 신뢰성 핵심이다.

## 2. 화면 및 진입

```
app/(tabs)/map.tsx → CampSiteMapWrapper → CampSiteMapView (네이버 지도)
  ├─ 유형 필터 칩 행 (전체/백패킹/대피소/캠핑장)
  ├─ 박지 마커 × n (유형별 색/아이콘)
  ├─ ★ 즐겨찾기 버튼 + 현재 위치 버튼 (우하단 세로 스택)
  └─ 마커 탭 → /camp-site/{id} → CampSiteDetailView (하단 바텀 시트)
                                     └─ 탭: 개요 / 날씨 / 후기
```

- 다섯 번째 탭 `지도` — iOS NativeTabs SF `map.fill`, Android JS 탭바 동일 순서. 탭 위치는 `배낭` 앞(창고/탐색/지도/배낭/정보).
- 웹은 네이버 지도 SDK 미지원이므로 탭 자체를 렌더하지 않는다.

## 3. 요구사항

### CS-1 지도 탭·지도 화면

**수용 기준**

- 초기 카메라: 위치 권한 허용 시 현재 위치 중심(줌 ~시 단위), 거부/미결정 시 남한 전역이 보이는 고정 카메라.
- `/camp-spot`의 `status == 'active'` 문서를 전량 로드해 마커로 표시한다(v1 데이터 규모 수백 건 — 클러스터링 없이 수용, 초과 시 미해결 질문 참조).
- 위치 권한은 지도 최초 진입 시 요청한다(`expo-location`, 날씨 지도 피커와 동일 흐름). 거부해도 지도·마커 조회는 가능(현재 위치 버튼만 비활성).
- 권한 허용 시 지도에 **내 위치를 네이티브 표시**(`showsUserLocation` 파란 점)한다. Android 기본 위치 버튼은 자체 버튼과 중복이라 숨긴다. `[제안]`
- 3단 래퍼 패턴(라우트 → Wrapper → View)과 도메인 모델(`CampSiteMap` + Dispatcher) 구조를 따른다.

### CS-2 마커·유형 필터

**수용 기준**

- 박지 유형은 string enum `CampSiteType`: `campground`(표시 **캠핑장**) / `shelter`(표시 **대피소**) / `wild`(표시 **백패킹**). 표시 라벨은 `CampSiteLabels.TYPE_LABEL` 단일 소스이며 데이터 값(enum)은 그대로 둔다. 마커는 유형별로 색을 달리한다 — 배낭 상세 카테고리 팔레트 재사용: 백패킹=`#4A90E2`(파랑), 대피소=`#50C878`(초록), 캠핑장=`#FFD700`(골드).
- **마커는 줌 수준과 무관하게 현재 화면(뷰포트) 영역 안의 필터 적용 마커를 전량 표시**한다(샘플링·개수 상한 없음). 겹침은 캡션 자동 숨김(`isHideCollidedCaptions`)이 처리하고 마커 자체는 항상 보인다. 카메라 이동/줌 변경 시 표시 대상을 갱신한다. **뷰포트 밖 마커는 렌더하지 않는다**(전체 spots를 전부 네이티브 마커로 올리면 탭 반응이 느려짐). `[제안]`
- **마커에는 박지 이름 캡션을 함께 표시**한다(마커 위, 검정 텍스트 + 흰 halo로 지도 위 가독성 확보). 마커·캡션이 겹치는 영역에서는 겹치는 마커의 캡션만 자동으로 숨긴다(`isHideCollidedCaptions`) — 마커 자체는 숨기지 않는다. 마커와 겹치는 **기본 지도 심볼(산 정상 POI 등)은 숨긴다**(`isHideCollidedSymbols`) — 이중 라벨 정리 + 심볼이 마커 탭을 가로채는 문제 방지. 마커 탭 표면은 44pt 히트 영역 전체가 동작해야 한다(아이콘 투명 픽셀로 탭이 통과하지 않게).
- **선택 마커 강조 + 애니메이션**: 마커를 탭해 상세 시트가 뜨면 **그 마커를 선택 상태로 강조**한다.
  - **마커(정적)**: 검정 링 없이 **유형색 원을 키우고(비선택 20 → 선택 28) + 두꺼운 흰 테두리 + 진한 그림자**로 지도에서 떠오르게 한다(유형색 유지 → 유형 정보 보존, 미니멀 톤 유지). 캡션도 살짝 키워 위로 올린다.
  - **선택 마커는 이름 캡션을 강제로 표시**한다: 비선택 마커는 겹침 시 캡션을 숨기지만(`isHideCollidedCaptions`, 줌·밀집에 따라 일부 이름이 안 보임), **선택(탭)한 마커는 `isHideCollidedCaptions=false` + 높은 `zIndex`로 이름이 항상 보이게** 한다 — 이름이 숨겨졌던 마커도 탭하면 이름이 뜬다.
  - **애니메이션**: 네이버 커스텀 뷰 마커는 정적 비트맵이라 마커 자체엔 프레임 애니메이션이 안 되므로 다음 둘로 시선을 유도한다. **(A) 펄스 링** — 선택 시 화면 중앙에 퍼졌다 사라지는 유형색 링 3회(RN Animated, 네이티브 드라이버). **(B) 카메라 포커스 이징** — 마커 탭 시 그 박지를 화면 중앙으로 부드럽게 이징(줌 유지, `animateCameraTo`). B가 선택 박지를 중앙으로 옮기므로 A(화면 중앙 고정 오버레이)가 좌표 투영 없이 마커와 정렬된다.
  - 선택 상태는 모델(`campSiteMap.getSelectedSpot`)이 단일 소스이며, 마커 레이어·펄스(observer)가 그 값을 읽어 강조한다(배낭 여행지 피커 DST-3은 자체 선택 상태를 `selectedSpotId`로 넘긴다).
- 지도 상단에 **필터 칩 두 행**(공용 `CategoryChipView` 톤) — 축당 한 행씩 담당해 리셋·색 범례가 항상 보이게 한다(두 축을 한 행에 합치면 "전체"가 스크롤 밖으로 사라지고 태그 발견 가능성이 떨어짐 — 디자인 리뷰로 확정).
  - **1행 유형 칩**: `전체 · [●백패킹] [●대피소] [●캠핑장]` — 무필터 `전체`를 **맨 왼쪽**에 두고 백패킹→대피소→캠핑장 순으로 잇는다(단일 선택). 필터 해제 수단이 늘 첫 자리에 있어야 찾기 쉽다. 라벨 앞 **마커 색 도트**(백패킹=파랑/대피소=초록/캠핑장=골드)가 지도 마커 색 범례를 겸하며, 선택(검정 채움) 상태에서는 도트에 흰 테두리를 둘러 시인성을 유지한다.
  - **2행 태그 칩**: `[산] [해변] … [숲]` 가로 스크롤. 유형과 행이 갈려 있어 `#` 접두 없이도 축이 구분되므로 접두를 붙이지 않는다. 별도 "전체" 없이 **선택된 칩을 다시 탭하면 해제**(토글)된다. 스크롤로 가려진 칩을 선택하면 보이도록 행을 자동 스크롤한다.
  - 유형·태그는 **AND 결합** — 태그 선택 시 해당 태그가 없는 spot(태그 미부여 포함)은 마커 표시에서 제외된다. 검색(CS-6)은 필터와 독립.
  - **결과 수 피드백**: 필터 변경 시 토스트로 결과 수를 알린다(예: `해변 백패킹 21곳` — 칩 라벨을 그대로 되읽으므로 `#`를 붙이지 않는다). 0건이면 `조건에 맞는 박지가 없어요`. 전체(무필터)로 돌아올 때는 토스트를 띄우지 않는다.
- 마커 탭 → **박지 상세(CS-3)를 하단 바텀 시트로** 연다(구글 지도 동작). 별도 요약 카드·요약 시트는 두지 않는다 — 상세가 곧 시트 내용이라 "자세히 보기" 같은 중간 단계가 없다.
  - **탭바를 가린다**: 시트가 탭바 위로 슬라이드 인/아웃하며 네이티브 시트 애니메이션이 그 전환을 담당한다(iOS `NativeTabs`는 탭바 전체를 숨기는 API가 없어 루트 레벨 시트로 덮는 방식을 쓴다).
  - **높이·확장**: `sheetAllowedDetents: [0.24, 0.4, 1]` — **기본은 40%**(`sheetInitialDetentIndex: 1`)이고, 위아래로 끌어 peek · 40% · 최대로 전환한다(네이티브 시트 기본 동작). 핸들바(`sheetGrabberVisible`) 노출, 모서리 radius 20.
  - **모든 detent에서 같은 레이아웃**을 쓴다 — 상단 블록·탭·탭 콘텐츠가 하나의 세로 스크롤이고 CTA만 하단 고정이라, 시트가 작아도(peek) 스크롤로 전체를 볼 수 있고 CTA는 잘리지 않는다. 그래서 detent별로 탭을 접거나 하지 않는다(이전의 peek 접기·높이 측정 로직은 이 단일 스크롤 구조에서 불필요해 제거).
    - 최소 detent 0.24는 유지한다 — 이름·설명·버튼이 보이는 최소 높이.
    - 시트 콘텐츠에 **`contentStyle`의 `bottom: 0`**(아래 항목)은 계속 필요하다 — 그래야 콘텐츠 래퍼가 시트 높이를 갖고 그 안에서 스크롤과 하단 CTA 고정이 성립한다.
  - **뒤 지도는 계속 조작 가능**: `sheetLargestUndimmedDetentIndex: 'last'`로 딤을 없애 시트가 떠 있는 동안 지도를 패닝·줌할 수 있다.
  - **닫힘**: 아래로 스와이프 또는 시트 좌상단 **닫기(X)** → 시트가 닫히고 마커 선택 강조가 해제된다. 지도 빈 곳 탭도 선택을 해제한다.
  - **시트는 항상 1개**: 시트가 떠 있는 동안에도 뒤 지도를 조작할 수 있어 다른 마커를 탭할 수 있다. 이때 **기존 시트를 닫고 새 시트를 연다**(`router.replace`) — 위로 쌓지 않는다. 닫히는 기존 시트의 선택 해제가 새로 선택된 박지의 강조를 지우지 않도록, 선택 해제는 **자기 박지가 아직 선택 상태일 때만** 수행한다.
- 지도에서 연 상세 시트 헤더에 **위치로 이동** 버튼을 둔다 — 시트가 열린 채 지도를 움직였다가 다시 해당 박지 위치로 카메라를 되돌린다(줌인 이동, 검색 결과 선택과 동일한 줌 레벨). 지도를 거치지 않고 연 상세(공유 딥링크 등)에는 되돌릴 지도가 없으므로 **표시하지 않는다**.

### CS-3 박지 상세

**수용 기준**

- 라우트는 `/camp-site/{id}`이며 **네이티브 `formSheet`로 표시**한다(CS-2). 지도 마커 탭이 주 진입이고, 공유 랜딩 딥링크(CS-7)로도 같은 화면이 열린다. 박지 데이터를 불러오는 동안 빈 화면 대신 **로딩 인디케이터**(중앙)를 표시한다.
- **시트 콘텐츠에 `contentStyle: { bottom: 0 }`을 반드시 준다** — `react-native-screens`는 formSheet의 콘텐츠 래퍼를 `top/left/right`만 건 absolute로 둔다(시트 높이 변경 시 깜빡임 방지). 그러면 **React 레이아웃 높이가 무제한**이 되어 `flex: 1`이 뷰포트를 못 잡고, ScrollView가 콘텐츠 높이만큼 늘어나 **스크롤이 아예 죽는다**(detent 아래는 잘려서 접근 불가). 하단 고정 요소(CTA·토스트)도 화면 밖에 배치된다.
  - `contentStyle`은 그 스타일 **뒤에 병합**되므로, 여기서 `bottom: 0`을 되돌리면 래퍼 높이 = 시트 높이가 된다. 그러면 `flex: 1` 체인이 살아나 스크롤·하단 고정 CTA·토스트가 정상 동작하고, **detent를 끌어 바꿔도 네이티브가 알아서 따라온다**(높이를 JS에서 계산하거나 `sheetDetentChange`를 구독할 필요가 없다).
  - 시트는 이미 홈 인디케이터 위로 떠 있으므로 **하단 세이프에어리어를 더하지 않는다** — 더하면 여백만 커진다.
  - RNS가 formSheet 안 ScrollView의 네이티브 프레임을 보정해 주는 경로(`[헤더, ScrollView]`를 화면 콘텐츠 직계 자식으로 두기)는 **이 앱에선 쓸 수 없다** — 레거시 아키텍처(`newArchEnabled: false`)에서 동작하지 않는 것으로 확인했다.
- **레이아웃**(네이버 지도 place 상세와 동일한 얼개): 위→아래로 **① 이름 ② 유형 배지·지역 ③ 설명 ④ 주요 기능 버튼 행 ⑤ 대표 사진 ⑥ 탭 바(sticky) ⑦ 탭 콘텐츠**, 그리고 **하단 고정 CTA**. ①~⑦은 하나의 세로 스크롤 안에 있고, **탭 바는 위로 스크롤될 때 상단에 고정(sticky)**된다 — 사진까지 밀어 올려도 탭은 남아 탭 전환이 가능하다.
  - **헤더 행**: 우상단에 **닫기(X)** 아이콘만 둔다(이름은 그 아래 큰 제목). 이름·설명·사진을 다 담으면 세로가 커지므로 액션은 아이콘 행이 아니라 아래 ④ 버튼 행으로 내린다.
  - **이름**: 큰 제목(1줄 말줄임). 그 아래 **유형 배지 · 지역**.
  - **설명**(`description`): 이름 바로 아래에 둔다 — "어떤 곳인지"가 사진·탭보다 먼저 읽혀야 한다. 최대 몇 줄로 제한하지 않고(짧은 스냅샷 텍스트) 그대로 표시, 비어 있으면 생략.
  - **주요 기능 버튼 행**: 설명 아래에 라벨 달린 pill 버튼을 가로로 — **공유**(CS-7) · **네이버 지도**(길찾기, CS-3) · (지도에서 연 경우) **위치로 이동**(CS-2). 아이콘+라벨 pill(네이버 place의 출발/공유/전화 톤). 버튼이 넘치면 가로 스크롤.
  - **대표 사진**: `imageUrl`이 있으면 표시(없으면 생략). 여러 장 지원 시 가로 스크롤이나 v1은 단일.
  - **탭 바**: `개요` · `날씨` · `후기` — 가로 스크롤 없이 3개. 선택 탭은 라벨 진하게 + 하단 인디케이터. 기본 `개요`. 44pt 터치 타깃 + `accessibilityRole='tab'`. **sticky 헤더로 지정**해 스크롤 시 상단에 붙는다.
  - **탭 콘텐츠**: 선택된 탭의 내용을 탭 바 아래에 인라인으로 그린다(별도 중첩 ScrollView가 아니라 바깥 스크롤에 이어진다). 탭 전환 시 스크롤 위치는 유지하지 않는다.
  - **고정 CTA**: `배낭 여행지로 설정`(CS-5)은 스크롤과 무관하게 **하단에 고정**한다 — 박지 단위 주 액션이라 어느 탭·스크롤 위치에서도 닿아야 한다. 여행지 허브(DST-8)에서 연 상세는 이 CTA를 숨긴다(`showSetBag=false`).
- **개요 탭**: 태그 칩(`#해변` 형태, 비인터랙티브), 주의·규제 고지(CS-4), 시설(화장실/식수/데크/매점 — 있는 것만 아이콘+라벨), 접근 정보(`accessInfo`), 출처(`source`). 설명·사진은 위 상단 블록으로 올라갔으므로 여기서 제외한다.
- **날씨 탭**: 주간 예보(아래 항목 참고).
- **후기 탭**: 유저 후기(CS-8) + 블로그·영상(CS-3 후기 콘텐츠).
- **네이버 지도에서 열기**: 헤더 아이콘 버튼. **`위치로 이동`(현재 지도 카메라를 되돌림)과 눈으로 구분돼야 한다** — 둘 다 지도 계열 아이콘이면 무엇이 무엇인지 알 수 없다(디자인 리뷰). `위치로 이동`은 조준(`locate`), 이 버튼은 **외부 길찾기 성격의 방향 화살표(`navigate-outline`)** 로 의미를 갈라 놓는다. 좌표·박지명으로 네이버 지도 앱을 연다(`nmap://place?lat=..&lng=..&name=..&appname=..`). 앱 미설치·실패 시 네이버 지도 웹 검색(`https://map.naver.com/p/search/{박지명}`)으로 폴백.
- **주간 날씨**: **`날씨` 탭**에 박지 좌표로 기존 `WeatherService`(WT) 예보를 조회·표시한다(로딩 인디케이터, 실패 시 `날씨를 불러오지 못했어요` + 재시도). **탭에 처음 들어갈 때 조회**하고 이후 재사용한다 — 상세 진입만으로는 날씨를 조회하지 않는다(불필요한 호출 방지). 별도 라우트(`/camp-site-weather/{id}`)와 `주간 날씨` 버튼은 두지 않는다 — 탭으로 흡수됐다.
- 진입/길찾기 클릭 이벤트를 [Analytics.md](Analytics.md) AN-3 규칙으로 계측한다(`click_camp_site`, `click_camp_site_directions` — 구현 시 표 갱신).
- **후기 콘텐츠** `[제안]`: 상세 하단(날씨 아래)에 `후기` 섹션을 표시한다. 검색어는 두 소스 모두 `"{박지명} 백패킹"`.
  - **블로그 후기 리스트**: 네이버 블로그 검색 API(`GET https://openapi.naver.com/v1/search/blog.json`, 헤더 `X-Naver-Client-Id`/`X-Naver-Client-Secret` — env `EXPO_PUBLIC_NAVER_SEARCH_CLIENT_ID`/`EXPO_PUBLIC_NAVER_SEARCH_CLIENT_SECRET`, 네이버 개발자센터 앱)로 상위 5건 — 제목·요약(description 1~2줄)·블로거명·작성일. 항목 탭 → 외부 브라우저(`Linking.openURL`). 제목/요약의 HTML 태그·엔티티는 제거해 표시.
  - **유튜브 영상 리스트**: YouTube Data API v3(`GET https://www.googleapis.com/youtube/v3/search?part=snippet&type=video&maxResults=4`, env `EXPO_PUBLIC_YOUTUBE_API_KEY`)로 상위 4건 — 썸네일(`snippet.thumbnails.medium`)+제목+채널명 카드를 가로 스크롤로 표시. 탭 → `https://www.youtube.com/watch?v={videoId}` 열기(유튜브 앱).
  - **후기 캐시(주 1회 최신화)**: 검색 결과는 Firestore `camp-spot-review/{spotId}`([DataModel.md](DataModel.md) DM-18)에 저장해 두고, 상세 진입 시 ① 캐시가 있으면 즉시 표시 ② `updatedAt`이 **7일 이내면 재조회하지 않음** ③ 7일 초과(또는 캐시 없음)면 두 소스를 재조회해 표시하고 **둘 다 성공했을 때만** 캐시를 갱신한다. 재조회 실패 시 기존 캐시를 그대로 유지·표시한다. 검색 쿼터(유튜브 기본 10,000유닛/일, 검색당 100유닛) 절약이 목적.
  - 소스별로 키 미설정·조회 실패·0건이면 해당 리스트만 조용히 생략(두 소스 모두 0건이면 후기 섹션 자체를 생략). 별도의 `더 보기` 행은 두지 않는다.
  - 블로그·유튜브·더보기 클릭은 `click_camp_site_review`로 계측한다(AN-3, 파라미터로 소스 구분 가능 시 `source: blog|youtube`).

### CS-4 주의·규제 고지 (필수)

**수용 기준**

- **박지별 경고와 유형 고정 고지는 무게를 달리한다** — 둘을 같은 주황 박스로 나란히 쌓으면 한 덩어리로 뭉쳐 보여 둘 다 안 읽히고(디자인 리뷰), 시트의 좁은 콘텐츠 영역을 경고가 차지해 설명이 밀린다.
  - `warnings` 필드가 있으면 개요 탭 상단에 **경고 박스**(주황 계열 시맨틱 색)로 항상 표시한다(접힘 없음). 이 박지에만 해당하는 정보라 눈에 띄어야 한다.
  - `wild`(노지) 유형에는 warnings 유무와 무관하게 고정 고지를 표시하되, **박스가 아니라 경고 아이콘 + 한 줄 텍스트**로 낮춘다: `노지 야영은 지역에 따라 금지될 수 있습니다. 이용 전 반드시 현지 규정을 확인하세요.` 유형 전체에 붙는 일반 안내라 박지별 경고보다 약해야 하며, 유형 배지(백패킹)가 이미 맥락을 준다.
- 지도 화면 최초 진입 시 1회(기기 저장) 동일 취지의 안내를 노출한다(토스트/배너 중 구현 시 결정).

### CS-5 배낭 여행지로 설정

**수용 기준**

- 상세에 `배낭 여행지로 설정` 버튼을 둔다. 내 배낭을 선택하면 공용 여행지 저장 동작([BagDestination.md](BagDestination.md) DST-5/DST-6)으로 박지 참조와 박지명·좌표 스냅샷을 해당 배낭의 여행지로 저장한다. 별도의 날씨 위치는 두지 않는다.
- 배낭 선택 시트 상단에 **`새 배낭 만들기` 행**을 둔다 → 탭 시 시트를 닫고 배낭 생성 formSheet(`/bag-new`)로 이동한다. 박지 여행지를 `PendingBagLocationHandoff`로 넘겨 배낭 이름 입력란을 **박지명으로 프리필**하고, 생성 완료 후 새 배낭의 여행지로 자동 저장한다(생성→편집 기존 흐름 유지). 배낭이 0개여도 이 행으로 새 배낭을 만들며 여행지를 설정할 수 있다.
- 시트 UX: 헤더에 **`{박지명}을 여행지로 설정해요` 서브텍스트**로 맥락을 준다. 생성 행과 배낭 목록은 `내 배낭` 소제목으로 영역을 나눈다. 배낭 목록은 **최근 수정순**(편집일 desc)으로 정렬해 방금 만든/최근 쓴 배낭을 위로 올린다. **이미 여행지가 설정된 배낭 행에는 `📍{기존 박지명}`을 표시**해 덮어쓰기 전에 인지시킨다.
- 기존 여행지가 선택한 박지와 다르면 `{기존 여행지명}에서 {박지명}(으)로 변경할까요?` 확인 후 저장한다. 같은 박지가 이미 연결돼 있으면 확인 없이 완료 처리한다.
- 설정 완료 토스트(`여행지로 설정했어요.`)에 **`이동` 액션 버튼**을 넣어 해당 배낭 상세(`/bag/{id}`)로 바로 이동할 수 있게 한다. (Android는 네이티브 토스트라 버튼 미지원 — 메시지만 표시, 기존 토스트 액션 관례와 동일)
- 비로그인은 로그인 안내를 표시한다. 배낭 0개는 시트를 열어 `새 배낭 만들기`만 제공한다.

### CS-6 박지 검색 `[제안]`

사용자는 지도에서 박지를 이름/지역으로 검색해 바로 이동할 수 있다.

**수용 기준**

- 지도 상단(필터 칩 행 위)에 검색 인풋(`박지 검색`, 흰 pill)을 상시 노출한다. 입력값으로 **로드된 spots를 클라이언트에서 필터**한다(추가 조회 없음): `name` 또는 `region`에 검색어 포함(대소문자 무시). 유형 필터(CS-2)와는 독립 — 검색은 전체 spots 대상.
- 입력 중에는 인풋 아래 **결과 리스트**(최대 20건: 이름·유형 배지·지역)를 드롭다운으로 표시한다. 결과 0건이면 `검색 결과가 없어요` 행.
- 결과 항목 탭 → 키보드/리스트 닫기 + 해당 박지로 **카메라 이동(줌인)** + 상세 시트 오픈(CS-2 흐름 재사용) + 검색어 유지.
- 인풋 클리어(X) 버튼으로 검색어·리스트 초기화(창고 WH-8과 동일한 커스텀 X 1개).
- 검색 리스트가 열려 있는 동안 지도 터치는 리스트를 닫는다(키보드 dismiss 포함).

### CS-7 공유 `[제안]`

사용자는 박지를 외부(카카오톡 등)로 공유하고, 받은 사람은 웹 랜딩을 거쳐 앱으로 진입한다.

**수용 기준**

- 상세 헤더 우측에 **공유 아이콘 버튼**(지도 열기 버튼 왼쪽). 탭 → OS 공유 시트(`Share.share`)로 URL `https://useless.my/camp-share/{encodeURIComponent(spotId)}`**만** 내보낸다(문서 id의 콜론은 메신저 자동 링크화가 끊기지 않게 `%3A`로 인코딩 — 웹 랜딩이 복원)(이름 등 텍스트를 붙이면 '복사' 시 URL이 아닌 문자열이 복사돼 링크로 동작하지 않음).
- 공유 클릭을 `click_camp_site_share`로 계측한다([Analytics.md](Analytics.md) AN-3).
- **웹 랜딩**(별도 레포 `lessismore`, `/camp-share/:id`): Firestore `/camp-spot/{id}`(공개 읽기)를 읽어 이름·유형·지역·사진·설명·주의를 보여주고, **`앱에서 보기`** 버튼으로 `lessismoreapp://camp-site/{id}` 딥링크(미설치 시 스토어 폴백)로 앱을 연다. Universal Link는 쓰지 않는다(웹 랜딩을 먼저 보여주는 의도).

### CS-8 유저 후기 (별점·글·다녀온 배낭) `[기획]`

이용자가 박지에 **별점(필수)·후기 글(선택)·다녀온 배낭(선택)**을 남기고, 다른 이용자는 이를 읽고 첨부된 배낭(장비 구성)을 앱 내에서 열람한다. 외부 블로그·유튜브 후기(CS-3)와는 **별개의 유저 생성 콘텐츠**(데이터: [DataModel.md](DataModel.md) DM-20). 작성자 식별·로그인 가드·소유자 삭제는 장비 댓글(Reply, [Reply.md](Reply.md)) 패턴을 재사용한다.

**수용 기준**

- **배치**: 상세의 **`후기` 탭**(CS-3) 안에 유저 후기를 먼저 두고, 그 아래에 외부 콘텐츠 섹션을 **`블로그·영상`**으로 이름을 바꿔 배치한다(두 "후기" 라벨 혼동 방지). 탭 이름이 이미 `후기`이므로 **유저 후기 쪽에 다시 `후기` 섹션 제목을 달지 않는다**.
- **요약 헤더**: 섹션 상단에 **평균 별점(★ n.n)·후기 수**를 표시한다. 후기가 0건이면 `첫 후기를 남겨보세요` — **빈 상태 안내는 `후기 쓰기` 버튼보다 위**에 둔다(안내 → 액션 순서).
- **작성 진입**: 섹션에 `후기 쓰기`(내 후기 없음) 또는 `내 후기 수정`(있음) 버튼. **전체 폭을 쓰지 않는다** — 하단 고정 CTA(`배낭 여행지로 설정`)와 폭이 같으면 주 액션이 둘로 보인다. 화면당 주 액션은 하나이며, 이 버튼은 보조로 읽히는 크기여야 한다. 탭 → 작성 화면(formSheet `/camp-review-write`, 박지 id·이름과 기존 내 후기를 모듈 핸드오프로 전달). 비로그인 시 전역 로그인 모달(`app.getLogInAlertManager()`, Reply 관례) 후 중단.
- **작성 화면**(`/camp-review-write`, formSheet): ① **별점 입력**(★ 1~5 탭, 필수 — 미선택 시 저장 비활성) ② **후기 글**(멀티라인, 선택, 최대 1000자) ③ **다녀온 배낭 선택**(선택) — `배낭 선택` 행 탭 시 내 배낭 시트(CS-5 `CampSiteBagSelectSheetView` 재사용, `새 배낭 만들기` 행은 숨김) → 고른 배낭의 이름·날짜·무게를 칩으로 표시하고 해제 가능. 저장 시 첨부 배낭은 **`bag.reviewShared=true`**(후기 전용 공개 플래그 — 링크 공유 `shared`와 별개)로 설정해 다른 이용자가 열람 가능하게 한다.
- **박지당 1개(수정)**: 후기 문서 id=작성자 uid라 한 박지에 유저당 1개(DM-20). 재작성은 기존 후기를 프리필해 **수정**(덮어쓰기). 저장은 DM-20 트랜잭션으로 요약 문서의 별점 집계(개수·평균)를 동기 갱신한다.
- **후기 리스트**: 최신순(`updatedAt` desc). 항목 = 작성자 닉네임 + 별점(★) + 날짜 + 글 + (첨부 시) **배낭 칩**(이름·무게·날짜). **내 후기는 상단 고정 + 강조**하고 `수정`/`삭제`(확인 다이얼로그)를 노출한다. 소유자 판정은 `authorId===내 uid` + 스토어 재검증(이중 방어).
- **첨부 배낭 열람**: 배낭 칩 탭 → 앱 내 **읽기전용 공유 배낭 뷰어** `/shared-bag/{bagId}`로 이동. `BagStore.getSharedBag(bagId)`로 소유자의 장비 구성을 로드해 배낭명·기간·총무게·장비 리스트를 **읽기전용**(편집·패킹 액션 없음)으로 표시한다. 뷰어는 **`reviewShared` 또는 `shared`가 true**인 배낭을 허용한다. 둘 다 아니거나 로드 실패면 `공유가 해제된 배낭이에요` 안내. (이 뷰어는 배낭 공유 [BagDetail.md](BagDetail.md) BD-7 링크의 앱 내 대응물로 재사용 가능.)
- **삭제**: 소유자만. DM-20 트랜잭션으로 요약 집계 반영(0건이면 요약 문서 정리). 첨부했던 배낭의 **`reviewShared`는 되돌리지 않는다** — 같은 배낭이 다른 박지 후기에도 첨부됐을 수 있어 레퍼런스 카운트 없이 유지하는 편이 안전하고, 후기 전용 플래그라 링크 공유(`shared`) 노출과도 무관하다.
- **계측**([Analytics.md](Analytics.md) AN-3): `click_camp_site_review_write`(작성 진입), `submit_camp_site_review`(저장 — 파라미터 `rating`·`has_bag`), `click_camp_site_review_bag`(첨부 배낭 열람). 구현 시 AN 표 갱신.

### CS-9 즐겨찾기 `[기획]`

이용자가 관심 박지를 즐겨찾기해 두고, 지도에서 즐겨찾기만 모아 볼 수 있다. 로그인 사용자 전용(비로그인 → 전역 로그인 안내, Reply 관례). 데이터: [DataModel.md](DataModel.md) DM-21.

**수용 기준**

- **토글 진입점**: 상세 상단 **주요 기능 버튼 행 맨 앞**에 `즐겨찾기` pill 버튼(별 아이콘). 미등록=`star-outline`+`즐겨찾기`, 등록=`star`(채움, 브랜드 액센트 없이 시맨틱 노랑 `#FFD700` — 마커 캠핑장색과 동일 리터럴)+`즐겨찾기됨` 라벨. 탭 시 즉시 토글(낙관적 갱신 — 실패 시 롤백 + 토스트 `잠시 후 다시 시도해주세요`).
- 비로그인 상태에서 토글 탭 → `app.getLogInAlertManager()` 로그인 안내 후 중단.
- **즐겨찾기 리스트 시트**: 지도 우하단 **현재 위치 버튼 위에 ★ 플로팅 버튼**을 둔다(별 아이콘 전용, 시맨틱 노랑 `#FFD700`, `accessibilityLabel='즐겨찾기 목록'`). 위치 권한과 무관하게 항상 노출한다(현재 위치 버튼은 권한 허용 시에만 나타나므로 위치 스택 상단에 단독으로 남을 수 있다). 탭 시 즐겨찾기한 박지 **리스트를 높이 조절 바텀 시트**로 연다 — 박지 상세 시트(CS-3)와 동일한 formSheet 라우트 방식(`sheetAllowedDetents: [0.2, 0.4, 1]`, `sheetLargestUndimmedDetentIndex: 'last'`로 딤 없이 뒤 지도 조작, `contentStyle` `bottom: 0`). 상세 시트가 아니라 라우트라 지도의 `CampSiteMap`엔 핸드오프로 콜백을 넘긴다.
  - **시트가 열려 있는 동안 지도에는 즐겨찾기 마커만** 표시한다(`favoriteOnly` 필터). 시트가 닫히면 필터를 해제해 전체 마커로 돌아간다. 필터는 유형·태그와 AND 결합한다.
  - 시트 헤더에 **닫기(X)** 버튼을 둔다(핸들바 스와이프로도 닫힘). 닫히면 필터를 해제한다.
  - 리스트 항목 = 박지명·유형 배지·지역, 우측에 **상세 버튼(chevron)**. **항목 본체 탭 → 시트를 유지한 채 그 박지로 카메라 이동**(근접 줌), **우측 상세 버튼 탭 → 즐겨찾기 시트를 그 박지 상세(CS-3)로 교체**(상세로 넘어가며 필터 해제). 여행지 선택기(DST-3)에선 항목 본체 탭 시 시트를 닫고 그 박지를 선택하고, **우측 상세 버튼 탭 시 박지 상세 오버레이(`CampSiteDetailOverlayView`)를 연다**(지도 탭과 동일하게 상세 버튼을 둔다).
  - **선택기(DST-3)도 같은 formSheet 라우트를 쓴다**: 선택기가 RN Modal이 아니라 `/bag-destination-picker` 라우트라(DST-3), 그 위로 `/camp-site-favorites`가 그대로 스택돼 지도 탭과 **동일한 디텐트·높이 조절**을 얻는다. 선택기 전용 바텀시트 구현은 두지 않는다.
  - 즐겨찾기 목록은 로드된 활성 박지와 즐겨찾기 id를 조인해 만든다(삭제·비활성 박지는 자연히 빠진다). 비로그인이 ★ 진입점(지도 탭 플로팅 버튼)을 탭하면 로그인 안내 후 중단하고, 로그인했으나 0건이면 시트에 `아직 즐겨찾기한 박지가 없어요` 빈 상태를 표시한다.
  - **여행지 선택기(DST-3)의 ★ 진입점도 지도 탭과 동일한 하단 플로팅 버튼**이다 — 하단 현재 위치 버튼 **위**에 ★ 버튼을 얹는다(우하단 세로 스택). 단 선택기는 **즐겨찾기 1건 이상일 때만** ★ 버튼을 노출한다(배낭은 로그인 전용이라 빈 상태가 사실상 없어 곧바로 리스트를 연다). 공용 `CampSiteFilterChipsView`의 ★ 칩은 지도 탭·선택기 모두 끈다(`showFavoriteChip={false}`).
- **로드**: 즐겨찾기 목록은 로그인 사용자의 지도 탭 초기화 시 1회 로드하고(`CampSiteMap`), 토글 시 로컬 상태와 Firestore를 함께 갱신한다. 상세·지도가 같은 스토어를 읽어 어느 화면에서 토글해도 즉시 반영된다.
- 즐겨찾기한 박지가 삭제·비활성돼도 즐겨찾기 문서는 남는다 — 지도 필터에는 활성 박지만 나타나므로 자연히 숨는다(DST-7과 동일한 관용).

  2. **큐레이션 시드**: 유명 노지 박지 목록(LLM 리서치 초안 → 수동 검수 필수)을 JSON으로 관리 → `wild` 유형. 좌표는 카카오 지오코딩(DST-3 재사용) 또는 수동 입력. 설명·주의 문구는 자체 작성(외부 텍스트 복사 금지).
  3. 실행 전 기존 데이터 백업 JSON 저장(`scripts/backup-*` 관례). upsert는 문서 id(`source:{외부id}` 또는 slug) 기준.

## 6. 엣지 케이스

- **위치 권한 거부**: 전국 카메라 폴백, 현재 위치 버튼 비활성. 마커·상세는 정상.
- **데이터 0건/로드 실패**: 지도 위 안내 배너(`박지 정보를 불러오지 못했어요`) + 재시도.
- **오프라인**: Firestore 캐시가 있으면 캐시 표시, 없으면 로드 실패와 동일.
- **사진 없는 박지**: 상세에서 이미지 영역 생략.

## 7. 수동 검증 체크리스트

- [ ] 지도 탭 진입 → 마커 표시, 유형 필터 동작
- [ ] 위치 권한 거부 → 전국 카메라 + 기능 정상
- [ ] 마커 탭 → 상세 시트(60%로 뜸, 탭바를 덮고 슬라이드 인, 뒤 지도 조작 가능), 시트 안 스크롤 동작, 닫기/스와이프 → 시트 닫힘 + 마커 강조 해제
- [ ] 시트를 위로 끌어 확장 → 콘텐츠가 늘어난 높이를 채운다(빈 흰 영역 없음), 축소 시 복귀
- [ ] 시트가 뜬 채 다른 마커 탭 → 시트가 쌓이지 않고 그 박지로 교체
- [ ] 공유 딥링크로 연 상세에는 위치로 이동 버튼이 없다
- [ ] 상세 시트 탭 전환(개요/날씨/후기) → 각 탭 콘텐츠 스크롤, 하단 CTA는 탭과 무관하게 유지
- [ ] 날씨 탭 첫 진입에만 예보 조회(개요만 보면 호출 없음)
- [ ] `wild` 상세 → 고정 규제 고지 한 줄 노출, warnings 있는 박지 → 경고 박스(둘이 시각적으로 구분됨)
- [ ] 길찾기 → 외부 지도앱 열림 (iOS/Android)
- [ ] 날씨 탭 예보 표시, 실패 시 재시도 안내
- [ ] 배낭 여행지로 설정 → 박지 참조 포함 여행지 저장 + 기존 여행지 변경 확인 + 날씨 갱신
- [ ] 배낭 0개 → 선택 시트에서 새 배낭 생성 후 동일 박지 여행지 자동 저장
- [ ] 즐겨찾기 토글(로그인 가드·낙관적 갱신) → 지도 ★ 필터에 반영
- [ ] 후기 쓰기(별점 필수, 글·배낭 선택) → 저장 후 리스트·평균 별점 반영
- [ ] 내 후기 수정/삭제 → 요약 별점 집계 갱신, 소유자만 노출
- [ ] 첨부 배낭 칩 탭 → 앱 내 읽기전용 공유 배낭 뷰어에서 장비 구성 표시
- [ ] 비로그인 후기 작성 시 → 로그인 모달
- [ ] 웹 → 지도 탭 미노출

## 8. 미해결 질문

- 마커 수가 수천 건(고캠핑 전량)이면 클러스터링/뷰포트 쿼리 필요 — v1은 큐레이션 중심으로 수백 건 이내 유지, 초과 시 재설계.
- 유저 **제보**(v2)는 검수 플로우·보안 규칙 설계 필요. (유저 후기=CS-8, 즐겨찾기=CS-9로 구현.)
- 후기 신고·차단·부적절 콘텐츠 모더레이션(v2): 현재 없음.
- 회원 탈퇴 시 유저 후기(`camp-spot-user-review`) 잔존 — 완전 삭제 정책은 [Auth.md](Auth.md) AU-8 미해결 질문과 함께 검토.
- 고캠핑 스냅샷 갱신 주기(수동 재실행 vs 주기 배치).
- 노지 박지 좌표 공개의 커뮤니티 반발 가능성(오버투어리즘) — 민감 박지 제외 기준.
