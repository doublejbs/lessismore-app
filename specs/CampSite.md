## 1. 개요

전국 백패킹 박지(공식 야영장·대피소·노지 박지)를 **지도 기반**으로 둘러보고 상세 정보를 확인하는 신규 탭.
데이터는 공공 API(고캠핑·국립공원) 스냅샷 + 큐레이션 시드를 Firestore `/camp-spot`(DM-17)에 배치 적재하고,
클라이언트는 Firestore만 읽는다. 지도는 **네이버 지도**(`@mj-studio/react-native-naver-map` v1 — 레거시 아키텍처용, 공식 네이티브 SDK 래퍼)를 사용한다.
네이티브 SDK라 지도 엔진 변경은 새 바이너리에 묶인다. 과금: NCP Mobile Dynamic Map(지도 뷰 생성당 — 단가는 NCP 요금표).

노지 야영은 국립공원·상수원보호구역 등에서 **불법**일 수 있다. 유형 배지와 주의·규제 고지(CS-4)가 이 기능의 신뢰성 핵심이다.

## 2. 화면 및 진입

```
app/(tabs)/map.tsx → CampSiteMapWrapper → CampSiteMapView (네이버 지도)
  ├─ 검색 인풋 → 결과 드롭다운 (구간: 박지 / 지명)
  │              └─ 검색 실행(submit) → 드롭다운 닫기 + 이름 일치 마커만 필터 (CS-6)
  ├─ 유형 필터 칩 행 (전체/백패킹/대피소/캠핑장)
  ├─ 박지 마커 × n (유형별 색/아이콘)
  ├─ ★ 즐겨찾기 버튼 + 현재 위치 버튼 (우하단 세로 스택)
  └─ 마커 탭 → /camp-site/{id} → CampSiteDetailView (하단 바텀 시트)
                                     └─ 탭: 개요 / 날씨 / 후기
```

- 다섯 번째 탭 `지도` — iOS NativeTabs SF `map.fill`, Android JS 탭바 동일 순서. 탭 위치는 `배낭` 앞(창고/탐색/지도/배낭/정보).
- 웹은 네이버 지도 SDK 미지원이므로 탭 자체를 렌더하지 않는다.

## 3. 요구사항

### CS-1 지도 탭·지도 화면

**수용 기준**

- 초기 카메라: 위치 권한 허용 시 현재 위치 중심(줌 ~시 단위), 거부/미결정 시 남한 전역이 보이는 고정 카메라.
- **현재 위치가 필요한 곳(초기 카메라·현재 위치 버튼)은 새 위치 fix를 요청하지 않는다.** 이미 구독 중인 위치(`watchPositionAsync`, 파란 점과 같은 소스)를 그대로 쓰고, 없을 때만 캐시(`getLastKnownPositionAsync`)로 폴백한다. 그래도 없으면 마지막에만 `getCurrentPositionAsync`를 **정확도와 시간 상한을 지정해** 부른다.
  - 근거: 안드로이드 FusedLocationProvider는 기기가 정지 상태면 위치 전달을 억제한다(`stationary throttling engaged` / `delivery blocked - too close`). 옵션 없는 `getCurrentPositionAsync({})`는 새 fix가 올 때까지 기다리므로, 책상에 둔 폰에서 **버튼을 눌러도 약 30초 뒤에야 지도가 움직였다**(2026-07-29 실기기 Pixel 7 Pro 실측). 예외가 아니라 지연이라 `catch`도 걸리지 않아 조용히 멈춘 것처럼 보였다. iOS엔 이 스로틀이 없어 안드로이드에서만 재현된다.
  - 파란 점이 정상인데 버튼만 안 듣는 것도 같은 이유다 — **점은 구독, 버튼은 일회성 요청**으로 경로가 갈려 있었다.
- **현재 위치 조회가 끝내 실패하면 토스트로 알린다.** 콘솔 로그만 남기면 사용자는 버튼이 죽은 것으로 인식한다.
- `/camp-spot`의 `status == 'active'` 문서를 전량 로드해 마커로 표시한다(v1 데이터 규모 수백 건 — 클러스터링 없이 수용, 초과 시 미해결 질문 참조).
- 위치 권한은 지도 최초 진입 시 요청한다(`expo-location`, 날씨 지도 피커와 동일 흐름). 거부해도 지도·마커 조회는 가능(현재 위치 버튼만 비활성).
- 권한 허용 시 지도에 **내 위치를 파란 점으로 표시**한다. 단 네이티브 위치 오버레이(`setLocationTrackingMode`)는 이 라이브러리(@mj-studio/react-native-naver-map)에서 **줌 스케일에 따라 점 위치가 실제 좌표에서 드리프트하는 버그**가 있어 쓰지 않고, 박지 마커와 동일한 지오 앵커 `NaverMapMarkerOverlay`(anchor `{0.5,0.5}`)로 직접 렌더한다. 위치는 `expo-location`의 `watchPositionAsync`로 구독해 갱신하고, 화면 이탈 시 구독을 해제한다.
  - **해제 기준은 언마운트가 아니라 포커스 상실(blur)이다.** 하단 탭 화면은 한 번 방문하면 다른 탭으로 옮겨도 마운트가 유지되므로, 언마운트에만 해제를 걸면 **앱이 살아 있는 내내 위치 구독이 돌아간다**(2026-07-29 확인 — 코드가 이 규칙을 지키지 못하고 있었다). 지도를 보고 있지 않은 동안 배터리를 쓰지 않으려면 포커스 기준이어야 한다.
  - **권한 요청과 초기 카메라 이동은 1회만** 한다 — 이것까지 포커스에 묶으면 탭을 오갈 때마다 카메라가 현재 위치로 되돌아가 사용자가 옮겨 둔 화면이 초기화된다.
  - **재진입 직후에는 이전 좌표를 "현재 위치"로 쓰지 않는다.** 탭을 벗어난 동안 사용자가 이동했을 수 있으므로, 구독을 다시 연 뒤 **첫 전달을 받기 전까지는** 보관 중이던 좌표를 현재 위치 버튼의 1순위로 쓰지 않고 폴백 사슬로 넘긴다. 파란 점 표시는 이전 좌표를 그대로 유지해 깜빡임을 만들지 않는다. 네이티브 기본 위치 버튼은 자체 버튼과 중복이라 숨긴다.
- 3단 래퍼 패턴(라우트 → Wrapper → View)과 도메인 모델(`CampSiteMap` + Dispatcher) 구조를 따른다.

### CS-2 마커·유형 필터

**수용 기준**

- 박지 유형은 string enum `CampSiteType`: `campground`(표시 **캠핑장**) / `shelter`(표시 **대피소**) / `wild`(표시 **백패킹**). 표시 라벨은 `CampSiteLabels.TYPE_LABEL` 단일 소스이며 데이터 값(enum)은 그대로 둔다. 마커는 유형별로 색을 달리한다: 백패킹=`#7C3AED`(퍼플), 대피소=`#44F27E`(초록), 캠핑장=`#F2D744`(골드). 백패킹은 내 위치 마커의 파랑(`#2D8CFF`)과 혼동되지 않고 지도 배경의 도로·수계 및 앱 라임 액센트와도 구분되도록 퍼플을 채택했다(2026-08-14 사용자 결정).
- **마커는 줌 수준과 무관하게 현재 화면(뷰포트) 영역 안의 필터 적용 마커를 전량 표시**한다(샘플링·개수 상한 없음). 겹침은 캡션 자동 숨김(`isHideCollidedCaptions`)이 처리하고 마커 자체는 항상 보인다. 카메라 이동/줌 변경 시 표시 대상을 갱신한다. **뷰포트 밖 마커는 렌더하지 않는다**(전체 spots를 전부 네이티브 마커로 올리면 탭 반응이 느려짐). `[제안]`
- **마커에는 박지 이름 캡션을 함께 표시**한다(마커 위, 검정 텍스트 + 흰 halo로 지도 위 가독성 확보). 마커·캡션이 겹치는 영역에서는 겹치는 마커의 캡션만 자동으로 숨긴다(`isHideCollidedCaptions`) — 마커 자체는 숨기지 않는다. 마커와 겹치는 **기본 지도 심볼(산 정상 POI 등)은 숨긴다**(`isHideCollidedSymbols`) — 이중 라벨 정리 + 심볼이 마커 탭을 가로채는 문제 방지. 마커 탭 표면은 44pt 히트 영역 전체가 동작해야 한다(아이콘 투명 픽셀로 탭이 통과하지 않게).
- **선택 마커 강조 + 애니메이션**: 마커를 탭해 상세 시트가 뜨면 **그 마커를 선택 상태로 강조**한다.
  - **마커(정적)**: 비선택은 **유형 의미색 원형 도트(18pt) + 흰 2px 테두리**, 선택은 `SpotPinView` 핀으로 표시한다. 비선택 도트는 유형색을 유지해 유형 정보를 보존하고, 선택 핀은 지도 관행의 핀 의미를 따른다. 캡션도 살짝 키워 위로 올린다.
  - **변경 이유(2026-08-14 사용자 결정)**: 지도 위에서 각진 면이 이질적이라, 지도 관행의 원형 도트로 정정했다.
  - **선택 마커는 이름 캡션을 강제로 표시**한다: 비선택 마커는 겹침 시 캡션을 숨기지만(`isHideCollidedCaptions`, 줌·밀집에 따라 일부 이름이 안 보임), **선택(탭)한 마커는 `isHideCollidedCaptions=false` + 높은 `zIndex`로 이름이 항상 보이게** 한다 — 이름이 숨겨졌던 마커도 탭하면 이름이 뜬다.
  - **애니메이션**: 네이버 커스텀 뷰 마커는 정적 비트맵이라 마커 자체엔 프레임 애니메이션이 안 되므로 다음 둘로 시선을 유도한다. **(A) 펄스 링** — 선택 시 화면 중앙에 퍼졌다 사라지는 유형색 링 3회(RN Animated, 네이티브 드라이버). **(B) 카메라 포커스 이징** — 마커 탭 시 그 박지를 화면 중앙으로 부드럽게 이징(줌 유지, `animateCameraTo`). B가 선택 박지를 중앙으로 옮기므로 A(화면 중앙 고정 오버레이)가 좌표 투영 없이 마커와 정렬된다.
  - 선택 상태는 모델(`campSiteMap.getSelectedSpot`)이 단일 소스이며, 마커 레이어·펄스(observer)가 그 값을 읽어 강조한다(배낭 여행지 피커 DST-3은 자체 선택 상태를 `selectedSpotId`로 넘긴다).
- 지도 상단에 **필터 칩 두 행**(공용 `CategoryChipView` 톤) — 축당 한 행씩 담당해 리셋·색 범례가 항상 보이게 한다(두 축을 한 행에 합치면 "전체"가 스크롤 밖으로 사라지고 태그 발견 가능성이 떨어짐 — 디자인 리뷰로 확정).
  - **1행 유형 칩**: `전체 · [●백패킹] [●대피소] [●캠핑장]` — 무필터 `전체`를 **맨 왼쪽**에 두고 백패킹→대피소→캠핑장 순으로 잇는다(단일 선택). 필터 해제 수단이 늘 첫 자리에 있어야 찾기 쉽다. 라벨 앞 **마커 색 도트**(백패킹=퍼플/대피소=초록/캠핑장=골드)가 지도 마커 색 범례를 겸하며, 선택(검정 채움) 상태에서는 도트에 흰 테두리를 둘러 시인성을 유지한다.
  - **2행 태그 칩**: `[산] [해변] … [숲]` 가로 스크롤. 유형과 행이 갈려 있어 `#` 접두 없이도 축이 구분되므로 접두를 붙이지 않는다. 별도 "전체" 없이 **선택된 칩을 다시 탭하면 해제**(토글)된다. 스크롤로 가려진 칩을 선택하면 보이도록 행을 자동 스크롤한다.
  - 유형·태그는 **AND 결합** — 태그 선택 시 해당 태그가 없는 spot(태그 미부여 포함)은 마커 표시에서 제외된다.
  - **검색 필터(CS-6)도 같은 AND 사슬에 들어간다**(2026-08-17): 검색 인풋에서 **제출한** 검색어는 `유형 ∧ 태그 ∧ 즐겨찾기 ∧ 이름 포함`의 한 항이다. 반면 **입력 중 드롭다운의 박지 결과는 필터와 독립**이며 전체 spots를 대상으로 한다 — 드롭다운은 "무엇이 있는지 찾는" 목록이라 걸어 둔 필터가 후보를 지우면 안 되고, 마커는 "지금 보고 있는 지도의 내용"이라 걸어 둔 조건을 모두 지켜야 한다. (이전 서술 "검색은 필터와 독립"은 드롭다운에만 해당한다.)
  - **필터 변경 시 토스트를 띄우지 않는다.** 결과는 지도 마커로 즉시 반영되므로 별도 토스트 피드백(결과 수·0건 안내)은 두지 않는다 — 상세 시트 위에 겹쳐 뜨는 등 노이즈가 커 제거함.
- 마커 탭 → **박지 상세(CS-3)를 하단 바텀 시트로** 연다(구글 지도 동작). 별도 요약 카드·요약 시트는 두지 않는다 — 상세가 곧 시트 내용이라 "자세히 보기" 같은 중간 단계가 없다.
  - **탭바를 가린다**: 시트가 탭바 위로 슬라이드 인/아웃하며 네이티브 시트 애니메이션이 그 전환을 담당한다(iOS `NativeTabs`는 탭바 전체를 숨기는 API가 없어 루트 레벨 시트로 덮는 방식을 쓴다).
  - **높이·확장**: `sheetAllowedDetents: [0.24, 0.4, 1]` — **기본은 40%**(`sheetInitialDetentIndex: 1`)이고, 위아래로 끌어 peek · 40% · 최대로 전환한다(네이티브 시트 기본 동작). 핸들바(`sheetGrabberVisible`) 노출, 모서리 radius 20.
  - **모든 detent에서 같은 레이아웃**을 쓴다 — 상단 블록·탭·탭 콘텐츠가 하나의 세로 스크롤이고 CTA만 하단 고정이라, 시트가 작아도(peek) 스크롤로 전체를 볼 수 있고 CTA는 잘리지 않는다. 그래서 detent별로 탭을 접거나 하지 않는다(이전의 peek 접기·높이 측정 로직은 이 단일 스크롤 구조에서 불필요해 제거).
    - 최소 detent 0.24는 유지한다 — 이름·설명·버튼이 보이는 최소 높이.
    - 시트 콘텐츠에 **`contentStyle`의 `bottom: 0`**(아래 항목)은 계속 필요하다 — 그래야 콘텐츠 래퍼가 시트 높이를 갖고 그 안에서 스크롤과 하단 CTA 고정이 성립한다.
  - **뒤 지도는 계속 조작 가능**: `sheetLargestUndimmedDetentIndex: 'last'`로 딤을 없애 시트가 떠 있는 동안 지도를 패닝·줌할 수 있다.
  - **닫힘**: 아래로 스와이프 또는 시트 좌상단 **닫기(X)** → 시트가 닫히고 마커 선택 강조가 해제된다. 지도 빈 곳 탭도 선택을 해제한다.
  - **시트는 항상 1개**: 시트가 떠 있는 동안에도 뒤 지도를 조작할 수 있어 다른 마커를 탭할 수 있다. 이때 **기존 시트를 닫고 새 시트를 연다**(`router.replace`) — 위로 쌓지 않는다. 닫히는 기존 시트의 선택 해제가 새로 선택된 박지의 강조를 지우지 않도록, 선택 해제는 **자기 박지가 아직 선택 상태일 때만** 수행한다.
- 지도에서 연 상세 시트 헤더에 **위치로 이동** 버튼을 둔다 — 시트가 열린 채 지도를 움직였다가 다시 해당 박지 위치로 카메라를 되돌린다(줌인 이동, 검색 결과 선택과 동일한 줌 레벨). 지도를 거치지 않고 연 상세(공유 딥링크 등)에는 되돌릴 지도가 없으므로 **표시하지 않는다**.

### CS-3 박지 상세

**수용 기준**

- 라우트는 `/camp-site/{id}`이며 **네이티브 `formSheet`로 표시**한다(CS-2). 지도 마커 탭이 주 진입이고, 공유 랜딩 딥링크(CS-7)로도 같은 화면이 열린다. 박지 데이터를 불러오는 동안 빈 화면 대신 **로딩 인디케이터**(중앙)를 표시한다.
  - **페이지 진입은 별도 라우트다**(2026-08-13 사용자 결정): 배낭 상세 > 여행지의 `박지 상세 보기`(DST-8)만 시트가 아니라 `/camp-site-page/{id}`를 **일반 푸시 페이지**로 연다. 지도 탭·여행지 선택기(DST-3)의 시트 진입은 그대로 유지한다.
  - 두 진입은 **같은 `CampSiteDetailView`** 를 쓰고 `presentation`(`CampSiteDetailPresentation`: `sheet` 기본 / `page`)만 갈린다 — 페이지에서는 시트용 **닫기(X)를 그리지 않고** 뒤로가기 헤더(LG-1: iOS 네이티브 투명 헤더, Android/Web 커스텀 back 행)를 쓰며, 스크롤은 iOS에서 `contentInsetAdjustmentBehavior='automatic'`으로 헤더 인셋을 받는다(시트는 `never`).
- **시트 콘텐츠에 `contentStyle: { bottom: 0 }`을 반드시 준다** — `react-native-screens`는 formSheet의 콘텐츠 래퍼를 `top/left/right`만 건 absolute로 둔다(시트 높이 변경 시 깜빡임 방지). 그러면 **React 레이아웃 높이가 무제한**이 되어 `flex: 1`이 뷰포트를 못 잡고, ScrollView가 콘텐츠 높이만큼 늘어나 **스크롤이 아예 죽는다**(detent 아래는 잘려서 접근 불가). 하단 고정 요소(CTA·토스트)도 화면 밖에 배치된다.
  - `contentStyle`은 그 스타일 **뒤에 병합**되므로, 여기서 `bottom: 0`을 되돌리면 래퍼 높이 = 시트 높이가 된다. 그러면 `flex: 1` 체인이 살아나 스크롤·하단 고정 CTA·토스트가 정상 동작하고, **detent를 끌어 바꿔도 네이티브가 알아서 따라온다**(높이를 JS에서 계산하거나 `sheetDetentChange`를 구독할 필요가 없다).
  - **하단 고정 요소(CTA)가 있는 시트**는 이미 홈 인디케이터 위로 떠 있으므로 **하단 세이프에어리어를 더하지 않는다** — 더하면 여백만 커진다. 반면 원본 배낭 선택 시트([Bag.md](Bag.md) BAG-5)처럼 하단 고정 요소 없이 스크롤 목록만 있는 시트는 마지막 행이 잘리지 않도록 스크롤 콘텐츠 하단에 여백을 준다. (즐겨찾기 리스트 시트(CS-9)는 이 여백이 없다 — 알려진 갭이며 마지막 행이 홈 인디케이터에 가깝게 붙는다.)
  - 헤더와 ScrollView를 **형제로 나란히 두는 배치**(`[헤더, ScrollView]`를 화면 콘텐츠 직계 자식으로 두어 RNS의 네이티브 프레임 보정을 기대하는 경로)는 이 앱(레거시 아키텍처, `newArchEnabled: false`)에서 **동작하지 않는 것으로 확인**했다. 대신 **ScrollView 자체를 화면 루트로 두는 배치**는 동작이 확인됐다([Bag.md](Bag.md) BAG-5 — 제목은 첫 자식 + sticky 헤더로 고정).
- **레이아웃**(네이버 지도 place 상세와 동일한 얼개): 위→아래로 **① 이름 ② 유형 배지·지역 ③ 설명 ④ 주요 기능 버튼 행 ⑤ 대표 사진 ⑥ 탭 바(sticky) ⑦ 탭 콘텐츠**, 그리고 **하단 고정 CTA**. ①~⑦은 하나의 세로 스크롤 안에 있고, **탭 바는 위로 스크롤될 때 상단에 고정(sticky)**된다 — 사진까지 밀어 올려도 탭은 남아 탭 전환이 가능하다.
  - **헤더 행**: 우상단에 **닫기(X)** 아이콘만 둔다(이름은 그 아래 큰 제목). 이름·설명·사진을 다 담으면 세로가 커지므로 액션은 아이콘 행이 아니라 아래 ④ 버튼 행으로 내린다. **페이지 진입(`presentation='page'`)에서는 닫기(X)를 그리지 않는다** — 내비 back이 그 역할을 한다.
  - **이름**: 큰 제목(1줄 말줄임). 그 아래 **유형 배지 · 지역**.
  - **설명**(`description`): 이름 바로 아래에 둔다 — "어떤 곳인지"가 사진·탭보다 먼저 읽혀야 한다. 최대 몇 줄로 제한하지 않고(짧은 스냅샷 텍스트) 그대로 표시, 비어 있으면 생략.
  - **주요 기능 버튼 행**: 설명 아래에 라벨 달린 pill 버튼을 가로로 — **공유**(CS-7) · **네이버 지도**(길찾기, CS-3) · (지도에서 연 경우) **위치로 이동**(CS-2). 아이콘+라벨 pill(네이버 place의 출발/공유/전화 톤). 버튼이 넘치면 가로 스크롤.
  - **대표 사진**: `imageUrl`이 있으면 표시(없으면 생략). 여러 장 지원 시 가로 스크롤이나 v1은 단일. **사진 바로 아래에 출처 크레딧 한 줄**을 둔다(CS-10) — 사진 위에 얹지 않는다.
  - **탭 바**: `개요` · `날씨` · `후기` — 가로 스크롤 없이 3개. 선택 탭은 라벨 진하게 + 하단 인디케이터. 기본 `개요`. 44pt 터치 타깃 + `accessibilityRole='tab'`. **sticky 헤더로 지정**해 스크롤 시 상단에 붙는다.
  - **탭 콘텐츠**: 선택된 탭의 내용을 탭 바 아래에 인라인으로 그린다(별도 중첩 ScrollView가 아니라 바깥 스크롤에 이어진다). 탭 전환 시 스크롤 위치는 유지하지 않는다.
  - **고정 CTA**: `배낭 여행지로 설정`(CS-5)은 스크롤과 무관하게 **하단에 고정**한다 — 박지 단위 주 액션이라 어느 탭·스크롤 위치에서도 닿아야 한다. 여행지 허브(DST-8)에서 연 상세는 이 CTA를 숨긴다(`showSetBag=false`).
- **개요 탭**: 태그 칩(`#해변` 형태, 비인터랙티브), 주의·규제 고지(CS-4), 시설(화장실/식수/데크/매점 — 있는 것만 아이콘+라벨), 접근 정보(`accessInfo`), 출처(`source`). 설명·사진은 위 상단 블록으로 올라갔으므로 여기서 제외한다.
- **날씨 탭**: 주간 예보(아래 항목 참고).
- **후기 탭**: 유저 후기(CS-8) + 블로그·영상(CS-3 후기 콘텐츠).
- **네이버 지도에서 열기**: 헤더 아이콘 버튼. **`위치로 이동`(현재 지도 카메라를 되돌림)과 눈으로 구분돼야 한다** — 둘 다 지도 계열 아이콘이면 무엇이 무엇인지 알 수 없다(디자인 리뷰). `위치로 이동`은 조준(`locate`), 이 버튼은 **외부 길찾기 성격의 방향 화살표(`navigate-outline`)** 로 의미를 갈라 놓는다. 좌표·박지명으로 네이버 지도 앱을 연다(`nmap://place?lat=..&lng=..&name=..&appname=..`). 앱 미설치·실패 시 네이버 지도 웹 검색(`https://map.naver.com/p/search/{박지명}`)으로 폴백.
- **주간 날씨**: **`날씨` 탭**에 박지 좌표로 기존 `WeatherService`(WT) 예보를 조회·표시한다(로딩 인디케이터, 실패 시 `날씨를 불러오지 못했어요` + 재시도). **탭에 처음 들어갈 때 조회**하고 이후 재사용한다 — 상세 진입만으로는 날씨를 조회하지 않는다(불필요한 호출 방지). 별도 라우트(`/camp-site-weather/{id}`)와 `주간 날씨` 버튼은 두지 않는다 — 탭으로 흡수됐다.
- 진입/길찾기 클릭 이벤트를 [Analytics.md](Analytics.md) AN-3 규칙으로 계측한다(`click_camp_site`, `click_camp_site_directions` — 구현 시 표 갱신).
- **후기 콘텐츠** `[제안]`: 상세 하단(날씨 아래)에 `후기` 섹션을 표시한다. 검색어는 두 소스 모두 `"{시·군·구} {박지명} 백패킹"`(`city`가 없으면 `region`, 둘 다 없으면 박지명만). **지역을 넣는 이유는 박지명이 유일하지 않기 때문이다** — 큐레이션 276건에 `감악산` 3곳(경기 파주·강원 원주 등), `백운산`·`축령산` 각 2곳이 있어 이름만으로 검색하면 다른 지역 박지의 후기가 올라온다. 라이브 실측 결과 **결과 수는 줄고 정확도는 오른다**(강원 원주 `감악산`: 이름 일치 30건 → 7건이지만 그 7건이 실제로 원주·제천 감악산 글이고, 이름만 검색한 30건은 대부분 파주 감악산이었다). 이름이 유일한 박지(`축령산`)는 거의 변화가 없다(30건 → 29건). **지역은 검색어에만 넣고 필수 토큰에는 넣지 않는다** — 넣으면 제목에 지역만 있는 무관한 글(`강원도 백패킹 명소`)이 통과한다.
  - **블로그 후기 리스트**: 네이버 블로그 검색 API(`GET https://openapi.naver.com/v1/search/blog.json`, 헤더 `X-Naver-Client-Id`/`X-Naver-Client-Secret` — env `EXPO_PUBLIC_NAVER_SEARCH_CLIENT_ID`/`EXPO_PUBLIC_NAVER_SEARCH_CLIENT_SECRET`, 네이버 개발자센터 앱)로 **후보 30건(`display=30`)을 받아 관련성 필터를 통과한 상위 5건** — 제목·요약(description 1~2줄)·블로거명·작성일. 항목 탭 → 외부 브라우저(`Linking.openURL`). 제목/요약의 HTML 태그·엔티티는 제거해 표시.
  - **유튜브 영상 리스트**: YouTube Data API v3(`GET https://www.googleapis.com/youtube/v3/search?part=snippet&type=video`, env `EXPO_PUBLIC_YOUTUBE_API_KEY`)로 **후보 25건(`maxResults=25`)을 받아 관련성 필터를 통과한 상위 4건** — 썸네일(`snippet.thumbnails.medium`)+제목+채널명 카드를 가로 스크롤로 표시. 탭 → `https://www.youtube.com/watch?v={videoId}` 열기(유튜브 앱). **`relevanceLanguage=ko`·`regionCode=KR`을 함께 보낸다** — `regionCode` 기본값이 US라 한국어 후기와 무관한 영어권 결과가 섞인다.
  - **관련성 필터(공용, 두 소스 공통)**: 외부 검색 API는 부분 매칭으로 무엇이든 돌려주므로, **응답을 그대로 표시하지 않고 필터를 통과한 항목만** 쓴다. 호출측이 `필수 토큰` 목록을 넘기고, **항목 제목에 필수 토큰이 하나도 없으면 버린다**(요약·설명에만 있는 항목도 버린다 — 실제 후기는 제목에 대상을 적는다). 토큰 판정은 양쪽을 소문자화하고 공백·하이픈·언더바·중점·마침표·**아포스트로피**(`'`·`’`)를 제거한 뒤 부분 문자열 포함으로 본다(아포스트로피를 제거해야 카탈로그의 `men's`·`women's`가 일반 토큰 `mens`·`womens`와 같은 형태가 된다 — 제거하지 않으면 성별 표기가 필수 토큰으로 새어 아무 제목에나 걸린다)(**길이 기준은 정규화 후**로 재므로 `X.`은 1자로 탈락한다). 박지(CS-3)의 필수 토큰은 **박지명을 공백으로 분리한 2자 이상 토큰**이며, 일반 토큰 제외는 공용 구현이 두 호출처에 같이 적용한다(박지명과 겹치는 사례는 실측 0건). **필수 토큰이 빈 배열이면 판정 근거가 없으므로 필터를 걸지 않고 후보를 그대로 쓴다** — 이름·제조사가 모두 일반 토큰인 커스텀 장비에서 실제로 닿는 경로이고, 여기서 전량 탈락시키면 섹션이 영구히 비어 버린다. 필터 후 0건이면 아래 0건 규칙대로 해당 리스트를 생략한다. 후보를 넉넉히 받는 이유는 필터로 줄어든 뒤에도 표시 건수를 채우기 위함이며, **유튜브 `search.list`는 `maxResults`와 무관하게 호출당 100유닛이라 후보 확대에 쿼터 추가 비용이 없다**.
  - **후기 캐시(주 1회 최신화)**: 검색 결과는 Firestore `camp-spot-review/{spotId}`([DataModel.md](DataModel.md) DM-18)에 저장해 두고, 상세 진입 시 ① **`queryVersion`이 현재 값 이상인** 캐시가 있으면 즉시 표시 ② `updatedAt`이 **7일 이내면 재조회하지 않음** ③ 7일 초과(또는 캐시 없음)면 두 소스를 재조회해 표시하고 **둘 다 성공했을 때만** 캐시를 갱신한다. 재조회 실패 시 기존 캐시를 그대로 유지·표시한다. 검색 쿼터(유튜브 기본 10,000유닛/일, 검색당 100유닛) 절약이 목적. 단 **`queryVersion`이 현재 값과 다른 캐시는 TTL과 무관하게 만료로 보고, 표시도 하지 않는다**(DM-18) — 옛 검색 규칙으로 담긴 결과는 이미 부적합하다고 판정된 값이라 노출하면 안 된다.
  - 소스별로 키 미설정·조회 실패·0건이면 해당 리스트만 조용히 생략(두 소스 모두 0건이면 후기 섹션 자체를 생략). 별도의 `더 보기` 행은 두지 않는다.
  - 블로그·유튜브·더보기 클릭은 `click_camp_site_review`로 계측한다(AN-3, 파라미터로 소스 구분 가능 시 `source: blog|youtube`).

### CS-4 주의·규제 고지 (필수)

**수용 기준**

- **박지별 경고와 유형 고정 고지는 무게를 달리한다** — 둘을 같은 주황 박스로 나란히 쌓으면 한 덩어리로 뭉쳐 보여 둘 다 안 읽히고(디자인 리뷰), 시트의 좁은 콘텐츠 영역을 경고가 차지해 설명이 밀린다.
  - `warnings` 필드가 있으면 개요 탭 상단에 **경고 박스**(주황 계열 시맨틱 색)로 항상 표시한다(접힘 없음). 이 박지에만 해당하는 정보라 눈에 띄어야 한다.
  - `wild`(노지) 유형에는 warnings 유무와 무관하게 고정 고지를 표시하되, **박스가 아니라 경고 아이콘 + 한 줄 텍스트**로 낮춘다: `노지 야영은 지역에 따라 금지될 수 있습니다. 이용 전 반드시 현지 규정을 확인하세요.` 유형 전체에 붙는 일반 안내라 박지별 경고보다 약해야 하며, 유형 배지(백패킹)가 이미 맥락을 준다.
- 지도 화면 최초 진입 시 1회(기기 저장) 동일 취지의 안내를 노출한다(토스트/배너 중 구현 시 결정).

### CS-5 배낭 여행지로 설정

**수용 기준**

- 상세에 `배낭 여행지로 설정` 버튼을 둔다. 내 배낭을 선택하면 공용 여행지 저장 동작([BagDestination.md](BagDestination.md) DST-5/DST-6)으로 박지 참조와 박지명·좌표 스냅샷을 해당 배낭의 여행지로 저장한다. 별도의 날씨 위치는 두지 않는다.
- 배낭 선택 시트 상단에 **핸들바(공용 `SheetGrabberView`)** 를 둔다 — 예전에는 Android에만 그렸는데, iOS `pageSheet` Modal도 OS 그래버가 없어 어포던스가 빠져 있었다(2026-07-31). 닫기(×)는 헤더 우측에 그대로 둔다.
- 배낭 선택 시트 상단에 **`새 배낭 만들기` 행**을 둔다 → 탭 시 시트를 닫고 배낭 생성 formSheet(`/bag-new`)로 이동한다. 박지 여행지를 `PendingBagLocationHandoff`로 넘겨 배낭 이름 입력란을 **박지명으로 프리필**하고, 생성 완료 후 새 배낭의 여행지로 자동 저장한다(생성→편집 기존 흐름 유지). 배낭이 0개여도 이 행으로 새 배낭을 만들며 여행지를 설정할 수 있다.
- 시트 UX: 헤더에 **`{박지명}을 여행지로 설정해요` 서브텍스트**로 맥락을 준다. 생성 행과 배낭 목록은 `내 배낭` 소제목으로 영역을 나눈다. 배낭 목록은 **최근 수정순**(편집일 desc)으로 정렬해 방금 만든/최근 쓴 배낭을 위로 올린다. **이미 여행지가 설정된 배낭 행에는 `📍{기존 박지명}`을 표시**해 덮어쓰기 전에 인지시킨다.
- 기존 여행지가 선택한 박지와 다르면 `{기존 여행지명}에서 {박지명}(으)로 변경할까요?` 확인 후 저장한다. 같은 박지가 이미 연결돼 있으면 확인 없이 완료 처리한다.
- 설정 완료 토스트(`여행지로 설정했어요.`)에 **`이동` 액션 버튼**을 넣어 해당 배낭 상세(`/bag/{id}`)로 바로 이동할 수 있게 한다. (Android는 네이티브 토스트라 버튼 미지원 — 메시지만 표시, 기존 토스트 액션 관례와 동일)
- 비로그인은 로그인 안내를 표시한다. 배낭 0개는 시트를 열어 `새 배낭 만들기`만 제공한다.

### CS-6 박지·지명 검색 `[제안]`

사용자는 지도에서 **등록된 박지**를 이름/지역으로 찾아 바로 열고, 등록 박지가 아닌 **지명**도 찾아 그 위치로 지도를 옮길 수 있다(2026-08-17 확장). 지명 검색은 배낭 여행지 선택기의 통합 검색([BagDestination.md](BagDestination.md) DST-4)과 **같은 서비스 모듈**(`model/bag-destination/GeocodeService.ts` — 카카오 로컬 키워드 검색)을 공유한다. 검색 경로를 새로 구현하지 않는다.

**검색에는 끝이 둘이다**(2026-08-17 사용자 결정). 같은 인풋에서 갈린다.

| 경로 | 조작 | 결과 |
| --- | --- | --- |
| **하나로 간다** | 드롭다운 **행 탭** | 박지 행이면 그 박지로 줌인 + 상세 시트, 지명 행이면 그 좌표로 카메라 이동 |
| **여러 개를 한눈에 본다** | 키보드 **검색 실행(submit)** | 드롭다운을 닫고, **이름에 검색어가 든 우리 박지만** 지도에 남긴다 |

행 탭은 결과 목록에서 하나를 지목하는 조작이라 그 하나로 데려가는 것이 맞고, 제출은 목록에서 아무것도 지목하지 않은 조작이라 "이 낱말에 걸리는 것 전부"를 지도에 펼치는 것이 맞다. 둘 중 하나가 다른 하나를 대체하지 않는다.

**수용 기준**

- 지도 상단(필터 칩 행 위)에 검색 인풋(`박지·지명 검색` — 지명까지 찾으므로 플레이스홀더도 함께 갱신한다. 지도 위라 불투명 흰 면 + 그림자)을 상시 노출한다. 인풋 클리어(X)로 검색어·리스트를 초기화한다(창고 WH-8과 동일한 커스텀 X 1개). **입력 중 드롭다운** 결과는 유형·태그 필터(CS-2)와 **독립**이다 — 전체 spots를 대상으로 한다. (**제출한** 검색어는 반대로 마커 필터가 되어 CS-2 필터와 AND로 결합한다 — 아래 `검색 제출 → 마커 필터` 참고.)
- 입력 중에는 인풋 아래 **결과 드롭다운**을 표시하고, 결과를 **두 구간**으로 나눈다: 위가 `박지`, 아래가 `지명`. **각 구간은 결과가 1건 이상일 때만 구간 헤더와 함께 렌더**한다(헤더만 남는 빈 구간을 두지 않는다). 박지가 위인 이유는 박지 결과만 상세·즐겨찾기·여행지 설정으로 이어지기 때문이다 — 지명은 카메라를 옮기는 것으로 끝난다.

**박지 구간**

- **로드된 spots를 클라이언트에서 필터**한다(추가 조회 없음): `name` 또는 지역 라벨(시/도 + 시/군/구, DM-17)에 검색어 포함(대소문자 무시). 최대 20건.
- 행 = **유형 색 도트**(지도 마커의 축소판) + 이름(rowTitle) + 메타 한 줄 `유형 · 지역`. **유형 배지를 쓰지 않는다**(HM-8 목록 행 배지 금지) — 예전 서술의 "이름·유형 배지·지역"을 한 줄에 나란히 두면 이름이 밀리고 지역이 오른쪽 끝에 떨어져 한 항목으로 안 읽혔다.
- 행 탭 → 키보드·드롭다운 닫기 + **유형·태그 필터 해제** + 해당 박지로 **카메라 이동(줌인)** + **박지 상세 시트 오픈**(CS-2/CS-3 흐름 재사용) + 검색어 유지. 필터를 해제하는 이유는 고른 박지가 필터에 걸려 마커까지 사라지면 카메라만 옮겨간 빈 지도가 남기 때문이다. **이 동작은 제출(마커 필터) 신설 이후에도 그대로다** — 행 탭은 '하나로 가는' 경로다. 행 탭은 검색 필터를 **걸지 않는다**(지목한 하나를 상세로 열었으므로 나머지를 지울 이유가 없고, 지우면 상세를 닫았을 때 그 박지만 남은 지도가 된다).

**지명 구간**

- 검색어 **2자 이상**이면 공용 지오코딩 서비스(카카오 로컬 키워드 검색)를 **400ms 디바운스**로 호출해 상위 **최대 5건**을 표시한다. 박지 구간의 로컬 매칭은 디바운스 없이 입력 즉시 갱신되므로 두 구간은 **병렬로 채워진다** — 지명 응답을 기다리며 박지 결과를 붙잡아 두지 않는다.
  - 디바운스·최소 글자수는 **DST-4와 같은 값**이다. 같은 서비스·같은 쿼터를 쓰므로 호출 규칙도 같아야 한다. (기존 CS-6에는 네트워크 호출이 없어 이 규칙 자체가 없었다 — 여기서 새로 정한다.)
- 행 = **장소명 + 주소 한 줄**. 값은 공용 결과 타입 `GeocodeResult`의 `name`(카카오 `place_name`)·`subtitle`(`road_address_name`이 없으면 `address_name`)을 그대로 쓴다 — 여행지 선택기가 쓰는 필드와 같다. **유형 도트를 두지 않는다**(지명에는 박지 유형이 없다).
- 행 탭 → 키보드·드롭다운 닫기 + **그 좌표로 카메라 이동만** 한다. 박지 선택·상세 시트·요약 카드를 열지 않고 **마커도 만들지 않는다** — 지명은 박지가 아니다. 검색어는 유지하고, 필터도 건드리지 않는다(옮겨간 화면의 마커는 현재 필터 그대로 보여야 한다). **이 동작도 제출 신설 이후 그대로다** — 지명 행 탭 역시 '하나로 가는' 경로다.
- 등록 박지와 **이름이 같고 좌표가 약 100m 이내**인 지명 결과는 지명 구간에서 제외한다(DST-4의 중복 규칙과 동일) — 상세·즐겨찾기로 이어지는 박지 행을 남긴다.
- **실패는 조용히 지명 구간만 생략**한다: 카카오 키 미주입·네트워크·HTTP 오류 시 알럿·토스트를 띄우지 않고 박지 구간만 그린다. 박지 검색은 네트워크와 무관하게 계속 동작해야 한다(DST-4의 실패 규칙과 같다).
- 카카오 REST 키는 **기존 `EXPO_PUBLIC_KAKAO_REST_KEY`를 재사용**한다 — 새 키·새 환경변수를 만들지 않는다.
- 같은 소스를 DST-4는 행 배지 `장소`로, 여기서는 구간 헤더 `지명`으로 부른다(사용자 요청 용어). 한 낱말로 통일할지는 §8 미해결 질문.

**검색 제출 → 마커 필터** (2026-08-17 사용자 결정)

- **제출 조작**: 키보드의 검색·완료 키(`onSubmitEditing`, `returnKeyType='search'`). 제출하면 ① 키보드·드롭다운을 닫고(포커스 해제 → CS-6 기존 규칙대로 필터 칩 행이 다시 보인다) ② **입력값을 검색 필터로 확정**하고 ③ 지도 마커를 그 필터로 좁힌다. 입력값이 공백뿐이면 제출은 초기화와 같다(아래 `초기화`).
- **필터 조건은 이름 포함 하나**다: `spot.name`에 검색어가 부분 문자열로 들어가면 남는다. 정규화는 **기존 박지 검색과 같은 규칙을 재사용**한다(`searchSpotsBy`/`getSearchResults` — 양쪽을 `trim()` + `toLowerCase()` 한 뒤 `includes`). 새 정규화 규칙을 만들지 않는다.
  - **지역·태그는 대상에서 뺀다.** 드롭다운의 박지 구간은 지역 라벨까지 대상으로 삼지만(`평창`으로도 찾히게), 마커 필터는 사용자가 확정한 낱말이 **마커 캡션에 그대로 보이는 것**이라야 결과가 납득된다 — 지역까지 걸면 `평창` 제출에 이름에 `평창`이 없는 마커들이 남아, 남은 마커와 검색어의 관계를 화면에서 읽을 수 없다. (사용자 확정 문구도 "입력값을 **이름에** 포함하는".)
  - **지명(카카오) 결과는 필터 대상이 아니다** — 우리 데이터가 아니라 지울 것도 남길 것도 없다. 제출은 지명 조회를 새로 부르지 않고, 진행 중이던 디바운스 호출은 드롭다운이 닫히면서 버려진다.
- **CS-2 필터와 AND**: `유형 ∧ 태그 ∧ 즐겨찾기(favoriteOnly) ∧ 이름 포함`. 제출은 사용자가 걸어 둔 유형·태그 칩을 **해제하지 않는다** — 제출은 "지금 보고 있는 조건에 낱말을 하나 더 얹는" 조작이다(하나를 지목하는 행 탭과 달라 필터를 풀어 줄 이유가 없다). 마커·뷰포트 계산(`getVisibleSpots`/`getSpotsInRegion`)의 상류에 이 항을 넣어 뷰포트 마커·즐겨찾기 마커가 모두 같은 조건을 따르게 한다.
  - 즐겨찾기 리스트 시트(CS-9)가 열려 있는 동안에는 시트가 검색 인풋을 덮어 제출 경로가 없다. 시트를 열기 전에 걸어 둔 검색 필터는 남고 `favoriteOnly`와 AND로 결합한다.
- **상태는 입력값과 별개다**: 모델은 입력값(`query`)과 **제출된 검색 필터**를 별도 필드로 들고 있는다. 입력값을 그대로 마커에 물리면 한 글자 칠 때마다 전국 마커가 사라지고 나타나 지도가 요동친다 — 제출 시점의 값만 필터가 된다.
  - 제출 후 입력값을 **편집하는 중**(비지 않은 다른 값)에는 이전 필터를 유지한다. 편집 중간 상태로 마커를 갈아 끼우면 같은 요동이 돌아온다. 다시 제출하면 새 값으로 교체된다.

**검색 필터가 걸린 것을 알리는 방법**

- **검색어가 인풋에 남는 것만으로는 부족하다.** 지도는 "원래 이 지역에 박지가 없는 것"과 "필터가 지운 것"을 스스로 구분해 주지 않는다. 제출 후 사용자는 지도를 패닝·줌하며 보게 되고, 그 사이 인풋의 낱말은 배경이 되어 남은 마커가 적은 이유로 읽히지 않는다.
- 그래서 **검색 필드 안, 클리어(X) 왼쪽에 결과 개수**를 **메타 단**(13/18, `Acg.textMuted`)으로 표시한다 — `12곳`. 지도 위에 알약·배너를 새로 띄우지 않는 이유는 지도 위 요소(검색 필드·칩 두 행·★·현위치)가 이미 많고, 개수는 **검색어 바로 옆에 붙어야** `이 낱말 → 12곳`이라는 인과가 한눈에 읽히기 때문이다.
  - 개수는 **제출된 검색어에 대한 값**이며 CS-2 필터를 AND로 적용한 뒤의 마커 수다(화면에 실제로 남을 수 있는 수 — 뷰포트로 자르기 전 값. 뷰포트 기준으로 세면 지도를 움직일 때마다 숫자가 흔들려 검색 결과 수로 읽히지 않는다).
  - 입력값이 제출값과 다르면(편집 중) **개수를 숨긴다** — 어긋난 숫자를 보여주지 않는다. 검색 필터가 없을 때도 숨긴다(전체 개수는 정보가 아니다).
  - 접근성: 숫자만 읽히면 무엇의 개수인지 알 수 없으므로 `accessibilityLabel='검색 결과 {n}곳'`으로 묶어 읽힌다.
- **0건**: 지도라 목록형 빈 상태 문구를 화면 가운데 놓을 수 없다(지도를 가린다). **CS-2 로드 실패 배너와 같은 문법**(지도 위 안내 배너 + 액션 1개)을 재사용해 검색 필드 아래(칩 행 자리)에 한 줄 배너를 띄운다: `'{검색어}' 검색 결과가 없어요` + 액션 **`전체 보기`**.
  - 액션은 재시도가 아니라 **해제**다 — 다시 불러올 것이 없고 사용자가 원하는 것은 돌아가기다. `전체 보기`는 **검색어와 유형·태그 필터를 함께 해제**한다: 0건의 원인이 검색어인지 걸어 둔 칩인지 분해하게 만들지 않는다(액션을 둘로 쪼개면 0건 배너에서 선택을 요구하게 된다).
  - **로드 실패 배너와 동시에 띄우지 않는다** — 로드 실패면 spots가 비어 검색도 필연적으로 0건이므로 로드 실패 배너(재시도)가 우선이고 검색 0건 배너는 생략한다.
  - 배너는 마커를 가리지 않는 상단 한 줄이며, 액션은 `accessibilityRole='button'`.

**초기화**

- 입력값이 **빈 문자열이 되면 검색 필터를 해제**해 전체 마커(CS-2 필터만 적용)로 돌아온다. 개수 표시와 0건 배너도 함께 사라진다.
- **클리어(X) 탭과 텍스트를 지워 비우는 것은 같은 경로**다 — 둘 다 입력값 변경 한 곳(`setQuery`)을 지나고, 그 안에서 빈 값이면 제출된 필터도 비운다. 클리어에만 해제를 걸면 백스페이스로 지운 사용자에게 필터가 남는다.
- 카메라는 초기화에서 **움직이지 않는다** — 보고 있던 화면에 마커가 다시 채워지는 것이 초기화이고, 여기서 전국으로 물러나면 사용자가 옮겨 둔 화면을 잃는다.

**제출 후 카메라**

- **결과가 화면에 들어오게 맞춘다**(현재 시점 유지하지 않음). 현재 시점을 유지하면 결과가 모두 화면 밖일 때 **아무 마커도 없는 지도**가 남아 제출이 아무 일도 하지 않은 것처럼 보인다 — 개수 배지에 `3곳`이 뜬 채 지도가 비는 최악의 조합이다. 다만 결과가 전국에 흩어질 수 있어 무조건 bounds fit도 옳지 않으므로 건수로 갈라 놓는다.

| 결과 | 카메라 |
| --- | --- |
| 0건 | 움직이지 않는다(맞출 대상이 없다) + 0건 배너 |
| 1건 | 그 좌표로 **줌인 이동**(박지 행 탭과 같은 줌 레벨). **상세 시트는 열지 않는다** — 제출은 보는 경로다 |
| 2건 이상 | 결과 좌표들의 **bounds에 패딩을 두고 맞춘다**(`animateCameraTo`/fitBounds). 단 **최대 축소 한계는 남한 전역 카메라**(CS-1 권한 거부 폴백과 같은 수준)이고, bounds가 그보다 넓으면 전역에서 멈춘다 |

- 축소 상한을 두는 이유: `계곡`처럼 흔한 낱말이 강원~전남에 퍼져 있으면 bounds fit이 전역보다 더 물러나 마커 2~3개가 화면 양 끝의 점으로 남는다. 그건 "한눈에 본다"는 목적을 도리어 깨뜨린다. 전역에서 멈추면 최소한 남한 지형 안에서 어디에 흩어져 있는지가 읽히고, 그다음은 사용자가 줌으로 좁힌다.
- 카메라 이동은 **제출 시 1회**다. 이후 사용자가 패닝·줌하면 뷰포트 밖 마커는 CS-2대로 렌더되지 않으며, **검색 필터는 카메라와 무관하게 유지된다**(카메라를 옮겨도 해제되지 않는다).

**공통**

- **0건 안내**: 두 구간이 모두 비고 **지명 조회까지 끝났을 때만** `검색 결과가 없어요` 행을 표시한다. 지명 응답 대기 중에 먼저 띄우면 안내가 떴다가 결과로 바뀐다. 대기 중 별도 스피너는 두지 않는다(디바운스 + 짧은 응답이라 깜빡임만 남는다).
- **접근성**: 두 구간의 행 모두 `accessibilityRole='button'`. 라벨은 박지 행 `{박지명} 지도에서 보기`, 지명 행 `{장소명}, {주소}`(주소가 없으면 장소명만). 구간 헤더는 `accessibilityRole='header'`.
- 드롭다운이 열려 있는 동안 **필터 칩 행은 숨긴다** — 검색은 필터와 독립이라 칩이 무의미하고, 드롭다운에 밀려 지도 한가운데 떠 보인다(디자인 리뷰).
- 검색 리스트가 열려 있는 동안 지도 터치는 리스트를 닫는다(키보드 dismiss 포함). 검색 포커스 시 열려 있던 박지 선택은 해제한다.
  - **지도 터치로 닫는 것은 제출이 아니다** — 리스트·키보드만 닫고 검색 필터는 걸지 않는다(이미 걸린 필터도 그대로 유지). 필터를 거는 조작은 키보드 검색 키 하나뿐이라야 사용자가 자기가 무엇을 했는지 안다.

### CS-7 공유 `[제안]`

사용자는 박지를 외부(카카오톡 등)로 공유하고, 받은 사람은 웹 랜딩을 거쳐 앱으로 진입한다.

**수용 기준**

- 상세 헤더 우측에 **공유 아이콘 버튼**(지도 열기 버튼 왼쪽). 탭 → OS 공유 시트(`Share.share`)로 URL `{웹 베이스}/camp-share/{encodeURIComponent(spotId)}`**만** 내보낸다(웹 베이스는 `constants/WebLinks.ts`의 `WEB_BASE_URL` 단일 소스 — 2026-07-28 `useless.my` → `https://lessismore-7e070.web.app`)(문서 id의 콜론은 메신저 자동 링크화가 끊기지 않게 `%3A`로 인코딩 — 웹 랜딩이 복원)(이름 등 텍스트를 붙이면 '복사' 시 URL이 아닌 문자열이 복사돼 링크로 동작하지 않음).
- 공유 클릭을 `click_camp_site_share`로 계측한다([Analytics.md](Analytics.md) AN-3).
- **웹 랜딩**(별도 레포 `lessismore`, `/camp-share/:id`): Firestore `/camp-spot/{id}`(공개 읽기)를 읽어 이름·유형·지역·사진·설명·주의를 보여주고, **`앱에서 보기`** 버튼으로 `lessismoreapp://camp-site/{id}` 딥링크(미설치 시 스토어 폴백)로 앱을 연다. Universal Link는 쓰지 않는다(웹 랜딩을 먼저 보여주는 의도).

### CS-8 유저 후기 (별점·글·다녀온 배낭) `[기획]`

이용자가 박지에 **별점(필수)·후기 글(선택)·다녀온 배낭(선택)**을 남기고, 다른 이용자는 이를 읽고 첨부된 배낭(장비 구성)을 앱 내에서 열람한다. 외부 블로그·유튜브 후기(CS-3)와는 **별개의 유저 생성 콘텐츠**(데이터: [DataModel.md](DataModel.md) DM-20). 작성자 식별·로그인 가드·소유자 삭제는 장비 댓글(Reply, [Reply.md](Reply.md)) 패턴을 재사용한다.

**수용 기준**

- **배치**: 상세의 **`후기` 탭**(CS-3) 안에 유저 후기를 먼저 두고, 그 아래에 외부 콘텐츠 섹션을 **`블로그·영상`**으로 이름을 바꿔 배치한다(두 "후기" 라벨 혼동 방지). 탭 이름이 이미 `후기`이므로 **유저 후기 쪽에 다시 `후기` 섹션 제목을 달지 않는다**.
- **요약 헤더**: 섹션 상단에 **평균 별점(★ n.n)·후기 수**를 표시한다. 후기가 0건이면 `첫 후기를 남겨보세요` — **빈 상태 안내는 `후기 쓰기` 버튼보다 위**에 둔다(안내 → 액션 순서).
- **작성 진입**: 섹션에 `후기 쓰기`(내 후기 없음) 또는 `내 후기 수정`(있음) 버튼. **전체 폭을 쓰지 않는다** — 하단 고정 CTA(`배낭 여행지로 설정`)와 폭이 같으면 주 액션이 둘로 보인다. 화면당 주 액션은 하나이며, 이 버튼은 보조로 읽히는 크기여야 한다. 탭 → 작성 화면(formSheet `/camp-review-write`, 박지 id·이름과 기존 내 후기를 모듈 핸드오프로 전달). 비로그인 시 전역 로그인 모달(`app.getLogInAlertManager()`, Reply 관례) 후 중단.
- **작성 화면**(`/camp-review-write`, formSheet): ① **별점 입력**(★ 1~5 탭, 필수 — 미선택 시 저장 비활성) ② **후기 글**(멀티라인, 선택, 최대 1000자) ③ **다녀온 배낭 선택**(선택) — `배낭 선택` 행 탭 시 내 배낭 시트(CS-5 `CampSiteBagSelectSheetView` 재사용, `새 배낭 만들기` 행은 숨김) → 고른 배낭의 이름·날짜·무게를 칩으로 표시하고 해제 가능. 저장 시 첨부 배낭은 **`bag.reviewShared=true`**(후기 전용 공개 플래그 — 링크 공유 `shared`와 별개)로 설정해 다른 이용자가 열람 가능하게 한다.
- **박지당 1개(수정)**: 후기 문서 id=작성자 uid라 한 박지에 유저당 1개(DM-20). 재작성은 기존 후기를 프리필해 **수정**(덮어쓰기). 저장은 DM-20 트랜잭션으로 요약 문서의 별점 집계(개수·평균)를 동기 갱신한다.
- **후기 리스트**: 최신순(`updatedAt` desc). 항목 = 작성자 닉네임 + 별점(★) + 날짜 + 글 + (첨부 시) **배낭 칩**(이름 · 날짜 · 무게). **내 후기는 상단 고정 + 강조**하고 수정·삭제를 노출한다. 소유자 판정은 `authorId===내 uid` + 스토어 재검증(이중 방어).
  - **수정·삭제는 카드 헤더 우측 `⋯` 메뉴**에 둔다(2026-08-03 디자인 리뷰). 장비 리뷰(`ReplyItemView`)가 쓰는 앱 공용 패턴(`ellipsis-horizontal` + `BottomMenuModalView`)을 그대로 쓴다. 삭제 확인 다이얼로그는 유지한다.
    - 예전에는 카드 하단에 `수정`/`삭제` 텍스트 버튼을 우측 정렬로 뒀는데, 카드에 배경·테두리가 없어 **다음 후기 작성자 이름 바로 위**에 놓였다. 내 후기가 상단 고정이라 항상 남의 후기와 맞닿아 **파괴적 액션의 대상이 모호**했고, 빨간 `삭제`가 카드에서 가장 먼저 눈에 들어와 하단 주 CTA와 시선을 다퉜다.
  - **첨부 배낭 칩은 본문보다 무겁지 않아야 한다** — 첨부물이 내용을 누른다. 날짜·무게는 `·`로 잇고(후기 작성 화면의 첨부 칩과 같은 문법), 표면색도 그 화면과 같은 `surfaceMuted`를 쓴다. 시각 높이는 낮추되 터치 타깃 44pt는 `hitSlop`으로 확보한다. 아이콘은 두지 않는다.
  - 긴 배낭 이름이 날짜·무게·chevron을 밀어내지 않게 이름·메타 모두 한 줄로 자른다.
  - **읽기 전용 별점은 하나의 접근성 그룹**으로 묶어 `별점 4.0점`처럼 읽히게 한다. 별 아이콘만 나열하면 VoiceOver에 평점이 아예 전달되지 않는다. 편집 모드는 별마다 버튼이라 묶지 않는다.
- **섹션 제목**: 유저 후기는 `이용자 후기`, 외부 후기는 `블로그·영상`으로 **둘 다 제목을 단다**(2026-08-03). 한쪽에만 있으면 제목 없는 섹션이 덩어리로 뜬다. 탭 이름(`후기`)과 겹치지 않는 표현을 쓴다.
- **구분선은 한 줄만** 그린다. 후기 카드가 각자 하단 구분선을 가지므로, 후기가 하나라도 있으면 섹션 끝에 구분선을 더 두지 않는다 — 겹치면 하드라인이 두 줄로 보인다.
- **첨부 배낭 열람**: 배낭 칩 탭 → 앱 내 **읽기전용 공유 배낭 뷰어** `/shared-bag/{bagId}`로 이동. `BagStore.getSharedBag(bagId)`로 소유자의 장비 구성을 로드해 배낭명·기간·총무게·장비 리스트를 **읽기전용**(편집·패킹 액션 없음)으로 표시한다. 뷰어는 **`reviewShared` 또는 `shared`가 true**인 배낭을 허용한다. 둘 다 아니거나 로드 실패면 `공유가 해제된 배낭이에요` 안내. (이 뷰어는 배낭 공유 [BagDetail.md](BagDetail.md) BD-7 링크의 앱 내 대응물로 재사용 가능.)
  - **뷰어는 자기 자신의 프레젠테이션(`fullScreenModal`)으로 띄운다**(2026-08-03). 일반 push로 두면 **박지 상세가 `formSheet`이라 그 위에서 밀어 넣을 때 시트 안에서 부모 스크린 컨트롤러를 못 찾아**(`Failed to find parent screen controller`) 화면이 마운트되고 데이터도 다 들어왔는데 레이아웃이 깨져 **빈 화면 + 헤더 없음**으로 보였다. 공유 링크 콜드스타트(스택 없음)에서도 전체 화면이라 자연스럽다.
- **삭제**: 소유자만. DM-20 트랜잭션으로 요약 집계 반영(0건이면 요약 문서 정리). 첨부했던 배낭의 **`reviewShared`는 되돌리지 않는다** — 같은 배낭이 다른 박지 후기에도 첨부됐을 수 있어 레퍼런스 카운트 없이 유지하는 편이 안전하고, 후기 전용 플래그라 링크 공유(`shared`) 노출과도 무관하다.
- **계측**([Analytics.md](Analytics.md) AN-3): `click_camp_site_review_write`(작성 진입), `submit_camp_site_review`(저장 — 파라미터 `rating`·`has_bag`), `click_camp_site_review_bag`(첨부 배낭 열람). 구현 시 AN 표 갱신.

### CS-9 즐겨찾기 `[기획]`

이용자가 관심 박지를 즐겨찾기해 두고, 지도에서 즐겨찾기만 모아 볼 수 있다. 로그인 사용자 전용(비로그인 → 전역 로그인 안내, Reply 관례). 데이터: [DataModel.md](DataModel.md) DM-21.

**수용 기준**

- **토글 진입점**: 상세 상단 **주요 기능 버튼 행 맨 앞**에 `즐겨찾기` pill 버튼(별 아이콘). 미등록=`star-outline`+`즐겨찾기`, 등록=`star`(채움, 브랜드 액센트 없이 시맨틱 노랑 `#FFD700` — 마커 캠핑장색과 동일 리터럴)+`즐겨찾기됨` 라벨. 탭 시 즉시 토글(낙관적 갱신 — 실패 시 롤백 + 토스트 `잠시 후 다시 시도해주세요`).
- 비로그인 상태에서 토글 탭 → `app.getLogInAlertManager()` 로그인 안내 후 중단.
- **즐겨찾기 리스트 시트**: 지도 우하단 **현재 위치 버튼 위에 ★ 플로팅 버튼**을 둔다(별 아이콘 전용, 시맨틱 노랑 `#FFD700`, `accessibilityLabel='즐겨찾기 목록'`). 위치 권한과 무관하게 항상 노출한다(현재 위치 버튼은 권한 허용 시에만 나타나므로 위치 스택 상단에 단독으로 남을 수 있다). 탭 시 즐겨찾기한 박지 **리스트를 높이 조절 바텀 시트**로 연다 — 박지 상세 시트(CS-3)와 동일한 formSheet 라우트 방식(`sheetAllowedDetents: [0.2, 0.4, 1]`, `sheetLargestUndimmedDetentIndex: 'last'`로 딤 없이 뒤 지도 조작, `contentStyle` `bottom: 0`). 상세 시트가 아니라 라우트라 지도의 `CampSiteMap`엔 핸드오프로 콜백을 넘긴다.
  - **시트가 열려 있는 동안 지도에는 즐겨찾기 마커만** 표시한다(`favoriteOnly` 필터). 시트가 닫히면 필터를 해제해 전체 마커로 돌아간다. 필터는 유형·태그와 AND 결합한다.
  - 시트 헤더에 **닫기(X)** 버튼을 둔다(핸들바 스와이프로도 닫힘). 닫히면 필터를 해제한다.
  - 리스트 항목 = 박지명·유형 배지·지역, 우측에 **상세 버튼(chevron)**. **항목 본체 탭 → 시트를 유지한 채 그 박지로 카메라 이동**(근접 줌), **우측 상세 버튼 탭 → 즐겨찾기 시트를 그 박지 상세(CS-3)로 교체**(상세로 넘어가며 필터 해제). 여행지 선택기(DST-3)에선 항목 본체·우측 상세 버튼 모두 마커 탭과 같이 동작해 **즐겨찾기 시트를 그 박지 상세 시트(`/camp-site/{id}`)로 교체(replace)** 한다 — 선택기는 박지 선택 상태를 들고 있지 않아 확정 경로가 상세의 CTA 하나뿐이다.
  - **선택기(DST-3)도 같은 formSheet 라우트를 쓴다**: 선택기가 RN Modal이 아니라 `/bag-destination-picker` 라우트라(DST-3), 그 위로 `/camp-site-favorites`가 그대로 스택돼 지도 탭과 **동일한 디텐트·높이 조절**을 얻는다. 선택기 전용 바텀시트 구현은 두지 않는다.
  - 즐겨찾기 목록은 로드된 활성 박지와 즐겨찾기 id를 조인해 만든다(삭제·비활성 박지는 자연히 빠진다). 비로그인이 ★ 진입점(지도 탭 플로팅 버튼)을 탭하면 로그인 안내 후 중단하고, 로그인했으나 0건이면 시트에 `아직 즐겨찾기한 박지가 없어요` 빈 상태를 표시한다.
  - **여행지 선택기(DST-3)의 ★ 진입점도 지도 탭과 동일한 하단 플로팅 버튼**이다 — 하단 현재 위치 버튼 **위**에 ★ 버튼을 얹는다(우하단 세로 스택). 단 선택기는 **즐겨찾기 1건 이상일 때만** ★ 버튼을 노출한다(배낭은 로그인 전용이라 빈 상태가 사실상 없어 곧바로 리스트를 연다). 공용 `CampSiteFilterChipsView`의 ★ 칩은 지도 탭·선택기 모두 끈다(`showFavoriteChip={false}`).
- **로드**: 즐겨찾기 목록은 로그인 사용자의 지도 탭 초기화 시 1회 로드하고(`CampSiteMap`), 토글 시 로컬 상태와 Firestore를 함께 갱신한다. 상세·지도가 같은 스토어를 읽어 어느 화면에서 토글해도 즉시 반영된다.
- 즐겨찾기한 박지가 삭제·비활성돼도 즐겨찾기 문서는 남는다 — 지도 필터에는 활성 박지만 나타나므로 자연히 숨는다(DST-7과 동일한 관용).

### CS-10 대표 사진 출처·매칭 (TourAPI·공공누리) `[기획]`

박지 사진의 **소스·크레딧 표기·후보 선정 규칙**을 이 요구사항이 소유한다 (2026-08-17 사용자 확정, **같은 날 실측으로 3차 정정**). 필드 계약은 [DataModel.md](DataModel.md) **DM-27 "카드 대표 사진"**(추천 카드용, 저장 위치가 여기다)과 **DM-17 "대표 사진"**(TourAPI·라이선스 계약, 레거시 `camp-spot.imageUrl`)이 정본이고, 여기서는 **화면에 어떻게 나타나는가**와 **어떤 사진을 붙일 수 있는가**를 정한다.

**소스와 라이선스 — 유형 확인이 전부다**

- 소스는 **한국관광공사 TourAPI(KorService2)** 뿐이다(계약 표는 DM-17 ②).
- **웹 크롤링은 쓰지 않는다.** 블로그·브랜드·지도 서비스에서 사진을 긁어 오는 경로는 소스가 박지로 바뀌어도 [DataModel.md](DataModel.md) §1이 세운 두 조건("남의 저작물"·"재유포 경로")에 그대로 걸린다. 사진을 붙일 근거는 **권리자가 허락한 라이선스**이며, 그 근거가 없는 사진은 넣지 않는다.
- **사용자 업로드도 이번 범위가 아니다** — 열면 §1이 폐기 유지로 못박은 UGC 재유포 경로가 박지 쪽으로 다시 생긴다.
- **공공누리 제1유형(`cpyrhtDivCd == 'Type1'`)만 쓴다.** 제2유형(상업적 이용금지)·제3유형(변경금지)·값 없음은 제외한다. **판정은 항목이 아니라 채택하는 그 이미지 단위**다 — 실측에서 `하화도 꽃섬길`은 항목이 `Type1`인데 갤러리 10장이 전부 `Type3`였다. 항목 값으로 판단하면 위반이다(DM-17 ②).
- **크롭이 `Type1`을 요구하는 이유**: 카드 밴드는 고정 높이에 `cover`로 넣어 원본 비율을 벗어난 영역을 잘라내므로 "변경"에 해당한다. 그래서 변경금지(`Type3`)를 쓸 수 없다.

**크레딧 표기 — 사진이 보이는 모든 표면에 닿아야 한다**

사진 우하단에 **한국관광공사 워터마크가 박혀 있지만 표기를 워터마크에 의존하지 않는다** — 크롭으로 잘려 나갈 수 있다. **캡션이 정본**이고, 워터마크가 잘리는 것은 허용한다. 대신 **워터마크를 일부러 지우거나 가리는 처리(블러·덮기·리터칭)는 금지**한다.

| **박지 상세**(CS-3 ⑤) | 사진 **바로 아래** 한 줄 — `imageAttribution` 값을 그대로. `AcgType.meta`(13) · `Acg.textMuted`, 사진과 같은 정렬선 | 사진이 가장 크게 보이는 자리. 개요 탭에 이미 `출처(source)` 줄이 있어 문법이 맞는다 |
| **정보 탭**(`데이터 출처` → `/info/data-sources`, [Auth.md](Auth.md) AU-4) | 소스별 일괄 표기 — 기관명·API명·공공누리 유형·원문 링크 | 앱 전체 데이터 출처의 정본 |
| **웹 랜딩**(`/camp-share/:id`, 별도 레포 `lessismore`) | 상세와 같은 한 줄 | 사진을 렌더하는 앱 밖 표면이라 같은 의무를 진다 — **별도 레포 후속 작업**(§8) |

- **표기 문구는 `imageAttribution`을 그대로 낸다**(DM-27). 뷰가 문구를 조립하지 않아 소스가 늘어도 화면을 고치지 않는다. 값이 없으면 `imageSource` + `imageLicense`로 조립하는 폴백을 쓴다.
- **크레딧을 낼 수 없는 사진은 표시하지 않는다** — 출처 없는 사진을 띄우는 것이 표기 의무 위반이다. 사진이 없는 것과 같은 폴백이라 화면은 정상 동작한다. (레거시 `camp-spot.imageUrl`은 예외적으로 **현행 표시를 유지**한다 — 유형 미확인 값의 처리는 [DataModel.md](DataModel.md) §8 미해결.)
- 크레딧 줄은 **사진 위에 겹치지 않는다**(글자·그라디언트·마스크 없음). HM-11 밴드·BAG-1 지도 밴드의 "밴드 위에 아무것도 얹지 않는다"와 같은 규칙이다.
- 크레딧에 링크를 걸지 않는다(외부 이동은 정보 탭이 맡는다).

**후보 선정 — 스크립트는 제안만, 채택은 사람이 한다**

- **앱은 런타임에 TourAPI를 호출하지 않는다.** 조회는 `scripts/suggest-feed-content-image.mjs`가 발행 준비 단계에서 수행하고 **후보 목록만 출력**한다. Firestore에 쓰지 않는다 — `feed-content` 쓰기는 admin 전용이고 값 입력은 CMS(웹 레포)가 맡는다(DM-27).
- 파이프라인: **`searchKeyword2`(박지명) → `contentid` 확보 → `detailImage2?contentId=&imageYN=Y` 갤러리 조회 → 이미지 단위 `Type1` 필터 → 좌표 거리 검증 → 사람이 고름**.
  - **`firstimage`를 확인 없이 쓰지 않는다** — 그 장소의 첫 사진일 뿐 대표성이 보장되지 않는다. 실측: `안반데기`의 `firstimage`는 **나무 안내판**이었고 갤러리에 고랭지 밭·풍력발전기 광각이 따로 있었다. 후보 풀에는 `firstimage`와 갤러리 이미지를 **함께** 올린다(확정 3건 중 둘은 `firstimage`가 채택됐다).
  - **좌표 거리 검증(권장 5km 이내)은 필수다.** 동명이인 함정이 실재한다 — `하화도(고흥)`는 대상 박지에서 **45km** 떨어져 있다. 거리 검증이 없으면 틀린다. `locationBasedList2` 응답의 `dist`(m)를 쓰면 계산이 필요 없다.
  - `Type1` 이미지가 하나도 없으면 **후보 없음으로 보고한다.**
- ★ **좌표 근접 폴백은 폐기했다**(2026-08-17 실측 후 결정). "이름은 안 맞지만 반경 안에 있는 `Type1` 후보를 제안"하는 규칙을 검토했다가 걷었다 — 40건 표본에서 그 폴백이 내놓은 후보가 `구미캠핑장 → 금오시장`, `약수골캠프촌 → 전기필불망비`, `자양보오토캠핑장 → 산청 조식 유적`, `카누글램핑펜션 → 토마토조각공원` 이었다. **반경 안에 있다는 것만으로는 그 박지의 사진이 아니고**, 시장·비석·조각공원 사진을 대표 이미지로 붙이면 사용자에게 거짓을 보여주는 것이다. **이름 매칭 + 이미지 단위 `Type1` + 거리 검증을 통과한 후보만 제시하고, 없으면 사진 없이 둔다.**
  - **예외는 사람이 판단하는 경로 하나뿐이다.** `구봉도`는 이름 매칭 `Type1`이 없었지만(동명 항목이 전부 `Type3`) 실제 낙조 코스의 일부인 **개미허리아치교** 사진을 사람이 확인해 채택했다(DM-27 확정 3건). 이런 판단은 **스크립트가 자동으로 하지 않는다** — 근처라서가 아니라 **그 박지를 보여주는 사진이라고 사람이 확인했기 때문에** 채택되는 것이다.
- **이름 검증** — 박지명과 후보 `title`을 정규화(소문자화 + 공백·중점·하이픈·언더바·마침표 제거)한 뒤 **완전 일치이거나 한쪽이 다른 쪽을 포함**할 때만 통과. 부분 토큰 일치는 받지 않는다.
- **오류 비용이 비대칭이라 이렇게 엄격하다.** 후기 관련성 필터(CS-3)는 틀리면 후기 목록이 비는 정도지만, 사진이 틀리면 **엉뚱한 장소가 그 박지의 얼굴로 박힌다.** 애매하면 채택하지 않는다.
- **후보 없음은 정상 결과다** — 사진 없이 발행하고, 카드는 밴드 없이 성립한다(HM-11). 스크립트는 후보 없는 박지를 목록으로 남겨 다음 시도의 입력으로 쓴다.
- **매칭률 실측(2026-08-17, `camp-spot` 532건 중 앞 40건 표본)**: 이름 매칭 + `Type1` + 5km = **6/40(15%)**(태기산·소래산·방장산·하화도·안반데기·청산도), 후보 없음 **17/40(42.5%)**. 이 숫자가 "사진 필드를 `camp-spot` 전역에 두지 않는다"는 결정의 근거다(DM-17 ①) — 발행 5건 규모에서는 사람이 확인할 수 있지만 532건 전수 자동화는 성립하지 않는다.

## 4. 데이터

- 읽기: `/camp-spot`(DM-17) — `where('status','==','active')` 전량. 유저 후기 `camp-spot-user-review`(DM-20). 날씨는 WT 파이프라인 재사용(쓰기 없음).
- 쓰기: 클라이언트는 CS-5에서 공용 배낭 여행지 저장 동작([BagDestination.md](BagDestination.md), DM-15), CS-8의 유저 후기(`camp-spot-user-review` DM-20, 트랜잭션) 및 첨부 배낭의 `bag.reviewShared`(후기 전용 공개 플래그, `shared`와 별개)만 쓴다. `/camp-spot` 적재는 관리 스크립트 전용.
- **적재 파이프라인** (`scripts/seed-camp-spots.mjs`, 수동 실행):
  1. **고캠핑 API**(한국관광공사, 공공데이터포털 무료 키) 스냅샷 → `campground` 유형으로 변환. **필터: 일반야영장 × 공공 관리주체(국립/공립/지자체/국립공원/자연휴양림)만 적재**(≈250곳) — v1 마커 상한(§8) 준수, 민간 글램핑·카라반 제외. 국립공원 대피소는 별도 소스(공공 API 또는 수동 표) → `shelter`.
  2. **큐레이션 시드**: 유명 노지 박지 목록(LLM 리서치 초안 → 수동 검수 필수)을 JSON으로 관리 → `wild` 유형. 좌표는 카카오 지오코딩(DST-3 재사용) 또는 수동 입력. 설명·주의 문구는 자체 작성(외부 텍스트 복사 금지).
  3. 실행 전 기존 데이터 백업 JSON 저장(`scripts/backup-*` 관례). upsert는 문서 id(`source:{외부id}` 또는 slug) 기준.
  4. **대표 사진은 이 파이프라인이 채우지 않는다** `[기획]` — 추천 카드용 사진은 `feed-content`(DM-27)에 있고 **웹 CMS가 사람 손으로 입력**한다. 이 레포의 `scripts/suggest-feed-content-image.mjs`는 TourAPI 후보를 **출력만** 한다(CS-10). `camp-spot.imageUrl`은 레거시 값으로 남기고 일괄 백필하지 않는다 — 자동 매칭률이 15%라 전역 필드로 두면 대부분 비어 잘못된 기대만 심는다(DM-17 ①).
  - **시드는 사람이 넣은 이미지 값을 되돌리지 않는다.** 지금 upsert는 `setDoc(..., { merge: true })`라 없는 키를 지우지는 않지만, 고캠핑 문서는 재시드마다 페이로드에 `imageUrl`(=`firstImageUrl`)을 실으므로 **수동 입력값을 덮어쓴다.** 사람이 확인해 넣은 `imageUrl`이 있는 문서는 그 키를 페이로드에서 빼거나 `scripts/camp-spots-curated.json`에 함께 기록한다(city 백필이 세운 관례 — DM-17 ①).
- **보안 규칙(콘솔 관리)**: `/camp-spot` 읽기 공개 + 클라이언트 쓰기 금지. 시드 실행 시에만 임시 허용 후 잠금(gear 마이그레이션 스크립트 관례) — 운영 절차로 기록.

## 6. 엣지 케이스

- **위치 권한 거부**: 전국 카메라 폴백, 현재 위치 버튼 비활성. 마커·상세는 정상.
- **데이터 0건/로드 실패**: 지도 위 안내 배너(`박지 정보를 불러오지 못했어요`) + 재시도.
- **오프라인**: Firestore 캐시가 있으면 캐시 표시, 없으면 로드 실패와 동일.
- **사진 없는 박지**: 상세에서 이미지 영역 생략(크레딧 줄도 함께 생략 — CS-10).
- **사진 로드 실패·깨진 URL**(CS-10): 사진 없는 박지와 **같은 폴백**이다 — 이미지 영역과 크레딧을 함께 생략한다. 깨진 이미지 아이콘·빈 회색 자리를 남기지 않는다. 원본이 사라져도(URL 직접 참조라 가능하다) 상세는 정상 화면이다.
- **출처를 알 수 없는 사진**(CS-10): 표기 문구를 낼 수 없으면 **사진을 표시하지 않는다** — 출처 없이 노출하는 것이 공공누리 표기 의무 위반이다. 단 레거시 `camp-spot.imageUrl`은 유형 미확인 값의 처리가 정해지기 전까지 **현행 표시를 유지**한다([DataModel.md](DataModel.md) §8).
- **카카오 키 미주입·지명 검색 실패**(CS-6): 지명 구간만 조용히 생략하고 박지 구간·마커 선택은 그대로 동작한다. 사용자에게 에러를 띄우지 않는다.
- **박지 로드 실패 + 지명 검색 성공**(CS-6): 박지 구간은 비고 지명 구간만 뜬다 — 지명으로 지도를 옮기는 것은 계속 가능하다(로드 실패 배너는 별도로 유지).
- **로드 실패 상태에서 검색 제출**(CS-6): spots가 비어 결과가 필연적으로 0건이므로 검색 0건 배너를 띄우지 않고 **로드 실패 배너(재시도)만** 유지한다. 개수 표시도 두지 않는다.
- **제출 결과가 유형·태그 칩 때문에 0건**(CS-6): 이름 일치 박지는 있으나 걸어 둔 칩과 AND로 0건이 되는 경우도 같은 0건 배너를 띄운다. 원인을 분해해 알리지 않고 `전체 보기` 한 번으로 검색어·칩을 함께 해제한다.
- **제출 직후 필터 칩 변경**(CS-6): 검색 필터는 그대로 두고 칩만 갈아 AND를 재계산한다 — 개수 표시와 0건 배너도 새 조합으로 갱신되며, 카메라는 움직이지 않는다(칩 변경은 CS-2대로 카메라를 건드리지 않는다).
- **제출된 검색어가 걸린 박지의 상세를 열고 닫음**(CS-6): 검색 필터는 유지된다 — 상세는 마커에서 열린 것이고 필터를 해제할 이유가 없다.

## 7. 수동 검증 체크리스트

- [ ] 지도 탭 진입 → 마커 표시, 유형 필터 동작
- [ ] 위치 권한 거부 → 전국 카메라 + 기능 정상
- [ ] 마커 탭 → 상세 시트(60%로 뜸, 탭바를 덮고 슬라이드 인, 뒤 지도 조작 가능), 시트 안 스크롤 동작, 닫기/스와이프 → 시트 닫힘 + 마커 강조 해제
- [ ] 시트를 위로 끌어 확장 → 콘텐츠가 늘어난 높이를 채운다(빈 흰 영역 없음), 축소 시 복귀
- [ ] 시트가 뜬 채 다른 마커 탭 → 시트가 쌓이지 않고 그 박지로 교체
- [ ] 공유 딥링크로 연 상세에는 위치로 이동 버튼이 없다
- [ ] 상세 시트 탭 전환(개요/날씨/후기) → 각 탭 콘텐츠 스크롤, 하단 CTA는 탭과 무관하게 유지
- [ ] 날씨 탭 첫 진입에만 예보 조회(개요만 보면 호출 없음)
- [ ] `wild` 상세 → 고정 규제 고지 한 줄 노출, warnings 있는 박지 → 경고 박스(둘이 시각적으로 구분됨)
- [ ] 길찾기 → 외부 지도앱 열림 (iOS/Android)
- [ ] 날씨 탭 예보 표시, 실패 시 재시도 안내
- [ ] 배낭 여행지로 설정 → 박지 참조 포함 여행지 저장 + 기존 여행지 변경 확인 + 날씨 갱신
- [ ] 배낭 0개 → 선택 시트에서 새 배낭 생성 후 동일 박지 여행지 자동 저장
- [ ] 즐겨찾기 토글(로그인 가드·낙관적 갱신) → 지도 ★ 필터에 반영
- [ ] 후기 쓰기(별점 필수, 글·배낭 선택) → 저장 후 리스트·평균 별점 반영
- [ ] 내 후기 수정/삭제 → 요약 별점 집계 갱신, 소유자만 노출
- [ ] 첨부 배낭 칩 탭 → 앱 내 읽기전용 공유 배낭 뷰어에서 장비 구성 표시
- [ ] 비로그인 후기 작성 시 → 로그인 모달
- [ ] 검색어 입력(2자 이상) → 드롭다운에 `박지`·`지명` 두 구간이 각각 결과가 있을 때만 헤더와 함께 뜬다
- [ ] 등록 박지만 매칭되는 검색어(예: 큐레이션 노지명) → `지명` 구간 없이 `박지` 구간만
- [ ] 등록 박지가 없는 지명(예: `속초해수욕장`·`남산타워`) → `지명` 구간에 장소명 + 주소, 최대 5건
- [ ] 박지 행 탭 → 필터 해제 + 카메라 줌인 이동 + 상세 시트 오픈 + 검색어 유지
- [ ] 지명 행 탭 → 카메라만 이동, 상세 시트·요약 카드가 열리지 않고 새 마커도 생기지 않음, 필터·검색어 유지
- [ ] 비행기 모드(또는 카카오 키 제거) → 지명 구간만 사라지고 박지 검색은 정상, 알럿·토스트 없음
- [ ] 타이핑을 빠르게 이어갈 때 지명 호출이 400ms 디바운스로 묶이고, 박지 결과는 즉시 갱신된다
- [ ] 두 구간 모두 0건 → 지명 조회가 끝난 뒤에만 `검색 결과가 없어요` (안내가 떴다 사라지지 않는다)
- [ ] 검색어 입력 후 **키보드 검색 키** → 드롭다운·키보드 닫힘 + 필터 칩 행 복귀 + **이름에 검색어가 든 박지 마커만** 남는다(이름에 없고 지역만 일치하는 박지는 사라진다)
- [ ] 제출 후 검색 필드에 **결과 개수(`n곳`)** 가 클리어(X) 왼쪽에 뜬다 / VoiceOver로 `검색 결과 n곳`으로 읽힌다
- [ ] 제출 결과 2건 이상 → 결과들이 모두 화면에 들어온다(bounds 맞춤) / 전국에 흩어진 검색어(예: `산`)는 남한 전역에서 멈추고 더 물러나지 않는다
- [ ] 제출 결과 1건 → 그 박지로 줌인 이동하되 **상세 시트는 열리지 않는다**
- [ ] 제출 후 유형 칩 선택 → 검색 필터가 유지된 채 AND로 좁혀지고 개수 표시가 갱신된다, 카메라는 그대로
- [ ] AND로 0건이 되는 조합(예: 이름은 맞고 유형이 다름) → 0건 배너 + `전체 보기` 탭 → 검색어·칩이 함께 풀려 전체 마커 복귀
- [ ] 제출 후 **클리어(X)** → 전체 마커 복귀, 개수·배너 사라짐, **카메라는 움직이지 않는다**
- [ ] 제출 후 **백스페이스로 전부 지움** → 클리어(X)와 완전히 같은 결과(필터 해제)
- [ ] 제출 후 한 글자만 지워 편집 중 → 마커는 이전 제출 값 그대로(요동 없음)이고 개수 표시는 숨는다, 다시 제출하면 새 값으로 교체
- [ ] 제출로 필터가 걸린 상태에서 지도 패닝·줌 → 필터가 유지되고 뷰포트 안의 일치 마커만 그려진다
- [ ] 드롭다운이 열린 상태에서 **지도를 터치**해 닫음 → 리스트·키보드만 닫히고 마커 필터는 걸리지 않는다
- [ ] 제출과 무관하게 **박지 행 탭 / 지명 행 탭**은 종전대로 동작한다(하나로 가는 경로)
- [ ] VoiceOver → 구간 헤더가 헤더로 읽히고, 지명 행이 `장소명, 주소` 버튼으로 읽힌다
- [ ] 웹 → 지도 탭 미노출

**[기획] 사진 출처·후보 선정 (CS-10, 구현 시 검증):**

표기·라이선스

- [ ] 사진이 있는 박지 상세에서 사진 **바로 아래**에 `사진: 한국관광공사 (공공누리 제1유형)` 한 줄이 보인다(사진 위에 겹치지 않는다)
- [ ] 사진이 없는 박지 상세에서 이미지 영역과 크레딧 줄이 **함께** 사라진다(빈 회색 자리 없음)
- [ ] URL을 일부러 깨뜨린 문서에서 깨진 이미지 아이콘 없이 사진 없는 상세와 같은 화면이 나온다
- [ ] 홈 추천 섹션(HM-11)에 **섹션 하단 크레딧 한 줄**이 보이고, **카드마다 반복되지 않는다**
- [ ] 카드 밴드가 크롭돼 **워터마크가 잘려도** 그 화면에 크레딧 표기가 함께 보인다(상세로 들어가지 않아도 출처가 닿는다)
- [ ] 워터마크를 가리는 오버레이·블러가 없다
- [ ] 정보 탭 `데이터 출처`(AU-4)에 한국관광공사 TourAPI 항목과 공공누리 제1유형 표기가 있다
- [ ] 저장된 URL이 전부 `https`이고 iOS·Android·Web에서 실제로 로드된다
- [ ] `imageUrl`이 있는 모든 `feed-content` 문서에 `imageSource`·`imageLicense`·`imageAttribution`이 함께 있다(세트 불변식)
- [ ] `imageLicense`가 전부 `kogl-type1`이다 — `Type2`·`Type3`·빈 값이 저장된 문서가 없다

후보 선정 스크립트

- [ ] 스크립트가 **Firestore에 쓰지 않는다**(후보 목록만 출력)
- [ ] `detailImage2` 갤러리를 조회해 후보를 낸다 — `firstimage` 한 장만 보고 끝내지 않는다(`안반데기`로 확인: 안내판이 아니라 풍경 후보가 나온다)
- [ ] **항목이 `Type1`이어도 갤러리 이미지가 `Type3`면 후보에서 빠진다**(`하화도 꽃섬길`로 확인 — 항목 `Type1` / 갤러리 10장 전부 `Type3`)
- [ ] **5km 밖 동명 항목을 후보로 내지 않는다**(`하화도(고흥)` 45km로 확인)
- [ ] 이름이 맞지 않는 **좌표 근접 후보를 제안하지 않는다**(`구미캠핑장`·`약수골캠프촌`으로 확인 — `금오시장`·`전기필불망비`가 나오지 않는다)
- [ ] `Type1` 후보가 없으면 **후보 없음으로 보고**하고 아무 값도 제시하지 않는다
- [ ] 앱 실행 중 TourAPI 호출이 **한 번도 없다**(네트워크 로그 확인) / 번들에 `TOUR_API_KEY`가 들어가지 않는다
- [ ] `seed-camp-spots.mjs --apply` 재실행이 사람이 넣은 `camp-spot.imageUrl`을 **되돌리지 않는다**

## 8. 미해결 질문

- 마커 수가 수천 건(고캠핑 전량)이면 클러스터링/뷰포트 쿼리 필요 — v1은 큐레이션 중심으로 수백 건 이내 유지, 초과 시 재설계.
- 유저 **제보**(v2)는 검수 플로우·보안 규칙 설계 필요. (유저 후기=CS-8, 즐겨찾기=CS-9로 구현.)
- 후기 신고·차단·부적절 콘텐츠 모더레이션(v2): 현재 없음.
- 회원 탈퇴 시 유저 후기(`camp-spot-user-review`) 잔존 — 완전 삭제 정책은 [Auth.md](Auth.md) AU-8 미해결 질문과 함께 검토.
- 고캠핑 스냅샷 갱신 주기(수동 재실행 vs 주기 배치).
- **대표 사진 재검증 주기·범위**(CS-10) — URL 직접 참조라 원본이 사라지면 사진이 조용히 준다. 실패율은 Storage 사본 승격 조건(DM-17 ③, 5%)의 기준값이므로 언제·어떻게(HEAD 샘플링 범위) 재검증할지 정해야 한다. 위 고캠핑 갱신 주기와 함께 볼 운영 항목이다.
- **웹 랜딩(`/camp-share/:id`)의 크레딧 표기** — 사진을 렌더하는 앱 밖 표면이라 같은 공공누리 표기 의무를 진다. **별도 레포(`lessismore`) 후속 작업**이며, 앱 쪽 결정만으로는 완성되지 않는다(장비 `imageUrl` 비공개 원칙이 웹 레포 확인으로 완성된 것과 같은 구조 — [DataModel.md](DataModel.md) §1).
- ~~**TourAPI 매칭 커버리지 미실측**~~ — **실측으로 해소(2026-08-17, CS-10)**: 532건 중 40건 표본에서 이름 매칭 + 이미지 `Type1` + 5km는 **15%**, 후보 없음이 **42.5%** 였다. 이 결과로 두 결정이 확정됐다 — ① 사진 필드를 `camp-spot` 전역에 두지 않고 `feed-content`(발행 단위)에 둔다, ② 좌표 근접 폴백을 폐기하고 사람이 채택한다. 남은 것은 **커버리지를 어떻게 늘릴지**인데, 규칙을 느슨하게 하는 방향은 위 실측(시장·비석 사진)이 이미 반증했으므로 **발행 시 사람이 후보를 확인하는 경로**로 간다.
- **`camp-spot.imageUrl` 레거시 값의 라이선스 유형 미확인**(CS-10) — 고캠핑 `firstImageUrl`은 응답에 `cpyrhtDivCd`가 없어 유형을 모른다. 상세는 크롭하지 않으므로 카드(크롭)와 같은 기준을 그대로 적용할 필요는 없으나, 결정 전까지 현행 표시를 유지한다([DataModel.md](DataModel.md) §8).
- 노지 박지 좌표 공개의 커뮤니티 반발 가능성(오버투어리즘) — 민감 박지 제외 기준.
- 카카오 결과의 낱말을 `지명`(CS-6 구간 헤더)과 `장소`(DST-4 행 배지) 중 하나로 통일할지 — 같은 소스를 두 화면이 다르게 부른다.
