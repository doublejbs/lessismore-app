# 신기능 안내 팝업 (원격 제어)

| 항목 | 내용 |
| --- | --- |
| 상태 | proposed `[기획]` |
| ID 프리픽스 | `FP` |
| 주요 코드 | `model/feature-popup/`, `components/feature-popup/`, `app/_layout.tsx`(시트 렌더) |
| 관련 스펙 | [DataModel.md](DataModel.md), [Announcement.md](Announcement.md), [AppLifecycle.md](AppLifecycle.md) |

## 1. 개요

Firestore 문서 하나(`config/featurePopup`)를 고치면 **앱을 열었을 때 신기능 안내 팝업이 뜨는** 원격 온보딩 기능이다. 릴리스 직후 "무엇이 새로워졌는지"를 카드형 목록으로 소개하고, 각 항목/메인 버튼으로 해당 기능 화면에 바로 진입시키는 용도다.

기존 인앱 공지([Announcement.md](Announcement.md), `AN`)는 **텍스트 한 줄 + 링크**의 가벼운 바텀 시트다. 이건 **제목·부제목 + 아이템 3개(썸네일·제목·설명·링크) + 메인 버튼**을 갖춘 더 큰 온보딩 팝업으로, 데이터 형태·닫음 정책·우선순위가 다르다. 둘은 **독립적인 매니저·시트**로 공존한다.

- **발송**: Firebase 콘솔에서 `config/featurePopup` 문서를 수정(코드/푸시 불필요).
- **반영**: 앱이 문서를 **실시간 구독**(`onSnapshot`)해 즉시 반영한다.
- **배포**: 네이티브 모듈 추가가 없어(Firestore는 이미 사용) **OTA로 배포 가능**하다.

## 2. 구성

- 전역 매니저: `FeaturePopupManager` — `app.getFeaturePopupManager()`로 접근(기존 매니저 패턴). `config/featurePopup` 구독, 표시 여부 판정, 닫음 상태 관리.
- 초기화: `app.initialize()`에서 인스턴스화 + 구독 시작(공지 매니저와 동일 위치).
- 시트 UI: `FeaturePopupSheetView` — `app/_layout.tsx` 최상위에서 렌더(모달이라 모든 화면 위).
- **웹 포함 전 플랫폼 동작**(Firestore는 웹에서도 동작). 네이티브 전용 분기 없음.

## 3. 요구사항

### FP-1 원격 팝업 문서 `[제안]`

**수용 기준**

- 단일 문서 `config/featurePopup`을 둔다(필드는 [DataModel.md](DataModel.md) DM-24). 콘솔에서 수동으로만 쓰고, 클라이언트는 읽기만 한다.
- **로그인 이전에도 표시**하므로 미인증 공개 읽기를 허용한다(`config/app`·`config/announcement`와 동일 정책). 보안 규칙에 `config/featurePopup` 읽기 허용 추가 필요 — **사용자 콘솔/규칙 배포 작업**.

### FP-2 신기능 팝업 표시 `[제안]`

신기능 안내를 **화면 중앙에 뜨는 카드형 모달**로 띄운다.

**수용 기준**

- `config/featurePopup`을 `onSnapshot`으로 **실시간 구독**한다. 문서가 바뀌면 팝업 상태가 즉시 갱신된다.
- 아래를 **모두** 만족할 때만 팝업을 띄운다:
  - `active === true`
  - `title`이 비어 있지 않음(표시할 대상)
  - 노출 기간 안(있을 때만): `startAt` ≤ 현재 ≤ `endAt`. 값이 없으면 그 방향 제한 없음.
  - 사용자가 이 `id`를 닫지 않았음(FP-5)
  - **강제 업데이트 게이트(APP-7)가 떠 있지 않음** (FP-6 우선순위)
- **표시 방식(Liquid Depth, 2026-08-11 이식)**: RN `Modal`(transparent) 안에서 잉크 막(`Liquid.scrim`) 위에 **흰 카드 하나**(공용 `LiquidCard tone='paper' radius='card'` — 22 + `shadow card`, 여백 `cardPadLg`)를 가운데 띄운다(fade). 전역 알럿(APP-3)과 같은 문법이라 두 중앙 오버레이가 한 가족으로 읽히고, 다른 점은 카드 안에 목록과 주 액션이 들어 있다는 것뿐이다. **전역 1곳**(`app/_layout.tsx` 최상위)에서 렌더 — 모든 탭·화면 위에 뜨므로 탭별 삽입은 불필요하다.
- **레이아웃**(위→아래):
  1. **제목**(`title`, 필수, `LiquidType.title3` bold, 가운데 정렬).
  2. (옵션) **부제목**(`subtitle`, `LiquidType.bodySm` `inkTertiary` 가운데) — 로그인 시트의 제목·부제 짝과 같은 값이다.
  3. **아이템 목록**(FP-3, 최대 3개): **조용한 아웃라인 컨테이너**(0.5px `Liquid.hairline`, radius `LiquidRadius.tileSm` 18 — 부모 카드 22보다 낮아야 안쪽 면이 카드 모서리를 밀어내지 않는다) 안에 [썸네일 | 제목 + 설명 | (링크 시)chevron] 행을 담고 행 사이만 헤어라인. 면을 더 얹지 않는 이유는 흰 카드 위에 회색 면을 또 깔면 카드 안에 카드가 생기기 때문이다.
  4. **메인 버튼**(FP-4, 필수): `LiquidPillButton variant='primary' block`(잉크 알약 h54, `shadow cta`) — 이 카드의 주 액션 하나다.
  5. (옵션) **건너뛰기**(FP-5): 글자 버튼(면 없음, `Liquid.inkMuted` 14, 44pt 터치 타깃).
- 시각 값은 `DesignTokens.ts`의 **`Liquid*` 그룹**이 단일 소스이고 글자는 `PretendardText`(weight prop)로만 렌더한다. 내용이 길면 카드 내부에서 스크롤되거나 자연스럽게 늘어난다(레이아웃이 깨지지 않게 — 스크롤 영역만 축소돼 메인 버튼·건너뛰기는 밀리지 않는다).
- 세이프에어리어: 카드는 화면 높이의 **85%까지만** 자라고 중앙 정렬이라 위아래로 7.5%가 남는다 — 그 여백이 홈 인디케이터(34)보다 넉넉해 **카드 안쪽에 `insets.bottom`을 더하지 않는다**. (2026-08-11 이식 전에는 더해서 가운데 카드가 아래로 치우쳐 보였다.)
- 문서가 없거나 조회 실패면 팝업을 띄우지 않는다(조용히 통과, 앱 동작에 영향 없음 — fail-open).

### FP-3 아이템(썸네일·제목·설명·링크) `[제안]`

**수용 기준**

- `items` 배열 중 **앞에서 최대 3개**만 렌더한다(초과분 무시). 0개면 아이템 영역을 그리지 않는다.
- 각 아이템: **썸네일**(`imageUrl`, 원격 이미지) + **제목**(`title`, 필수) + (옵션) **설명**(`description`).
  - `imageUrl`이 없거나 로드 실패면 빈 썸네일 박스로 대체한다(크래시·깨짐 금지). 썸네일은 48 정사각 · radius `LiquidRadius.thumb`(12) · 면은 `Liquid.surfaceSunken`이며, 빈 박스도 같은 치수라 행 높이가 흔들리지 않는다.
  - `title`이 없는 아이템은 그리지 않는다(스킵).
- **아이템 탭 이동**: `link`가 있으면 탭 시 이동하고, 이동 후 팝업을 닫는다(FP-5, id 영구 닫음).
  - 앱 내부 경로(예: `/bag`, `/map`)면 라우터로 이동.
  - `http(s)://`로 시작하면 외부 브라우저로 연다.
  - `link`가 없으면 아이템은 정보 표시용(탭 비활성). 잘못된 link는 무시(크래시 금지).
- 접근성: 탭 가능한 아이템에 `accessibilityRole='button'` + 라벨(제목). 터치 타깃 44pt 이상.

### FP-4 메인 버튼 `[제안]`

**수용 기준**

- **필수** 채움형 풀폭 버튼. 라벨은 `buttonLabel`(비어 있으면 기본값 `확인`).
- `buttonLink`가 있으면 탭 시 이동(내부 경로/`http(s)`, FP-3과 동일 규칙) 후 팝업을 닫는다.
- `buttonLink`가 없으면 탭 시 팝업만 닫는다(이동 없음).
- 어느 경우든 **닫으면 id 영구 닫음**(FP-5).

### FP-5 닫음 정책 (id당 1회) `[제안]`

**수용 기준**

- **닫으면 그 `id`는 다시 뜨지 않는다** — 닫은 `id` 목록을 기기 로컬(AsyncStorage)에 **영구 저장**한다. 앱을 재실행해도 같은 `id`는 안 뜬다.
- **닫음으로 처리되는 경로**: 메인 버튼(FP-4) · 아이템 이동(FP-3) · 건너뛰기 · 딤 배경 탭 · 하드웨어 back(안드로이드). 모두 `id`를 영구 닫음 처리한다.
- **건너뛰기**는 **옵션**이다: `showSkip !== false`일 때만 하단 텍스트 버튼으로 노출한다(기본 노출). `false`면 건너뛰기를 숨긴다(메인 버튼·딤 탭으로만 닫음).
- 새 공지가 필요하면 콘솔에서 **`id`를 바꾼다** — 닫았던 사용자에게도 다시 뜬다.
- 닫음 상태는 **기기 로컬**이라 재설치 시 초기화된다(known issue로 수용, 서버 저장 안 함).

### FP-6 표시 우선순위 (기존 공지와 공존) `[제안]`

동시에 표시 조건이 되는 오버레이가 여럿일 때 **한 번에 하나만** 띄운다. 우선순위는:

```
강제 업데이트 게이트(APP-7)  >  신기능 팝업(FP)  >  텍스트 공지 배너(AN)
```

**수용 기준**

- 신기능 팝업(FP-2)은 **강제 업데이트 게이트가 떠 있으면 표시하지 않는다**(`ForceUpdateManager.getNeedsUpdate()` 참조 — 공지 시트와 동일 방식).
- 텍스트 공지 시트(`AnnouncementSheetView`)는 **신기능 팝업이 표시 조건이면 표시하지 않는다**. 즉 `AnnouncementSheetView`의 표시 판정에 `!featurePopupManager.shouldShow()` 조건을 추가한다.
- 강제 업데이트 게이트는 일반 absolute View라 Modal이 그 위로 뜨므로, FP·AN 모두 게이트가 떠 있을 땐 표시 조건에서 배제해 게이트를 최상위로 유지한다.

### FP-7 강제 모드 (차단형) `[제안]`

`forced === true`면 팝업이 **차단형**이 된다 — 강제 업데이트 게이트(APP-7)처럼 사용자가 닫을 수 없고, 원격으로만 내릴 수 있다. 점검 안내·필수 고지 용도.

**수용 기준**

- **닫기 경로가 전부 없다**: 건너뛰기 숨김(`showSkip` 값 무시), 딤 배경 탭·하드웨어 back(안드로이드) 무시. 닫음 상태를 저장하지 않는다.
- **이전에 같은 `id`를 닫았어도 표시한다**(닫음 목록 무시) — 강제 팝업의 노출 스위치는 원격 문서뿐이다.
- **아이템 링크는 탭 비활성**(정보 표시만, chevron 숨김) — 모달이 계속 덮여 있어 내부 이동이 무의미하다.
- **메인 버튼**: `buttonLink`가 있으면 이동만 하고 **팝업은 유지**된다(닫히지 않음 — 외부 링크/스토어 안내 용도). `buttonLink`가 없으면 버튼을 숨긴다(콘텐츠만 표시).
- **내리는 방법은 원격뿐**: `active=false` / 문서 삭제 / `forced=false`(일반 모드 전환) — `onSnapshot`으로 즉시 반영된다.
- 우선순위(FP-6)는 그대로 적용: 강제 업데이트 게이트가 떠 있으면 강제 팝업도 표시하지 않는다.

## 4. 데이터

- 문서·필드는 [DataModel.md](DataModel.md) **DM-24 (`config/featurePopup`)** 에 정의한다.
- 닫음 상태(닫은 `id` 목록)는 서버에 저장하지 않고 기기 로컬(AsyncStorage)에만 둔다.

## 5. 엣지 케이스

- **문서 없음 / 오프라인 / 조회 실패**: 팝업 없음(조용히 통과, fail-open).
- **`active=false`**: 팝업 없음.
- **기간 밖**: 팝업 없음(`startAt`/`endAt` 경계 포함).
- **`title` 빈 값**: 팝업 없음(표시할 대상 없음).
- **`items` 없음/3개 초과**: 없으면 아이템 영역 생략, 초과분은 앞 3개만.
- **`imageUrl` 로드 실패**: 빈 썸네일 박스로 대체.
- **잘못된 `link`/`buttonLink`**: 내부 경로로 해석 안 되면 무시(이동 안 함, 크래시 금지).
- **비로그인**: 미인증 읽기 허용이므로 로그인 전에도 표시된다.
- **강제 업데이트 게이트 동시 표시**: FP-6에 따라 게이트만 노출.

## 6. 수동 검증 체크리스트

- [ ] `config/featurePopup`에 `active=true`+`title`+아이템 넣기 → 앱 진입 시 중앙 카드 팝업
- [ ] 아이템 3개 초과 → 앞 3개만 렌더
- [ ] 아이템 `link`(내부/외부) 탭 → 이동 + 팝업 닫힘, 재실행 시 같은 `id`면 안 뜸
- [ ] 메인 버튼(`buttonLink` 있음/없음) → 이동 또는 닫기, 이후 같은 `id` 안 뜸
- [ ] `showSkip=false` → 건너뛰기 숨김 / 미지정 → 건너뛰기 노출
- [ ] `id` 변경 → 닫았던 사용자에게도 다시 표시
- [ ] `active=false` / 기간 밖 / `title` 빈 값 → 안 뜸
- [ ] `imageUrl` 깨진 URL → 빈 썸네일로 대체(크래시 없음)
- [ ] 강제 업데이트 게이트가 떠 있을 때 → 팝업 안 뜸(게이트만)
- [ ] 신기능 팝업 표시 조건일 때 → 텍스트 공지 시트(AN) 안 뜸
- [ ] 문서 삭제·오프라인 → 팝업 없이 앱 정상
- [ ] `forced=true` → 건너뛰기 없음, 딤 탭·back 무시, 아이템 chevron 없음·탭 무반응
- [ ] `forced=true` + `buttonLink` → 버튼 탭 시 이동만 하고 팝업 유지 / `buttonLink` 없음 → 버튼 숨김
- [ ] `forced=true`는 이전에 닫은 `id`여도 표시됨
- [ ] `forced=true`에서 `active=false`/`forced=false`로 원격 변경 → 즉시 내려감/일반 모드 전환

## 7. 결정 사항 / 미해결 질문

**결정됨(사용자 확인)**

- 썸네일: **원격 이미지 URL**(아이콘 키 미지원 — 필요 시 나중에 확장).
- 닫음: **`id`당 1회, 영구 저장**(닫으면 재실행해도 같은 `id` 안 뜸).
- 우선순위: **강제 업데이트 게이트 > 신기능 팝업 > 텍스트 공지**.

**결정됨(디자인 리뷰 반영)**

- **배지 필(`badge`) 제거**: 목업 상단의 "대규모 업데이트" 필은 제거했다(스키마·UI 모두). 앱 톤에 맞춰 제목→부제목→아이템 그룹→CTA로 단순화.
- 아이템은 목업의 무거운 회색 카드 대신 **아웃라인 그룹 컨테이너 + 행 구분선 + 링크 시 chevron**(앱 그룹 리스트/정보 탭 톤). 2026-08-11 Liquid Depth 이식에서도 이 판단을 유지했다 — 값만 `Liquid*`로 옮겼다(자세한 값은 FP-2 레이아웃).

**미해결(구현 확인 필요)**
