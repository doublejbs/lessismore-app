## 1. 개요

장비 1개의 상세 화면. 기본 정보, 이 장비를 담았던 배낭 기록(사용/미사용 통계), 리뷰(댓글) 미리보기를
제공한다. 창고·검색·배낭 상세 어디서든 `/gear-detail/{id}`로 진입한다.

## 2. 화면 및 진입

```
app/gear-detail/[id]/index.tsx → WarehouseDetailWrapper → WarehouseDetailView
  ├─ WarehouseDetailInformationView   (제조사/이름/색상/무게)
  ├─ WarehouseDetailBagRecordView     (배낭 기록 — bags가 있을 때만)
  └─ WarehouseDetailReviewSectionView (리뷰 미리보기)
```

- 장비 조회는 `GearStore.getGear(id)`: `users/{uid}/gears/{id}` 우선, 없으면 카탈로그 `gear/{id}`.

### GD-1 기본 정보 섹션

**수용 기준**

- 제조사(`getDisplayCompany()` — 한글 표시명 우선, 리스트 화면과 동일, **제품명과 동일한 타이포** — [Warehouse.md](Warehouse.md) WH-1 공통 규칙), 이름(`getDisplayName()`), 색상, 무게를 표시한다. **이미지는 사용자가 올린 본인 사진만 표시한다**([DataModel.md](DataModel.md) §1, 2026-07-29 개정) — 카탈로그 크롤 이미지는 계속 쓰지 않으며 **폴백하지 않는다**. 업로드·교체·삭제는 GD-13.
  - 구성은 **사진 줄 + 정체 줄** 두 층이다(2026-07-29 사용자 결정).
    - **1층 — 사진**: **140pt 정사각**(radius `Radius.card`)을 **가운데 단독 줄**로 둔다. 사진이 없으면 **이 줄 자체를 렌더하지 않는다** — 빈 칸·플레이스홀더를 남기지 않는다(이미지 없는 장비가 다수라 그쪽이 기본 모습이다).
    - **2층 — 정체 줄**: **좌측에 브랜드 → 이름 → 메타 라인, 우측에 무게**. 사진 유무와 **무관하게 항상 이 형태**다.
  - **좌 정체 · 우 지표는 앱 전역의 행 문법이다** — 창고 목록([Warehouse.md](Warehouse.md) WH-1)·배낭 목록([Bag.md](Bag.md) BAG-1)·배낭 상세 장비 행이 모두 이 문법이고 무게가 항상 우측 같은 자리에 온다. 상세만 다른 문법을 쓰면 목록에서 익힌 자리 감각이 끊긴다.
  - **무게는 콘덴스드 `AcgType.displayMedium`(28) 우측 정렬, `무게` 캡션은 생략**한다(2026-08-12, 타입 스케일 — [Home.md](Home.md) HM-8. 이전 서술은 32pt). `g` 단위가 이미 무엇인지 말해주고 목록 행에도 캡션이 없다. 캡션 없이도 화면에서 가장 큰 활자라 **시각 앵커는 무게**다 — 사진은 "내 물건이 맞나" 확인용이지 판단 근거가 아니며, 앱 정체성이 무게 줄이기다.
  - **사진 유무로 무게 배치를 바꾸지 않는다.** 사진이 있을 때만 무게를 컬럼 안에 넣고 없을 때는 히어로로 키우면 같은 화면이 두 얼굴이 된다.
  - 폐기된 시안(기록): ① 사진을 위에 전체 폭으로 두기 — 393pt 폭에서 140pt만 쓰고 우측 250pt 이상이 빈 채로 남았다. ② 사진을 좌측 100pt로 줄이고 우측 컬럼에 정보를 몰기 — 우측 여백은 해소됐지만 사진이 작아지고, 무게를 컬럼 안에 넣으니 목록 행과 자리 감각이 어긋났다.
- 카테고리·색상·사이즈는 이름 아래 **메타 라인**에 `카테고리 · 색상 · 사이즈` 형식 보조 텍스트(`textSecondary`)로 표시한다(칩 아님). 카테고리는 **세분 카테고리 한글 라벨**(DM-4, 매핑에 없으면 그룹 라벨 폴백), 색상은 `colorKorean || color`, 사이즈는 `sizeKorean || size`. 빈 항목은 생략, 모두 없으면 라인 미노출.
- 무게는 정체 줄 우측에 큰 숫자로 둔다(캡션 없음 — 위 2층 구성 참고).
- `수정하기`는 본문 중앙 텍스트 버튼 대신 **헤더 우상단** 액션(44pt)으로 이동한다(보유 장비만). 화면 본문의 중앙 정렬 액션 나열을 줄여 주 액션 위계를 명확히 한다(HIG).
- 헤더: 스크롤이 기본 정보 섹션을 지나면 헤더에 **제품명 타이틀**이 나타난다(컨텍스트 유지).
- 접근성·터치 타깃(HIG): 뒤로가기 버튼은 44×44pt 터치 영역과 `accessibilityLabel`/`accessibilityRole`을 가진다. 헤더 액션도 동일 기준.

### GD-2 배낭 기록 섹션

사용자는 이 장비를 어떤 배낭에 담았고 실제로 썼는지 볼 수 있다.

> GD-9~GD-12(사용 인사이트)로 **대체·확장됨**. 아래 기준은 확장 전 기본 동작으로 유지된다.

**수용 기준**

- 장비의 `bags`가 0개면 섹션 자체를 렌더하지 않는다.
- 담긴 배낭 수, USED 횟수(`used.length`), USELESS 횟수(`useless.length`)를 표시한다.
- 횟수가 0회인 통계 카드는 값·라벨을 `textSecondary`로 낮춰 유효 정보 스캔을 돕는다.
- 배낭별 행에 사용 여부 태그(USED/USELESS)를 표시하고, 행을 누르면 해당 배낭 상세로 이동한다.

### GD-9 사용 지표 히어로 `[제안]`

> **화면 복귀 시 전체 재조회**(2026-07-31). 사용 여부 기록(`/useless/{id}`)·배낭 편집·리뷰 작성에서 돌아오면 지표도, 함께한 여행 목록도, 리뷰도 바뀌어 있을 수 있다. 무엇이 바뀌었는지 화면이 알 방법이 없어 **포커스 시 통째로 다시 읽는다**.
> - 재조회는 `initialized` 플래그를 건드리지 않는다 — 내리면 래퍼가 잠깐 아무것도 안 그려 화면이 깜빡인다.
> - 첫 진입은 초기화가 이미 읽으므로 중복 조회하지 않는다(초기화 전에는 재조회가 아무것도 하지 않음).


보유 장비의 상단(기본 정보 아래)에 **내 기록 요약**을 보여준다 — "이 장비를 계속 데려갈까"에 답하는 화면의 시작점. 모든 값은 이미 로드되는 데이터의 파생값이며 **추가 Firestore 읽기 0회**.

**수용 기준**

- **보유 장비(`isAdded`)에만** 표시한다. `bags`가 0개면 "아직 배낭에 담은 적이 없어요" 안내만(지표 없이) 표시한다.
- 지표: **사용 M** · **사용 안함 K** 둘뿐이다(라벨 `사용 안함` → `사용 안함`, 2026-07-31). 산정 기준은 **실제 로드된 배낭 목록**(삭제 잔여 id 제외) — 타임라인 행 수·"함께한 여행 N회" 헤더와 항상 일치해야 한다.
- ~~**담김 N회**~~ · ~~**미기록 R**~~ — **2026-07-30 제거(사용자 결정).** 담김 수는 바로 아래 `함께한 여행 N회` 헤더가 같은 값을 말해 중복이었고, 미기록은 타임라인의 `미기록` 태그로 행마다 이미 드러난다. 미기록을 "사용 안함"으로 합산하지 않는다는 3-상태 원칙(BD-5 정합)은 그대로다 — 히어로에서 세지 않을 뿐 상태 자체는 유지된다.
- ~~**사용률**(`used/(used+useless)`)~~ · ~~**보유 D일째**~~ — **2026-07-29 제거(사용자 결정).** 지표 타일(담김·사용·사용 안함·미기록) 아래 보조 문구로 두 값을 합쳐 보여줬으나, 사용률은 미기록이 분모에서 빠져 6번 담고 2번만 기록한 장비가 `사용률 100%`로 읽히는 문제가 있었다. 모수 병기(`사용률 100%(2건)`)로 정직하게는 만들었지만 문구만 길어지고 타일이 이미 같은 정보를 더 정확히 보여준다는 판단이다. `보유 D일째`도 함께 걷었다. 되살릴 경우 `createDate`가 신뢰 불가한 경우(카탈로그 진입 등) 미표시 규칙이 필요하다.
- 기존 GD-2 상단 통계 카드(담김/USED/USELESS)는 이 히어로로 통합한다(중복 표기 금지).

### GD-10 함께한 여행 타임라인 `[제안]`

GD-2의 배낭별 행을 **여행 카드**로 강화한다. 배낭 문서에 이미 있는 필드만 쓴다(추가 읽기 0회).

**수용 기준**

- 정렬: `startDate` 내림차순(최신 여행 먼저). 날짜 없는 배낭은 뒤로.
- 행 구성: 배낭 이름 · 기간(`startDate~endDate`) · **여행지 이름**(`location.name`, 없으면 생략) · **날씨 요약**(`weather.daily`에서 기간 내 최저~최고 기온 범위 + 강수 있으면 비 아이콘, 데이터 없으면 생략) · **사용 여부 3-상태 태그**(`사용` / `사용 안함` / `미기록`).
  - **태그 자리에 문장을 넣지 않는다.** 실측에서 미기록 행이 `사용 여부를 입력해주세요`라는 한 문장으로 렌더돼, 배낭 이름이 말줄임되는데 보조 문구가 더 넓은 자리를 차지했다(2026-07-29). 미기록도 **`미기록` 태그 한 단어**로 두고, 입력 유도는 행 우측 꺾쇠(›)와 탭 동작이 담당한다.
  - **`미기록`이 세 태그 중 가장 도드라진다.** `사용`·`사용 안함`은 이미 끝난 기록이라 조용해도 되지만, 미기록은 사용자가 눌러주길 바라는 유일한 상태다. 실측에서 `사용`이 검정 채움이고 `미기록`이 저대비 회색이라 **위계가 정반대**였다(2026-07-29). 완료된 두 상태를 낮추고 미기록을 한 단계 올린다.
- **메타 라인(기간 · 여행지)은 1줄로 말줄임한다.** `location.name`에 짧은 지명 대신 전체 주소가 저장된 배낭이 있어(`강원특별자치도 강릉시 성산면 보광리 산 544`) 메타가 2줄로 흐르면서 행 높이가 제각각이 되고, 주 정보인 배낭 이름보다 보조 정보가 길어져 위계가 뒤집혔다. **`[미해결]`** 저장 시점에 짧은 지명을 넣는 문제는 [BagDestination.md](BagDestination.md) 쪽 데이터 이슈로 별도 처리한다.
- 행 탭 시 배낭 상세 이동(기존 동작 유지).
- 챙김/안 챙김(패킹) 표시는 **두지 않는다** — 구현 후 사용자 결정으로 제거(2026-07-23). 패킹 기반 인사이트(챙겼는데 사용 안함 등)는 Packing.md 후속 아이디어로 남긴다.
- `BagItem` 매핑에 `weather`·`location`(name)·`activity` 필드를 추가한다(현재 매핑에서 버려지는 필드 활용 — 데이터 계약 변경 없음).
- 배낭이 30개를 초과하면 `in` 쿼리를 30개 단위로 청크 분할해 모두 조회한다([DataModel.md](DataModel.md) DM-25).

### GD-11 함께한 활동 누적 `[제안]`

**사용(`used`)한 여행**들의 운동 기록(DM-22 `bag.activity`)을 합산해 보여준다.

**수용 기준**

- 합산 대상: `used`에 포함된 배낭 중 `activity`가 있는 것. 대상이 0개면 섹션을 렌더하지 않는다.
- 표기: **누적 거리**(km, 소수 1자리) · **누적 시간**(시간·분) · **누적 상승고도**(m, 있을 때만) · **누적 칼로리**(kcal, 있을 때만). 문구 예: "이 장비와 87.3km를 걸었어요".
- 심박·경로는 서버에 없으므로(HA-5) 다루지 않는다.

### GD-12 덜어내기 시그널 `[제안]`

앱 정체성(useless)의 핵심 — 데이터가 "덜어낼 후보"라고 말할 때 조용히 알려준다.

**수용 기준**

- **표시 조건**: 기록된 여행(`used+useless`)이 **3회 이상**이고, **기록 기준 최근 3회가 모두 '사용 안함'**일 때. (최근 판정은 해당 배낭들의 `startDate` 내림차순 기준, 날짜 없으면 `editDate`.)
- 배너 문구: "최근 3번의 여행에서 쓰지 않았어요 — 배낭에서 빼면 **−{weight}g**" (`weight`는 `Number()` 변환, 무게 없으면 무게 문구 생략).
- 정보성 배너다 — 탭 액션 없음, 삭제 유도 아님(파괴적 행동 버튼 금지). 시각은 경고 빨강이 아닌 차분한 강조(브랜드 톤).
- 조건 미충족이거나 기록 부족 시 렌더하지 않는다.

### GD-3 리뷰 미리보기 섹션

**수용 기준**

### GD-5 외부 링크 (브랜드 공식몰 · 쿠팡 파트너스)

사용자는 카탈로그 장비 상세에서 **브랜드 공식몰 상품 페이지**와 **쿠팡 파트너스 최저가**로 바로 이동할 수 있다.

**2026-08-08 — 브랜드 공식몰 링크(`productUrl`)를 더한다.** 지금까지 이 섹션은 쿠팡 링크 하나였는데, 실데이터에서 `coupangUrl`은 **27건(0.1%)** 뿐이고 `productUrl`은 **37,576건(90.8%)** 이다([DataModel.md](DataModel.md) DM-3). 사용자가 보는 장비 대부분에 아무 외부 링크가 없었던 셈이다.

**수용 기준**

- 섹션 소제목은 **`공식 링크`** 이며 다른 섹션(스펙·리뷰)과 같은 위계·여백을 쓴다(17pt semibold, `marginVertical: 20`). 소제목이 없으면 앞 섹션에 딸린 것처럼 읽힌다 — 이 화면에서 소제목 없는 섹션은 히어로뿐이다.
- 두 링크 모두 **행 하나씩**으로 낸다. 둘 다 있으면 두 행, 하나만 있으면 그 행만, 둘 다 없으면 섹션 자체를 렌더하지 않는다.
- 차례는 **브랜드 → 쿠팡**이다. 커버리지가 90.8% 대 0.1%라 브랜드 행이 사실상 기본이고 쿠팡은 예외다 — 기본을 위에 두지 않으면 대다수 장비에서 섹션 첫 줄이 비는 셈이 된다.
- **브랜드 행 라벨은 링크 대상이 공식몰인지에 따라 갈린다**(`model/gear/GearBrandLink.ts`):
  - **공식몰**: `{브랜드} 공식몰에서 보기`. 브랜드명이 비면 `공식몰에서 보기`.
  - **그 외(편집숍 등)**: `{도메인}에서 보기` (예: `thegearshop.co.kr에서 보기`). 도메인도 못 얻으면 `상품 페이지 보기`.
  - 판정은 **호스트에 브랜드 슬러그(`company`)가 들어 있는지**로 한다. 실데이터 23개 도메인 중 21개가 이 방식으로 100% 맞고, 최다 도메인인 더 기어샵(11,806건·31%)은 아크테릭스·스카르파 등을 함께 파는 **편집숍**이라 0%로 갈린다 — 여기에 `아크테릭스 공식몰`이라 쓰면 사실이 아니다.
  - 슬러그가 약어라 공식몰을 못 맞히는 경우(`hmg` vs `hyperlitemountaingear.co.kr`, 102건)는 중립 라벨로 떨어진다. **틀리는 방향을 이쪽으로 고정한 것** — 편집숍을 공식몰이라 부르는 쪽이 더 나쁘다.
- **브랜드 행은 상품 이미지가 있는 링크 미리보기 카드로 낸다**(2026-08-09, 아래 §GD-5a).
- **파트너스 고지는 쿠팡 행에만 딸린다.** 브랜드 링크는 수수료와 무관하므로 고지가 그 아래로 내려가면 사실과 다르다.
- 두 링크는 **같은 카탈로그 문서 한 번 읽기**로 함께 가져온다(`GearStore`의 기존 캐시 재사용) — 링크 하나 늘었다고 Firestore 읽기가 늘어나면 안 된다.
- 카탈로그 `gear/{id}.coupangUrl`이 있을 때만 `쿠팡에서 최저가 보기` 링크를 노출한다. 값이 없으면 그 행과 고지 문구 모두 미노출.
- 배치는 **보유 여부로 분기**한다 — 이 화면은 보유자(관리)와 탐색자(쇼핑) 겸용이므로 각 모드의 관심사를 위로 올린다:
  - **미보유(카탈로그 진입)**: 현행대로 제품 정보 바로 뒤 (구매 판단 동선).
  - **보유(`isAdded`)**: 배낭 기록 섹션 **뒤**, 리뷰 섹션 위 (내 기록이 최저가 링크보다 우선).
  - 어느 위치든 **독립 섹션**이며, 다른 섹션과 동일한 구분선(`SeperaterView`, 상단 10px `#F2F4F6` 밴드)을 섹션 상단에 넣는다.
- 링크는 **항상 카탈로그 `gear/{id}`에서만** 읽는다. 커스텀 장비는 카탈로그 문서가 없어 자연스럽게 미노출되고, 창고 사본으로 진입해도 카탈로그에서 읽는다.
- 링크를 누르면 `click_gear_purchase` 이벤트(`source`: `coupang` \| `brand`)를 전송한 뒤 외부 링크를 연다. 열기 실패는 조용히 무시한다.
- **여는 방식은 행마다 다르다** — 목적이 다르기 때문이다:
  - **브랜드 행: 인앱 브라우저**(`expo-web-browser`의 `openBrowserAsync`). 제품 정보를 확인하고 앱으로 돌아오는 동선이라 앱을 떠나게 할 이유가 없다. 시트를 닫으면 장비 상세로 복귀한다.
  - **쿠팡 행: `Linking.openURL` 유지.** 파트너스 링크(`link.coupang.com/a/...`)는 유니버설 링크라 쿠팡 앱이 깔려 있으면 앱으로 넘어간다 — 인앱 브라우저로 감싸면 그 전환이 막혀 파트너스 수수료 귀속에 불리하다.
- 쿠팡 행 바로 아래에 수수료 고지 문구(`쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.`)를 상시(숨김/접힘 없이) 표시한다.
- 고지 문구는 상시 노출을 유지하되 링크보다 시각 위계를 낮춘다(fontSize 11, `textSecondary`) — 법적 고지가 링크 본문보다 무거워 보이지 않게.

### GD-5a 브랜드 링크 미리보기 카드

**2026-08-09 결정.** 브랜드 행을 가운데 정렬 텍스트 링크에서 **링크 미리보기 카드**로 바꾼다. 카카오톡·슬랙이 링크를 붙였을 때 보여주는 그 카드와 같은 성격이다.

**수집은 미리 하지 않는다 — 처음 열릴 때 한 번 가져오고 그 값을 저장한다.**

```
1회차: 상세 진입 → 상품 페이지 og:image 읽기 → 표시 → gear/{id}.productImageUrl에 기록
2회차~: gear 문서를 읽을 때 URL이 함께 실려 옴 → 즉시 표시, 추가 요청 0
```

전량 백필(37,382건·약 1시간)을 하지 않는 이유는 **필요가 없어서**다. 실제로 열리는 장비만 채워지면 되고, 장비 상세는 어차피 `gear/{id}` 문서를 한 번 읽으므로(쿠팡·브랜드 링크) **조회 시점 추가 비용이 0**이다. 반대로 매 조회마다 og를 긁는 방식은 브랜드 서버를 조회수만큼 때린다 — 저장 방식은 **상품당 사실상 1회**다.

`<head>`만 잘라 받는 안(HTTP Range)도 검증했으나 **상위 7개 도메인 중 1개(cayl.co.kr)만 206을 준다**. 나머지는 동적 페이지라 범위를 못 자르고 전체(179~332KB)를 보낸다.

**수용 기준**

- **이미지가 있으면 상단 이미지 밴드(180pt) + 하단 텍스트 줄**, 없으면 **좌측 아이콘 타일 + 텍스트 한 줄**로 떨어진다. 빈 밴드를 남기지 않으려고 형태를 나눈다.
- 밴드는 `resizeMode: contain` · 흰 배경이다. 상품 사진이 대부분 흰 배경 정사각이라 좌우 letterbox가 사진 배경과 이어져 보이지 않는다.
- **로딩 구간이 둘이고 둘 다 스켈레톤으로 덮는다** — ① og 수집(URL을 아직 모름), ② 이미지 다운로드(URL은 알지만 아직 안 그려짐). 수집 단계부터 밴드 자리를 잡아둬야 이미지가 도착할 때 **카드 높이가 튀지 않는다**. 캡션 줄은 처음부터 실제 텍스트로 그린다.
- 로드에 실패하면 스켈레톤을 걷고 **아이콘 형태로 떨어진다** — 깨진 썸네일을 남기지 않는다.
- 이미지는 **브랜드 CDN URL로만** 렌더한다. 우리 Storage 사본(`imageUrl`)으로 대체 금지([DataModel.md](DataModel.md) §1 경계).
- **수집은 네이티브에서만** 한다 — 웹은 남의 사이트 HTML 읽기를 CORS가 막는다. 웹은 네이티브가 채워 둔 값을 읽기만 하므로 시간이 지날수록 커버리지가 따라 올라간다.
- **한 세션에서 같은 장비를 다시 시도하지 않는다.** 죽은 링크가 27%가량이라 재시도는 곧 낭비다.
- **사이트 공용 로고는 거른다.** 시에라디자인은 상품 637건이 전부 같은 `og.jpg`(사이트 로고)를 반환한다 — 그리면 미리보기가 없느니만 못하다. 알려진 URL을 코드 상수(`GENERIC_IMAGES`)로 제외한다.
- **도메인 차단 스위치**를 코드 상수(`BLOCKED_HOSTS`)로 둔다. 브랜드 이의·Referer 차단 시 여기에 추가하고 **OTA로 내보낸다** — 스토어 심사 없이 반영된다. (Firestore 원격 설정 안은 보안 규칙을 함께 열어야 하고, 규칙이 없으면 조용히 무력해져서 접었다.)
- **출처 도메인을 노출한다**(`snowpeak.co.kr`). 미리보기의 핵심 정보이고 §1 경계 조건 ③이다.
  - 단 라벨이 이미 도메인인 경우(공식몰이 아닐 때)는 **도메인 줄을 생략한다** — 같은 문자열이 두 번 나오면 지저분하다.
- 카드 전체가 하나의 터치 타깃이며 동작은 기존 브랜드 행과 같다(`click_gear_purchase` `source: brand` → 인앱 브라우저).
- 쿠팡 행은 카드로 바꾸지 않는다 — 파트너스 고지가 딸려 구조가 다르고 27건(0.1%)뿐이라 통일할 실익이 없다.

**검증 체크리스트**

- [ ] 수집 전 장비를 처음 열면 → 밴드가 스켈레톤으로 뜬 뒤 이미지가 채워지고(카드 높이 변화 없음), `productImageUrl`이 Firestore에 기록된다 (GD-5a)
- [ ] 같은 장비 재진입 → 추가 og 요청 없이 즉시 이미지 표시 (GD-5a)
- [ ] 이미지 URL이 404/차단 → 깨진 썸네일 없이 상점 아이콘 (GD-5a)
- [ ] 공식몰 링크 → `{브랜드} 공식몰에서 보기` + 도메인 2줄 (GD-5a)
- [ ] 편집숍 링크 → `{도메인}에서 보기` 1줄, 도메인 중복 없음 (GD-5a)
- [ ] 카드 탭 → 인앱 브라우저, 닫으면 장비 상세 복귀 (GD-5a)
- [ ] 섹션 소제목 `공식 링크`가 스펙·리뷰와 같은 위계로 보인다 (GD-5)
- [ ] 웹에서 → 수집은 안 하지만 이미 채워진 장비는 이미지가 보인다 (GD-5a)
- [ ] 카드가 우리 Storage `imageUrl`을 **절대** 렌더하지 않는다 (GD-5a)

### GD-6 외부 후기 (네이버 블로그·유튜브)

사용자는 장비 상세에서 해당 장비의 외부 후기(블로그 글·유튜브 영상)를 바로 확인할 수 있다. 박지 상세(CS-3)의 후기 섹션과 동일한 공용 모듈을 재사용한다.

**수용 기준**

- 섹션 타이틀은 `블로그·유튜브 후기`(앱 내 사용자 `리뷰` 섹션과 구분). **배치는 보유 여부로 분기**한다 — 미보유(쇼핑 맥락)는 외부 후기가 구매 판단에 더 유용하므로 리뷰(댓글) 섹션 **위**, 보유는 리뷰 섹션 아래.
- **면 없이 흰 지면에 그대로 둔다**(2026-08-13 사용자 결정) — 박지 상세(CS-3) 후기 섹션과 같은 문법. 카드·리스트가 자체 썸네일 면을 가져, 회색 면(GD-0)으로 감싸면 면 안의 면이 된다. GD-0 "면 = 회색+12" 규칙의 예외.
- **검색어는 소스별로 다르게 조립한다** — 두 소스의 검색 특성이 달라 같은 문자열을 쓰면 한쪽이 망가진다(캐시 100건 실측: 블로그는 제품명 일치 93.3%인데 유튜브는 56.3%).
  - **두 소스 공통**: 검색어에 넣는 장비명은 **일반 토큰(사이즈·성별)을 제거한 형태**를 쓴다. 사이즈까지 넣으면 검색이 과하게 좁아져 후보 자체가 사라진다 — 라이브 실측: `"몽벨 montbell 버사자켓 남 미디엄"`은 유튜브 후보 **0건**, `"몽벨 montbell 버사자켓"`은 **25건**(블로그도 6건 → 30건). 단 **모델 번호처럼 1자인 토큰은 검색어에서 빼지 않는다**(`에어로라이트 2`와 `3`이 구분돼야 한다) — 길이 규칙은 필수 토큰 판정에만 적용된다.
  - **블로그**: `"{제조사 표시명} {일반 토큰 제거한 장비명} 후기"`(표시명 = `getDisplayName()` 계열, 제조사 없으면 생략).
  - **유튜브**: `"{제조사 표시명} {제조사 영문} {일반 토큰 제거한 장비명}"`. ① **`후기`를 넣지 않는다** — `추천 판매순위 Top10 ... 후기 비교` 류 리스티클이 여러 장비에 공통으로 붙는 원인이다. ② **영문 제조사(`getCompany()`)가 표시명과 다르면 함께 넣는다** — 카탈로그 `companyKorean`이 실제로 아무도 쓰지 않는 음차인 경우가 많다(`에이엠지티타늄` ↔ 실제 표기 `AMG티타늄`/`AMG-TITANIUM`).
- **유튜브 영상**(상위 4건, 가로 카드)과 **네이버 블로그**(상위 5건, 리스트) 구성·동작은 CS-3와 동일 — 후보 확대(`maxResults=25`/`display=30`) 후 **관련성 필터**를 적용해 상위 건수만 남기고, 유튜브에 `relevanceLanguage=ko`·`regionCode=KR`을 함께 보낸다(규칙은 CS-3 `관련성 필터` 항목이 단일 소스). 탭 시 외부 앱/브라우저로 이동, HTML 태그·엔티티 제거, 소스별 실패·0건이면 해당 리스트만 생략(둘 다 0건이면 섹션 생략).
  - 장비(GD-6)의 **필수 토큰은 장비명 토큰만** 쓴다 — `getDisplayName()`과 `getName()`을 각각 공백으로 분리한 2자 이상 토큰에서 사이즈·성별 등 **일반 토큰**(`mens`·`남`·`엑스라지`·`s`/`m`/`l` 등, 목록은 공용 모듈에 둔다)을 뺀 집합. **제조사만 일치하는 항목은 통과시키지 않는다** — 브랜드는 맞고 제품이 다른 결과(`몽벨 버사자켓` 상세에 `몽벨 아울렛 득템후기`)가 사용자에게 가장 무관하게 읽힌다. 토큰이 비었을 때의 처리는 아래 **필수 토큰 폴백**이 규정한다.
  - **판정 전용 제외 목록에는 카테고리·품목 명사(`텐트`·`배낭`·`필로우`·`매트`·`파우치` 등)도 넣는다.** 카테고리 명사만으로 판정하면 **같은 품목의 다른 제품**이 그대로 통과한다 — 라이브 실측: `엑스패드 렘 필로우` 상세에서 필수 토큰이 `["필로우"]`뿐이라 `엑스패드 딥슬립 필로우`·`랩 스트라토스피어 필로우`(타사 제품)가 통과했다. 모델명이 함께 있는 장비(`스텔라릿지 텐트`)는 모델명 토큰이 판정을 계속 담당하므로 동작이 바뀌지 않는다. **단 카테고리 명사는 검색어에서는 빼지 않는다**(위 검색어 규칙은 사이즈·성별만 제거) — 빼면 `엑스패드 렘`처럼 품목이 사라진 문구가 되어 후보를 못 찾는다. 즉 제외 목록은 **사이즈·성별(검색어·판정 공통)** 과 **카테고리 명사(판정 전용)** 두 벌이다.
  - **필수 토큰 폴백**: ① 이름(표시명·캐논컬명)**별로** 낱말 토큰을 뽑고, **어떤 이름이 낱말 토큰을 하나도 못 내면 그 이름의 전체 토큰**(사이즈·성별 낱말을 뺀 나머지를 공백 없이 이어 붙인 형태 — 제목에 사이즈를 적지 않으므로 `콕 파우치 - S`를 `콕파우치s`로 만들면 아무 제목에도 걸리지 않는다)을 대신 넣는다 → ② 그렇게 모은 집합이 그래도 비면 제조사 토큰(제조사는 낱말로 쪼개지 않고 문자열 전체를 한 토큰으로 — 쪼개면 `노스` 같은 조각이 무관한 제목에 걸린다).
    - 전체 토큰이 필요한 이유는 `렘`처럼 **1자 고유 모델명이 길이 규칙(2자)에 걸려 버려지기** 때문이다. 라이브 실측에서 `["필로우"]` → 블로그 통과 20건(대부분 타사 제품)이 `["렘필로우"]` → **3건 전부 해당 제품**으로 바뀌었다.
    - **이름별로 판단하는 이유**: 전체 집합이 빌 때만 폴백하면 한글 표시명이 토큰을 못 내도 **영문 캐논컬명의 로마자 토큰이 남아 폴백을 건너뛴다.** 라이브 카탈로그 11건이 이 상태다(`돔 3 텐트 매트`/`Dome 3 Tent Mat` → `["dome"]`, `콕 파우치 - S`/`Kok Pauchi - S` → `["kok","pauchi"]`). 한국어 제목은 이 토큰에 걸리지 않아 **후보가 전량 탈락하고 섹션이 사라진다.**
    - 제조사 폴백을 마지막에 두는 이유는 그것이 `브랜드만 일치` 문제를 되살리기 때문이다.
- **후기 캐시(주 1회 최신화)**: Firestore `gear-review/{gearId}`([DataModel.md](DataModel.md) DM-19)에 저장. 정책은 DM-18과 동일 — 캐시 우선 표시, `updatedAt` 7일 초과 시 재조회, 두 소스 모두 성공 시에만 갱신, 실패 시 기존 캐시 유지. `queryVersion` 불일치 캐시는 TTL과 무관하게 만료·미표시(DM-18/19).
- 블로그·유튜브 클릭은 `click_gear_review`(파라미터 `source: blog|youtube`)로 계측한다.

### GD-7 공유 `[제안]`

사용자는 카탈로그 장비를 외부로 공유하고, 받은 사람은 웹 랜딩을 거쳐 앱으로 진입한다(박지 공유 CS-7과 동일 구조).

**수용 기준**

- **카탈로그 장비(`!isCustom`)** 상세 헤더 우측에 공유 아이콘(수정하기 왼쪽). 커스텀 장비는 웹 랜딩 대상이 아니라 노출하지 않는다.
- 탭 → OS 공유 시트(`Share.share`)로 URL `{웹 베이스}/gear-share/{encodeURIComponent(gearId)}`**만** 내보낸다. 웹 베이스는 `constants/WebLinks.ts`의 `WEB_BASE_URL` 단일 소스를 쓴다(2026-07-28 커스텀 도메인 `useless.my` → Firebase Hosting 기본 도메인 `https://lessismore-7e070.web.app`). 공유 클릭은 `click_gear_share`로 계측한다.
- **웹 랜딩**(별도 레포 `lessismore`, `/gear-share/:id`): Firestore `/gear/{id}`(공개 읽기)를 읽어 제조사·이름·무게·카테고리를 보여주고(장비 이미지 미제공 원칙 — 사진 없음. 장비 `imageUrl` 렌더는 2026-08-14 웹 레포 커밋 4068e33에서 제거됨 — [DataModel.md](DataModel.md) §1 '앱 밖 표면' 해소), `앱에서 보기` 버튼으로 `lessismoreapp://gear-detail/{id}` 딥링크(미설치 시 스토어 폴백)로 앱을 연다.

### GD-8 카테고리별 스펙 표 `[기획]`

크롤 파이프라인이 기록한 `gear.specs`(DM-3)를 카테고리별 스키마에 맞춰 상세에 표시한다.

**수용 기준**

- 기본 정보 아래(배낭 기록/최저가 위)에 **`스펙` 섹션**을 두고, `specs`에 값이 있는 필드만 `라벨 : 값` 2열 표로 표시한다. `specs`가 없거나 전부 비면 섹션 자체를 렌더하지 않는다(레거시·커스텀 장비 호환).
- 스키마 사본 `model/gear/GearSpecsSchema.ts`가 계약: 웹 `specs-schema.js`와 **필드 키·한글 라벨·단위·타입을 동일하게** 유지한다(카테고리 33키). 스키마에 없는 미지의 키는 키명 그대로 표시(값 문자열화).
- 값 포맷: boolean은 `예`/`아니오`, `unit` 있으면 `값+단위`(예: `1500mm`, `850FP`, `-5°C`), enum은 한글 표시(`down`→`덕다운/합성` 등 라벨은 스키마에 정의), 빈 문자열·null은 해당 행 생략.
- 표는 토큰 톤(라벨 `textSecondary`, 값 `textPrimary`), 행 구분은 `borderLight`.

### GD-13 내 장비 사진 업로드 `[제안]`

사용자는 자기 장비의 사진을 직접 올려 창고·배낭에서 알아보기 쉽게 만들 수 있다. **본인만 보는 사진**이다([DataModel.md](DataModel.md) §1, 2026-07-29 개정).

**수용 기준**

- **보유 장비(`isAdded`)에만** 업로드 UI를 둔다. 카탈로그로만 진입한 미보유 장비에는 노출하지 않는다 — 저장할 문서(`users/{uid}/gears/{id}`)가 없다.
- 진입점: 이미지가 없으면 정보 블록 위 **사진 추가 영역**(점선 테두리 + `사진 추가`, 44pt 이상), 이미지가 있으면 이미지를 탭해 **교체/삭제 액션 시트**를 연다.
- 사진 출처는 **앨범 선택 + 카메라 촬영** 두 갈래를 제공한다(`expo-image-picker` — 필름 카드 `model/bag-film-card/BagFilmCard.ts`가 이미 쓰는 의존성 재사용).
  - **카메라를 쓰므로 `app.json`의 `expo-image-picker` 플러그인에 `cameraPermission` 한국어 문구가 있어야 한다.** 2026-07-28 제거 때 빠져 있었고, 없으면 iOS `NSCameraUsageDescription`에 영문 기본값이 박혀 심사 리젝 사유가 된다. `photosPermission`도 장비 사진 맥락을 포함하도록 갱신한다.
  - **권한 문구는 네이티브 Info.plist 값이라 OTA로 나가지 않는다 — 이 기능은 새 EAS 빌드가 필요하다.**
- **권한 거부** 시 알럿으로 안내하고 설정 이동 경로를 제시한다. 권한 거부는 실패로 처리하되 에러 문구를 띄우지 않는다(사용자의 선택).
- 업로드 흐름: 선택 → **업로드 중 표시**(진행 인디케이터, 화면 이탈 금지 아님) → Storage `/{userId}/{fileName}` 업로드(DM-9) → 다운로드 URL을 `users/{uid}/gears/{id}.imageUrl`에 저장 → 화면 즉시 반영.
- **교체·삭제 시 이전 Storage 파일을 함께 지운다**(DM-9). 삭제는 확인 다이얼로그를 거치고, 확정 시 `imageUrl`을 제거한다.
- **업로드 실패**(네트워크·용량)는 토스트로 알리고 기존 상태를 유지한다. 부분 실패로 `imageUrl`이 깨진 URL을 가리키지 않게, **Storage 업로드 성공 후에만** 문서를 갱신한다.
- 이미지 로드 실패(파일이 지워진 레거시 URL 등)는 **이미지 없음과 동일하게** 처리한다 — 깨진 아이콘을 남기지 않는다. 2024~2026 업로드분 중 참조가 끊긴 것이 있을 수 있다.
- **장비를 수정해도 사진이 지워지지 않아야 한다.** 원인이 둘이라 양쪽을 막는다 — ① `GearStore.update`가 문서를 통째로 덮어쓰던 것을 **부분 갱신으로 바꾼다**([DataModel.md](DataModel.md) DM-11), ② 편집 폼이 `getExtra()`로 `Gear`를 재구성하므로 `Gear.getData()`에도 `imageUrl`을 포함시킨다. 폐기 기간에 실제로 ①번 경로로 값이 유실될 수 있었다(§1 — 배포 전이라 실제 유실은 없었다).
- 업로드한 이미지는 **창고 목록**([Warehouse.md](Warehouse.md) WH-1)과 **배낭 상세 장비 행**([BagDetail.md](BagDetail.md) BD-1)에도 나타난다. **공유 배낭·후기 첨부 배낭 등 제3자 표면에는 나타나지 않는다**(§1 비공개 원칙).

- [ ] 브랜드 행 탭 → **인앱 브라우저 시트**로 열리고, 닫으면 장비 상세로 복귀 (GD-5)
- [ ] 쿠팡 행 탭 → 쿠팡 앱(미설치 시 외부 브라우저)으로 이동 — 인앱 브라우저로 열리지 않는다 (GD-5)
- [ ] 둘 다 있는 장비 → 브랜드 행, 그 아래 쿠팡 행 + 고지 (GD-5)
- [ ] 둘 다 없는 장비·커스텀 장비 → 섹션 전체(구분선 포함) 미노출 (GD-5)
- [ ] 보유 장비 → 섹션 순서가 정보 → 배낭 기록 → 외부 링크 → 리뷰 (GD-5)
- [ ] 미보유 장비 → 섹션 순서가 정보 → 외부 링크 → 리뷰 (GD-5, 현행 유지)
- [ ] 카테고리 있는 장비 → 이름 아래 메타 라인에 `카테고리 · 색상` 표시, 둘 다 없으면 라인 미노출 (GD-1)
- [ ] 수정하기가 헤더 우상단에 노출 (GD-1)
- [ ] 스크롤을 정보 섹션 아래로 내리면 헤더에 제품명 표시, 최상단 복귀 시 사라짐 (GD-1)
