# 인앱 공지 배너 (원격 제어)

| 항목 | 내용 |
| --- | --- |
| 상태 | proposed `[기획]` |
| ID 프리픽스 | `AN` |
| 주요 코드 | `model/announcement/`, `components/announcement/`, `components/Layout.tsx`(배너 삽입) |
| 관련 스펙 | [DataModel.md](DataModel.md), [Notification.md](Notification.md), [AppLifecycle.md](AppLifecycle.md) |

## 1. 개요

Firestore 문서 하나를 고치면 **앱 안에 배너가 뜨는** 원격 공지 기능이다. 점검 안내·이벤트·업데이트 소식처럼 앱 밖 푸시까지 필요 없는 가벼운 공지를 위해 쓴다.

기존 원격 공지([Notification.md](Notification.md) NT-5)는 **FCM 푸시**(Firebase 콘솔 수동 발송, OS 레벨 알림)라 서로 다르다. 이건 **앱을 열었을 때 화면 안에서** 보이는 배너이며, 둘은 독립적으로 공존한다.

- **발송**: Firebase 콘솔에서 `config/announcement` 문서를 수정(코드/푸시 불필요).
- **반영**: 앱이 문서를 **실시간 구독**(`onSnapshot`)해 즉시 반영한다.
- **배포**: 네이티브 모듈 추가가 없어(Firestore는 이미 사용) **OTA로 배포 가능**하다.

## 2. 구성

- 전역 매니저: `AnnouncementManager` — `app.getAnnouncementManager()`로 접근(기존 매니저 패턴). `config/announcement` 구독, 표시 여부 판정, 닫음 상태 관리.
- 초기화: `app.initialize()`에서 인스턴스화 + 구독 시작.
- 시트 UI: `AnnouncementSheetView` — `app/_layout.tsx` 최상위에서 렌더(모달이라 모든 화면 위).
- **웹 포함 전 플랫폼 동작**(Firestore는 웹에서도 동작). 네이티브 전용 분기 없음.

## 3. 요구사항

### AN-1 원격 공지 문서 `[제안]`

**수용 기준**

- 단일 문서 `config/announcement`를 둔다(필드는 [DataModel.md](DataModel.md) DM-23). 콘솔에서 수동으로만 쓰고, 클라이언트는 읽기만 한다.
- **로그인 이전에도 표시**하므로 미인증 공개 읽기를 허용한다(`config/app`과 동일 정책). 보안 규칙에 `config/announcement` 읽기 허용 추가 필요 — **사용자 콘솔/규칙 배포 작업**.

### AN-2 공지 바텀 시트 표시 `[제안]`

공지를 **하단에서 올라오는 바텀 시트(모달)** 로 띄운다. 상단 인라인 배너보다 주목도가 높아 공지를 확실히 노출한다.

**수용 기준**

- `config/announcement`를 `onSnapshot`으로 **실시간 구독**한다. 문서가 바뀌면 시트 상태가 즉시 갱신된다.
- 아래를 **모두** 만족할 때만 시트를 띄운다:
  - `active === true`
  - 노출 기간 안(있을 때만): `startAt` ≤ 현재 ≤ `endAt`. 값이 없으면 그 방향 제한 없음.
  - 사용자가 이 공지를 닫지 않았음(AN-4)
- **표시 방식**: RN `Modal`(transparent) 기반 바텀 시트(기존 `components/ui/BottomMenuModalView.tsx` 패턴 재사용). 하단에서 slide-up, 그랩 핸들, 딤(dim) 배경. **전역 1곳**(`app/_layout.tsx` 최상위)에서 렌더 — 모달이라 모든 탭·화면 위에 뜨므로 탭별 삽입은 불필요하다.
- 내용: 그랩 핸들 + **메시지 텍스트**(필수) + (link 있으면 CTA 버튼, AN-3) + **닫기 버튼**. 세이프에어리어(하단 홈 인디케이터) 존중.
- 닫기 경로: 딤 배경 탭 · 그랩 핸들 아래로 스와이프 · 닫기 버튼 — 어느 쪽이든 시트를 내리고 AN-4의 닫음 처리를 한다.
- 디자인 토큰(`DesignTokens.ts`)·`PretendardText`를 쓴다. 메시지가 길면 시트 안에서 스크롤되거나 자연스럽게 늘어난다(레이아웃이 깨지지 않게).
- 문서가 없거나 조회 실패면 시트를 띄우지 않는다(조용히 통과, 앱 동작에 영향 없음).

### AN-3 링크 이동 `[제안]`

**수용 기준**

- `link`가 있으면 시트에 **CTA 버튼**(예: `자세히 보기`)을 두고, 탭 시 이동한다. 이동 후 시트를 닫는다(AN-4 닫음 처리 포함).
  - 앱 내부 경로(예: `/bag`, `/gear-detail/123`)면 라우터로 이동.
  - `http(s)://`로 시작하면 외부 브라우저로 연다.
- `link`가 없으면 CTA 버튼을 두지 않는다(닫기만 가능).
- 접근성: CTA·닫기 버튼에 `accessibilityRole='button'`과 라벨(44×44pt 터치 타깃). 잘못된 link는 무시(크래시 금지).

### AN-4 닫기 → 재표시 안 함 `[제안]`

**수용 기준**

- 배너의 닫기(X)를 누르면 **그 공지는 다시 뜨지 않는다.** 문서의 `id`(공지 식별자)를 기기에 기억한다(AsyncStorage).
- `id`가 바뀌면(= 새 공지) 이전에 닫았어도 **다시 뜬다.** 즉 닫음 상태는 `id` 단위.
- `active`를 껐다가 같은 `id`로 다시 켜면 뜨지 않는다(이미 닫은 공지). 다시 띄우려면 `id`를 바꾼다.
- 닫음 상태는 **기기 로컬**이라 재설치 시 초기화된다(known issue로 수용, 서버 저장 안 함).

## 4. 데이터

- 문서·필드는 [DataModel.md](DataModel.md) **DM-23 (`config/announcement`)** 에 정의한다.
- 닫음 상태(닫은 `id` 목록)는 서버에 저장하지 않고 기기 로컬(AsyncStorage)에만 둔다.

## 5. 엣지 케이스

- **문서 없음 / 오프라인 / 조회 실패**: 배너 없음(조용히 통과).
- **`active=false`**: 배너 없음.
- **기간 밖**: 배너 없음(`startAt`/`endAt` 경계 포함).
- **`message` 빈 값**: 배너 없음(표시할 내용 없음).
- **비로그인**: 미인증 읽기 허용이므로 로그인 전에도 표시된다.
- **잘못된 `link`**: 내부 경로로 해석 안 되면 무시(이동 안 함, 크래시 금지).

## 6. 수동 검증 체크리스트

- [ ] `config/announcement`에 `active=true`+`message` 넣기 → 앱 모든 탭 상단에 배너
- [ ] `link`(내부 경로) 넣고 배너 탭 → 해당 화면 이동 / `http` 링크 → 외부 브라우저
- [ ] 닫기(X) → 배너 사라짐, 앱 재실행해도 같은 `id`면 안 뜸
- [ ] `id` 변경 → 닫았던 사용자에게도 다시 표시
- [ ] `active=false` / 기간 밖 / `message` 빈 값 → 배너 안 뜸
- [ ] 문서 삭제·오프라인 → 배너 없이 앱 정상
- [ ] 콘솔에서 문서 수정 → 앱 재시작 없이 배너 실시간 갱신

## 7. 결정 사항 / 미해결 질문

**결정됨(초안 기본값 — 이론 여지 있으면 조정)**

- 내용: **메시지 텍스트 + 선택적 링크**(제목/본문 분리·이미지는 범위 밖).
- 표시: **바텀 시트(하단 모달)**, 전역 1곳 렌더. (상단 인라인 배너에서 변경)
- 닫기: **`id` 단위로 한 번 닫으면 안 뜸**(재실행에도 유지, 새 `id`면 재표시).
- 문서 형태: **단일 문서**(공지 하나만 활성). 여러 공지 동시 노출·이력은 범위 밖.

**미해결**

- 배너 색/강조(정보·경고 등 유형별 스타일)를 나중에 둘지.
- 특정 앱 버전·플랫폼 타겟팅(`config/app`의 버전 게이트와 유사)을 나중에 둘지.
