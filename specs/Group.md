## 1. 개요

그룹은 **같이 가는 한 번의 여행**을 준비하는 공간이다. 여행을 만들고 일행을 초대하면 서로의 배낭을 보며 무엇을 챙겼는지 확인하고, 박지·코스·지도 위 정보를 한곳에 모아 공유한다.

혼자 쓰는 배낭이 "내가 무엇을 챙겼나"를 답한다면, 그룹은 **"우리가 무엇을 챙겼나"** 를 답한다. 텐트가 둘인지, 물을 어디서 받는지, 어느 길로 가는지는 혼자서는 알 수 없고 모여야 보인다.

**그룹의 단위는 여행 1건이다.** 배낭이 이미 여행 단위(이름·기간·여행지)이므로 그룹과 배낭이 자연스럽게 1:1로 붙고, 여행이 끝나면 그룹도 함께 지나간 기록이 된다. 지속되는 모임(동아리·크루)과 그 안의 여러 일정은 이번 범위가 아니다.

**MVP 범위**: 그룹 생성, 초대 링크 참여, 멤버 관리, 배낭 서로 보기, 박지·일정 공유, 코스(GPX) 업로드와 지도 표시, 지도 포인트 주석(물보급지 등).

**MVP에서 제외**: 지속 모임과 다중 일정, 그룹 채팅, 공동 편집 배낭(한 배낭을 여럿이 수정), 장비 분담 배정, 푸시 알림(초대·활동), 그룹 검색·공개 그룹, 정산, 사진 앨범, 그룹 내 댓글, 외부 웹 공유 페이지.

## 2. 화면 및 진입

```text
app/(tabs)/bag.tsx → 세그먼트 `배낭 | 템플릿 | 그룹` (BT-2 확장, 탭은 늘리지 않는다 — APP-5)
                      └─ 그룹 목록(GroupListView)

app/group/new.tsx → GroupCreateWrapper → GroupCreateView
                      └─ 이름 · 기간 · 여행지(박지 선택 재사용)

app/group/[id].tsx → GroupDetailWrapper → GroupDetailView
                      ├─ GroupHeaderView: 이름 · 기간 · 여행지 · 멤버 아바타
                      ├─ GroupMemberBagListView: 멤버별 배낭 요약 행
                      ├─ GroupRouteListView: 코스 목록
                      ├─ GroupPointListView: 지도 포인트 목록
                      └─ GroupInviteView: 초대 링크 복사

app/group/[id]/member/[uid].tsx → 멤버 배낭 상세(읽기 전용, SharedBagView 문법 재사용)

app/group/[id]/map.tsx → GroupMapWrapper → GroupMapView
                      ├─ 코스 폴리라인 · 포인트 마커 · 박지 마커
                      └─ 롱프레스 → GroupPointCreateSheetView

app/group/[id]/edit.tsx → 그룹 정보 수정(방장)

app/group/join.tsx → 초대 수락(그룹 이름·기간·멤버 수 확인 후 참여)
```

- 진입 경로: 배낭 탭 세그먼트 `그룹`, 초대 링크 딥링크, **연결된 배낭의 상세 헤더**([BagDetail.md](BagDetail.md) BD-1). 홈 `다가오는 일정` 카드의 그룹 배지는 `[후속]`이다 — [Home.md](Home.md) HM-1에 해당 수용 기준이 없고 MVP에서 구현하지 않았다. 넣으려면 HM-1을 먼저 갱신한다.
- 탭은 다섯 개를 유지한다([AppLifecycle.md](AppLifecycle.md) APP-5). 그룹은 배낭 탭 안의 세그먼트로 들어가고 본문은 푸시 라우트가 맡는다 — 창고·내 정보가 밟은 경로와 같다.
- 열람·참여 모두 로그인이 필요하다. 비로그인 상태로 초대 링크를 열면 전역 로그인 모달을 띄우고, 로그인 후 같은 초대 화면으로 돌아온다.

## 3. 요구사항

### GRP-1 그룹 목록 `[제안]`

사용자는 자신이 속한 그룹을 한곳에서 보고 들어갈 수 있다.

**수용 기준**

- 배낭 탭 상단 세그먼트는 이미 `배낭 | 템플릿` 두 칩이다([BagTemplate.md](BagTemplate.md) BT-2). 여기에 `그룹`을 더해 세 칩으로 만든다. 공용 `CategoryChipView` 문법·기본 선택 `배낭`·정렬 드롭다운 위치는 BT-2를 그대로 따르고, `그룹` 세그먼트에서는 정렬 드롭다운을 렌더하지 않는다(정렬이 출발일 고정).
- 목록은 내가 멤버인 그룹을 **출발일이 가까운 순**으로 표시한다. 종료일이 지난 그룹은 목록 아래 `지난 그룹` 구분선 뒤에 최신순으로 둔다.
- 각 행은 그룹 이름, `YYYY.MM.DD ~ YYYY.MM.DD` 기간, 여행지 이름, 멤버 수, 내 배낭 연결 여부를 표시한다. 행 문법은 목록 행 규칙(이름 16 medium + 메타 14 잉크 한 줄)을 따른다([Home.md](Home.md) HM-8).
- 빈 상태는 `아직 참여한 그룹이 없어요` 한 줄과 `그룹 만들기` 알약 버튼을 표시한다.
- 주 액션 `그룹 만들기`는 배낭 탭의 `배낭 추가`와 같은 위치·크기의 플로팅 알약으로 둔다([Bag.md](Bag.md) BAG-1).
- 조회 오류는 빈 상태와 섞지 않고 `그룹을 불러오지 못했어요`와 `다시 시도`만 표시한다.

### GRP-2 그룹 만들기 `[제안]`

사용자는 여행 하나를 그룹으로 만들고 일행을 부를 수 있다.

**수용 기준**

- 입력은 이름(필수, trim 후 2~40자), 기간(필수, 시작일·종료일), 여행지(선택)다.
- 여행지는 배낭의 여행지 선택기(`/bag-destination-picker`)를 재사용한다([BagDestination.md](BagDestination.md) DST-1). 등록 박지를 고르면 `campSpotId`를, 자유 위치를 고르면 표시 이름만 저장한다 — **자유 위치의 좌표는 그룹에 저장하지 않는다**(GRP-5 공개 원칙).
- 만든 사람이 방장(`owner`)이 되고 멤버로 함께 등록된다.
- 생성 직후 그룹 상세로 이동하고, 초대 링크 복사를 유도하는 안내를 한 번 표시한다.
- 기간은 시작일 ≤ 종료일이어야 하고, 최대 30일까지 허용한다. **양끝을 모두 세어 30일**이다(종료일 − 시작일 ≤ 29일). 하루짜리 여행은 시작일 = 종료일.
- 한 사용자가 동시에 속할 수 있는 그룹은 20개까지다.

### GRP-3 초대 링크와 참여 `[제안]`

사용자는 링크 하나로 일행을 그룹에 부를 수 있다.

**수용 기준**

- 그룹 상세에 `초대 링크 복사` 액션을 둔다. 링크는 `{WEB_BASE_URL}/group/{groupId}` 형식이고 배낭 공유와 같은 `WEB_BASE_URL` 단일 소스를 쓴다([BagDetail.md](BagDetail.md) BD-7).
- 앱이 설치된 기기에서 링크를 열면 `app/group/join.tsx`로 딥링크되어 그룹 이름·기간·여행지·멤버 수를 먼저 보여주고, `참여하기`를 눌러야 멤버가 된다. 확인 없이 가입시키지 않는다.
- 이미 멤버면 참여 화면 대신 그룹 상세로 바로 보낸다.
- 링크에는 별도 토큰을 두지 않고 **`groupId` 자체를 비밀로 취급**한다. 문서 ID는 Firestore 자동 생성 20자라 추측이 불가능하고, 배낭 링크 공유와 같은 보안 수준이다. 토큰·만료·재발급은 후속 범위로 둔다.
- 멤버 상한은 20명이다. 가득 찬 그룹의 링크를 열면 `정원이 찼어요` 안내만 표시하고 참여 버튼을 비활성화한다.
- 방장은 초대 링크를 잠글 수 있다(`inviteEnabled = false`). 잠긴 링크로 들어오면 `초대가 마감됐어요`를 표시한다.
- 앱은 Universal Links / App Links를 쓰지 않는다(`app.json`에 `associatedDomains`·`intentFilters`가 없다). 따라서 `{WEB_BASE_URL}/group/{groupId}`는 브라우저로 열리고, **웹 랜딩이 앱 스킴 `lessismoreapp://group/join?groupId={groupId}`로 넘겨준다.** 이미 장비·박지 공유가 같은 방식이다(`gear-share`·`camp-share` 랜딩이 각각 `lessismoreapp://gear-detail/{id}`·`lessismoreapp://camp-site/{id}`를 연다).
  - 네이티브 링킹 설정으로 가면 링크가 앱을 바로 열지만 **OTA로 못 나가고 새 빌드가 필요하다.** 초대 한 줄을 위해 릴리스를 묶지 않는다.
- 웹 랜딩(별도 레포 `lessismore`, 경로 `/group/:id`)은 그룹 이름·기간·여행지·멤버 수를 먼저 보여주고 `앱에서 열기`로 위 스킴을 연다. 스킴이 열리지 않으면 스토어로 보낸다 — 장비·박지 공유 랜딩과 같은 동작이다.
- **앱의 웹 빌드를 이 호스팅 사이트에 배포하지 않는다.** 앱에도 `/group/{id}` 라우트가 생겨 경로가 문자 그대로 겹치고, 앱 웹을 올리면 초대 링크가 랜딩 대신 로그인이 필요한 앱 그룹 상세로 열린다. 이 사이트는 `lessismore` 레포가 소유한다.
- 랜딩이 읽는 것은 그룹 문서가 아니라 **초대 공개 요약 `groupInvites/{groupId}`** 다([DataModel.md](DataModel.md) DM-29). 그룹 문서는 로그인한 사용자만 읽을 수 있고 랜딩은 비인증이라, 초대 화면에 필요한 값(이름·기간·여행지·멤버 수·잠금 여부)만 서버가 복제해 둔다. **집합 메모와 멤버 uid는 복제하지 않는다** — 링크는 전달될 수 있고, 집합 메모는 일행이 실제로 언제 어디서 모이는지를 담는다.
- 미러가 아직 없거나 읽기가 실패하면 그룹 정보 없이 `앱에서 열기`와 설치 안내만 남는 축소 형태로 떨어진다. 초대 링크가 통째로 죽는 것보다 낫다.
- 참여 화면 라우트(`app/group/join.tsx`)는 동적 세그먼트가 없으므로 **쿼리 `groupId`** 로 받는다.

### GRP-4 멤버와 역할 `[제안]`

그룹에는 방장과 멤버가 있고, 누구나 스스로 나갈 수 있다.

**수용 기준**

- 역할은 `owner`(방장) · `member` 두 가지다. 만든 사람이 방장이고 MVP에서 방장 위임은 없다.
- 멤버 목록은 방장을 맨 위에 두고 참여한 순서로 표시한다. 각 행에 닉네임(참여 시점 스냅샷)과 배낭 연결 여부를 표시한다.
- 방장은 그룹 정보 수정, 멤버 내보내기, 초대 링크 잠금, 그룹 해산을 할 수 있다. 멤버는 자기 배낭 연결·해제, 포인트·코스 추가, 그룹 나가기를 할 수 있다.
- 포인트·코스는 **올린 사람과 방장만** 지울 수 있다.
- 멤버 내보내기는 **멤버 행의 `⋯`** 에서 시작한다. 이 `⋯`는 방장에게만, 그리고 **자기 자신이 아닌 행에만** 보인다 — 멤버에게는 어떤 형태로도 노출하지 않는다. 길게 누르기 같은 숨은 제스처로 감추지 않는다.
- 내보내기는 `{닉네임}님을 내보낼까요?`와 **그 사람의 배낭 스냅샷도 함께 사라진다**는 안내를 확인한 뒤 실행하고, 파괴적 액션이므로 확인 버튼을 경고색으로 그린다.
- 내보내면 대상의 멤버 문서와 배낭 스냅샷을 지우고 `memberIds`·`memberCount`를 줄인다. 성공하면 멤버 목록·배낭 목록·일행 합계가 곧바로 반영된다. 실패하면 화면 상태를 유지하고 토스트로만 알린다(GRP-12).
- 대상의 역인덱스(`users/{uid}/groups/{groupId}`)는 클라이언트가 지울 수 없어 **서버 트리거 몫**이다([DataModel.md](DataModel.md) DM-29) — 내보낸 직후 그 사람의 그룹 목록에 잠시 남아 보일 수 있고, 이는 정상이다.
- 방장이 나가려면 먼저 그룹을 해산해야 한다. 해산은 `이 그룹을 해산할까요?` 확인을 거치고, 그룹과 그 하위 데이터(멤버·배낭 스냅샷·포인트·코스)를 모두 지운다.
- 멤버가 나가면 그 사람의 배낭 스냅샷을 함께 지운다. 그가 올린 포인트·코스는 남기고 작성자 표시만 `(나간 멤버)`로 바꾼다 — 코스 정보는 남은 일행에게 계속 쓸모가 있다.
- `(나간 멤버)` 치환은 **화면에서 파생한다**: 포인트·코스의 `authorId`가 현재 멤버 목록에 없으면 `authorName` 대신 이 문구를 렌더한다. 저장된 `authorName`을 서버가 덮어쓰지 않는다 — 나가는 사람이 남의 문서를 못 쓰고, 이 한 줄을 위해 트리거를 더 두는 값이 없다. 회원 탈퇴(계정 삭제)는 이와 달라 `(탈퇴한 사용자)`이며 서버가 `authorName`을 비운다(GRP-12).
- 닉네임은 유니크하지 않으므로([DataModel.md](DataModel.md) DM-2) 같은 닉네임이 여럿일 수 있다. 멤버 식별은 항상 `uid`로 하고 화면에서는 닉네임을 그대로 표시한다.

### GRP-5 배낭 연결과 공유 `[제안]`

멤버는 자기 배낭 하나를 그룹에 연결해 일행에게 장비 목록을 보여준다.

**수용 기준**

- 그룹 상세에서 `내 배낭 연결`을 누르면 본인 배낭 목록 시트가 열린다. 시트는 커뮤니티 패킹 첨부와 같은 것을 재사용한다([Community.md](Community.md) CM-4).
- 연결하면 **공개용 배낭 스냅샷**이 그룹 하위에 생성된다. 스냅샷에 담기는 것과 빠지는 것은 커뮤니티 패킹 스냅샷과 **같은 계약**을 따른다([DataModel.md](DataModel.md) DM-28 `bagSnapshot`).
  - 담는 것: 배낭 이름, 기간, 여행지 표시 이름, 총 무게, 장비 수, 장비별 브랜드·이름·무게·카테고리, 카탈로그 장비의 `gearId`.
  - **빼는 것: 메모, 정확한 좌표, 이동 경로, 건강·활동 기록, 개인 장비 사진(`imageUrl`), 사용자 정의 장비 문서 ID.**
- 커뮤니티 스냅샷과 다른 점은 **원본을 따라간다**는 것이다. 연결된 배낭의 장비·이름·기간이 바뀌면 그룹 스냅샷을 다시 써서 일행이 최신 구성을 본다. 갱신 시점은 ① 배낭 편집 확인 ② 배낭 정보 수정 ③ 그룹 상세 진입 시 본인 것 재동기화 세 가지다.
  - **`bag` 문서를 그룹원이 직접 읽게 하지 않는다.** 배낭에는 메모·좌표·건강 기록이 함께 들어 있어 읽기 권한을 열면 그것까지 열린다. 스냅샷을 그룹 하위에 따로 두면 공개 범위가 데이터 모양으로 고정되고, 보안 규칙도 그룹 컬렉션만 잠그면 된다. 배낭 링크 공유가 뷰가 아니라 데이터 레이어에서 사진을 걸러내는 것과 같은 판단이다([BagDetail.md](BagDetail.md) BD-7).
  - 따라서 반영은 실시간 구독이 아니라 **쓰기 시점 동기화**다. 일행이 장비를 바꾸는 즉시 내 화면이 갱신되지는 않고, 다음 조회에서 보인다.
- 연결을 해제하면 스냅샷을 지운다. 다른 배낭으로 바꾸면 스냅샷 전체를 새 값으로 교체한다.
- **배낭 하나는 그룹 하나에만 연결된다**(2026-09-23 사용자 결정). 여행 1건 = 그룹 1개이고 배낭도 기간·여행지·날씨를 가진 여행 단위라, 한 배낭이 두 여행에 동시에 속할 이유가 없다.
  - 배낭 선택 시트에서 이미 **다른 그룹에 연결된 배낭**은 메타 줄에 `{그룹 이름}에 연결됨` 조각을 붙인다(배지 금지, HM-8).
  - 그런 배낭을 고르면 `{다른 그룹}에서 빼고 이 그룹으로 옮길까요?`를 확인한 뒤, 기존 연결을 해제하고 새로 연결한다. 취소하면 아무것도 바꾸지 않는다.
  - 한 사람이 같은 그룹에 연결하는 배낭은 원래부터 하나다(`members/{uid}.bagId`). 배낭 상세에서 그룹에 연결할 때 그 그룹에 **내가 이미 다른 배낭을 연결해 두었으면** `이 그룹에는 이미 {다른 배낭}을 연결해 두었어요. 이 배낭으로 바꿀까요?`를 확인한다 — 배낭 쪽에서는 그 그룹에 무엇이 연결돼 있는지 보이지 않아 모르고 바꿀 수 있다. 그룹 상세의 `배낭 변경`은 이미 연결된 배낭이 보이는 자리라 묻지 않는다.
  - 이 제약은 클라이언트가 지킨다. 보안 규칙은 여러 문서를 가로질러 검사할 수 없다. 이 결정 이전에 여러 그룹에 연결해 둔 배낭은 그대로 두고, 배낭 상세에는 출발일이 가장 가까운 그룹 하나를 보여준다.
- **연결할 때 기간·여행지가 그룹과 다르면 맞출지 한 번 묻는다**(2026-09-23 사용자 결정). `그룹 일정으로 맞출까요?` → 맞추면 배낭의 기간을 그룹 기간으로 바꾼다. 맞추지 않아도 연결은 된다.
  - 여행지는 **그룹 여행지가 등록 박지일 때만** 맞출 수 있다. 박지는 공개 좌표가 있어 배낭 여행지(`BagLocation`)로 옮길 수 있고, 그러면 배낭 날씨도 그 박지 기준이 된다. 자유 위치는 좌표를 저장하지 않으므로(GRP-2) 기간만 맞추고 여행지는 그대로 둔다 — 이 경우 문구도 기간만 말한다.
  - 한 번 맞춘 뒤에는 둘이 따로다. 방장이 그룹 기간을 바꿔도 멤버 배낭은 따라가지 않는다. 남의 배낭을 서버가 고치지 않는다는 원칙을 지키기 위해서다.
  - 배낭 쪽에서 연결할 때(BD-1 `⋯` 메뉴)도 같은 확인을 거친다.
- 배낭이 하나도 없으면 시트에 `먼저 배낭을 만들어주세요`만 표시한다.
- 멤버 배낭 행을 탭하면 읽기 전용 상세로 들어간다. 장비 목록은 카테고리별 섹션으로 보이고, 카탈로그 장비는 장비 상세로 이동할 수 있다([Community.md](Community.md) CM-4와 같은 문법). 원본 배낭 편집 화면으로는 갈 수 없다.
- 그룹 헤더에 **일행 전체 합계**(멤버 수, 연결된 배낭 수, 총 무게 합)를 표시한다.

### GRP-6 겹치는 장비 보기 `[기획]`

일행이 같은 장비를 중복해서 챙기는 것을 미리 알 수 있다.

**수용 기준**

- 연결된 배낭들에서 같은 `gearId`(카탈로그 장비)가 둘 이상 나오면 해당 장비에 `N명 중복` 배지를 붙인다.
- 그룹 상세에 `겹치는 장비` 요약 섹션을 두고 중복 장비와 보유자 닉네임을 나열한다.
- 사용자 정의 장비는 ID가 없어 중복 판정에서 제외한다.
- **MVP 범위가 아니다.** GRP-5가 자리 잡은 뒤 별도로 진행한다. 장비 분담 배정(누가 무엇을 가져올지 정하기)은 그 다음 단계다.

### GRP-7 일정과 박지 `[제안]`

그룹에 여행 정보를 달아 일행이 같은 것을 본다.

**수용 기준**

- 그룹은 이름·기간·여행지를 갖는다. 여행지가 등록 박지면 `campSpotId`를 저장하고 박지 이름·유형을 함께 표시한다.
- 박지를 탭하면 기존 박지 상세 시트(`/camp-site/{id}`)를 연다([CampSite.md](CampSite.md) CS-3).
- 등록 박지가 연결된 그룹은 상세 상단에 **공개 박지 좌표로 만든 지도 밴드**를 표시한다. 자유 위치는 좌표를 저장하지 않으므로 이름만 표시한다.
- 방장은 집합 시간·장소를 한 줄 메모(`meetingNote`, 최대 200자)로 남길 수 있다. 자유 텍스트이며 좌표를 갖지 않는다.
- 날씨는 그룹에 저장하지 않는다. 필요하면 각자 자기 배낭의 날씨를 본다([Weather.md](Weather.md)).

### GRP-8 코스(GPX) `[제안]`

멤버는 GPX 파일을 올려 일행에게 갈 길을 보여준다.

**수용 기준**

- 그룹당 코스는 5개까지, 파일 하나는 **5MB 이하**다. 확장자 `.gpx`만 받는다.
- 업로드하면 클라이언트가 GPX를 파싱해 트랙 좌표를 읽고 다음을 저장한다: 이름(파일명 또는 `<trk><name>`, 최대 40자), 총 거리, 고도 상승, 트랙포인트 수, 경계 상자, **지도 렌더용 축약 좌표**.
- 코스 이름이 40자를 넘으면 **거절하지 않고 40자로 자른다.** 이름은 사용자가 타이핑한 값이 아니라 파일명·트랙명에서 자동으로 딸려오는 값이라, 길다는 이유로 업로드를 막으면 사용자가 고칠 방법이 없다.
- 축약 좌표에는 **고도를 함께 싣는다**(`{ lat, lng, ele? }`). 고도 그래프가 이 값을 그대로 쓰므로 원본 GPX를 다시 내려받지 않는다. GPX에 고도가 없으면 키를 생략하고, 그래프도 그리지 않는다.
- **고도 그래프**: 코스를 열면 거리(가로) 대비 고도(세로) 단면을 그린다. 축은 시작·끝·최고점만 적어 숫자를 어지럽히지 않는다. 고도가 없는 코스는 그래프 자리를 비우고 거리·트랙포인트만 보여준다.
- **그래프를 손가락으로 훑으면 지도에 그 지점이 표시된다.** 그래프의 x 위치가 코스 위 한 점을 가리키고, 지도에 그 좌표의 마커가 따라 움직이며 그때의 거리·고도를 함께 읽는다. 손을 떼면 표시가 사라진다 — 어느 오르막이 어디인지 지도에서 바로 확인하려는 것이 이 기능의 목적이다.
- 그래프와 지도를 나란히 볼 수 있어야 한다. 그래프가 지도를 가리면 훑는 동안 위치를 못 보므로, 그래프는 지도 아래(또는 지도를 가리지 않는 자리)에 둔다.
- **웹에서는 그래프만 그리고 지도 연동은 하지 않는다**(웹은 지도 자체가 목록으로 대체된다).
- 코스는 배낭에도 붙일 수 있다([BagDetail.md](BagDetail.md) BD-11, [DataModel.md](DataModel.md) DM-30). 두 곳은 **파서·고도 그래프·목록 행을 공유하고 사는 곳만 다르다.** 상한(5개·5MB·축약 2~500점)과 실패 사유도 같다 — 수치를 갈라 두면 사용자가 둘을 다르게 기억해야 한다.
- **배낭 코스를 그룹에 올리면 복사한다**(문서 + Storage 원본). 참조로 두지 않는 이유는 그룹 멤버가 남의 배낭을 읽지 못한다는 격리를 깨야 하기 때문이다(GRP-5). 복사이므로 올린 사람이 원본을 지우거나 그룹을 나가도 그룹 코스는 남는다 — GRP-4의 "나간 멤버의 코스는 남긴다"와 같은 철학이다.
- **반대 방향(그룹 코스 → 배낭)은 복사하지 않는다.** 배낭 상세는 연결된 그룹의 코스를 읽어서 출처 배지와 함께 보여주기만 하고, 그 배낭이 그룹에 연결돼 있는 동안만 보인다.
- **코스 뒤집기**: 코스를 역방향으로 볼 수 있다. 뒤집으면 좌표 순서·고도 그래프·거리 누적·상승이 모두 바뀐다(원래의 하강이 새 상승이 된다).
  - **뒤집기는 보는 사람의 화면 설정이다.** 서버에 저장하지 않고 기기에만 기억한다(코스 ID 단위). 그룹 코스를 누가 뒤집어도 다른 멤버의 화면은 바뀌지 않는다 — 방향은 각자 고른다(2026-09-23 사용자 결정). 배낭 코스도 같은 규칙을 따른다 — 규칙을 하나로 두면 두 곳이 갈리지 않고, 코스 문서 수정을 막아 둔 보안 규칙을 열 필요도 없다.
  - Storage의 원본 GPX와 코스 문서는 뒤집기로 바뀌지 않는다.
  - 뒤집은 상태에서 보이는 상승 값은 원래의 하강이다. 새로 올리는 코스는 파싱할 때 하강(`elevationLoss`)을 함께 저장하고, 하강이 없는 기존 코스는 저장된 축약 좌표의 고도로 계산한다(원본 전체 점으로 잰 값보다 조금 작을 수 있다).
- 코스를 고르면(그룹 지도의 코스 칩, 그룹 상세 코스 행에서 지도로 넘어올 때, 배낭 코스 목록의 행) **지도 카메라를 그 코스 전체가 들어오게 옮긴다.** 이미 선택된 코스를 다시 골라도 옮긴다.
- **시작·끝 마커**: 지도의 코스 폴리라인 양끝에 시작점과 끝점을 서로 다른 모양으로 표시한다. 방향이 지도에서 보이지 않으면 뒤집기가 그래프에만 반영되고 지도에서는 아무 변화가 없기 때문이다. 뒤집으면 두 마커의 자리가 바뀐다.
  - 축약 좌표는 500점을 넘지 않게 간소화한다. 원본 트랙포인트 전체는 Firestore에 넣지 않는다 — 1MB 문서 한도와 렌더 성능 때문이다.
  - 원본 파일은 Storage `groups/{groupId}/routes/{routeId}.gpx`에 보관하고, 그룹원만 읽을 수 있게 한다.
- 파싱에 실패하거나 트랙이 없는 파일은 `코스를 읽지 못했어요`로 거절하고 아무것도 저장하지 않는다.
- 코스 목록은 이름·거리·고도 상승·올린 사람을 표시한다. 탭하면 그룹 지도에서 해당 코스를 강조한다.
- 코스를 지우면 Firestore 문서와 Storage 파일을 함께 지운다.
- **이 요구사항은 건강 기록 경로와 다른 것이다.** [HealthActivity.md](HealthActivity.md) HA-5는 기기 건강 허브에서 읽은 **개인 이동 기록**의 서버 저장을 금지한다. 그룹 코스는 사용자가 일행에게 보여주려고 의도적으로 올리는 계획 경로이므로 저장한다. 건강 기록에서 읽은 경로를 그룹 코스로 옮기는 기능은 두지 않는다.
- **릴리스 제약**: 파일 선택에 `expo-document-picker`가 새로 필요하다. 네이티브 의존성이 늘어나므로 이 요구사항이 포함된 릴리스는 **OTA로 내보낼 수 없고 새 스토어 빌드가 필요하다**([AppLifecycle.md](AppLifecycle.md) OTA 규칙). 나머지 GRP 요구사항은 모두 OTA로 나갈 수 있다.

### GRP-9 지도 포인트 `[제안]`

멤버는 지도 위에 물보급지 같은 정보를 찍어 일행과 나눈다.

**수용 기준**

- 포인트 유형은 `물보급` · `쉼터` · `주의` · `메모` 네 가지다. 유형별 마커 색·아이콘은 박지 유형 마커와 같은 문법을 따른다([CampSite.md](CampSite.md) CS-2).
- 그룹 지도에서 **길게 눌러** 좌표를 찍고, 시트에서 유형·제목(필수, 1~40자)·설명(선택, 최대 200자)을 입력해 저장한다.
- 화면 가운데 좌표로 추가하는 경로도 함께 둔다(길게 누르기는 발견성이 약하고 기기에 따라 인식이 어긋난다). 이 경로를 쓸 때는 **화면 정중앙에 조준 마커를 띄워 어느 지점에 찍히는지 눈으로 알 수 있게 한다.** 마커는 지도를 움직이는 동안 화면에 고정돼 있고, 지도가 그 아래에서 움직인다.
- 조준 마커는 **포인트 추가 모드일 때만** 보인다 — 늘 떠 있으면 실제 등록된 포인트 마커와 헷갈린다. 모드에 들어가면 `이 위치에 추가` 같은 확정 액션과 취소 수단을 함께 보여준다.
- 조준 마커는 등록된 포인트 마커와 **생김새가 달라야 한다**(조준선·반투명 등). 같은 모양이면 아직 찍히지 않은 것과 이미 찍힌 것이 구분되지 않는다.
- 포인트는 그룹당 50개까지다.
- 목록과 지도 양쪽에서 볼 수 있고, 목록 행을 탭하면 지도가 그 포인트로 이동한다.
- 올린 사람과 방장만 수정·삭제할 수 있다. 작성자 닉네임과 등록 시각을 표시한다.
- 포인트 좌표는 **그룹 안에서만 보이고** 공개 박지 카탈로그(`camp-spot`)에는 기여하지 않는다. 카탈로그는 운영자 큐레이션 전용이다([DataModel.md](DataModel.md) DM-17).

### GRP-10 그룹 지도 `[제안]`

일행은 코스·포인트·박지를 한 화면에서 본다.

**수용 기준**

- 그룹 지도는 코스 폴리라인, 포인트 마커, 연결된 박지 마커를 함께 그린다. 기존 박지 지도의 네이버 지도 구성을 재사용한다([CampSite.md](CampSite.md) CS-1).
- 처음 열면 코스와 포인트가 모두 들어오도록 카메라를 맞춘다. 아무것도 없으면 박지 위치로, 박지도 없으면 현재 위치로 간다.
- 유형 칩으로 포인트를 걸러 볼 수 있다.
- 코스가 여럿이면 선택한 코스를 굵게, 나머지를 옅게 그린다.
- 웹은 지도 탭 자체를 렌더하지 않으므로([AppLifecycle.md](AppLifecycle.md) APP-5) 그룹 지도도 웹에서 제공하지 않는다. 웹에서는 코스·포인트를 목록으로만 보여준다.

### GRP-11 화면 문법과 접근성 `[제안]`

- 색·여백·모서리·타이포는 디자인 토큰만 참조한다([Home.md](Home.md) HM-8). 라임은 화면당 주 액션 하나에만 쓴다.
- 터치 타깃 44×44pt, 아이콘 전용 컨트롤에 `accessibilityLabel`과 `accessibilityRole`을 둔다.
- iOS는 다른 푸시 화면과 같은 네이티브 투명 헤더를 쓴다([LiquidGlassNavigation.md](LiquidGlassNavigation.md) §2 표준 패턴 LG-1). Android는 커스텀 헤더를 쓴다.
- 멤버 배낭 상세·포인트 입력 시트는 커뮤니티·박지에서 쓰는 시트 문법을 그대로 따른다.
- Dynamic Type에서 멤버 행·칩·버튼 텍스트가 잘리지 않아야 한다.

### GRP-12 나가기·해산·회원 탈퇴 `[제안]`

- 멤버가 나가면 멤버 문서와 그 사람의 배낭 스냅샷을 지우고 `memberIds`에서 뺀다.
- 방장이 해산하면 그룹과 하위 데이터(멤버·배낭 스냅샷·포인트·코스 문서, Storage의 GPX 파일)를 모두 지운다. 삭제 연쇄는 재시도 가능한 서버 작업으로 처리한다([DataModel.md](DataModel.md) DM-29).
- 회원 탈퇴 시([Auth.md](Auth.md) AU-8) 그가 속한 모든 그룹에서 멤버·배낭 스냅샷을 지운다. 그가 방장인 그룹은 해산한다. 그가 올린 포인트·코스는 남기고 작성자 표시를 `(탈퇴한 사용자)`로 바꾼다.
- 이 치환의 계약은 **서버가 `authorName`을 빈 문자열로 만들고 화면이 빈 값을 탈퇴 신호로 읽는 것**이다. 서버가 `(탈퇴한 사용자)` 문구를 직접 써넣지 않는다 — 문구를 데이터에 박으면 다국어가 깨지고, 나중에 문구를 바꿀 때 기존 문서를 전부 고쳐야 한다.
- 삭제·나가기 실패 시 화면 상태를 유지하고 토스트로 알린다.

## 4. 데이터

- 읽기/쓰기 경로는 [DataModel.md](DataModel.md) `DM-29 그룹`을 참조한다.
- 그룹은 앱에서 **세 번째 가시성 등급**을 처음 도입한다. 지금까지는 `공개`(커뮤니티·박지 카탈로그)와 `본인만`(`users/*`), 그리고 `링크를 아는 사람 전부`(`bag.shared`) 뿐이었고, **특정 사용자 집합에게만 보이는 데이터는 없었다.**
- 멤버십 판정은 `groups/{groupId}.memberIds` 배열 하나로 한다. 보안 규칙에서 `get()` 한 번으로 끝나고 배열 크기가 20으로 제한되어 규칙 비용이 예측 가능하다.
- **선행 보안 작업**: 현재 배포된 규칙은 커뮤니티 4개 컬렉션을 뺀 나머지가 전면 개방(`allow read, write: if !isCommunityCollection()`)이다. 그룹 컬렉션은 신규라 처음부터 제대로 잠글 수 있지만, `bag`·`users`가 열려 있는 한 "그룹원만 본다"는 약속은 앱 화면 안에서만 성립한다. 그룹 출시와 별개로 기존 컬렉션을 좁히는 작업이 필요하다.

## 6. 엣지 케이스

- 비로그인으로 초대 링크 진입 → 로그인 모달, 완료 후 같은 초대 화면 복귀.
- 해산된 그룹의 링크 진입 → `사라진 그룹이에요`와 `돌아가기`.
- 정원이 찬 그룹 → 참여 버튼 비활성 + `정원이 찼어요`.
- 배낭을 연결한 뒤 그 배낭을 삭제 → 다음 동기화에서 스냅샷을 지우고 `연결된 배낭이 없어요`로 되돌린다.
- 장비가 0개인 배낭 연결 → 허용하되 `아직 담은 장비가 없어요`를 표시한다.
- GPX 파싱 실패·용량 초과·트랙 없음 → 저장하지 않고 사유를 구분해 안내.
- 지도 권한 거부 → 포인트 추가는 롱프레스로 가능하므로 막지 않는다. 현재 위치 버튼만 비활성.
- 오프라인 → 목록·상세는 캐시를 보여주고 쓰기 액션은 실패 토스트.

## 7. 수동 검증 체크리스트

- [ ] 배낭 탭 세그먼트 `배낭 | 템플릿 | 그룹` 전환, 세 칩이 Dynamic Type에서 잘리지 않음
- [ ] 그룹 생성 → 초대 링크 복사 → 다른 계정에서 링크 열기 → 참여 확인 후 멤버 추가
- [ ] 이미 멤버인 계정이 링크를 열면 상세로 바로 이동
- [ ] 정원(20명)·초대 잠금·해산된 그룹 링크의 각 안내
- [ ] 배낭 연결 → 멤버 배낭 상세에서 장비 목록·카탈로그 장비 이동
- [ ] 연결한 배낭의 장비를 바꾸고 그룹에 다시 들어가면 갱신 반영
- [ ] 멤버 배낭 상세에 메모·좌표·건강 기록·개인 장비 사진이 **보이지 않음**
- [ ] GPX 업로드 → 거리·고도·지도 폴리라인, 5MB 초과·손상 파일 거절
- [ ] 지도 롱프레스 → 유형 4종 포인트 등록·수정·삭제, 권한별 노출
- [ ] 멤버 나가기 / 방장 해산 / 회원 탈퇴 후 데이터 정리
- [ ] iOS·Android 헤더와 시트 문법, 웹에서 지도 미제공 대체 화면

## 8. 미해결 질문

- 초대 링크에 만료·재발급을 둘 것인가. MVP는 `groupId`를 비밀로 쓰는데, 링크가 원치 않게 퍼졌을 때 되돌릴 방법이 초대 잠금뿐이다.
- 그룹 활동(초대 수락, 코스 추가)을 알릴 방법. 현재 푸시는 토픽 `all` 수동 발송뿐이고 사용자 타깃 발송 인프라가 없다([Notification.md](Notification.md) NT-5). 토큰 저장과 서버 트리거가 모두 신규라 MVP에서 제외했다.
- 배낭 스냅샷 동기화를 클라이언트가 맡는다. 연결한 사람이 앱을 오래 안 열면 낡은 스냅샷이 남는데, 서버에서 배낭 변경을 감지해 갱신할지 아니면 조회 시각을 표시해 감수할지.
- 그룹이 끝난 뒤(종료일 경과) 자동 보관·삭제 정책.
- 같은 여행에 배낭과 그룹이 각각 있으면 기간·여행지가 두 곳에 중복 입력된다. 배낭을 연결할 때 그룹 정보를 자동 채울지.
