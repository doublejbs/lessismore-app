## 1. 개요

배낭 1개의 상세 화면과 부속 화면들. 총 무게·카테고리 무게 분해·카테고리별 장비 목록·메모·사용 여부 기록(앱 정체성인 "쓸모없음" 측정)·
링크 공유를 제공한다. 상단 액션은 여행 상태(출발 전/중/후)에 따라 관련 기능을 강조한다(BD-10). (레디샷 기능은 2026-07-21 제거 — 진입 타일이 2026-07-12에 빠진 뒤 어느 화면에서도 도달할 수 없는 상태였다)

## 2. 화면 및 진입

| 라우트 | 화면 | 역할 |
| --- | --- | --- |
| `/bag/[id]` | BagDetailView | 상세 (무게, 차트, 필터, 장비 목록, 공유, 메모) |
| `/bag/[id]/edit` | BagEditView | 창고 장비 담기/빼기 |

## 3. 요구사항

### BD-1 상세 기본 표시

화면 구성(위→아래): **정체성 헤더**(이름·기간·총무게·무게 분해) → **액션 그리드**(BD-10) → 구분선 → **장비 목록**(sticky 필터 BD-2) → **하단 액션 바**(BD-9).

**수용 기준**

- 내비 바는 뒤로(좌) + 우측 아이콘만 둔다. **총 무게는 내비 타이틀이 아니다.**
- `[제안]` **헤더 우측을 2버튼으로 개편한다**(2026-08-13 사용자 확정): **필름 카드([BagShare.md](BagShare.md) BS-1) + `⋯` 메뉴**. 기존 3버튼(복사·공유·필름 카드) 중 복사·공유는 `⋯` 메뉴 안으로 이동한다.
  - `⋯` 메뉴 버튼: `ellipsis-horizontal` 아이콘, 44pt 히트 영역, `accessibilityRole='button'` + `accessibilityLabel='배낭 메뉴'`(배낭 목록 카드의 `⋯` 버튼과 같은 라벨 — [Bag.md](Bag.md) BAG-1).
  - 메뉴는 공용 `BottomMenuModalView`로 항목 순서 **`복사` → `공유` → `템플릿으로 저장` → `삭제`**(파괴적 액션은 맨 아래 — 2026-08-16 사용자 확정으로 `삭제` 추가).
    - `복사` → 기존 복사 아이콘 동작 그대로(BD-8 — 복사 모달).
    - `공유` → 기존 공유 아이콘 동작 그대로(BD-7 — `/bag-share` 링크 공유 시트).
    - `템플릿으로 저장` → [BagTemplate.md](BagTemplate.md) **BT-1과 동일 동작**(이름 입력 시트 → 템플릿 저장, 프리필·실패 알럿·토스트·비로그인 규칙 포함). 문구는 배낭 목록 카드 `⋯` 메뉴와 같은 `템플릿으로 저장`을 쓴다 — 배낭 추가 시트의 `템플릿으로 만들기`(템플릿→배낭)와 **방향이 반대**라 라벨을 구분한다(저장은 배낭→템플릿).
    - `삭제` → 메뉴 닫힘 → **확인 다이얼로그**([Bag.md](Bag.md) BAG-3와 동일 문구 `{이름} 배낭을 삭제할까요?`, 확인 버튼 `삭제`) → 확인 시 **BAG-3와 동일한 배치 삭제**(장비의 `bags`/`used`/`useless`에서 배낭 ID 제거 → `bag/{id}` 삭제 → `users/{uid}.bags`에서 제거) → **상세 화면을 닫고 배낭 목록으로 복귀**하며 목록이 갱신되어 삭제된 배낭이 보이지 않는다. 파괴적 액션의 시각 구분은 메뉴 항목이 아니라 **다이얼로그가 맡는다**(BAG-3 규칙 참조 — 공용 시트에 red 항목 변형을 추가하지 않는다).
  - 항목 선택 시 **메뉴 시트를 먼저 닫고** 다음 시트/모달을 띄운다 — 시트 위에 시트를 겹쳐 쌓지 않으며, 후속 액션은 **닫힘 애니메이션 완료 후** 실행한다([Bag.md](Bag.md) BAG-3과 같은 규칙 — 타이밍 근거도 BAG-3 참조).
  - 필름 카드는 웹에서 렌더하지 않으므로([BagShare.md](BagShare.md) BS-1) 웹의 우측 아이콘은 `⋯` 하나다. [이력] 개편 전에는 복사·공유·필름 카드 3아이콘(웹 2개)이었다 — BS-1의 "복사·공유와 같은 행" 서술은 개편 전 기준.
- **배낭 이름을 라지 타이틀**(좌측 정렬)로, 그 아래 여행 기간 + **상황 라벨**을 표시한다. 상황 라벨: 출발 전 `D-{n}`(당일 `오늘 출발`), 여행 중 `여행 중`, 종료 후 `지난 여행`(`BagDetail.getTripPhase`/`getPhaseLabel`).
  - **이름·기간이 길어도 수정(연필) 아이콘이 잘리지 않는다.** 두 행은 각각 텍스트 + 연필 한 행이고, 텍스트가 폭을 양보해 연필이 항상 화면 안에 남는다. 텍스트는 **최대 2줄**까지 줄바꿈하고 넘치면 말줄임한다 — 그 이상 길어지면 헤더가 화면을 잡아먹으므로, 전체 이름은 수정 시트에서 확인·편집한다. 기간 행도 Dynamic Type 확대 시 2줄까지 늘어나 상황 라벨이 잘리지 않는다.
- 이름·기간 행은 각각 탭하면 **`배낭 정보 수정` 네이티브 formSheet**(`/bag-info-edit`, 공용 `BagFormContent` = 이름 입력 + 날짜 범위 달력 + 취소/저장 가로 버튼)를 연다 — 배낭 생성(`bag-new`)/복사(`bag-copy`) 시트와 동일한 UI 언어. 현재 이름·날짜가 프리필되며, 이름 공백은 저장 거부, 날짜는 달력이 역순을 방지한다. 배낭 상세의 model 인스턴스는 뷰 스코프라 정렬 시트와 같은 **모듈 핸드오프**(`BagInfoEditHandoff`)로 현재값·저장 콜백을 전달한다.
- 기간 라벨 아래 **총 무게(kg)를 히어로 스탯**으로 표시한다(=`bag.weight`/1000). 그 아래 **무게 분해**(BD-3)를 항상 표시한다.
  - 라벨(`총 무게`)이 값 위에 오고 값은 콘덴스드 34pt다(2026-08-11 — 홈 지표·레퍼런스와 같은 문법). **손그림 라임 동그라미로 두르지 않는다**: 라임은 화면당 하나(하단 주 액션)이고, 큰 숫자는 장식 없이도 이미 앵커다.
- 장비 목록은 카테고리별로 그룹핑, 비어 있지 않은 카테고리만 렌더. 섹션 헤더는 카테고리명만 표시(소계 없음).
- **시각 문법은 [Home.md](Home.md) HM-8을 따른다**(2026-08-11 개정 as-built):
  - 지면 **순백**(지형 그래픽은 홈에만), 장비 섹션 머리는 공용 `AcgSectionHeaderView`로 `장비 N개`(19pt semibold, 형광펜 띠 없음).
  - 장비 행은 **브랜드(메타 단, 뮤트, 이름 위 보조 줄) + 이름(두 줄까지) + 메타 한 줄 잉크(`무게 · 색상 · 사용률`) + 우측 셰브론**, 치수는 토큰 `AcgRow`, 행 사이 헤어라인. 종이 면·그림자를 두지 않는다 — 지면이 순백이 되면서 흰 면은 보이지 않고 그림자만 남았다.
    - **브랜드는 이름 위다**(2026-08-13 사용자 결정) — 탐색 셀(FD-2: 브랜드 → 제품명 → 무게)과 같은 순서. HM-8 목록 문법(브랜드를 메타 조각으로)의 화면별 예외로, 메타 줄에서는 브랜드를 뺀다.
  - **사용률은 배지가 아니라 메타 줄의 조각**이다. 면 없이 헤어라인으로만 가르는 목록에서 배지는 유일한 예외 면이 된다.
  - 카테고리 라벨은 **15pt `textMuted`** — 섹션 제목(19)보다 한 단 작다. 같은 크기면 목록 안에 섹션이 여럿 있는 것처럼 읽힌다.
  - 액션 그리드 타일(BD-10)은 **연회색 채움 + 모서리 12**(강조 타일만 잉크 면). 필터 칩은 탐색 탭과 같은 `FeedChipView`를 쓴다(BD-2 자동 스크롤이 칩 좌표를 재야 해 이 컴포넌트가 ref를 받는다).
  - **빈 상태 영역을 두지 않는다**(2026-08-13 사용자 결정 — 장비 추가 CTA가 이미 화면에 있어 빈 목록이 스스로 설명된다). 담긴 장비가 0개면 `장비 0개` 머리 아래가 그대로 비고, 안내 면·문구·CTA를 그리지 않는다.
- 장비 행 썸네일 규칙은 창고 목록과 같다([Warehouse.md](Warehouse.md) WH-1) — 사용자가 올린 본인 사진이 있을 때만 표시하고, 없으면 빈 칸 없이 텍스트 우선 행을 쓴다. 업로드는 [GearDetail.md](GearDetail.md) GD-13. **단 공유 배낭(BD-7)에서는 표시하지 않는다**([DataModel.md](DataModel.md) §1 비공개 원칙).
- **장비가 30개를 넘는 배낭도 정상 조회된다.** `bag.gears` → `users/{userId}/gears` 조회는 `where('__name__','in', gears)`라 Firestore `in` 30개 상한에 걸리므로, 30개 단위로 청크 분할해 병렬 조회하고 병합한다([DataModel.md](DataModel.md) DM-25).
  - 이 조회 경로(`BagStore.getBag`/`getSharedBag`)는 **상세·패킹·메모·편집(BD-4)·사용 기록(BD-5)·공유 배낭(BD-7)이 모두 공유**하므로, 한 곳만 고치면 나머지가 남는다.
  - **이 경로에는 사용자가 고르는 정렬이 없다** — 상세는 카테고리 그룹핑(위 항목), 편집(BD-4)은 담김 여부·무게 계산용이라 순서가 화면에 안 드러나고, 사용 기록(BD-5)·공유 배낭(BD-7)에는 정렬 UI가 없다. 창고의 정렬 규칙([Warehouse.md](Warehouse.md) WH-3 — `가벼운순` 0g 뒤로 등)도 여기엔 적용되지 않는다.
  - 다만 **표시 순서는 이름 오름차순으로 고정한다.** 청크 분할 후에는 서버 `orderBy`가 청크별로만 걸려 무의미하므로, 병합 뒤 클라이언트에서 `name` 오름차순으로 정렬한다 — 기준은 Firestore와 같은 **코드포인트 순**(`localeCompare` 아님)이라 30개 이하 배낭과 순서 규칙이 갈리지 않는다. 이 순서는 상세의 카테고리 그룹 **내부** 행 순서, 패킹([Packing.md](Packing.md)), 사용 기록(BD-5), 공유 배낭(BD-7)에 그대로 보인다.
  - `name`이 비어 있는 문서는 **뒤로** 보낸다. 기존 서버 `orderBy('name')`은 이런 문서를 결과에서 아예 제외했으므로, 청크 분할 이후 목록에 새로 나타날 수 있다(사라지는 것보다 낫다는 판단 — `name`은 캐논컬 값이라 실제로는 거의 없다, [DataModel.md](DataModel.md) DM-3).
- 장비 행 클릭 → `/gear-detail/{gearId}`. 행을 **왼쪽으로 스와이프**하면 트레일링 액션 `수정`·`삭제`가 노출된다(창고 WH-5와 동일한 `ReanimatedSwipeable` 패턴 — 배낭 목록 BAG-1은 2026-08-13에 스와이프를 걷고 `⋯` 메뉴로 갔으니 그 화면을 근거로 삼지 말 것). `⋮` 더보기 메뉴는 제거한다. `[제안]`
  - `수정` 탭 → `bagDetail.goToEditGear(gear)`(장비 편집 진입). `삭제` 탭(red) → `bagDetail.delete(gear)`(이 배낭에서 장비 제거, 확인 다이얼로그 없음 — 기존 동작 유지). 각 액션은 44pt 이상 히트 영역과 `accessibilityLabel`(`{이름} 수정`/`{이름} 삭제`)을 가진다. `[제안]`

### BD-2 카테고리 필터와 스크롤 동기화

**수용 기준**

- sticky 필터 바에는 **배낭에 담긴 카테고리만** 노출된다.
- 필터 클릭 시 해당 카테고리 섹션으로 스크롤한다.
- 스크롤 시 현재 보이는 첫 카테고리가 필터에 자동 선택된다.

### BD-3 무게 분해 (카테고리 비중)

**수용 기준**

- 총 무게 스탯 바로 아래에 **항상 표시되는** 스택 바 + 인라인 범례(`● 카테고리 {%}`)로 무게 분해를 보여준다. (접기/펼치기·별도 차트 화면 없음 — 요약 영역에 통합.)
- `배낭/텐트/침낭/매트`는 `베이스`로 묶어 집계한다.
- 항목은 무게 비중 내림차순 정렬, 8색 팔레트를 순환 사용한다(데이터 시각화 색 — DesignTokens 예외).

### BD-4 장비 편집 (담기/빼기)

**수용 기준**

- 편집 화면은 창고 전체 장비를 필터/정렬/검색과 함께 보여준다. **검색 인풋**(이름/브랜드 클라이언트 필터, 결과 없으면 `검색 결과가 없어요`)을 `내 장비` 타이틀 아래·필터 칩 위에 둔다([Warehouse.md](Warehouse.md) WH-8과 동일). 정렬은 하단 바텀시트(WH-3) — 옵션 구성·저장 방식·**`가벼운순`에서 무게 미입력(0g)을 뒤로 보내는 규칙**이 창고와 같다. 단 **정렬 선택값은 창고와 공유되지 않는다**(`selectedOrderType_` 저장 키가 창고는 `warehouse`, 배낭 편집은 `bag`).
- 담기/빼기 선택은 **원형 체크 배지**로 표시한다(담김=검정 원+체크가 팝 애니메이션, 안 담김=빈 원). 패킹(PK)·사용여부(BD-5)와 같은 체크 인터랙션 계열. 단 편집은 창고 전체를 훑는 맥락이라 행 dim은 쓰지 않는다.
- 장비 토글 시 헤더의 총 무게가 실시간 갱신된다(선택 장비 `weight` 합 / 1000).
- **토글할 때마다 즉시** 트랜잭션 `BagStore.save`가 실행된다(이탈 시 일괄 저장 아님): `bag.gears`/`bag.weight` 갱신 + 추가 장비의 `bags`에 ID 추가 + 제거 장비의 `bags`/`used`/`useless`에서 ID 제거.
- `bag.weight`는 담긴 전체 장비의 `parseInt(weight)` 합으로 다시 계산해 저장한다.
- "장비 추가" 버튼(헤더 우측 아이콘) → **장비 추가 선택 시트(`gear-add-options`, 배낭 컨텍스트 `bagId` 전달)** 를 연다([GearEdit.md](GearEdit.md) GE-8). 두 갈래: `검색으로 추가`(카탈로그 검색 → **이 배낭에 바로 담기**, GE-8) / `직접 입력`(`/custom/bag-gear/{bagId}` 수동 폼, 저장 시 이 배낭에 추가).
- 하단에 고정 `완료` 버튼을 표시한다. 누르면 배낭 상세로 돌아간다. (변경사항은 토글마다 이미 저장돼 있으므로 추가 저장은 없다 — 버튼은 편집 종료 신호.)

### BD-5 사용 여부 기록 (useless)

여행 후 실제로 사용한 장비만 체크해 "줄일 수 있는 무게"를 확인하는 핵심 기능.

**수용 기준**

- 진입 문구: 기록 전 `사용 여부 기록하고 줄어든 무게 확인하기`, 기록 후 `사용한 제품만 측정해보니 {usedWeight}kg 까지 줄어들어요`.
- `usedWeight` = 이 배낭에서 `used`에 기록된 장비 무게 합(kg, 소수점 둘째 자리 반올림).
- 기록 화면 초기 상태: `useless` 포함 → 미선택, `used` 포함 → 선택. **배낭 전체에 기록이 하나도 없으면** 전체 선택으로 시작한다. 단, 기록이 일부라도 있는 배낭에서는 미기록 장비가 **미선택**으로 표시된다(미해결 질문 참조).
- 기록 화면은 **패킹 모드와 동일한 진행 헤더**를 둔다: 선택/전체 카운트(`{선택} / {전체} 사용`) + 프로그레스 바(선택/전체 비율) + **사용/총 무게**(`{선택kg}kg / {전체kg}kg`). 전체 선택/해제 토글을 헤더에 함께 제공한다.
- 장비 행은 **패킹 모드 행과 동일한 인터랙션**: 원형 체크 배지 + 상태 애니메이션. 단 여기서는 **미선택(안 쓴) 장비가 dim**된다(선택=선명+체크).
- 완료 시 각 장비의 `used`/`useless` 배열에 배낭 ID를 반영해 일괄 저장한다(`GearStore.updateGears`).
- 이 화면에는 **정렬 UI가 없다.** 장비는 이름 오름차순으로 표시하며(BD-1), 정렬 선택 개념 자체가 없으므로 창고의 정렬 규칙([Warehouse.md](Warehouse.md) WH-3 — `가벼운순` 0g 뒤로 등)은 여기에 적용되지 않는다.
- 상세의 장비 목록에서 useless 장비는 **44pt useless 로고 마크(50% 투명)** + **행 본문 50% 투명**으로 표시한다. 장비 이미지 미제공([DataModel.md](DataModel.md) §1)으로 썸네일이 폐지돼 오버레이를 얹을 숙주가 없어졌기 때문에 로고를 독립 배치하되, 행이 이름 + 메타 한 줄 문법(위 BD-1)이 된 뒤에는 **우측 셰브론의 왼쪽**에 둔다(2026-08-11) — 행의 오른쪽 끝은 이동 표시의 자리다. 마크 크기는 32pt로 줄여 행 높이를 늘리지 않는다. 행 `accessibilityLabel`에는 `사용 안 함`을 포함해 시각 표기에만 의존하지 않는다.

### BD-6 메모

**수용 기준**

- 멀티라인 입력, 완료 버튼은 trim 후 내용이 있을 때만 활성화.
- 삭제 버튼은 기존 메모가 있을 때만 노출되고, 확인 모달 후 빈 문자열로 저장한다.
- **삭제 실패 안내는 화면에 남아야 한다** `[제안]` — 지금은 실패 알럿이 뜨는 즉시 사라진다. 확인 콜백 안에서 새 알럿을 열면 같은 tick의 `hide()`가 그것을 끄기 때문이며, 처방(실패는 토스트로 알린다)은 [AppLifecycle.md](AppLifecycle.md) **APP-9**가 정본이다.
- 상세 화면에는 메모가 있으면 내용, 없으면 `메모 작성하기` 링크를 표시한다.
- **내비 타이틀은 `메모`다** — 비워 두지 않는다. HIG에서 내비 타이틀은 화면의 대상을 가리키며, 형제 화면인 운동 기록도 `운동 기록`을 준다([HealthActivity.md](HealthActivity.md)).

**시각 문법** (2026-08-17 정정 — [Home.md](Home.md) HM-8 준수)

작성 화면의 동작만 명세돼 있어 구세대(ACG) 잔재를 판정할 수 없었다. 아래를 수용 기준으로 고정한다.

- **입력 면은 `Acg.controlFill` + `AcgRadius.thumb`(12) + 그림자 없음.** 각진 사각 인풋은 ACG 세대 잔재다(정본: `components/reply/ReplyEditView.tsx`의 여러 줄 입력).
- **본문 타입은 문단 단 `AcgType.body`(14/21)** 다 — 한 줄 메타 단(`rowSubtitle` 14/20)이 아니라 여러 줄 입력이라 줄간에 여유가 필요하다.
- **`TextInput`에 `fontFamily`(`Pretendard-Regular`)를 직접 지정한다.** `TextInput`은 `PretendardText`를 쓸 수 없어 서체를 지정하지 않으면 **시스템 폰트로 렌더된다** — 2026-08-17 진단에서 실제 누락이 확인됐다(구현 몫). 앱 전 화면이 Pretendard인데 메모 본문만 서체가 갈려선 안 된다.
- 화면 좌우 패딩은 `AcgLayout.screenPadding`(24) 하나로 통일한다(헤더·본문·버튼 영역 공통). 인풋 **내부** 패딩은 14다.
- **완료(저장) 버튼은 라임 알약이다**: `Acg.lime` 채움 + 높이의 절반 모서리 + 라벨 `AcgType.control` + **글자·로딩 인디케이터 `Acg.ink`**(흰색은 라임 위에서 보이지 않는다). 고정 `height` 대신 `minHeight` 52 + 세로 패딩을 쓴다(Dynamic Type). 비활성은 `Acg.controlFill` 면 + `Acg.textMuted` 글자 — `Acg.hairline` 면을 쓰지 않는다.
- 이 화면의 주 액션은 완료 버튼 **하나**다. 라임을 다른 요소에 쓰지 않으며, 글자색으로도 쓰지 않는다(`Acg.limeText` 폐기 — [HealthActivity.md](HealthActivity.md) HA-6, 2026-08-17 사용자 확정).
- 삭제 아이콘의 red(`#FF3B30`)는 시맨틱 상태색이라 토큰 예외다.

**접근성**

- 아이콘 전용 컨트롤은 **44×44pt 이상 히트 영역 + `accessibilityRole='button'` + 라벨**을 갖는다: 뒤로가기 `뒤로가기`, 삭제 `메모 삭제`. **iOS·Android 헤더 분기 양쪽 모두**에 적용한다 — 한쪽 분기만 갖춘 상태였다(2026-08-17 진단).
- 완료 버튼은 `accessibilityRole='button'` + `accessibilityLabel='메모 저장'` + `accessibilityState={{ disabled }}`를 갖는다. 비활성이 색으로만 표현되면 스크린리더 사용자에게 신호가 사라진다.

### BD-7 링크 공유

**수용 기준**

- 진입: 헤더 공유 아이콘(`[제안]` 헤더 개편 후에는 `⋯` 메뉴의 `공유` 항목 — BD-1) → **네이티브 formSheet**(`/bag-share`, 배낭 생성/복사/정보수정 시트와 동일한 UI 언어) → 공유 시 `bag.shared = true`로 갱신하고 `{웹 베이스}/bag-share/{bagId}` 링크를 클립보드에 복사한다(웹 베이스는 `constants/WebLinks.ts`의 `WEB_BASE_URL` 단일 소스 — 2026-07-28 `useless.my` → `https://lessismore-7e070.web.app`). 시트는 공유 상태를 관찰(observer)해 공유 중이면 링크 행 + `공유 취소`를 표시한다. BagDetail 인스턴스는 `BagShareHandoff` 모듈로 전달한다.
- 공유 해제 시 `shared = false`.
- 공유 조회(`BagStore.getSharedBag`)는 `shared === true`를 확인하고, 아니면 `공유되지 않은 배낭입니다.` 알럿을 띄운다. 장비는 `bag.userId` 경로의 `users/{userId}/gears`에서 읽는다.
- **공유 화면에는 장비 사진이 오지 않는다**([DataModel.md](DataModel.md) §1 비공개 원칙, 2026-07-29). 이 조회는 소유자의 `users/{userId}/gears`를 읽지만 **보는 사람이 업로더가 아니므로**, 뷰에서 거르는 대신 **데이터 레이어에서 `imageUrl`을 애초에 채우지 않는다**(`getSharedBag`은 사용자 문서용 정규화를 쓰지 않는다). 뷰 차단은 화면이 늘 때마다 빠뜨릴 수 있어 경로 자체를 막는 편이 안전하다. 같은 이유로 박지 후기에 첨부된 배낭([CampSite.md](CampSite.md) CS-8)에서도 표시되지 않는다.

### BD-8 배낭 복사

사용자는 보고 있는 배낭을 상세 화면에서 바로 복제할 수 있다.

**수용 기준**

- 진입: 헤더 우측 복사 아이콘(공유 아이콘 왼쪽, 44pt 이상 히트 영역). `[제안]` 헤더 개편 후에는 `⋯` 메뉴의 `복사` 항목이다(BD-1) — 아이콘은 사라지고 동작은 그대로 옮겨간다.
- 진입 → 복사 모달을 띄운다. 모달·프리필(`{이름} 복사본`)·날짜 기본값·확정·토스트 동작은 [Bag.md](Bag.md) BAG-4와 동일하다.
- 확정 시 복사본 상세를 push로 열고 **곧바로 장비 편집 화면을 연다** (뒤로가기 → 복사본 상세 → 원본 상세).

### BD-9 하단 액션 바 (패킹 + 수정)

**수용 기준**

- 상세 하단에 고정 **액션 바**를 둔다: **`장비 추가`(주 버튼, 잉크 풀폭 flex)** + 패킹 노출 조건 충족 시 그 왼쪽에 **패킹(보조 버튼)**. (기존 우하단 플로팅 버튼은 폐기 — 장비 행을 가리던 문제 해소.)
- `장비 추가` → 장비 편집(BD-4)으로 이동. 라벨이 `수정하기`였을 때는 이 버튼이 무엇을 수정하는지(이름? 날짜? 장비?) 모호했다 — 실제로 여는 화면은 창고에서 장비를 고르는 편집 화면 하나뿐이라 동작을 그대로 라벨에 쓴다(2026-08-05).
- 패킹 버튼의 노출 조건·상태별 라벨(`패킹 시작`/`패킹 {n}/{m}`/`패킹 완료`)·이동 동작은 [Packing.md](Packing.md) **PK-1**을 따른다.

### BD-10 상세 액션 그리드 (상황형)

**수용 기준**

- 요약 아래에 **2열 그리드**로 액션 타일을 둔다: 사용 기록(BD-5)·메모(BD-6)·여행지([BagDestination.md](BagDestination.md) DST-2)·운동 기록([HealthActivity.md](HealthActivity.md) HA-1 `[기획]` — 권한 없음·웹·미래 여행이면 렌더하지 않아 3개로 줄 수 있다). 각 타일은 아이콘 + 제목 + 현재값 부제 구조이며, 면은 **`Acg.controlFill` + `AcgRadius.thumb`(12) + 그림자 없음**, 부제 글자는 `Acg.textMuted`다(강조 타일만 잉크 면 — 아래 상황형 강조). (레디샷 타일은 2026-07-12 제거, 기능 자체도 2026-07-21 제거)
  - `[이력]` 이 줄은 부제를 "회색 `surfaceMuted`"로 적고 있었다 — 구세대 토큰 이름 잔재였다. 실제 구현(`BagDetailMemoView`/`BagDetailActivityView`)이 이미 `Acg.controlFill` 면 + `Acg.textMuted` 글자라 **코드에 맞춰 스펙을 갱신했다**(2026-08-17). BD-1의 "액션 그리드 타일은 연회색 채움 + 모서리 12" 서술과 같은 값이다.
- **상황형 강조**: 여행 상태에 따라 관련 타일 하나를 **검정(강조) 전체 폭 가로 카드로 최상단에 배치**한다 — `지난 여행`이면 `사용 기록`, `출발 전`·`여행 중`이면 `여행지`. 강조 카드는 아이콘·라벨 좌측 + 값 우측의 가로 레이아웃(높이 축소). 나머지 2개는 그 아래 회색 2열(48%).
- 사용 기록 타일 부제: 기록됨 → `{usedWeight}kg로 줄어요`, 미기록·지난 여행 → `줄어든 무게 확인`, 미기록·출발 전/중 → `여행 후 기록`.
- 여행지 타일: 미설정이면 `여행지 선택`을 표시하고 탭 시 공용 지도 선택기를 바로 연다. 설정됨이면 위치명을 주 정보로 표시하고, 날씨가 있으면 상태(`비/눈/맑음`) + 기간 `{최저}~{최고}°`를 보조 정보로 표시한다. 등록된 박지는 위치명 앞에 `📍`를 표시한다.
- 여행지가 설정된 타일을 탭하면 `/bag/{id}/weather`로 이동하고, 사용자 노출 화면 제목은 `여행지`로 표시한다(DST-2).

### BD-11 비로그인 상태의 `복사`·`템플릿으로 저장` `[제안]`

비로그인 사용자가 `⋯` 메뉴에서 `복사`·`템플릿으로 저장`을 누르면 **로그인 시트가 실제로 뜬다.**

**(a) 현재 무엇이 어떻게 죽는가** (2026-08-17 클릭 전수 점검)

- `components/bag-detail/BagDetailView.tsx`의 `handleCopy`·`handleSaveTemplate`는 비로그인이면
  `app.getLogInAlertManager()?.show()`를 부른다. 그런데 로그인 시트를 그리는 `LogInView`는
  `components/Layout.tsx`에만 있고 **이 화면은 `Layout`을 쓰지 않는다** — `ToastView`·`AlertView`만
  직접 얹었고 `LogInView` import가 없다. `app/_layout.tsx`·`app/(tabs)/_layout.tsx`에도 없다.
- 결과: 매니저 상태(`visible = true`)만 켜지고 **시트가 없어 탭이 완전히 무반응**이다. 메뉴 시트는 닫히므로
  사용자에게는 "메뉴가 그냥 닫혔다"로 보인다. 이후 그 화면에서는 계속 무반응이다.
- 같은 파일의 주석("`Layout`을 쓰지 않아 알럿을 그리는 뷰가 없다 — 직접 얹는다")이 지적한 함정이
  **로그인 시트에는 적용되지 않았다.** 구조적 원인과 처방은 [AppLifecycle.md](AppLifecycle.md) **APP-10**이다.

**(b) 기대 동작**

- 전역 오버레이가 루트에서 1회 마운트되므로(APP-10) 이 화면도 아무것도 얹지 않고 로그인 시트를 얻는다.
- 순서는 지금 코드를 유지한다 — **메뉴 시트를 먼저 닫고** 로그인 시트를 띄운다(RN `Modal` 두 개가 겹치지 않게).
- **로그인 성공 후 원래 하려던 동작을 자동으로 이어가지 않는다.** 재개할 액션을 기억하는 상태가 없고,
  메뉴 시트도 이미 닫혀 문맥이 사라졌다. 로그인한 뒤 `⋯`를 다시 열면 정상 동작한다 —
  자동 재개는 로그인 직후 예상 못한 화면 전환(복사 시트·템플릿 저장 시트)을 만든다.

**(c) 수용 기준**

- [ ] 비로그인 상태에서 `⋯` → `복사` → 메뉴 시트가 닫힌 뒤 **로그인 시트가 뜬다**.
- [ ] 비로그인 상태에서 `⋯` → `템플릿으로 저장` → 동일하게 로그인 시트가 뜬다.
- [ ] 로그인 시트를 취소해도 배낭 상세가 그대로 남고, 같은 메뉴 항목을 다시 눌러도 또 뜬다(1회성이 아니다).
- [ ] 로그인에 성공하면 시트가 닫히고 배낭 상세로 돌아온다 — 복사·템플릿 시트가 저절로 열리지 않는다.
- [ ] 이 화면은 `LogInView`·`AlertView`·`ToastView`를 직접 렌더하지 않는다(APP-10 — 루트 마운트로 옮기고
      화면에서는 제거한다). 알럿·토스트가 두 겹으로 뜨지 않는지 함께 확인한다.
- [ ] 패킹 모드 화면에서도 같다 — 같은 이유로 직접 얹었던 오버레이를 제거하고 정상 동작한다.

## 6. 엣지 케이스

- **빈 배낭**: 총 무게 0kg, 무게 분해 바·범례 없음, 필터 없음. 장비 목록 자리도 **빈 채로 둔다** — 빈 상태 안내 면·CTA는 그리지 않는다(BD-1, 2026-08-13 사용자 결정).
- **긴 배낭 이름**: 라지 타이틀이 2줄까지 늘어나고 넘치면 말줄임, 수정(연필) 아이콘은 화면 안에 남는다(BD-1).
- **삭제된 장비 참조**: `bag.gears`에 ID가 남아 있어도 실제 조회된 문서만 매핑되어 자동 무시된다.
- **장비 30개 초과**: 청크 분할로 정상 조회된다(BD-1, [DataModel.md](DataModel.md) DM-25). 분할 전에는 `in` 상한 예외가 던져져 상세·패킹·메모·편집·사용 기록이 초기화에 실패하고(편집은 `loading` 플래그가 고정돼 재진입도 막혔다), 공유 배낭은 예외가 삼켜져 **`공유되지 않은 배낭`으로 오표시**됐다.
- **로딩**: 상세 `BagDetailSkeletonView`, 편집/useless는 초기화 전 미렌더.

## 7. 수동 검증 체크리스트

- [ ] 편집에서 장비 추가/제거 → 상세 총 무게·무게 분해·필터 즉시 반영
- [ ] 장비 30개 초과 배낭: 상세·패킹·메모·편집·사용 기록·공유 링크가 모두 열리고 장비가 전부(31개째 이후 포함) 보인다
- [ ] 장비 30개 초과 배낭과 30개 이하 배낭 모두 장비가 **이름 오름차순**으로 표시된다(청크 경계에서 순서가 끊기거나 같은 장비가 중복되지 않는다) — 상세의 카테고리 그룹 내부·패킹·사용 기록·공유 배낭 공통
- [ ] 이 변경 전후로 기존 배낭의 장비 행 순서가 **그대로**다(회귀 없음)
- [ ] 이름 라지 타이틀 + 기간 상황 라벨(출발 전 D-day / 여행 중 / 지난 여행)
- [ ] 이름을 화면 폭보다 길게 지정 → 타이틀 2줄 말줄임, 수정(연필) 아이콘이 화면 안에 온전히 보임 + 탭하면 수정 시트 열림
- [ ] 액션 그리드 상황형 강조: 지난 여행=사용 기록 검정 / 출발 전·중=여행지 검정
- [ ] 여행지 미설정 타일 → 지도 선택기 바로 열림 / 설정 타일 → `여행지` 화면 이동
- [ ] 여행지 타일 → 위치명 주 정보 + 날씨 상태·기온 보조 정보, 등록 박지는 `📍` 표시
- [ ] 하단 바: 장비 추가(주 — **라임 알약**) + 패킹(보조 — 연회색 알약), 플로팅 없음·장비 행 안 가림
- [ ] 장비 행에 종이 면·그림자·사용률 배지가 없고, 헤어라인으로만 갈린다. 카테고리 첫 행에는 선이 없다 (BD-1)
- [ ] 빈 배낭: 장비 목록 자리에 안내 면·문구·CTA가 **없고**(BD-1), 머리 `장비 0개` 아래 여백만 남으며 하단 바 `장비 추가`로 편집에 진입할 수 있다
- [ ] 사용 여부 기록 화면: 진행 헤더(카운트·바·사용/총 무게) + 행 원형 체크·미선택 dim
- [ ] 사용 여부 기록 → "줄어들어요" 문구의 kg 값이 used 장비 합과 일치
- [ ] useless 장비 행: 지표 컬럼 왼쪽 44pt 로고 마크(50% 투명) + 본문 50% 투명, 무게 컬럼 정렬 유지, `accessibilityLabel`에 `사용 안 함` 포함
- [ ] 공유 → 링크 복사, 비로그인 브라우저에서 공유 페이지 열람 가능, 해제 후 접근 불가
- [ ] 이름/날짜 수정 → 목록 화면에 반영
- [ ] 메모 작성/삭제 왕복
- [ ] 메모 화면 본문이 **Pretendard로 렌더**된다(시스템 폰트가 아니다 — 다른 화면 본문과 글자 모양을 나란히 대조)
- [ ] 메모 입력 면이 연회색 + **모서리 12**(각진 사각형 아님), 화면 좌우 패딩이 헤더·본문·버튼 영역 모두 24로 같다
- [ ] 메모 완료 버튼이 **라임 알약 + 잉크 글자**(각진 잉크 사각형 아님), 저장 중 인디케이터도 잉크. 비활성일 때 연회색 면 + `textMuted` 글자
- [ ] 메모 화면 내비 타이틀이 `메모`다(빈 제목 아님)
- [ ] 메모 화면 VoiceOver(iOS·Android 양쪽): 뒤로가기 `뒤로가기` · 삭제 `메모 삭제`가 각각 44pt 이상으로 잡히고, 완료 버튼이 `메모 저장` + 비활성 상태까지 읽힌다
- [ ] 액션 그리드 타일: 연회색 면 + 모서리 12 + 부제 `textMuted`(강조 타일만 잉크 면), 그림자 없음
- [ ] 헤더 우측이 필름 카드 + `⋯` 2버튼(웹은 `⋯` 하나) — 복사·공유 아이콘이 따로 없다 (BD-1 헤더 개편)
- [ ] `⋯` → 메뉴 시트에 `복사` → `공유` → `템플릿으로 저장` → `삭제` 4항목, 항목 선택 시 시트가 **완전히 닫힌 뒤**(닫힘 애니메이션 완료 후) 다음 시트/모달이 뜬다
- [ ] 메뉴 `복사` → 복사 모달(타이틀 `배낭 복사`, 이름 프리필) → 복사본 상세 push + 토스트, 뒤로가기 시 원본 상세
- [ ] 메뉴 `공유` → `/bag-share` 시트(기존 공유 아이콘과 동일 동작)
- [ ] 메뉴 `템플릿으로 저장` → 이름 입력 시트 → 저장 토스트, 템플릿 세그먼트에 새 행 ([BagTemplate.md](BagTemplate.md) BT-1과 동일)
- [ ] 메뉴 `삭제` → 시트가 닫힌 뒤 확인 다이얼로그(`{이름} 배낭을 삭제할까요?`, 확인 버튼 `삭제`)가 **반드시 표시**된다 → 확인 시 상세가 닫히고 배낭 목록으로 복귀, 목록에서 해당 배낭이 사라짐 + 담겨 있던 장비의 "배낭 기록"에서도 사라짐
- [ ] 메뉴 `삭제` 다이얼로그에서 취소 → 아무 변화 없이 상세 화면 유지
- [ ] 비로그인 → 메뉴 `복사`/`템플릿으로 저장` 탭 시 시트가 닫히고 **로그인 시트가 실제로 뜬다**(무반응 아님), 취소 후 다시 눌러도 또 뜬다 (BD-11 · [AppLifecycle.md](AppLifecycle.md) APP-10)
- [ ] `[제안]` 메모 삭제를 실패시키면 실패 안내가 화면에 남는다(뜨자마자 사라지지 않음) — BD-6 · APP-9
- [ ] `[제안]` 배낭 삭제·장비 빼기 확인 알럿을 네트워크 차단 상태로 확정 → 알럿이 닫히고 실패 토스트가 뜬다(알럿이 박히지 않음) — APP-9
- [ ] VoiceOver: 헤더에서 `필름 카드 만들기` 다음에 `배낭 메뉴` 버튼이 읽히고, 시트 안 4항목이 각각 읽힘
- [ ] 편집 화면: 검색(이름/브랜드) 동작, 담기/빼기 원형 체크(담김 검정·안 담김 빈 원), 하단 `완료` → 상세로 복귀, 토글 변경사항 반영 (상세 `장비 추가` 경유·생성/복사 직행 두 경로 모두)

## 8. 미해결 질문
