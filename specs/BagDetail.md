## 1. 개요

배낭 1개의 상세 화면과 부속 화면들. 총 무게·카테고리 무게 분해·카테고리별 장비 목록·메모·사용 여부 기록(앱 정체성인 "쓸모없음" 측정)·
링크 공유를 제공한다. 상단 액션은 여행 상태(출발 전/중/후)에 따라 관련 기능을 강조한다(BD-10). (레디샷 기능은 2026-07-21 제거 — 진입 타일이 2026-07-12에 빠진 뒤 어느 화면에서도 도달할 수 없는 상태였다)

### 화면 문법 (as-built, 2026-08-10 — Liquid Depth)

상세(`/bag/[id]`)의 시각만 서술한다. 무엇을 언제 보여주는지는 BD-1~BD-10이 정의한다.

- 지면은 **지형 이미지(0.8) + 위→아래로 짙어지는 베일 + 좌측 중단 라임 글로우**다(홈·패킹과 같은 지면 계열). 화면 좌우 여백은 20, 섹션 사이는 26.
- 크롬은 지면 위에 뜬 **유리**다: iOS는 네이티브 투명 헤더가 원형 글래스 back + 글래스 바 버튼을 내주고(LG-1), Android·Web은 같은 그림을 직접 그린다(원 38 + 아이콘 칸 34짜리 캡슐). 유리 원·캡슐은 패킹 모드와 **같은 공용 프리미티브**(`components/liquid/LiquidGlassCircleButton`·`LiquidGlassCapsule`)에서 나온다 — 두 화면의 크롬이 어긋나면 시스템이 아니라 화면별 장식으로 읽힌다.
- 콘텐츠는 **알약 → 라지 타이틀 → 히어로 카드 → 타일 → 목록** 순으로 쌓인다. 각진 면은 쓰지 않는다(카드 22, 히어로 26, 알약은 height/2).
- **라임 면은 화면에 하나뿐이다** — 히어로 카드의 델타 배지(BD-3). 주 액션(`장비 추가`)은 잉크 면이고, 강조 타일도 잉크다.
- 숫자·기간·무게는 **콘덴스드(Archivo Narrow)**, 한글이 섞이는 값은 본문 서체(Pretendard)를 쓴다. 상황 알약(`여행 예정 · D-6`)은 한글이 섞이므로 본문 서체다.
- 카테고리 그룹 머리글은 큰 제목이 아니라 **대문자 마이크로 라벨**이고, 장비 목록 머리는 `담긴 장비` + 개수 두 조각이다(예전 `총 {n}개의 장비` 한 덩어리를 대상과 수치로 나눴다).

### 부속 화면 문법 (as-built, 2026-08-11 — Liquid Depth)

편집(BD-4)·사용 기록(BD-5)·메모(BD-6)·공유 시트(BD-7)의 시각이다. 목업에 없는 화면이라 이식된
12화면의 관례로 유도 적용했다 — 값의 단일 소스는 `constants/DesignTokens.ts`의 `Liquid*`다.

- **지면**: 편집·메모는 지형 없는 중성 지면 + 우상단 라임 글로우(창고·장비 상세 계열), 사용 기록은
  **패킹 모드와 같은 지형(0.8) + 짙은 베일 + 글로우 없음** — 이 화면은 패킹의 짝이라 같은 지면을 쓴다.
- **크롬**: iOS는 네이티브 투명 헤더(LG-1), Android·Web은 **유리 원형 버튼 + 유리 텍스트 알약**을 직접
  그린다(`LiquidGlassCircleButton`·`LiquidGlassCapsule`). 각진 SVG 아이콘은 걷고 Ionicons로 통일했다.
- **행**: 편집·사용 기록 모두 행 하나가 곧 카드다(radius 20, 그림자 `tile`) — 좌측 정체(브랜드·이름·메타),
  우측 무게(콘덴스드), 그 오른쪽에 26pt 체크 원. 스프링에 `overshootClamping`을 걸고, 상태 전환은
  자리 이동 없이 면과 투명도로만 말한다.
- **입력**: 검색 필드는 떠 있는 유리 알약(h48), 메모는 지면 위 **흰 종이 카드**(radius 22)다. 폼 시트
  (공유·정보 수정)는 종이 면 위에 가라앉은 알약 입력을 얹는다.
- **주 액션은 화면당 하나**이고 전부 잉크 알약(h54, `LiquidPillButton`)이다. 사용 기록의 라임 면은
  진행률 알약 하나뿐이다.

## 3. 요구사항

### BD-1 상세 기본 표시

화면 구성(위→아래): **타이틀 블록**(상황 알약·이름·기간) → **무게 히어로 카드**(총무게·무게 분해 BD-3) → **액션 타일**(BD-10) → **장비 목록**(`담긴 장비` 머리 + sticky 필터 BD-2) → **하단 액션 바**(BD-9).

**수용 기준**

- 내비 바는 뒤로(좌) + 복사·공유·필름 카드 아이콘(우)만 둔다([BagShare.md](BagShare.md) BS-1 — 필름 카드는 웹에서 렌더하지 않아 웹은 2개). **총 무게는 내비 타이틀이 아니다.**
- **상황 라벨은 이름 위 회색 알약**이다(2026-08-10 개정). 출발 전은 `여행 예정 · D-{n}`(당일 `오늘 출발`), 여행 중 `여행 중`, 종료 후 `지난 여행`(`BagDetail.getTripPhase`/`getPhaseLabel`). 구간 이름은 배낭 목록의 섹션 라벨과 **같은 말**을 쓴다([Bag.md](Bag.md) BAG-1) — 한 배낭이 목록과 상세에서 다르게 불리면 안 된다. 알약은 상태 표시라 **탭 대상이 아니다.**
- **배낭 이름을 라지 타이틀**(좌측 정렬)로, 그 아래 여행 기간을 표시한다. 기간은 숫자·구분자뿐이라 콘덴스드 서체를 쓴다.
  - **이름·기간이 길어도 수정(연필) 아이콘이 잘리지 않는다.** 두 행은 각각 텍스트 + 연필 한 행이고, 텍스트가 폭을 양보해 연필이 항상 화면 안에 남는다. 텍스트는 **최대 2줄**까지 줄바꿈하고 넘치면 말줄임한다 — 그 이상 길어지면 헤더가 화면을 잡아먹으므로, 전체 이름은 수정 시트에서 확인·편집한다. 기간 행도 Dynamic Type 확대 시 2줄까지 늘어나 상황 라벨이 잘리지 않는다.
- 이름·기간 행은 각각 탭하면 **`배낭 정보 수정` 네이티브 formSheet**(`/bag-info-edit`, 공용 `BagFormContent` = 이름 입력 + 날짜 범위 달력 + 취소/저장 가로 버튼)를 연다 — 배낭 생성(`bag-new`)/복사(`bag-copy`) 시트와 동일한 UI 언어. 현재 이름·날짜가 프리필되며, 이름 공백은 저장 거부, 날짜는 달력이 역순을 방지한다. 배낭 상세의 model 인스턴스는 뷰 스코프라 정렬 시트와 같은 **모듈 핸드오프**(`BagInfoEditHandoff`)로 현재값·저장 콜백을 전달한다.
- 기간 아래 **흰 히어로 카드**에 총 무게(kg, =`bag.weight`/1000)를 큰 수치로 두고, 같은 카드 안에 **무게 분해**(BD-3)를 항상 표시한다. `총 무게` 라벨은 글자로 두지 않고(`8.4` + `kg` 한 덩어리로 읽힌다) `accessibilityLabel`로만 남긴다.
- 장비 목록은 카테고리별로 그룹핑, 비어 있지 않은 카테고리만 렌더. 그룹 머리는 카테고리명만 표시(소계 없음)하고, 그 그룹의 행은 **하나의 흰 카드** 안에서 0.5px 헤어라인으로 나뉜다.
- 장비 행은 **좌 정체 / 우 수치** 한 줄이다(2026-08-10 개정): 이름(주) 아래 `브랜드 · 색상 · 사용률 {n}%`를 **한 줄 메타**로 잇고 — 값이 없는 조각은 빼 ` · `가 홀로 남지 않게 한다 — 우측에 무게를 콘덴스드로 둔다. 무게는 행마다 같은 자리에 와야 장비끼리 비교된다. (예전에는 브랜드·이름·색상이 각각 한 줄이고 사용률이 별도 배지였다.)
- 장비 행 썸네일 규칙은 창고 목록과 같다([Warehouse.md](Warehouse.md) WH-1) — 사용자가 올린 본인 사진이 있을 때만 표시하고, 없으면 빈 칸 없이 텍스트 우선 행을 쓴다. 업로드는 [GearDetail.md](GearDetail.md) GD-13. **단 공유 배낭(BD-7)에서는 표시하지 않는다**([DataModel.md](DataModel.md) §1 비공개 원칙).
- **장비가 30개를 넘는 배낭도 정상 조회된다.** `bag.gears` → `users/{userId}/gears` 조회는 `where('__name__','in', gears)`라 Firestore `in` 30개 상한에 걸리므로, 30개 단위로 청크 분할해 병렬 조회하고 병합한다([DataModel.md](DataModel.md) DM-25).
  - 이 조회 경로(`BagStore.getBag`/`getSharedBag`)는 **상세·패킹·메모·편집(BD-4)·사용 기록(BD-5)·공유 배낭(BD-7)이 모두 공유**하므로, 한 곳만 고치면 나머지가 남는다.
  - **이 경로에는 사용자가 고르는 정렬이 없다** — 상세는 카테고리 그룹핑(위 항목), 편집(BD-4)은 담김 여부·무게 계산용이라 순서가 화면에 안 드러나고, 사용 기록(BD-5)·공유 배낭(BD-7)에는 정렬 UI가 없다. 창고의 정렬 규칙([Warehouse.md](Warehouse.md) WH-3 — `가벼운순` 0g 뒤로 등)도 여기엔 적용되지 않는다.
  - 다만 **표시 순서는 이름 오름차순으로 고정한다.** 청크 분할 후에는 서버 `orderBy`가 청크별로만 걸려 무의미하므로, 병합 뒤 클라이언트에서 `name` 오름차순으로 정렬한다 — 기준은 Firestore와 같은 **코드포인트 순**(`localeCompare` 아님)이라 30개 이하 배낭과 순서 규칙이 갈리지 않는다. 이 순서는 상세의 카테고리 그룹 **내부** 행 순서, 패킹([Packing.md](Packing.md)), 사용 기록(BD-5), 공유 배낭(BD-7)에 그대로 보인다.
  - `name`이 비어 있는 문서는 **뒤로** 보낸다. 기존 서버 `orderBy('name')`은 이런 문서를 결과에서 아예 제외했으므로, 청크 분할 이후 목록에 새로 나타날 수 있다(사라지는 것보다 낫다는 판단 — `name`은 캐논컬 값이라 실제로는 거의 없다, [DataModel.md](DataModel.md) DM-3).
- 장비 행 클릭 → `/gear-detail/{gearId}`. 행을 **왼쪽으로 스와이프**하면 트레일링 액션 `수정`·`삭제`가 노출된다(배낭 리스트 BAG-4·창고 WH-5와 동일한 `ReanimatedSwipeable` 패턴). `⋮` 더보기 메뉴는 제거한다. `[제안]`
  - `수정` 탭 → `bagDetail.goToEditGear(gear)`(장비 편집 진입). `삭제` 탭(red) → `bagDetail.delete(gear)`(이 배낭에서 장비 제거, 확인 다이얼로그 없음 — 기존 동작 유지). 각 액션은 44pt 이상 히트 영역과 `accessibilityLabel`(`{이름} 수정`/`{이름} 삭제`)을 가진다. `[제안]`

### BD-2 카테고리 필터와 스크롤 동기화

**수용 기준**

- sticky 필터 바에는 **배낭에 담긴 카테고리만** 노출된다.
- 필터 클릭 시 해당 카테고리 섹션으로 스크롤한다.
- 스크롤 시 현재 보이는 첫 카테고리가 필터에 자동 선택되고, 선택된 칩이 가로 스크롤로 화면에 들어온다.
- iOS는 필터 줄이 두 벌 존재한다(스크롤 안 인라인 + 핀 상태 유리 띠 오버레이, §2 화면 문법). 모델의 필터 ref 슬롯은 **단일**이므로 **그때 보이는 한 벌만** 등록하고, 가려진 쪽은 ref 등록과 접근성 노출을 함께 넘긴다 — 두 벌이 등록하면 나중 마운트가 앞을 덮어쓰고 언마운트 후 복원되지 않아 칩 자동 스크롤이 죽는다.

### BD-3 무게 분해 (카테고리 비중)

**수용 기준**

- 총 무게 수치 바로 아래, **같은 히어로 카드 안에** 스택 바 + 인라인 범례(`● 카테고리 {%}`)로 무게 분해를 **항상** 보여준다. (접기/펼치기·별도 차트 화면 없음 — 히어로 카드에 통합.)
- `배낭/텐트/침낭/매트`는 `베이스`로 묶어 집계한다.
- 항목은 무게 비중 내림차순 정렬, **8색 팔레트를 순환 사용한다**: 앞 5칸은 배낭 카테고리 의미색(`catBase`·`catClothing`·`catCooking`·`catSafety`·`catEtc` — 변경 금지 대상), 카테고리가 더 많은 배낭을 위해 뒤에 중립 잉크 3단을 잇는다. 세그먼트는 사이 간격 3에 각각 모서리를 깎아(radius 5) 이가 빠져 보이지 않게 한다.
  - 목업 §6은 이 자리를 `ink/limeInk/lime/…` 무채색 램프로 그렸으나 **채택하지 않았다**: 라임을 데이터 색으로 쓰면 라임 면이 화면에 둘(델타 배지 + 세그먼트)이 되고, 카테고리 의미색을 바꾸지 않는다는 규칙과도 어긋난다.
- **줄일 수 있는 무게 델타 배지**(2026-08-10 신설): 사용 기록(BD-5)이 있는 배낭에서 `총 무게 − usedWeight`가 0보다 크면 총 무게 우측에 라임 알약 `-{n}kg`(하강 화살표 아이콘)을 붙인다. 앱의 정체성인 값이라 **이 화면의 유일한 라임 면**을 여기 쓴다. 기록이 없거나 차이가 0이면 배지를 달지 않는다. 총 무게 행은 배지까지 **한 덩어리로 읽는다** — 행 하나를 접근성 요소로 묶고 라벨을 `총 무게 {n}kg, 사용 기록 기준 {m}kg 줄일 수 있어요`로 합친다(부모가 `accessible`이면 자식 라벨은 개별로 읽히지 않으므로 배지에 따로 달지 않는다).

### BD-4 장비 편집 (담기/빼기)

**수용 기준**

- 편집 화면은 창고 전체 장비를 필터/정렬/검색과 함께 보여준다. **검색 인풋**(이름/브랜드 클라이언트 필터, 결과 없으면 `검색 결과가 없어요`)을 `내 장비` 타이틀 아래·필터 칩 위에 둔다([Warehouse.md](Warehouse.md) WH-8과 동일). 정렬은 하단 바텀시트(WH-3) — 옵션 구성·저장 방식·**`가벼운순`에서 무게 미입력(0g)을 뒤로 보내는 규칙**이 창고와 같다. 단 **정렬 선택값은 창고와 공유되지 않는다**(`selectedOrderType_` 저장 키가 창고는 `warehouse`, 배낭 편집은 `bag`).
- 담기/빼기 선택은 **원형 체크 배지**로 표시한다(담김=잉크 원 + 라임 체크가 팝 애니메이션, 안 담김=빈 원 1.5px). 패킹(PK)·사용여부(BD-5)와 같은 체크 인터랙션 계열. 단 편집은 창고 전체를 훑는 맥락이라 행 dim·면 낮춤을 쓰지 않는다 — **모든 행이 흰 종이 카드로 떠 있고 담김 여부는 체크 원 하나가 말한다**(2026-08-11 as-built). 행 전체가 토글이며 스크린리더에는 `checkbox` 롤로 읽힌다.
- **필터 칩은 개수를 라벨에 붙인다**(2026-08-11 as-built — `의류 5`). 별도 카운트 배지를 겹치면 알약이 두꺼워지고, 숫자는 그것이 세는 대상과 한 덩어리로 읽혀야 한다(카피 규칙). 칩 줄은 화면 좌우로 블리드해 스크롤이 가장자리에서 끊기지 않는다.
- 장비 토글 시 헤더의 총 무게가 실시간 갱신된다(선택 장비 `weight` 합 / 1000).
- **토글할 때마다 즉시** 트랜잭션 `BagStore.save`가 실행된다(이탈 시 일괄 저장 아님): `bag.gears`/`bag.weight` 갱신 + 추가 장비의 `bags`에 ID 추가 + 제거 장비의 `bags`/`used`/`useless`에서 ID 제거.
- `bag.weight`는 담긴 전체 장비의 `parseInt(weight)` 합으로 다시 계산해 저장한다.
- "장비 추가" 버튼(헤더 우측 아이콘) → **장비 추가 선택 시트(`gear-add-options`, 배낭 컨텍스트 `bagId` 전달)** 를 연다([GearEdit.md](GearEdit.md) GE-8). 두 갈래: `검색으로 추가`(카탈로그 검색 → **이 배낭에 바로 담기**, GE-8) / `직접 입력`(`/custom/bag-gear/{bagId}` 수동 폼, 저장 시 이 배낭에 추가).
- 하단에 고정 `완료` 버튼을 표시한다. 누르면 배낭 상세로 돌아간다. (변경사항은 토글마다 이미 저장돼 있으므로 추가 저장은 없다 — 버튼은 편집 종료 신호.)

### BD-5 사용 여부 기록 (useless)

여행 후 실제로 사용한 장비만 체크해 "줄일 수 있는 무게"를 확인하는 핵심 기능.

**수용 기준**

- 진입 문구: 기록 전 `사용 여부 기록하고 줄어든 무게 확인하기`, 기록 후 `사용한 제품만 측정해보니 {usedWeight}kg 까지 줄어들어요`.
- `usedWeight` = 이 배낭에서 `used`에 기록된 장비 무게 합(kg, 소수점 둘째 자리 반올림).
- 기록 화면 초기 상태: `useless` 포함 → 미선택, `used` 포함 → 선택. **배낭 전체에 기록이 하나도 없으면** 전체 선택으로 시작한다. 단, 기록이 일부라도 있는 배낭에서는 미기록 장비가 **미선택**으로 표시된다(미해결 질문 참조).
- 기록 화면은 **패킹 모드와 동일한 진행 카드**를 둔다: 선택/전체 카운트(콘덴스드 `{선택} / {전체}`) + 라임 퍼센트 알약 + 프로그레스 바(선택/전체 비율, 잉크 채움) + **사용/총 무게**(`{선택kg}kg / {전체kg}kg`). 카드는 지면 위에 뜬 유리 면(radius 26)이다(2026-08-11 as-built — 예전에는 지면 위 텍스트 + 각진 라임 바였다).
- **전체 선택/해제 토글은 내비 바에 둔다**(2026-08-11 as-built): iOS는 `headerRight` 텍스트 버튼, Android·Web은 유리 텍스트 알약 — 패킹 모드의 `처음부터 다시`와 같은 자리다. 진행 카드 안에 두면 라임 퍼센트 알약과 자리를 다툰다.
- 장비 행은 **패킹 모드 행과 동일한 인터랙션**: 원형 체크 배지 + 상태 애니메이션. 단 **가라앉는 쪽이 반대다** — 쓴 장비가 흰 종이 카드로 떠 있고, **미선택(안 쓴) 장비가 `surfaceDone` 면 + 본문 낮춤**으로 내려앉는다(선택=흰 면 + 잉크 원 + 라임 체크). 항목은 지우거나 자리를 바꾸지 않는다.
- 완료 시 각 장비의 `used`/`useless` 배열에 배낭 ID를 반영해 일괄 저장한다(`GearStore.updateGears`).
- 이 화면에는 **정렬 UI가 없다.** 장비는 이름 오름차순으로 표시하며(BD-1), 정렬 선택 개념 자체가 없으므로 창고의 정렬 규칙([Warehouse.md](Warehouse.md) WH-3 — `가벼운순` 0g 뒤로 등)은 여기에 적용되지 않는다.
- 상세의 장비 목록에서 useless 장비는 **44pt useless 로고 마크(50% 투명)** + **행 본문 낮춤**으로 표시한다. 본문 투명도는 완료·미사용 항목 공통값을 쓴다(2026-08-10 개정: 50% → `doneOpacity` 0.6 — 목록에서 지우지 않고 무게만 빼는 표현을 앱 전체에서 한 값으로 맞춘다). 장비 이미지 미제공([DataModel.md](DataModel.md) §1)으로 썸네일이 폐지돼 오버레이를 얹을 숙주가 없어졌기 때문에 로고를 독립 배치하되, 행이 좌 정체·우 지표 2열([Warehouse.md](Warehouse.md) WH-1 공통 행 레이아웃)이 되면서 **지표 컬럼(무게)의 왼쪽**에 둔다 — 무게 컬럼의 세로 정렬이 useless 행에서도 깨지지 않게 한다(공용 행 컴포넌트의 `aside` 자리). 행 `accessibilityLabel`에는 `사용 안 함`을 포함해 시각 표기에만 의존하지 않는다.

### BD-6 메모

**수용 기준**

- 멀티라인 입력, 완료 버튼은 trim 후 내용이 있을 때만 활성화. **입력은 지면 위 흰 종이 카드**(radius 22 + 카드 그림자)이고 완료는 잉크 알약이다(2026-08-11 as-built) — 가라앉은 채움은 지면과 붙어 입력 영역 경계가 사라진다. 저장 중에는 라벨을 유지한 채 앞에 인디케이터를 붙인다.
- 삭제 아이콘은 파괴적 액션이라 의미색(`danger`)을 유지한다 — 리디자인 대상이 아니다.
- 삭제 버튼은 기존 메모가 있을 때만 노출되고, 확인 모달 후 빈 문자열로 저장한다.
- 상세 화면에는 메모가 있으면 내용, 없으면 `메모 작성하기` 링크를 표시한다.

### BD-7 링크 공유

**수용 기준**

- 공유 버튼 → **네이티브 formSheet**(`/bag-share`, 배낭 생성/복사/정보수정 시트와 동일한 UI 언어) → 공유 시 `bag.shared = true`로 갱신하고 `{웹 베이스}/bag-share/{bagId}` 링크를 클립보드에 복사한다(웹 베이스는 `constants/WebLinks.ts`의 `WEB_BASE_URL` 단일 소스 — 2026-07-28 `useless.my` → `https://lessismore-7e070.web.app`). 시트는 공유 상태를 관찰(observer)해 공유 중이면 링크 행 + `공유 취소`를 표시한다. BagDetail 인스턴스는 `BagShareHandoff` 모듈로 전달한다.
- **시트 시각 (as-built 2026-08-11 — Liquid Depth)**: 종이 면 시트에 제목(22/700) → 설명(14 보조 잉크) → 공유 중이면 링크 면(가라앉은 타일 radius 20 + 복사 아이콘 — 아이콘 전용 컨트롤이라 링크 줄 높이를 밀지 않는 28 프레임 + `hitSlop` 8로 **44×44pt**를 채운다) → 하단 잉크 알약(h54) 하나다. 처리 중에도 **라벨을 유지하고 앞에 인디케이터만 붙인다**(예전 `처리 중...`으로 라벨을 갈아 무엇을 기다리는지 사라졌다).
- 공유 해제 시 `shared = false`.
- 공유 조회(`BagStore.getSharedBag`)는 `shared === true`를 확인하고, 아니면 `공유되지 않은 배낭입니다.` 알럿을 띄운다. 장비는 `bag.userId` 경로의 `users/{userId}/gears`에서 읽는다.
- **공유 화면에는 장비 사진이 오지 않는다**([DataModel.md](DataModel.md) §1 비공개 원칙, 2026-07-29). 이 조회는 소유자의 `users/{userId}/gears`를 읽지만 **보는 사람이 업로더가 아니므로**, 뷰에서 거르는 대신 **데이터 레이어에서 `imageUrl`을 애초에 채우지 않는다**(`getSharedBag`은 사용자 문서용 정규화를 쓰지 않는다). 뷰 차단은 화면이 늘 때마다 빠뜨릴 수 있어 경로 자체를 막는 편이 안전하다. 같은 이유로 박지 후기에 첨부된 배낭([CampSite.md](CampSite.md) CS-8)에서도 표시되지 않는다.

### BD-8 배낭 복사

사용자는 보고 있는 배낭을 상세 화면에서 바로 복제할 수 있다.

**수용 기준**

- 헤더 우측 공유 아이콘 왼쪽에 복사 아이콘을 표시한다 (44pt 이상 히트 영역).
- 복사 아이콘 → 복사 모달을 띄운다. 모달·프리필(`{이름} 복사본`)·날짜 기본값·확정·토스트 동작은 [Bag.md](Bag.md) BAG-4와 동일하다.
- 확정 시 복사본 상세를 push로 열고 **곧바로 장비 편집 화면을 연다** (뒤로가기 → 복사본 상세 → 원본 상세).

### BD-9 하단 액션 바 (패킹 + 수정)

**수용 기준**

- 상세 하단에 고정 **액션 바**를 둔다: **`장비 추가`(주 버튼, 잉크 알약, 남은 폭 flex)** + 패킹 노출 조건 충족 시 그 왼쪽에 **패킹(보조 = 유리 알약 + `bag-check` 아이콘)**. 두 버튼 모두 높이 54 알약이고, 바 자체에는 면을 깔지 않는다 — 흰 띠가 버튼 주위를 감싸면 지형이 끊긴다. (기존 우하단 플로팅 버튼은 폐기 — 장비 행을 가리던 문제 해소.)
- `장비 추가` → 장비 편집(BD-4)으로 이동. 라벨이 `수정하기`였을 때는 이 버튼이 무엇을 수정하는지(이름? 날짜? 장비?) 모호했다 — 실제로 여는 화면은 창고에서 장비를 고르는 편집 화면 하나뿐이라 동작을 그대로 라벨에 쓴다(2026-08-05).
- 패킹 버튼의 노출 조건·상태별 라벨(`패킹 시작`/`패킹 {n}/{m}`/`패킹 완료`)·이동 동작은 [Packing.md](Packing.md) **PK-1**을 따른다.

### BD-10 상세 액션 그리드 (상황형)

**수용 기준**

- 히어로 카드 아래에 **2열 그리드**로 액션 타일을 둔다: 사용 기록(BD-5)·메모(BD-6)·여행지([BagDestination.md](BagDestination.md) DST-2)·운동 기록([HealthActivity.md](HealthActivity.md) HA-1 `[기획]` — 권한 없음·웹·미래 여행이면 렌더하지 않아 3개로 줄 수 있다). 각 타일은 **흰 종이 면**(radius 22, 최소 높이 96)에 아이콘(위) + 제목 + 현재값 부제(아래)를 담는다. (레디샷 타일은 2026-07-12 제거, 기능 자체도 2026-07-21 제거)
- **상황형 강조**: 여행 상태에 따라 관련 타일 하나를 **잉크 면 + 라임 아이콘**으로 뒤집고 그리드 **첫 칸**에 둔다 — `지난 여행`이면 `사용 기록`, `출발 전`·`여행 중`이면 `여행지`. 강조 타일도 다른 타일과 **같은 크기·같은 세로 레이아웃**이다(2026-08-10 개정: 예전 서술의 `전체 폭 가로 카드`는 구현된 적이 없고, 목업 §6도 2×2의 첫 칸만 잉크로 그린다). 강조는 **그리드에서 한 장만** 켠다.
- 사용 기록 타일 부제: 기록됨 → `{usedWeight}kg로 줄어요`, 미기록·지난 여행 → `줄어든 무게 확인`, 미기록·출발 전/중 → `여행 후 기록`.
- 여행지 타일: 미설정이면 `여행지 선택`을 표시하고 탭 시 공용 지도 선택기를 바로 연다. 설정됨이면 위치명을 주 정보로 표시하고, 날씨가 있으면 상태(`비/눈/맑음`) + 기간 `{최저}~{최고}°`를 보조 정보로 표시한다. 등록된 박지는 위치명 앞에 `📍`를 표시한다.
- 여행지가 설정된 타일을 탭하면 `/bag/{id}/weather`로 이동하고, 사용자 노출 화면 제목은 `여행지`로 표시한다(DST-2).

## 6. 엣지 케이스

- **빈 배낭**: 총 무게 0kg, 무게 분해 바·범례 없음, 필터 없음. 목록 자리에는 **사실 + 다음 걸음 두 줄**(`담긴 장비가 없어요` / `창고에서 장비를 골라 담아보세요`) + `장비 추가하기` 알약을 둔 카드를 그린다 — 하단 바와 같은 경로·같은 로그다. 단 **주 액션은 하단 바 쪽 하나**라 카드 안 알약은 조용한 위계(흰 면 + 아웃라인)로 낮춘다.
- **긴 배낭 이름**: 라지 타이틀이 2줄까지 늘어나고 넘치면 말줄임, 수정(연필) 아이콘은 화면 안에 남는다(BD-1).
- **삭제된 장비 참조**: `bag.gears`에 ID가 남아 있어도 실제 조회된 문서만 매핑되어 자동 무시된다.
- **장비 30개 초과**: 청크 분할로 정상 조회된다(BD-1, [DataModel.md](DataModel.md) DM-25). 분할 전에는 `in` 상한 예외가 던져져 상세·패킹·메모·편집·사용 기록이 초기화에 실패하고(편집은 `loading` 플래그가 고정돼 재진입도 막혔다), 공유 배낭은 예외가 삼켜져 **`공유되지 않은 배낭`으로 오표시**됐다.
- **로딩**: 상세 `BagDetailSkeletonView`, 편집/useless는 초기화 전 미렌더.

## 7. 수동 검증 체크리스트

- [ ] 편집에서 장비 추가/제거 → 상세 총 무게·무게 분해·필터 즉시 반영
- [ ] 장비 30개 초과 배낭: 상세·패킹·메모·편집·사용 기록·공유 링크가 모두 열리고 장비가 전부(31개째 이후 포함) 보인다
- [ ] 장비 30개 초과 배낭과 30개 이하 배낭 모두 장비가 **이름 오름차순**으로 표시된다(청크 경계에서 순서가 끊기거나 같은 장비가 중복되지 않는다) — 상세의 카테고리 그룹 내부·패킹·사용 기록·공유 배낭 공통
- [ ] 이 변경 전후로 기존 배낭의 장비 행 순서가 **그대로**다(회귀 없음)
- [ ] 타이틀 블록: 상황 알약(`여행 예정 · D-6` / `여행 중` / `지난 여행`) → 이름 라지 타이틀 → 기간
- [ ] 무게 히어로 카드: 총 무게 + 스택 바·범례가 한 카드 안에 있고, 사용 기록이 있는 배낭에만 라임 델타 배지(`-{n}kg`)가 붙는다 (기록 없는 배낭에는 라임 면이 하나도 없다)
- [ ] 장비 행: 이름 + `브랜드 · 색상 · 사용률` 한 줄 + 우측 무게, 카테고리별 흰 카드 안에서 헤어라인으로 나뉜다
- [ ] 이름을 화면 폭보다 길게 지정 → 타이틀 2줄 말줄임, 수정(연필) 아이콘이 화면 안에 온전히 보임 + 탭하면 수정 시트 열림
- [ ] 액션 그리드 상황형 강조: 지난 여행=사용 기록 잉크 / 출발 전·중=여행지 잉크, 잉크 타일은 그리드 첫 칸 한 장뿐이고 나머지와 크기가 같다
- [ ] 여행지 미설정 타일 → 지도 선택기 바로 열림 / 설정 타일 → `여행지` 화면 이동
- [ ] 여행지 타일 → 위치명 주 정보 + 날씨 상태·기온 보조 정보, 등록 박지는 `📍` 표시
- [ ] 하단 바: 장비 추가(주) + 패킹(보조), 플로팅 없음·장비 행 안 가림
- [ ] 사용 여부 기록 화면: 진행 헤더(카운트·바·사용/총 무게) + 행 원형 체크·미선택 dim
- [ ] 사용 여부 기록 → "줄어들어요" 문구의 kg 값이 used 장비 합과 일치
- [ ] useless 장비 행: 지표 컬럼 왼쪽 44pt 로고 마크(50% 투명) + 본문 낮춤, 무게 컬럼 정렬 유지, `accessibilityLabel`에 `사용 안 함` 포함
- [ ] 공유 → 링크 복사, 비로그인 브라우저에서 공유 페이지 열람 가능, 해제 후 접근 불가
- [ ] 이름/날짜 수정 → 목록 화면에 반영
- [ ] 메모 작성/삭제 왕복
- [ ] 헤더 복사 아이콘 → 복사 모달(타이틀 `배낭 복사`, 이름 프리필) → 복사본 상세 push + 토스트, 뒤로가기 시 원본 상세
- [ ] 편집 화면: 검색(이름/브랜드) 동작, 담기/빼기 원형 체크(담김 검정·안 담김 빈 원), 하단 `완료` → 상세로 복귀, 토글 변경사항 반영 (상세 `장비 추가` 경유·생성/복사 직행 두 경로 모두)

## 8. 미해결 질문

- 기록이 일부 있는 배낭에서 미기록 장비가 미선택으로 시작하는 동작(BD-5)이 의도인지 확인 필요 — "기록 없음 = 사용으로 간주"가 의도라면 버그.
- `BagEdit.save()`는 호출처가 없는 데드 코드(토글마다 즉시 저장이므로) — 정리 후보.
